    datamunge::sim

    Native rigid-body physics and batched reinforcement-learning rollouts.

    datamunge/sim/articulation.hpp

    Classes

    ArticulationBody identifiers for one model instance, scoped to its borrowed world. Copies contain identifiers only; removing bodies invalidates those identifiers.
    UrdfModelImmutable native URDF dynamics/collision model, independent of rendering and MuJoCo. Supports rooted trees, fixed/revolute/continuous/prismatic joints, affine mimic gearing, full rotated COM tensors, and box/sphere/cylinder/STL collision geometry. Cylinders use 32-sided hulls; meshes use deterministic sampled convex hulls (concavities require multiple collision elements). Missing inertias are rejected unless explicitly given nominal import options. Copies share immutable geometry.
    UrdfPhysicsOptionsExplicit physical import approximations for URDF collision meshes and missing inertias. Source units are metres/radians/kg. No external physics engine is used.

    datamunge/sim/batch.hpp

    Classes

    BatchWorldFixed-size collection of independent native worlds for CPU rollouts. Construction deep-copies a prototype, including pending forces and solver state. Stepping/reset reuse reserved storage; capture_reset allocates during setup. Each world has an independent deterministic random stream. Streams advance across episode resets; reseeding is explicit. Single-writer: do not mutate worlds concurrently with a batch operation. GPU physics is not yet supported.

    datamunge/sim/conveyor.hpp

    Classes

    ConveyorEnvironmentA headless, single-payload conveyor and two physical sorting bins. Uses the native rigid-body solver at 240 Hz, SI units and Y-up coordinates. A friction-driven belt stops when the centre crosses X=0.10 m; the next fruit cannot spawn until the current one is sorted, missorted or lost. Basic apples use a 78 mm sphere proxy; bananas use a 160 by 46 mm capsule proxy. Diverse selects six meshes per class and scales/rotates the corresponding proxy; entry X is [-1,-.7] m, across-belt Z is [-.065,.065] m, yaw is [0,2*pi), and pitch/roll are [-.12,.12] rad. Appearance draws are shared across classes. Payload rotation is locked as a stable initial manipulation approximation. Bins are centred at (0.10, 0.44, +/-0.42) m; the negative-Z bin is for apples. The workcell includes a pedestal at X=0.62 m, ready for a Z-up URDF visual translated to CAD (0.62,0,0.72). Robot actuation, grasping and arm collision geometry belong to the external controller; this class does not infer them from visual CAD. world() exposes forces/body edits for later control tasks. Instances are single-writer; reset(seed) repeats the same fruit sequence.
    ConveyorObservationOwned observation, using physics coordinates X along belt, Y up, Z across belt. CAD scene methods convert to X along belt, Z up, Y across belt.
    FruitAppearanceSeeded rendering/shape parameters, independent of camera or policy predictions. Prototype IDs 0..5 have separate apple/banana geometries. The skin palette is shared by both classes to prevent a red-versus-yellow color shortcut.

    Types and constants

    ConveyorStageenum Latched arrival and placement status of the single active payload.
    FruitKindenum Payload identity; default sorting maps apples to red and bananas to yellow.
    FruitVariationenum Reproducible fruit-domain protocol; Basic preserves earlier checkpoints/examples.

    datamunge/sim/devarm_camera.hpp

    Classes

    DevArmWristCameraFixed wrist camera with native CPU RGB rendering, matching the real URDF pose. The mount is end_link local (-.09,-.075,.045) m, viewing local (.13,0,0), with local +Z as image-up. These extrinsics never track fruit coordinates. Intrinsics are square pixels, configurable vertical field of view, and a 2 mm near plane. capture() includes real arm self-occlusion and static geometry. Simple backgrounds are cached while joint/finger coordinates stay identical. The attached owner's Realistic visual profile renders complete scenes with shared materials and studio lighting, including cross-object shadows. Validated static/robot triangles are retained while joint/finger coordinates are unchanged; moving actors are always prepared from the supplied frame. The realistic base-only RGB/depth/ID image is retained at that exact pose. Empty actor captures return independent copies; registered references reuse those same base pixels when no non-fruit objects remain. Other reference actors are always rendered afresh. Caches do not alter samples or lighting. The borrowed environment must outlive this single-writer camera.
    ImageBoxPixel bounds of the visible RGB foreground, with exclusive right/bottom edges. Empty detections have zero width/height. Coordinates refer to the raw camera image.
    WristInspectionUnannotated wrist RGB, a foreground box and a square padded RGB classifier crop. The registered empty-scene RGB reference supplies localization; no depth, IDs, fruit coordinates, semantic label or classifier prediction determines the box.

    datamunge/sim/devarm_pick.hpp

    Classes

    DevArmPickEnvironmentHeadless DevArm pick-and-place environment with a caller-selected bin objective. Nine actions operate a bounded Cartesian lattice; numerical IK drives the six real URDF joint coordinates, clamped to limits and limited to 1.5 rad/s. IK accepts up to 12 mm position residual and uses a soft wrist-down preference. The grasp point is end_link local (-.02,0,0) m, between the finger tips. Tool and carried-payload collision guards reject moves through workcell solids. The grasp is an ideal proximity latch with size-dependent jaw aperture and payload orientation stabilization; opening restores dynamic gravity/contact physics. Robot servos are kinematic: this is not torque control, a full mesh-collision robot simulator, or hardware deployment. Observations are privileged state, not image observations. Instances are single-writer and own independent worlds.
    PickObservationOwned state and render frame in CAD Z-up metres and URDF radians.
    PickPolicyFrozen tabular Q-learning policy with a portable text checkpoint. Rows match state_space_size() for the training protocol and nine actions. Basic tables have 2971 rows; Diverse tables have 8911 and must be retrained.
    PickTrainingResultPer-episode learning evidence and the final, frozen policy.

    Functions

    train_pick_bin()Train native Q-learning for an explicitly requested bin, independent of fruit class. Pair the returned table with the same set_destination() value at inference; Q checkpoints do not encode goal metadata. See train_red_bin() for algorithm details.
    train_red_bin()Train model-free, epsilon-greedy tabular Q-learning from real task transitions. Reuses the canonical algorithms::q_learning implementation with alpha=.3, gamma=.98 and epsilon=.25. No demonstrations, scripted policy or action masking are used. Every training reset selects Red; train_pick_bin() also supports Yellow. Evaluation must use separate seeds and the returned frozen policy.

    Types and constants

    PickActionenum Cartesian 30 mm servo motions and proximity-gripper commands.
    PickBinenum Requested placement goal, independent of the payload's ground-truth class.

    datamunge/sim/fruit_stream.hpp

    Classes

    FruitStreamEnvironmentNative continuing multi-fruit conveyor, real-URDF servos and asynchronous outcomes. The belt always runs at .22 m/s. Independent exponential inter-arrival times are scheduled even during arm motion, and insertion is quantized by at most one 1/240-second physics tick. Fruit passing X=.30 m is missed. There is no between-pick reset, teleport, stopped belt or hidden queue at the source. An opt-in training_proxy accelerates empty/servo intervals using analytic belt transport and a .4 s bin-settling approximation, omitting fruit-fruit contacts. Arrivals and task rewards are shared, but the proxy is incompatible with articulated dynamics and is not physics evidence. Use articulated_physics for contact-based learning/evaluation; it imports link inertias/collision hulls and simulates finite actuator effort, free payload rotation, slip and physical release momentum. Interception options target the oldest/second-oldest observed fruit, inspect it through a supplied classifier, time a descending grasp, lift, traverse and release. Fixed IK servos are not learned torques; the scheduler is trainable. The default perception channel is explicitly SYNTHETIC and intended for fast RL training, with configured class-error probabilities. Supply set_perception() for actual RGB evaluation; unknown predictions never use true-label fallback. With watch_infeed enabled, reset starts at a camera-aimed entry observation pose. Empty-queue waits return there via guarded, rate-limited waypoints; the next decision can interrupt after 0.125 seconds. This orients the real rigid camera, not a virtual pan. Queue state still uses privileged tracking, not RGB detection. Instances are single-writer; callbacks must not mutate the environment.
    FruitStreamOptionsConfiguration of an unbounded-time, bounded-memory sorting workcell. Arrivals are never postponed for a busy arm. At capacity, arrivals are counted as overflow misses. Outcomes are removed after two seconds (self-emptying bins). Legacy mode stabilizes orientation and uses ideal latches. Articulated mode integrates free rotation, force-limited servos and physical grasps. Motor geometry remains privileged state; nominal physics is not a hardware calibration.
    StreamCountersCumulative event counts since the one initial reset; unresolved fruit remain explicit.
    StreamFrameOwned frame of a continuing world, suitable for deterministic video replay.
    StreamFruitRecorded payload geometry, scheduling and latched classifier prediction.
    StreamPolicyVersioned finite scheduler table; learned choices never select a bin from true labels.
    StreamPredictionImage classifier output; an unknown result leaves the fruit unhandled.
    StreamTrainingOptionsDuration-aware Q-learning controls for independent truncated continuing rollouts. No artificial terminal reward is applied at a rollout boundary; the target bootstraps with discount_per_second raised to the measured option duration.
    StreamTrainingResultPer-window learning evidence and final frozen scheduler.
    StreamTransitionOne continuing semi-Markov transition, including all arrivals/misses during a servo option.

    Functions

    articulated_physics_version() ×2Report the optional articulated engine version, without creating a simulation.
    stream_learning_environment()Borrow a continuing workcell as a native discrete learning environment. Independent reset seeds map deterministically to a uniform arrival-rate curriculum, separate from policy/replay RNGs. Keeps perception/recorder callbacks; the caller owns the single-writer environment for the returned callbacks' lifetime.
    train_fruit_stream()Train a continuing hierarchical Q scheduler using measured option transitions. Uses independent randomized stream windows, no termination bootstrap, and fixed low-level IK options. The supplied environment's perception channel is retained; the default is an explicit, calibrated synthetic training channel. Optional replacing Watkins traces propagate delayed placement rewards across earlier options. Next behavior is selected before Q updates; nongreedy behavior clears traces. Decay is discount_per_second^elapsed_seconds times trace_decay per decision, with traces below 1e-8 pruned and independent windows cleared. Optional action masking applies to exploration, greedy choice and bootstrapping.

    Types and constants

    StreamActionenum Duration-varying interception options for a continuously moving belt. Options use fixed, rate-limited IK servos; Q-learning selects timing/target/gate.
    StreamFruitStatusenum Physical lifecycle of one fruit; outcome counters never depend on held poses.

    datamunge/sim/tasks.hpp

    Classes

    TaskBatchBatched native InvertedPendulum or Hopper rollouts without a graphics dependency. CPU worlds use persistent parallel workers. Actions and all output arrays are finite double precision, with no NN dependency. Single-writer, including reset. Invalid actions fail before forces are applied. A native solver error propagates; reset selected worlds before retrying after such an error. Reset uses small independent uniform joint perturbations and never touches another row's RNG.
    TaskOutputPreallocated observations, rewards and independent episode-end flags. Observations are row-major [environments,observation_size]. Terminal observations stay in final_observations until the next terminal transition for that index. No auto-reset occurs. Masked-out rows keep all previous values.

    Types and constants

    Taskenum Built-in native rigid-body control task, using SI units and Y-up coordinates. These are datamunge task definitions, not numerical replicas of another simulator.

    datamunge/sim/types.hpp

    Classes

    BodyOwned rigid-body creation and edit parameters; no dependency on a renderer. Coordinates use SI units. Validation matches the implemented VSim component ranges. Quaternion input must already be unit length within 1e-6.
    ColliderImmutable local convex geometry and its transform within a rigid body. Dimensions are full extents in metres. ConvexHull uses vertices instead. Shared vertex storage must remain immutable for the lifetime of bodies/snapshots.
    JointA joint from a dynamic child to a parent body or the fixed world. Anchor/axis are in the child's rotated local frame; coordinate zero is its authored pose. Connected bodies do not collide. Each child has at most one joint.
    JointStateJoint coordinate/rate pair in radians/radians per second or metres/metres per second.

    Types and constants

    BodyIdtype Body identifier scoped to one world's lifetime; zero is reserved for the world.
    JointTypeenum Joint type with one unconstrained generalized coordinate.
    Motionenum Body motion classification.
    Quaterniontype Unit quaternion in w,x,y,z order, right-handed with Y up.
    Shapeenum Convex collision primitive; all dimensions are full extents.
    Vec3type Three Cartesian components, in metres or SI units specified by the field.

    datamunge/sim/workcell_visuals.hpp

    Functions

    workcell_lights()Construct consistent workcell lights for external and wrist views.
    workcell_presentation()Build an independent exterior presentation copy without changing the calibrated sensor scene. Refines floor/rubber/plastic/metal finishes and seeded fruit surface maps, retaining source meshes/transforms and brand/fruit hues. Optional factory context and a cosmetic flexible servo harness add visual geometry only. Lighting is a warm key, cool fill and rim. Apply once to each fresh component; pass robot link-derived anchors again when constructing a new joint pose. The function is deterministic, consumes no domain RNGs and creates no physics bodies. Keep the original scene for wrist RGB and classifier calibration.
    workcell_presentation_options()Full-quality exterior settings with antialiasing and analytic studio reflections. Uses 2x2 primary sampling, six soft-shadow rays and three local occlusion rays per hit, plus a 0.55-strength analytic studio environment. The CPU wrist sensor's workcell_render_options() is unchanged. This approximates studio illumination rather than tracing scene reflections or multiple light bounces.
    workcell_render_options()Configure native render quality for a workcell view. Realistic enables linear-light microfacet shading, tone mapping, soft shadows and local occlusion. Sensor-sized views use fewer samples for training speed.

    Types and constants

    WorkcellVisualStyleenum Rendering-only workcell profile; collision geometry and random arrivals are unchanged. Simple preserves earlier examples. Realistic adds rounded fixtures, hardware, surface maps, botanical fruit detail and studio lighting. Its fruit tints use overlapping natural green/gold/russet palettes rather than saturated debug colors.

    datamunge/sim/world.hpp

    Classes

    ContactOne solved contact point between two body identifiers. Normal points from first to second; separation is signed (negative penetration). Sensor contacts are observations only and carry no response impulse.
    PhysicsStateOwned solver snapshot including contacts, velocities, sleeping state and joint warm starts. It can be restored only into the same world with unchanged topology/configuration. Default construction is empty. Copies share immutable snapshot storage.
    WorldA library-owned, noncopyable native physics world; no window or external physics runtime. World methods are single-writer; use independent worlds for parallel rollouts. Bodies are world-scoped positive IDs, never reused. External input is validated before mutation. A failed solve restores the pre-step state. Snapshots retain solver state and must not be confused with authored scene serialization.
    WorldOptionsExplicit fixed-capacity physics controls; capacities reserve reusable working memory.
