    ConveyorEnvironment

    class ConveyorEnvironment
    #include <datamunge/sim/conveyor.hpp> source

    A headless, single-payload conveyor and two physical sorting bins. Uses the native rigid-body solver at 240 Hz, SI units and Y-up coordinates. A friction-driven belt stops when the centre crosses X=0.10 m; the next fruit cannot spawn until the current one is sorted, missorted or lost. Basic apples use a 78 mm sphere proxy; bananas use a 160 by 46 mm capsule proxy. Diverse selects six meshes per class and scales/rotates the corresponding proxy; entry X is [-1,-.7] m, across-belt Z is [-.065,.065] m, yaw is [0,2*pi), and pitch/roll are [-.12,.12] rad. Appearance draws are shared across classes. Payload rotation is locked as a stable initial manipulation approximation. Bins are centred at (0.10, 0.44, +/-0.42) m; the negative-Z bin is for apples. The workcell includes a pedestal at X=0.62 m, ready for a Z-up URDF visual translated to CAD (0.62,0,0.72). Robot actuation, grasping and arm collision geometry belong to the external controller; this class does not infer them from visual CAD. world() exposes forces/body edits for later control tasks. Instances are single-writer; reset(seed) repeats the same fruit sequence.

    Example
    dm::sim::ConveyorEnvironment env;
env.reset(42);
for (int i=0; i<720; ++i) env.step(1./120);
auto state = env.observation();
std::print("{}\n", state.stage == dm::sim::ConveyorStage::Waiting); // true

    next_fruit

    #source
    void next_fruit()

    Replace a completed payload with the next seeded fruit; retain both bins.

    Throws
    std::logic_error

    Current fruit is still travelling or waiting.

    Example
    dm::sim::ConveyorEnvironment env;
auto s = env.observation();
auto b = env.world().body(s.fruit);
b.position={0.1,0.5,s.kind==dm::sim::FruitKind::Apple ? -0.42 : 0.42};
env.world().set_body(s.fruit,b);
for(int i=0;i<120;++i) env.step(1./120);
env.next_fruit();
