    datamunge::optim

    Callback-based continuous optimization, declared solver controls and diagnostic fixtures.

    Canonical checked native producers and owned values.

    datamunge/optim/acor.hpp

    Classes

    ACORAnt Colony Optimization for continuous domains (ACOR), Socha & Dorigo (2008). A solution archive of size k is maintained; each iteration, new ants are sampled from a Gaussian kernel mixture built from the archive (ranked by quality, so better solutions attract denser sampling), then the archive is truncated back to its k best members merged with the new ants. Derivative-free, box-constrained.
    ACOROptions

    datamunge/optim/adadelta.hpp

    Classes

    AdaDeltaAdaDelta on the DifferentiableFunction callback interface. Uses squared-gradient and squared-update exponential averages. The update multiplies the gradient by sqrt(previous_update_average+epsilon)/sqrt(current_gradient_average+epsilon). No separate learning-rate option. Tests the gradient used after applying its update; O(p) reset local state. The caller supplies finite, dimensionally consistent callbacks. Inputs are borrowed; coordinates mutate in place and can retain a partial state if a callback throws. Calls use local optimizer state and propagate callback exceptions; sharing a mutable objective across threads requires external synchronisation. Normal return alone is not a uniform convergence certificate.
    AdaDeltaOptionsConfiguration for AdaDelta; fields retain their documented native defaults. Supply finite values in the supported ranges. Controls are copied at construction; validation, stopping and loss scaling belong to optimize().

    datamunge/optim/analysis.hpp

    Classes

    CurveResidualAnalytic exponential, offset-exponential and logistic residuals for Levenberg-Marquardt studies. The optimizer returns half SSE. Parameters are unconstrained; positivity of amplitude/rate is not imposed. Parameter order is (A,k), (A,k,c), or (L,k,mid) for exponential, offset-exponential, or logistic respectively. Logistic evaluation uses a stable inverse link. Callback coordinate dimensions and finiteness are checked.
    EqualityQuadraticEuclidean projection onto sum(x)=total, with exact KKT control. The optimum is target-(sum(target)-total)/dimension in every coordinate. Raw gradients at a constrained optimum generally do not vanish. Pure owned fixture.
    L1LeastSquaresObjectiveMean-loss lasso objective with an exact soft-threshold proximal map. No hidden standardisation. Unpenalised coefficient zero supports an explicit intercept column. Stationarity uses the proximal-gradient mapping, not raw smooth-gradient zero. Dense calls own no mutable caches.
    LeastSquaresObjectiveFull-sum linear least squares with inspectable per-row components. evaluate/gradient are sums. SGD and SAGA use mean component gradients; SVRG uses the full gradient divided by n as its mean snapshot. All share the same unpenalised minimizer, but a step size must name its loss convention.
    NonnegativeQuadraticProjection onto x>=0 with a closed-form log-barrier path. The constrained solution is max(target,0) coordinatewise. InteriorPoint needs strictly positive coordinates even though this fixture accepts boundary points.
    OptimizationRunResult of a recorded optimizer call; no convergence certificate is inferred. exception is empty on normal return. A nonempty exception retains the last mutated coordinates and preceding callback evidence. value is the returned scalar (NaN on failure); checked_value and gradient_norm are post-run checks, excluded from fitting counters. A small smooth-gradient norm is inappropriate for proximal or constrained stationarity; use their mapping/KKT conditions.
    OptimizationTraceOwned callback history; events are requests, not accepted iterations. Value calls include rejected line-search/population proposals. Gradient calls may be at look-ahead points. Diagnostic sampling after fitting is separate work and assumes a deterministic objective without callback side effects.
    QuadraticObjectiveConvex quadratic .5*(x-centre)'H*(x-centre), with optional coupled/rotated axes. H starts diagonal, adds coupling*11', then rotates its first two axes by angle radians. Positive diagonal and nonnegative coupling make H positive definite. Inputs are owned; calls validate finite coordinate shape and never mutate them.
    SmoothBenchmarkRosenbrock valley (1-x)^2+100*(y-x^2)^2, Rastrigin or a quadratic-plus-sinusoidal bumpy surface. Rastrigin is 20+sum(x_j^2-10*cos(2*pi*x_j)); their global minima are zero, at (1,1) for Rosenbrock and (0,0) for Rastrigin. Bumpy is (x-3)^2+(y+1)^2+5*sin(x)*cos(y), bounded below by -5; no exact global minimizer is asserted. Analytic derivatives are available even when a derivative-free optimizer is used. No mutable caches.

    Functions

    check_residual_jacobian()Compare an analytic residual Jacobian with central finite differences. This is a post-fit diagnostic, not used by LevenbergMarquardt. One pair of residual calls per parameter; truncation/rounding error depends on step.
    optimization_comparison()Plot explicitly sampled callback points from several recorded runs. Replays one pure objective evaluation per selected event after fitting. No accepted-iteration or wall-time claim is made. The y display is log10(max(f-reference,1e-14)); flooring is a plotting convention only. Nonfinite sampled values are omitted, while the run exception and final checks remain in summary(). Trials can exceed initial loss. For population studies best_observed shows a running minimum of evaluated trials, not a certified bound or necessarily an accepted trajectory.
    optimization_curve_data()Make declared noisy curve fixtures, including the original offset-exponential/logistic recipes.
    proximal_mapping_norm()Euclidean proximal-gradient mapping norm for a declared positive step. This first-order stationarity diagnostic includes nonsmooth penalties through the supplied prox. It performs one gradient and one prox call after fitting.
    residual_gradient_norm()Compute the post-run norm of J transpose times residuals.
    trace_optimize()Run a native optimizer through an explicitly chosen abstract interface. Preserves callback order and adds no fitting evaluations. Captures std::exception text and nonfinite value/gradient/residual requests, retaining the partial trace. Final value/gradient checks are separate post-run callbacks, excluded from counts; use pure objectives for reproducible diagnostic sampling. No native stop reason is invented, and value-call indices must not be labelled accepted iterations.

    datamunge/optim/estimation_of_distribution.hpp

    Classes

    EstimationOfDistributionEstimation of Distribution Algorithm (EMNA-style, full-covariance Gaussian) on an ArbitraryFunction within a box constraint. Unlike explicit-operator methods (GA, DE) or covariance-adapting methods (CMA-ES), EMNA builds an explicit multivariate Gaussian model of where the good solutions are each generation – re-estimating its mean and covariance from scratch as the empirical mean/covariance of the current generation's elite, with no smoothing or evolution paths – and samples the next generation directly from that model. Derivative-free.

    datamunge/optim/function_types.hpp

    Classes

    ArbitraryFunctionThe most general objective function: only supports evaluation. Optimizers that consume this type (e.g. SimulatedAnnealing) are derivative-free.
    DifferentiableFunctionAn objective function that additionally supports exact gradient evaluation. Optimizers that consume this type (GradientDescent, Adam, LBFGS) use the full gradient at every step.
    DifferentiableSeparableFunctionA function that is both differentiable and separable – the common case for machine learning loss functions (a sum of per-example losses). Optimizers that consume this type (SGD) can update coordinates from a single term's gradient without evaluating the full objective.
    EqualityConstrainedFunctionSmooth equality-constrained objective for constrained optimizers.
    HessianFunction
    InequalityConstrainedFunction
    ProximalFunctionComposite objective for proximal methods. gradient() is the gradient of the smooth component, and proximal() applies the non-smooth component's proximal operator.
    ResidualFunction
    SeparableFunctionAn objective that decomposes as a sum over num_functions() independent terms (e.g. one term per training example). evaluate() defaults to summing every term, but remains overridable for a more efficient full-objective computation.

    datamunge/optim/moead.hpp

    Classes

    MOEADApproximate a multi-objective minimum using neighboring scalar subproblems. Weights use the largest Das-Dennis lattice fitting max(requested,m); exactly requested for two objectives. Neighbors use Euclidean weight distance; equal distances retain the standard sort's unspecified tie arrangement. Tchebycheff uses max(w,1e-6)*abs(f-ideal); weighted_sum uses sum(w*(f-ideal)). No global archive or convergence guarantee. Final non-dominated extraction is quadratic in population size, so the complete optimizer is not merely O(N*T). Fixed seed repeats on the same standard library; callbacks and shared variation operators remain observable. Const calls share no optimizer state, but the callback is mutable and responsible for its own concurrency behavior.
    MOEADDiscreteChoiceActual discrete scalarization choice for a supplied weight.
    MOEADOptionsOwned configuration for the native MOEA/D variant. Validation occurs on optimize()/trace(), before callbacks except objective dimension, which requires one actual discarded probe. Same legacy field order.
    MOEADReplacementActual two scalar values and update decision for one neighboring slot. Both scores use the same ideal point after the child evaluation. Equality replaces, so duplicate individuals can propagate. Values are observed, not replayed.
    MOEADStepActual offspring and all neighbor updates from one subproblem visit. Parents are drawn with replacement and can coincide. Only the first SBX child is mutated/evaluated. These are sequential in-place population updates.
    MOEADTraceOwned actual setup, offspring, scalar decisions and final population/front. The probe determines objective count but is discarded from the population and ideal point. Capture units count bound scalars, each stored vector row plus its elements, each ParetoPoint record plus coordinates/objectives, ideal scalars, each offspring record plus child coordinates/objectives/ideal, and each replacement record. Options and other scalar metadata are not additional units.
    ZDT1FrontSummaryObserved coverage and vertical gaps of an approximate ZDT1 front. Empty fronts are rejected by the producer. Gaps are objective2 minus 1-sqrt(objective1), not hypervolume, distance to a set or a convergence proof.
    ZDT1ObjectiveNative original ZDT1 benchmark, minimizing two objectives on[0,1]^n. f1=x0, g=1+9*mean(x1..), f2=g*(1-sqrt(f1/g)). Optimum g=1 gives f2=1-sqrt(f1). No optimizer or sampling is hidden in the objective.

    Functions

    moead_original_choices()Retain the original five-rounded-points/five-weights scalarization illustration. Candidates(0,1),(.25,.5),(.5,.293),(.75,.134),(1,0), weights(1,0),(.7,.3), (.5,.5),(.3,.7),(0,1). First strict minimum wins.     zdt1_front_summary()Summarize actual two-objective values against the analytic ZDT1 curve. O(N) work, O(1) driver storage; coordinates are ignored and no refitting occurs.
