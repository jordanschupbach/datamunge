    namespace datamunge

    datamunge::game

    Library-only game scenes, fixed clocks and native behavior lifecycle.

    datamunge/game/clock.hpp

    Classes

    FixedClockFixed-step accumulator; callers execute returned ticks in their own application loop. This library owns no window, process main loop or wall clock. Each instance is single-writer and stores only the unconsumed fraction of a fixed tick.
    TickBatchResult of accumulating one render-frame duration into fixed simulation ticks.

    datamunge/game/courier.hpp

    Functions

    courier_behaviors()Build independently owned native factories for both Crystal Courier reference games. Registers courier_grid (turn-based tile movement/pickups/traps/exit), courier_3d (accelerated planar movement, grounded edge-triggered jump, hazards and pickups), orbit_camera and oscillating_lift. Per-entity factory instances own all mutable state. Names/components/prefabs follow the frozen VSim reference scenes. No Lua interpreter or renderer is required. Restart by constructing a fresh Simulation from the authored scene, which also recreates behavior state.
    courier_import()Explicitly map known script-bearing IDs in one frozen Courier reference scene. This opt-in mapping does not inspect or execute source. Grid scene ID 1 maps to courier_grid. The 3D scene maps IDs 1/3/110 to courier_3d/orbit_camera/oscillating_lift. Use a custom SceneImport for scenes with other IDs or different game rules.

    datamunge/game/io.hpp

    Classes

    SceneImportExplicit replacements for legacy Lua-bearing entities and prefabs. Keys are original scene IDs or prefab names. Every nonempty legacy script needs one nonempty native factory name; unused mappings are rejected. Mapping never executes, translates or retains Lua source. Simulation later validates mapped factory names against its BehaviorRegistry.

    Functions

    encode_scene()Encode a validated scene deterministically as version-one UTF-8 JSON. Preserves live IDs, next_id, prefabs, authored components and native behavior names. Writes no file and includes no solver state or Lua. Finite doubles use sufficient decimal precision for exact round trips; keys and entity IDs are ordered.
    load_scene()Read a bounded scene file and parse it with explicit legacy replacements. Reads at most 16 MiB before invoking the same transactional parser as parse_scene.
    parse_scene()Parse a validated native/VSim version-one scene while preserving exact IDs and next_id. Accepts strict scalar UTF-8 JSON, at most 16 MiB, 64 nested containers, 10000 entities and 10000 prefabs. Duplicate/unknown keys, missing parents and joint cycles fail before any scene is returned. Live IDs are in [1,INT64_MAX); next_id may equal INT64_MAX for an exhausted scene. Legacy scripts require explicit replacements. Native behavior and damping fields extend the original schema. Sphere/capsule dimension differences within the original 1e-5 tolerance are canonicalized to exact equal diameters. No source script is executed.

    datamunge/game/render.hpp

    Classes

    AmbientOcclusionScreen-space ambient occlusion controls in world metres and dimensionless strength.
    RenderConfigBounded native offscreen render controls, with no window or GUI state.
    RendererNative offscreen Vulkan renderer retaining its own or a shared compute context. Procedural box/sphere/crystal intersections, GGX metallic/roughness lighting, geometric shadow rays, HDR/ACES presentation, screen-space AO and bitmap overlays run without NVRHI or a window. Frame shading/composition runs on the selected Vulkan device; capture is an explicit host readback. Single-writer. Shader arithmetic is float32. Geometry/lens values that overflow or underflow required positive float32 fields are rejected before drawing.
    RenderViewOne perspective view into a normalized top-left-origin output rectangle. Uses a right-handed local -Z camera, unit w,x,y,z rotation and SI positions.

    datamunge/game/scene.hpp

    Classes

    CameraPerspective camera with right-handed local -Z view and zero-to-one depth.
    EntityOwned scene components; spatial is the single source of transform and velocities. spatial.position/rotation/dimensions describe the entity even when physics is disabled. Enabling physics uses all spatial fields as the rigid-body settings. No Lua source is executed: behavior names refer to explicitly registered native factories.
    MeshLinear-RGB metallic/roughness mesh appearance.
    SceneOwned authoring scene with validated, transactional entity edits and prefabs. IDs are never reused within a snapshot. Scene copies are separate snapshots; references must not be retained across replacement. Methods are single-writer.

    datamunge/game/simulation.hpp

    Classes

    BehaviorPer-entity native behavior; instances retain state between ticks. A factory supplies one exclusive instance per entity. Lifecycle order is ascending entity ID, start once then update (including the first tick). Native callbacks are trusted caller code and may propagate exceptions.
    BehaviorRegistryExplicit name-to-native-factory mapping; no script interpreter or global registry.
    SimulationOwned native scene, behavior instances and physics world with deterministic visit order. Single-writer, library-only game update. New entities first run on the next tick; destroyed entities skip later callbacks. Renaming a behavior replaces its instance on the next visit. Errors propagate with entity context; earlier successful callbacks are not rolled back. Invalid input fails before callbacks.

    Types and constants

    InputFrametype Named normalized controls for one tick; absent controls are zero and never latch.
