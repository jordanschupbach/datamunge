    datamunge/bspline_regression.hpp

    Classes

    BsplineB-spline design factory, analogous to R's splines::bs(). Owns a clamped basis on fixed boundaries, reused for training and prediction. By default the first basis column is omitted, so a formula's intercept does not duplicate the partition of unity. No fitting or smoothing is performed. Const evaluations are independent and safe to run concurrently.
    BSplineRegressionA least-squares B-spline regression curve y ≈ Σ_j β_j B_j(x). dm::BSR for short.

    Functions

    bs()Construct an owned B-spline basis for repeated evaluation with eval(). Free-function spelling of Bspline: construction fixes the knots and boundaries without evaluating a design matrix or fitting a model. The returned value owns its basis; the input knot vector may be modified or destroyed after this call.

    datamunge/linalg/bindings.hpp

    Classes

    LinalgMatrixBinding counterpart of Mat/SpMat with shared, immutable expression operands. Transpose, multiplication and inverse actions defer native computation until eval(), values() or text(). Handles keep temporary operands alive across garbage collection. Sparse products use CSR; solves use the canonical dense LU/QR implementation. Concurrent const evaluation is safe; no evaluation cache is mutated.

    datamunge/linalg/matrix.hpp

    Classes

    BasicMatOwned floating-point matrix backed by canonical DenseMatrix or SparseCSR storage. Initialisers are rows and must be rectangular. Empty rows and zero dimensions are valid. Dense reads are constant time; sparse reads use a row binary search. set() is constant time for dense storage and linear in rows plus stored entries for sparse storage. Expressions borrow lvalue matrices, so those matrices must outlive evaluation. They own temporary matrices and copy expression nodes (including any matrices those nodes own). Mutations before eval()/printing are visible; construction/assignment to Mat or SpMat takes a snapshot, safely handling aliased operands. Nonfinite entries are stored; dense products follow IEEE arithmetic, while sparse products skip structural zeros. Solving rejects nonfinite coefficient/right-hand-side entries. Concurrent reads/evaluations are safe only while all borrowed operands remain unmodified.

    Functions

    cbind()Bind a numeric vector before matrix columns, like R's cbind(y, X). Copies both inputs into dense storage, preserving the matrix scalar type. dm::Vector<T> implicitly supplies its underlying standard vector.
    mat()Create an owned, zero-initialised dense matrix. Allocates rows times cols scalar entries. Empty dimensions are valid; indices are zero-based. The returned matrix owns its storage and supports lazy algebra.
    solve() ×2Defer an inverse action; multiplying by a right-hand side performs a linear solve. No factorisation, transpose, product or inverse is computed here. eval()/printing of a standalone solve(A) explicitly computes A inverse by solving against the identity. In solve(A)*B*C the right-hand-side product B*C is evaluated before one factorisation/solve; it avoids an inverse and an A.cols() by B.cols() solved intermediate. This reassociation may change floating-point rounding. The written normal equations still square the design's condition number; solve(X,y) uses QR directly for tall systems. Sparse inputs/products retain CSR storage until the coefficient matrix/right-hand sides enter the dense solve backend; this is not a sparse LU implementation. Lvalue matrices must outlive evaluation.
    spmat()Create an owned, zero-initialised compressed sparse row matrix. Allocates only rows plus one row offsets; no coefficient entries are stored. Empty dimensions are valid and indices are zero-based. Coefficient assignment inserts nonzeros or removes stored zeros using the canonical CSR mutation path.
    t()Short namespace spelling for the native linear algebra API.

    Types and constants

    Densetype Dense storage policy for Mat; identical to linalg::DMat.
    Mattype Typed matrix facade with lazy transpose/product/solve expressions. Defaults to dense storage and double scalars. Float, double and long double preserve their type through expressions and solves; the sparse storage policy keeps products in CSR until a solve's dense boundary. This is the same facade as la::Mat<Storage, T>, with owned matrix storage and lifetime-aware expressions. The storage policy comes first; Mat<Sparse> uses double-precision CSR storage.
    Sparsetype Compressed sparse row storage policy for Mat; identical to linalg::SpMat.
    SpMattype Owned CSR matrix; zero initializer entries consume no sparse storage. Products of sparse expressions remain sparse; inverse actions produce dense solutions.

    #source
    template<class Storage = Dense, class T = double>
using Mat = BasicMat< linalg::MatrixStoragePolicy< Storage >::sparse, T >

    Typed matrix facade with lazy transpose/product/solve expressions. Defaults to dense storage and double scalars. Float, double and long double preserve their type through expressions and solves; the sparse storage policy keeps products in CSR until a solve's dense boundary. This is the same facade as la::Mat<Storage, T>, with owned matrix storage and lifetime-aware expressions. The storage policy comes first; Mat<Sparse> uses double-precision CSR storage.

    Template parameters
    Storage

    Dense (default) or Sparse storage policy.

    T

    Floating-point scalar, default double.

    Example
    dm::Mat<> X = {{1, 0}, {1, 1}, {1, 2}};
dm::Mat<dm::Dense, double> y = {{1}, {3}, {5}};
dm::Mat<> beta = dm::solve(X.t() * X) * X.t() * y;
std::print("{:.0f} {:.0f}\n", beta(0, 0), beta(1, 0));  // 1 2
