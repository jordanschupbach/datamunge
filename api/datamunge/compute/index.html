    namespace datamunge

    datamunge::compute

    Explicit execution contexts and byte buffers for numerical libraries.

    datamunge/compute/context.hpp

    Classes

    BufferShared allocation or bounded byte view retaining its creating context. Copies alias bytes. A view survives destruction of the original handle. Host pointers are exposed only for CPU allocations. Concurrent writes to overlapping bytes need caller synchronization. A default handle is undefined.
    ContextExecution context with persistent workers and shared, bounded allocations. Context copies share workers and allocations. CPU and current GPU commands are synchronous; parallel_for serializes submissions on one context and propagates callback exceptions after all workers finish. Separate contexts can run concurrently. No global thread count or current-device setting is changed.
    DeviceAn explicit backend and ordinal, with no hidden current-device state. CPU accepts index zero only; GPU indices refer to backend enumeration order.
    DeviceInfoDescribe one backend without treating missing support as an available GPU.
    KernelSourceNative program source and its explicit, backend-neutral argument layout. Vulkan takes SPIR-V words; CUDA takes null-terminated PTX text. Programs have buffer parameters first, followed by one by-value parameter block when nonempty. Vulkan uses descriptor set zero with sequential storage-buffer bindings and a push-constant block. CUDA uses the equivalent pointer parameters and packed block.
    MatrixProductPacked row-major C[m,n] = op(A)[m,k] op(B)[k,n], with no host evaluation. Stored A is [m,k] or [k,m]; stored B is [k,n] or [n,k], according to the transpose flags. Each dimension must fit a signed 32-bit integer. Zero output dimensions do no work; zero inner dimension writes exact zeros.
    ProgramShared native GPU kernel retaining its context and compiled resources. Default construction is undefined; context.program compiles a backend program.
