    ZhuTakaoka

    class ZhuTakaoka
    #include <datamunge/algorithms/string_search_extra.hpp> source

    Compiled Zhu-Takaoka matcher with a two-byte bad-character shift and strong good suffix.

    Preprocessing costs O(m+256^2) time/storage for pattern length m. The 256^2-entry int table is retained for searches over many separate texts. Scans compare right to left and cost O(n*m) in the worst case; periodic matches can require full comparisons at every position. Empty patterns match nowhere by this library's convention. Matching is case-sensitive on bytes, with embedded NUL and high-bit bytes supported; there is no Unicode normalisation. Const scans may run concurrently on this immutable object; returned positions and tables own their storage.

    Example
    const dm::algorithms::ZhuTakaoka matcher("ana");
const auto hits = matcher.search("banana"); // {1,3}
    References

    • R. F. Zhu and T. Takaoka (1987), On improving the average case of the Boyer-Moore string matching algorithm, Journal of Information Processing 10(3), 173-177. https://ipsj.ixsq.nii.ac.jp/records/59825

    trace

    #source
    dstruct::DataFrame trace(const std::string & text) const

    Trace every alignment of the actual matcher, including the selected shift.

    Columns: offset, matched_suffix, comparisons, match (0/1), digram_shift, suffix_shift and advance. On full matches only the suffix shift is used, and digram_shift is zero. A single-byte pattern advances by one.

    Parameters
    text

    Borrowed byte string.

    Returns

    Owned trace; numeric offsets are represented exactly up to 2^53.

    Example
    const auto trace = dm::algorithms::ZhuTakaoka("aa").trace("aaaa");
const auto rows = trace.nrows(); // 3
    References

    • R. F. Zhu and T. Takaoka (1987), Journal of Information Processing 10(3), 173-177.
