    BloomFilter

    class BloomFilter
    #include <datamunge/algorithms/bloom_filter.hpp> source

    Owned approximate set of uint64 keys, using packed bits and deterministic double hashing. Insert/query use exactly the same probes, so inserted keys cannot test negative while the filter remains unmodified except by insertions. Positive queries require an exact backing-set check. There is no erase, resizing or insertion count: duplicates are idempotent and the object retains no original keys. Storage is 64*ceil(m/64) payload bits plus object/allocation bookkeeping. Copies own independent state; moved-from objects support destruction/assignment only. Mutation requires external synchronisation, while concurrent const reads are safe when no thread mutates the object. Probes retain the existing uint64 mapping: (h1+i*h2) wraps modulo 2^64 before reduction modulo m. Odd h2 need not give distinct probes for arbitrary m.

    Example
    dm::algorithms::BloomFilter filter(8000,6);
filter.add(42);
std::print("{} {}\n",filter.maybe_contains(42),filter.storage_bytes()); // true 1000
    References

    • B. H. Bloom (1970), Space/time trade-offs in hash coding with allowable errors, Communications of the ACM 13(7), 422-426, doi:10.1145/362686.362692.

    • A. Kirsch and M. Mitzenmacher (2008), Less hashing, same performance: Building a better Bloom filter, Random Structures & Algorithms 33(2), 187-218, doi:10.1002/rsa.20208. The finite wrapped probes here are not independent hashes.

    static int optimal_num_hashes(int m, int n)

    Round the model's continuous optimum (m/n)*ln(2), clamped to at least one. This is a sizing rule, not an exact optimiser for finite wrapped probes. Returns one for n=0. O(1); no filter is constructed or modified.

    Parameters
    m

    Positive logical bit budget.

    n

    Nonnegative expected distinct key count.

    Returns

    Positive rounded probe count; ties round upward.

    Throws
    std::invalid_argument

    If m<=0 or n<0.

    Example
    std::print("{}\n",dm::algorithms::BloomFilter::optimal_num_hashes(8000,1000)); // 6
    References

This model is not an exact finite probability or a guarantee for deterministic, correlated wrapped probes. The caller supplies distinct inserted keys; duplicate calls do not add load.
