    datamunge/random/blum_blum_shub_analysis.hpp

    Classes

    BlumBlumShubOrbitOwned bounded state path, optionally closed by an actual repeated modular state. states begins at the inspected engine state. On closure it includes the closing duplicate, so states.size()=transient+period+1. Unknown closure has period and transient zero; this is a budget result, not evidence of an infinite orbit.
    BlumBlumShubStepOwned before/after modular state and low bit for one actual engine transition. The bit belongs to after, not before. No engine or input is borrowed by a record.

    Functions

    blum_blum_shub_orbit()Inspect a copy of the engine until its first repeated state or an explicit step budget. The caller's raw state and distribution cache are unchanged. Each step uses next_bit(); a hash table records first visits. With B observed transitions, expected O(B) time and O(B) owned storage; hash collisions may worsen time. Prime-factor assumptions imply purely periodic admissible states, but this inspector also reports transients for structurally accepted composite factors.
    blum_blum_shub_trace()Advance a BBS engine while recording its actual canonical bit transitions. Uses next_bit(), the same transition used by next_u64(). Exactly count squares; output records are owned and leave the normal() cache intact. Reserves storage before advancing, so an allocation/length failure leaves engine state unchanged. O(count) work/storage with fixed-width arithmetic; count zero is an empty no-op.

    datamunge/random/chacha20_analysis.hpp

    Classes

    ChaCha20DrawOwned location, capacity and value of one actual ChaCha20 raw draw. The location describes the consumed word, not the next draw. No key or nonce is copied into a record; values are still raw keystream and may be sensitive.

    Functions

    chacha20_seed_key()Expand a 64-bit simulation seed using four SplitMix64 words, low half first. Matches the ChaCha20 seed constructor exactly. All 64-bit seeds are accepted, but at most 2^64 different keys can result: this adds no entropy. Returns an owned array, does not mutate the caller and uses constant work/storage without allocation. Safe for concurrent independent calls; unsuitable for secret keys.
    chacha20_trace()Consume raw engine draws while recording their actual buffered stream locations. No cipher is replayed. Before drawing, checks count against remaining capacity and reserves all records; any validation/allocation failure leaves both raw state and normal() cache unchanged. Successful draws preserve the normal cache like next_u64(). Locations follow from remaining capacity: for R>0, the counter is UINT32_MAX-(R-1)/8 and the word index is (8-R%8)%8. Owns all output records; count zero is an empty no-op even at exhaustion. O(count) work/storage. This is a public-test diagnostic, not an independent stream or entropy source.

    datamunge/random/lagged_fibonacci_analysis.hpp

    Classes

    LaggedFibonacciParityOrbitOwned normalized oldest-first parity masks until the first repeat or explicit cap. Bit i denotes parity of the i-th oldest ring word, eliminating physical index rotation. This is an exact finite-state projection, not the full64-bit engine period or a randomness certificate. complete=false has no inferred period. All masks are distinct; the repeated closing mask is identified by offset.
    LaggedFibonacciTraceOwned complete before/after physical rings and every actual consumed modular transition. captured_entries=2*k+count counts both full boundary-ring words and scalar transition records, not fields/capacities/bytes/RAM. Allocation/admission of both rings and all records finishes before the caller engine is advanced. No input engine references or replay; normal cache is left intact.

    Functions

    lagged_fibonacci_parity_orbit()Inspect the exact parity-state orbit of an independent complete engine copy. Require k<=63 so oldest-first parities fit one uint64 mask. At each actual copied-engine transition inspect the current mask, stop on first repeated mask, or return incomplete before retaining a new mask beyond max_states. Original engine/raw position/distribution cache unchanged. O(k*S) inspection work and O(k+S) storage for S distinct visited masks; does not claim full engine period.
    lagged_fibonacci_trace()Consume exactly count actual ring updates after admitting/allocating complete output. Captures original/final ring and every next_step() record. Caller engine advances count times; no prefix replay or second generation. Known count/quota/allocation failures occur before advancement; subsequent fixed-ring updates/copies do not allocate or throw. O(k+count) time/owned capture. Inherited normal cache untouched.

    datamunge/random/mt19937_64_analysis.hpp

    Functions

    mt19937_64_conformance()Compare raw MT19937-64 streams with std::mt19937_64 for declared seeds. Each row constructs fresh engines and compares every word, including refills. This is an implementation check against the standard library, not a randomness test or proof of the period. Seeds and endpoint words are hexadecimal strings to preserve all 64 bits. Duplicate seeds retain duplicate rows; empty seeds returns an empty typed table. Inputs are borrowed and unchanged; O(seeds*draws) work and O(seeds) result storage, with fixed-size engine temporaries.
    mt19937_64_temper_steps()Inspect the four invertible MT19937-64 output-tempering stages. Shifts and masked XORs operate modulo 2^64. Tempering changes the output map, not the engine state or period; it does not conceal state information. O(1) work/storage without allocation; no shared mutation.
    mt19937_64_twist_steps()Inspect one MT19937-64 twist word without mutating an engine. All arithmetic is unsigned 64-bit. Combine the upper 33 bits of left with the lower 31 bits of right, shift right once, conditionally XOR the twist mask, and XOR lag. During a refill, arguments must follow the ordered in-place recurrence: some later lag/right inputs are already updated words. O(1) work/storage, no allocation; safe for concurrent independent calls.
    mt19937_64_untemper()Invert all four MT19937-64 tempering stages, recovering one raw word. Reverses the stages with finite geometric-series inverses of nilpotent masked-shift maps over F2. Every 64-bit input has exactly one preimage. O(1) work/storage without allocation; no shared state. This recovers a word, not a seed, a block alignment or the normal sampler's cache.

    datamunge/random/random.hpp

    Classes

    Acorn64ACORN: an add-with-carry-style generator modulo 2^64.
    BlumBlumShubEducational uint64 Blum-Blum-Shub engine with explicit modular state and bit output. Initialise x0=(seed mod N)^2 mod N, then square modulo N before emitting each low bit. The caller must supply distinct primes p,q congruent to 3 modulo 4; the constructor checks congruence, product range and seed coprimality, not primality. Known small default factors and a modulus of at most 64 bits do not provide cryptographic security. Seed 1 is allowed and gives a constant stream. Instances own their state; copies also preserve the inherited normal cache. Separate objects share no state; concurrent mutation needs external locking.
    ChaCha20Buffered RFC 8439 ChaCha20 engine emitting little-endian 64-bit words. Uses a fixed 256-bit key, 96-bit nonce and checked 32-bit block counter. Eight next_u64() calls consume one 64-byte block; unused words remain buffered. The counter never carries into the nonce. Copies preserve raw position and the inherited normal() cache: copying duplicates a stream, not an independent key. Separate instances share no state; concurrent mutation needs external locking. Raw calls take constant amortised time/storage with no allocation. This wrapper supplies no entropy acquisition, nonce management, authentication, reseeding, backtracking resistance, key erasure or machine-code constant-time assurance. Public fixed keys are for conformance checks; a 64-bit seed is for simulation.
    LaggedFibonacci64Own an additive lagged-Fibonacci ring x[n]=x[n-j]+x[n-k] modulo2^64. Require0<j<k. SplitMix64(seed) fills k initial words in physical order; index0 is oldest. Each output overwrites the oldest slot by its sum with the actual short-lag word. Unsigned wrap is intended. This is not cryptographic; parity follows a linear recurrence, and arbitrary lag pairs do not guarantee maximal period or statistical quality. Scalar seeding explores at most2^64 states. Construction/storage O(k), each raw update O(1), observations do not replay. Objects own state and inherited distribution cache; copies preserve both. Independent objects share no state; concurrent mutation requires synchronization.
    LinearCongruential64Full-period mixed unsigned64 affine generator with explicit raw transition evidence. Recurrence x_next=a*x+c modulo2^64, returning the updated state. Constructor requires a=1 modulo4 and odd c, exactly the mixed full-period conditions for this modulus. Any seed is valid, including0. The period theorem is not an empirical traversal of2^64 states, independence or cryptographic security. Low bits have short autonomous periods; all raw outputs are predictable from known state/parameters. Copies own raw state and inherited normal() spare cache. Raw next calls leave that cache unchanged, matching other engines. O(1) raw step/time/storage; separate instances share no mutable state, concurrent mutation requires synchronization. Default constants are not a quality proof.
    MersenneTwister64MT19937-64: a 312-word simulation engine with period 2^19937-1. Scalar seeding and every raw output match std::mt19937_64. The recurrence updates in place in increasing index order, with an invertible output temper. Period refers to the nonzero effective recurrent state, not to a short test, all arbitrary restored arrays, or 19968 independent stored bits. A scalar seed chooses at most 2^64 streams. This is not a cryptographic generator. Instances own state; copying preserves both raw position and the inherited normal() cache. Separate instances share no state; concurrent mutation of one instance needs external synchronisation. Construction/refill cost O(312); next_u64() is O(1) amortised, with 312 stored 64-bit words plus metadata/cache.
    Pcg32PCG XSH-RR with 64-bit state and odd selectable increment. Two consecutive 32-bit outputs form each next_u64(), first in the high half. Stream selectors differing only in bit63 alias after doubling; different streams are not claimed statistically independent. Each odd-increment state transition has period 2^64. Deterministic simulation use, not cryptography. Instances own state; copies continue identically, including inherited caches. Concurrent mutation of one instance requires external synchronisation.
    Pcg32StepOne actual PCG XSH-RR state transition and output permutation.
    RandomGeneratorCommon distribution samplers driven by a deterministic raw-word interface. Instances own a cached Box-Muller normal spare; copying an engine also copies that cache and duplicates the stream. Distribution calls may consume zero (cached normal), one, or multiple (rejection/retry) raw words. Mutating one instance concurrently requires external synchronization. Floating results use the host libm; raw deterministic sequences do not guarantee cross-libm bitwise transcendental results. No entropy, independence or security claim follows from sampling.
    Sfc64Small Fast Counter raw64-bit engine with inspectable actual transitions. Owns three uint64 words and a counter, plus the inherited normal spare. Updates use modulo2^64 addition, xor/right11, multiplication by9 and rotate-left24. Historical local seeding expands the supplied seed through three SplitMix64 steps, initializes counter1 and performs NO warmup; this seeding policy differs from some reference-library initialization recipes. All raw states, including zeros and counter wrap, are supported. Raw next calls do not clear the inherited normal spare; copying the engine preserves both raw state and distribution cache. State snapshots exclude that cache. O(1) step work/storage; no entropy/security or universal period claim. Concurrent mutation requires caller synchronization.
    SplitMix64SplitMix64 raw engine with a64-bit Weyl counter and canonical mixing. Any seed is permitted; state advances modulo2^64. Constant raw step work/storage, no allocation, no entropy/security guarantee. Inherits distribution methods and their owned normal cache. Mutating a shared instance concurrently requires synchronization.

    Xoshiro256StarStarxoshiro256** 1.0: a 256-bit linear state transition with a nonlinear output permutation.

    sample_distributions_run()Sample interleaved distributions through the canonical RandomGenerator methods. A fresh SplitMix64(seed) supplies raw words to a counting adapter whose inherited distribution methods are the canonical implementation, including rejection and normal spare caching. Each tuple calls integer, Bernoulli, normal, exponential in that order, then one final uniform draw follows all tuples. This preserves the original report stream. Validates all parameters before generating any raw word, even for count0; all outputs owned. Includes rejected integer candidates, positive-u1 retries, and the final uniform draw; cached normal samples consume no new raw words. The raw-word history bound is checked before underlying engine mutation. Other semantics/storage match sample_distributions_run(), plus O(actual_raw_draws) retained words.
