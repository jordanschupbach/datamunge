#+begin_abstract
The most-used interpolation in all of computing is also the simplest: draw a straight
line between each pair of adjacent samples and read off the value in between. *Linear
interpolation* underlies lookup tables, audio resampling, animation, and the humble
=lerp= of graphics. It is exact when the data really is linear, continuous everywhere
(though kinked at the samples), and its error shrinks as \(O(h^2)\) with the sample
spacing. This report implements it in =datamunge='s C++ =algorithms::linear_interpolate=,
verified to reproduce affine data exactly, and shows its error falling as samples are
added.
#+end_abstract

* A line between each pair of points

Given samples \((x_i, y_i)\) with the \(x_i\) increasing, the value at a query
\(x\) in \([x_k, x_{k+1}]\) is the straight-line blend

\[ y(x) = y_k + \frac{x - x_k}{x_{k+1}-x_k}\,(y_{k+1} - y_k) = (1-t)\,y_k + t\,y_{k+1}, \]

with \(t\in[0,1]\) the fractional position in the interval. It is *exact* whenever the
underlying function is affine (a straight line has nothing for the interpolant to miss),
\(C^0\) but not \(C^1\) (the slope jumps at each node), and its worst-case error on
a smooth function is bounded by \(\tfrac18 h^2 \max|f''|\) -- so *halving the spacing
quarters the error*. Outside the sample range =datamunge= extrapolates along the nearest
end segment.

* Algorithm

#+begin_example
LINEAR-INTERPOLATE(xs, ys, x):
  k <- index with xs[k] <= x <= xs[k+1]   (clamped for extrapolation)
  t <- (x - xs[k]) / (xs[k+1] - xs[k])
  return ys[k] + t * (ys[k+1] - ys[k])
#+end_example

* Worked example: sampling a sine, and the O(h^2) error

We sample \(\sin x\) on \([0,2\pi]\) at a handful of nodes, reconstruct it with
linear interpolation on a fine grid, and measure how the maximum error falls as we add
nodes.

#+name: li-run
#+begin_src c++ :eval no
    auto f = [](double x) { return std::sin(x); };
    const double x0 = 0.0, x1 = 2.0 * M_PI;

    // 7-node reconstruction for the figure.
    const int nodes = 7;
    std::vector<double> xs, ys;
    for (int i = 0; i < nodes; ++i) { const double x = x0 + (x1 - x0) * i / (nodes - 1); xs.push_back(x); ys.push_back(f(x)); }

    std::vector<double> xf, yexact, ylin;
    for (int i = 0; i <= 300; ++i) {
        const double x = x0 + (x1 - x0) * i / 300.0;
        xf.push_back(x); yexact.push_back(f(x)); ylin.push_back(linear_interpolate(xs, ys, x));
    }

    // Verify exactness on affine data.
    const std::vector<double> ax{0, 1, 3, 6}, ay{1, 4, 10, 19}; // y = 3x + 1
    std::cout << "=== exactness check on y = 3x+1 ===\n";
    std::cout << "linear_interpolate at x=2.5 -> " << linear_interpolate(ax, ay, 2.5) << " (exact " << 3 * 2.5 + 1 << ")\n\n";

    // Error vs node count.
    std::cout << "nodes    h          max |error|\n";
    for (int n : {3, 5, 9, 17, 33, 65}) {
        std::vector<double> gx, gy;
        for (int i = 0; i < n; ++i) { const double x = x0 + (x1 - x0) * i / (n - 1); gx.push_back(x); gy.push_back(f(x)); }
        double maxe = 0.0;
        for (int i = 0; i <= 1000; ++i) { const double x = x0 + (x1 - x0) * i / 1000.0; maxe = std::max(maxe, std::fabs(linear_interpolate(gx, gy, x) - f(x))); }
        std::printf("%5d    %.5f    %.4e\n", n, (x1 - x0) / (n - 1), maxe);
    }

    auto plot = RPlot::create();
    plot.line(xf, yexact, "exact sin", RGB{16, 185, 129}, 2.0);
    plot.line(xf, ylin, "linear interp", RGB{220, 38, 38}, 2.0);
    plot.points(xs, ys, "samples", RGB{37, 99, 235}, 7.0);
    plot.legend({"exact sin x", "piecewise-linear", "7 samples"}, {{16, 185, 129}, {220, 38, 38}, {37, 99, 235}});
    plot.title("Linear interpolation: straight segments between samples")
        .x_label("x").y_label("y").background({250, 250, 252});
    plot.save_svg("build/org/linear_interpolation.svg");
    std::cout << "\nwrote linear_interpolation.svg\n";
#+end_src

The reconstruction reproduces the affine test data exactly, and on the sine it tracks the
curve with visible straight segments between samples. The error table shows the promised
\(O(h^2)\) behaviour: as the grid refines, each doubling of the node count -- halving
\(h\) -- settles toward cutting the maximum error by a factor of four.

The red interpolant is a chain of straight chords touching every blue sample; where the
sine curves most (the peaks and troughs) the chords cut across and the error is largest,
which is exactly why more samples help. Simple, cheap, and everywhere -- but the kinks at
the nodes are what the smoother Hermite and spline methods set out to remove.
