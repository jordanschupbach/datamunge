#+begin_abstract
Exact clustering compares many point pairs with an accurate -- and often expensive --
distance. *Canopy clustering* (McCallum, Nigam & Ungar 2000) is a cheap first pass
that groups points into overlapping "canopies" using a fast approximate distance and
two thresholds \(T_1 > T_2\), so that a subsequent expensive clustering need only
compare points that *share a canopy*. This report implements it in =datamunge='s C++
=algorithms::canopy_clustering= as a literate program: every number and figure comes
from one compiled binary. We build canopies over three well-separated blobs and show
how the two thresholds control the number of canopies and their overlap.
#+end_abstract

* The two-threshold rule

Canopy clustering consumes points from a pool:

1. Pick any remaining point as a new canopy *center*.
2. Every point within the *loose* threshold \(T_1\) *joins* that canopy -- canopies may
   overlap, so a point can belong to several.
3. Every point within the *tight* threshold \(T_2 \le T_1\) is *removed from the pool*,
   so it can never seed a future canopy. This bounds the number of canopies.

Repeat until the pool is empty. The design contract: any two points closer than
\(T_2\) end up in a common canopy, so a downstream clusterer that only compares
within-canopy pairs never misses a genuinely close pair, while skipping the vast
majority of far-apart comparisons.

** Pseudocode

#+begin_example
Canopy(points, T1, T2):        # T1 >= T2
    pool = all points;  canopies = []
    while pool not empty:
        c = remove any point from pool
        canopy = { p : dist(c, p) < T1 }        # members (overlap allowed)
        remove from pool every p with dist(c, p) < T2
        canopies.append(canopy)
    return canopies
#+end_example

* A worked example

We place three well-separated Gaussian blobs and build canopies. With \(T_2\) large
enough to claim a whole blob but far below the inter-blob distance, we get one canopy
per blob; loosening \(T_1\) makes neighboring canopies start to overlap.

#+name: canopy-run
#+begin_src c++ :eval no
    std::vector<std::vector<double>> pts;
    const std::vector<std::vector<double>> centers = {{0, 0}, {10, 0}, {5, 8}};
    for (const auto& c : centers)
        for (int i = 0; i < 30; ++i)
            pts.push_back({c[0] + 0.05 * (i % 6) - 0.15, c[1] + 0.04 * (i / 6) - 0.1});

    auto canopies = canopy_clustering(pts, 3.0, 2.5);
    std::cout << "=== Canopy clustering on 3 blobs (T1=3.0, T2=2.5) ===\n";
    std::cout << "points: " << pts.size() << ",  canopies formed: " << canopies.size() << '\n';
    for (std::size_t k = 0; k < canopies.size(); ++k)
        std::cout << "  canopy " << k << ": center point " << canopies[k].center << ", "
                  << canopies[k].members.size() << " members\n";

    // Overlap grows as T1 increases (T2 fixed): count total membership.
    std::cout << "\ntotal memberships (overlap indicator) vs T1 (T2=2.5):\n";
    for (double t1 : {3.0, 6.0, 9.0, 12.0}) {
        auto        cs = canopy_clustering(pts, t1, 2.5);
        std::size_t total = 0;
        for (const auto& c : cs) total += c.members.size();
        std::cout << "  T1=" << t1 << ": " << cs.size() << " canopies, " << total
                  << " total memberships (points=" << pts.size() << ")\n";
    }

    // Figure: points colored by their (first) canopy, centers marked.
    std::vector<int> owner(pts.size(), -1);
    for (std::size_t k = 0; k < canopies.size(); ++k)
        for (std::size_t m : canopies[k].members)
            if (owner[m] < 0) owner[m] = static_cast<int>(k);
    const std::vector<RGB> cols = {{239, 68, 68}, {37, 99, 235}, {22, 163, 74}, {202, 138, 4}};
    RPlot                  p    = RPlot::create();
    for (std::size_t k = 0; k < canopies.size(); ++k) {
        std::vector<double> xs, ys;
        for (std::size_t i = 0; i < pts.size(); ++i)
            if (owner[i] == static_cast<int>(k)) { xs.push_back(pts[i][0]); ys.push_back(pts[i][1]); }
        p.points(xs, ys, "", cols[k % cols.size()], 3.5);
    }
    std::vector<double> cxs, cys;
    for (const auto& c : canopies) { cxs.push_back(pts[c.center][0]); cys.push_back(pts[c.center][1]); }
    p.points(cxs, cys, "centers", {17, 24, 39}, 9.0);
    p.save_svg("build/org/canopy_clusters.svg");
    std::cout << "\nwrote build/org/canopy_clusters.svg\n";
#+end_src

  T1=12: 3 canopies, 270 total memberships (points=90)
#+end_example

Each blob becomes exactly one canopy of 30 points -- a clean three-way pre-partition.
The number of canopies is fixed by \(T_2\) (three, one seed per blob) and does not
change as \(T_1\) grows; but once \(T_1\) exceeds the inter-blob distance (here between
\(T_1=9\) and \(T_1=12\)) the total membership jumps past the point count -- every point
now lies inside all three canopies. That overlap is the mechanism that guarantees
genuinely close pairs are never separated across canopies. The figure shows the three
canopies and their seed centers.

* Role and relatives

Canopy clustering is a *pre-processing accelerator*, not a final clustering: run it
first with a cheap distance, then run k-means or hierarchical clustering *within*
canopies with the expensive distance, comparing only points that share a canopy. This
turns a quadratic all-pairs cost into something far smaller when the data has many
well-separated groups. It pairs naturally with k-means (the canopy centers seed the
means, and assignments are restricted to overlapping canopies) and is a classic
MapReduce-friendly clustering primitive for very large datasets. The two thresholds
are the only knobs: \(T_2\) sets how many canopies form, \(T_1\) sets how much they
overlap.

* Complexity

Naively \(O(n^2)\) distance checks, but with a *cheap* approximate distance (or a
spatial index for the pool queries) the constant is small and far below the cost of
the exact clustering it accelerates; memory is \(O(\sum_k |\text{canopy}_k|)\) for the
(possibly overlapping) memberships.
