#+begin_abstract
We fit generalized linear models -- logistic (binomial, logit link) and
Poisson (log link) regression -- to Fisher's (1936) iris data using
=datamunge='s C++ =stats::GLM=, and report it as a literate program: every
fragment below is a real, compiled, executed chunk of the single C++ binary
that produced every number and figure in this document. A logistic
regression separating /versicolor/ from /virginica/ on petal measurements
reaches 94.00% resubstitution accuracy (residual deviance 20.56 on 97 df,
AIC 26.56), with both coefficients significant at the 5% level and a
textbook sigmoid-shaped fitted-probability curve. We then deliberately
attempt the same model on a perfectly (not just well) separable pair --
/setosa/ versus every other species -- and report the genuine numerical
consequence: every coefficient, standard error, and the residual deviance
itself come back as =NaN=, a real IRLS failure mode driven by the fitting
weights collapsing to exactly zero, not a bug in the demonstration. A
Poisson regression on a derived count response, fit by the identical IRLS
engine under a different family and link, and a same-data AIC comparison
between the binomial fit and a deliberately mismatched Gaussian fit on the
same binary response round out the report. We derive the exponential-family
GLM framework, the IRLS fitting algorithm as iteratively weighted least
squares on a working response, deviance and dispersion, and the
perfect-separation degeneracy from first principles, tying each to the
corresponding library call.
#+end_abstract

* Introduction

Every regression report in this project so far has fit a single
distributional family: the
[[file:lm_penguins_analysis.org][linear regression companion report]]
fits Gaussian-response OLS, and the
[[file:elastic_net_iris_analysis.org][elastic net companion report]]
fits penalized variants of the same Gaussian model. This report generalizes in
the direction OLS's own name promises: a /generalized/ linear model,
=stats::GLM=, extends the same linear-predictor machinery to response
distributions from the exponential family -- Gaussian, binomial, Poisson,
and Gamma -- each paired with a link function connecting the linear
predictor to the mean of a possibly non-Gaussian, possibly bounded or
discrete response. We work two members of that family in detail --
logistic regression for a binary species indicator, Poisson regression for
a count -- and use a third, deliberately broken fit to make the method's
best-known failure mode, perfect separation, concrete rather than abstract.

As with its companions, this document is a /literate program/: prose and
source are interleaved in reading order, and a single "assembling the
program" step (§3.3.9) weaves every named chunk below into one =.cpp= file,
compiles it, and runs it. Every number and figure from §4 onward is that
program's literal output.

§2 derives the exponential-family GLM framework, the IRLS fitting
algorithm, deviance and dispersion, and the perfect-separation degeneracy,
each tied to the specific library call that implements it. §3 describes the
program chunk by chunk. §4 reports the fitted logistic model, its
diagnostic plots, a predicted-probability curve with a confidence band, the
perfect-separation demonstration, the Poisson fit, and an AIC comparison
across families. §5 discusses what these results say about GLM as a

* Background: Generalized Linear Models

** Setup and notation

$n$ observations, a linear predictor $\eta_i = x_i^\top \beta$ built from
the same formula engine (=stats::Formula=) every other report in this
project uses, and a response $y_i$ whose /mean/ (not $y_i$ itself) is
related to $\eta_i$ through a link function $g$: $g(\mu_i) = \eta_i$, where
$\mu_i = \mathrm{E}[y_i]$. Setting $g$ to the identity function and
requiring $y_i$ Gaussian recovers exactly the
[[file:lm_penguins_analysis.org][linear regression companion report]]'s
OLS -- GLM is a strict generalization, not a different method.

** The exponential family and canonical links

Each response distribution =stats::GLMFamily= supports belongs to the
exponential family, and each is paired with its /canonical/ link -- the
link for which the model's log-likelihood is guaranteed concave, matching
R's =glm()= defaults exactly: Gaussian uses the identity link
($\mu_i = \eta_i$), binomial uses the logit link
($\eta_i = \log\frac{\mu_i}{1-\mu_i}$), Poisson uses the log link
($\eta_i = \log \mu_i$), and Gamma uses the inverse link
($\eta_i = 1/\mu_i$). Every family also has a distribution-specific /variance
function/ $V(\mu)$ describing how the response's variance depends on its
mean -- constant for Gaussian, $\mu(1-\mu)$ for binomial, $\mu$ for
Poisson -- which is exactly what makes a Poisson or binomial response
/heteroscedastic/ by construction, unlike OLS's constant-variance
assumption.

** Iteratively reweighted least squares

Maximizing a GLM's log-likelihood has no closed form in general (unlike
OLS's normal equations), so =GLM::fit= uses /iteratively reweighted least
squares/ (IRLS) -- algebraically equivalent to Fisher scoring, and, for a
canonical link, to Newton-Raphson on the log-likelihood directly. Each
iteration linearizes the link function around the current fit to build a
/working response/

\[
z_i = \eta_i + (y_i - \mu_i) \, g'(\mu_i) ,
\qquad
w_i = \frac{1}{g'(\mu_i)^2 \, V(\mu_i)} ,
\]

then solves the /weighted/ normal equations
$\hat\beta \leftarrow (X^\top W X)^{-1} X^\top W z$ for that iteration's
$w_i$ and $z_i$ -- exactly a weighted least-squares problem, re-solved from
scratch every iteration as $\mu_i$, and therefore $z_i$ and $w_i$, change.
=GLMOptions::max_iter= (default 25) and =tol= (default $10^{-8}$) bound
this loop; =final_weights_= (exposed indirectly through
=standard_errors()='s covariance) are the $w_i$ from the last iteration.
§2.7 returns to what happens when $w_i \to 0$ for enough observations.

** Deviance

Where OLS uses residual sum of squares, a GLM's goodness of fit is measured
by /deviance/, $D = 2\big(\ell_{\text{sat}} - \ell(\hat\beta)\big)$: twice
the log-likelihood gap between the fitted model and the /saturated/ model
(one parameter per observation, the best any model in this family could
possibly do). =null_deviance()= is the same quantity for the
intercept-only model, so the gap between =null_deviance()= and
=deviance()= plays the same "how much did the predictors help" role
$R^2$ plays for OLS, without requiring a Gaussian response. Per-observation
/deviance residuals/ -- =residuals()=, the =Min/1Q/Median/3Q/Max= line in
every =print_summary()= call below -- are signed square roots of each
observation's contribution to $D$, $\mathrm{sign}(y_i - \mu_i)\sqrt{d_i}$,
constructed so that, for a well-fitting model, they behave like the
Gaussian residuals the diagnostic plots in §3.4.3 and §3.4.7 already know
how to display (mirroring R's =plot.glm=, itself close to =plot.lm=).

** Dispersion, standard errors, and AIC

The binomial and Poisson variance functions in §2.2 fully determine the
response's variance from its mean alone, so their /dispersion/ parameter
$\phi$ is fixed at exactly 1 (=dispersion()=). Gaussian and Gamma do not
share that property, so =GLM= estimates $\phi$ from the Pearson residuals,
$\hat\phi = \sum_i (y_i-\mu_i)^2 / V(\mu_i) \big/ (n-p)$, and the fitted
covariance matrix (=covariance()=) is $\hat\phi (X^\top W X)^{-1}$
throughout, unifying both cases into one formula. Coefficient significance
then follows the matching reference distribution: a $z$ statistic against
the standard normal when $\phi$ is fixed (binomial, Poisson), a $t$
statistic against $n-p$ degrees of freedom when $\phi$ is estimated
(Gaussian, Gamma) -- =test_statistics()= and =p_values()= switch
automatically based on =family()=. Finally, =aic()= reports
$2p - 2\ell(\hat\beta)$ (plus, for Gaussian/Gamma, the extra parameter for
$\hat\phi$ itself); unlike deviance, AIC is valid to compare /across/
different families fit to the /same/ response data, since it is built
directly from each model's log-likelihood on that data rather than from a
family-specific saturated-model baseline -- §4.6 uses this directly.

** Confidence intervals via the delta method

A prediction's standard error is naturally computed on the /link/ scale,
where the model is linear in $\beta$ and the usual
$\mathrm{Var}(x_0^\top\hat\beta) = x_0^\top \hat\phi(X^\top WX)^{-1} x_0$
applies; =predict(newdata, GLMPredictionInterval::Confidence)= builds the
interval there, then maps the endpoints back through the inverse link
$g^{-1}$ to the response scale (the delta method). This is why the
confidence band in §4.3's sigmoid figure narrows smoothly and never
leaves $[0,1]$: the interval is constructed in a space where it can be
made symmetric and unbounded, then transformed, rather than being
symmetric on the response scale itself, where symmetry could push it
outside the range the response can actually take.

** Perfect separation

Binomial IRLS's weights are $w_i = \mu_i(1-\mu_i)$ under the canonical
logit link (§2.2's variance function, since $g'(\mu)^2 V(\mu)$ simplifies
exactly to $1/[\mu(1-\mu)]$ for the logit link). If a predictor combination
exists that perfectly separates the two response classes, the
maximum-likelihood fit drives $\hat\eta_i \to \pm\infty$ for every
observation to push every $\mu_i$ arbitrarily close to its observed $y_i
\in \{0,1\}$ -- there is no finite maximizer, only a supremum approached in
the limit. Concretely, this collapses every $w_i$ toward exactly zero as
the iterations proceed, which makes the weighted design matrix
$X^\top W X$ increasingly singular; §4.4 shows what =GLM= actually returns
when this happens (spoiler: not a large number, but =NaN=, once the matrix
becomes exactly singular to floating-point precision within
=max_iter= iterations). This is a well-documented, genuine degeneracy of
maximum-likelihood logistic regression (see e.g. Albert & Anderson, 1984)
and not specific to this implementation -- R's own =glm()= produces a
"fitted probabilities numerically 0 or 1 occurred" warning and similarly
unusable standard errors on the same kind of data.

** What we will report

Given the fits, we report exploratory data, the logistic model's own
summary and diagnostic plots, resubstitution accuracy, a
predicted-probability curve with a confidence band, the perfect-separation
demonstration, the Poisson model's summary and diagnostics, an AIC
comparison across families on the same response, and predictions for three
new flowers.

* Data and Methods

** The data

As in every companion report: =datamunge::datasets::iris()= returns
Fisher's 150 flowers -- 50 each of /setosa/, /versicolor/, /virginica/ --
measured on =Sepal.Length=, =Sepal.Width=, =Petal.Length=, =Petal.Width=
(cm), with no missing values. The logistic and separation-demo models use a
binary species indicator built from this data (never a native three-level
factor, since binomial =GLM= expects a $\{0,1\}$ response); the Poisson
model uses =Sepal.Length= rounded to the nearest integer as a synthetic
count response, purely to have a genuine non-negative-integer variable to
demonstrate the family on.

** Software

The entire analysis is one C++ program against =datamunge=:
=dstruct::DataFrame= for the data, the formula-driven =stats::GLM= for
every model in this report, and =plot::RPlot= for every figure. No external
plotting or statistics package is used.

#+name: glm-fit-logit
#+begin_src c++ :eval no
    std::vector<double> is_virginica, petal_length, petal_width;
    for (std::size_t i = 0; i < iris.nrows(); ++i) {
        const auto species = iris.string_at("Species", i);
        if (species != "versicolor" && species != "virginica") continue;
        is_virginica.push_back(species == "virginica" ? 1.0 : 0.0);
        petal_length.push_back(iris.double_at("Petal.Length", i));
        petal_width.push_back(iris.double_at("Petal.Width", i));
    }
    DataFrame sub;
    sub.add_column("Petal.Length", petal_length);
    sub.add_column("Petal.Width", petal_width);
    sub.add_column("is_virginica", is_virginica);

    std::cout << "\n=== Logistic regression (binomial, logit link) ===\n";
    GLMOptions logit_options;
    logit_options.family = GLMFamily::Binomial;
    GLM logit(sub, "is_virginica ~ Petal.Length + Petal.Width",
              logit_options);
    logit.print_summary(std::cout);
#+end_src

*** Predicted-probability curve with a confidence band

Petal length varies across the grid; petal width is held at its sample
mean, giving the classic single-predictor sigmoid view of a two-predictor
fit.

#+name: glm-logit-curve
#+begin_src c++ :eval no
    double width_mean = 0.0;
    for (const double w : petal_width) width_mean += w;
    width_mean /= static_cast<double>(petal_width.size());

    constexpr std::size_t kGridN = 100;
    double pl_min = *std::min_element(petal_length.begin(),
                                       petal_length.end()) - 0.3;
    double pl_max = *std::max_element(petal_length.begin(),
                                       petal_length.end()) + 0.3;
    std::vector<double> grid_x(kGridN), grid_width(kGridN, width_mean);
    for (std::size_t i = 0; i < kGridN; ++i)
        grid_x[i] = pl_min + (pl_max - pl_min)
            * static_cast<double>(i) / static_cast<double>(kGridN - 1);
    DataFrame grid;
    grid.add_column("Petal.Length", grid_x);
    grid.add_column("Petal.Width", grid_width);
    const auto curve = logit.predict(grid, GLMPredictionInterval::Confidence);

    {
        auto plot = RPlot::create();
        std::vector<double> obs_x0, obs_y0, obs_x1, obs_y1;
        for (std::size_t i = 0; i < is_virginica.size(); ++i) {
            (is_virginica[i] > 0.5 ? obs_x1 : obs_x0)
                .push_back(petal_length[i]);
            (is_virginica[i] > 0.5 ? obs_y1 : obs_y0)
                .push_back(is_virginica[i]);
        }
        plot.points(obs_x0, obs_y0, "versicolor (0)", {37, 99, 235}, 5.0);
        plot.points(obs_x1, obs_y1, "virginica (1)", {220, 38, 38}, 5.0);
        plot.line(grid_x, curve.lower, "lower 95%", {252, 165, 165}, 1.5);
        plot.line(grid_x, curve.upper, "upper 95%", {252, 165, 165}, 1.5);
        plot.line(grid_x, curve.fit, "P(virginica)", {124, 58, 237}, 2.5);

** AIC comparison across families

#+begin_example
Binomial (logit) AIC: 26.564  deviance: 20.564
Gaussian (identity) AIC on the same 0/1 response: 25.948  deviance: 7.006
#+end_example

The two deviance figures are /not/ comparable to each other -- each is
defined relative to its own family's saturated-model baseline (§2.4), so
20.564 and 7.006 live on different scales. The two AIC figures, per §2.5,
/are/ directly comparable, since both are built from each model's actual
log-likelihood on the identical 100 observations -- and, perhaps
surprisingly, the mismatched Gaussian fit's AIC (25.948) is very slightly
/lower/ than the correctly-specified binomial fit's (26.564). §5 discusses
why this is a genuine property of comparing a bounded-likelihood family
against an unbounded one, not a reason to prefer linear probability models
for binary data in general.

* Discussion

**What perfect separation says about maximum-likelihood logistic
regression, concretely.** Every textbook treatment of logistic regression
mentions perfect separation as a theoretical concern; §4.4 turns it into a
reproducible, real numerical event using this project's own iris data and
this project's own =GLM= implementation. The practical lesson is narrow but
important: a predictor combination that fits /too/ well for a
maximum-likelihood binomial GLM is not a success to celebrate uncritically
-- it is a sign the likelihood has no finite maximizer at all, and a
production system should check for near-zero IRLS weights or
non-finite output (exactly what §4.4 reports) rather than silently
reporting a coefficient table full of noise. Real fixes -- Firth's
bias-reduced logistic regression (Firth, 1993) being the standard one --
are outside =GLM='s current scope but a natural extension.

**What the AIC comparison does and does not show.** §4.6's headline
number -- a mismatched Gaussian fit narrowly beating the correctly
specified binomial fit on AIC -- is a real property of comparing a
continuous (unbounded log-likelihood as residual variance shrinks) family
against a genuinely bounded one (binomial log-likelihood is bounded above
for any finite $\beta$), not evidence that linear probability models are
generally preferable for binary responses. A linear probability model
still routinely produces fitted "probabilities" outside $[0,1]$ on data
less cleanly separated than this pair, and its constant-variance
assumption is simply wrong for a $\{0,1\}$ response (§2.2) regardless of
what AIC reports on any one dataset; this comparison is included precisely
to make that subtlety concrete rather than to recommend the mismatched
model.

**Connection to the wider project.** This report's logistic regression is,
mechanically, the closest relative in this project to the six classifiers
in the LDA/SVM/decision-tree/random-forest/GBM/XGBoost reports: all seven
produce a decision boundary (implicit, here, in the $P=0.5$ contour of
§4.3's sigmoid) from the same 150 flowers. Logistic regression's 94.00%
resubstitution accuracy on the harder /versicolor//virginica/ pair sits
squarely in the same 95-100% range every other method reports on the full
three-class problem, and its genuine failure mode (§4.4) is a reminder,
distinct from every other method's shared resubstitution-accuracy caveat,
that a GLM's coefficients can fail outright rather than merely overfit.

* Conclusion

Fitting logistic and Poisson regression with =datamunge='s C++
=stats::GLM= reproduces the standard behavior of both members of the
generalized linear model family on real data: a clean, significant,
94.00%-accurate logistic fit separating two genuinely overlapping iris
species, and a Poisson fit correctly identifying its true underlying
predictor. Deliberately pushing the same method to a perfectly separable
pair produces a real, reproducible numerical failure -- coefficients,
standard errors, and deviance all returning =NaN= -- that concretely
demonstrates a well-known theoretical degeneracy of maximum-likelihood
logistic regression rather than merely describing it, and a same-data AIC
comparison across families shows precisely why deviance and AIC play
different roles in model comparison. As with its companions, this entire
report is reproducible end to end via =just org-example glm_iris_analysis=,
which re-executes §3.3.9's assembly block -- and therefore every number
and figure above -- from the =datamunge= source tree.
