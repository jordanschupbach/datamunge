#+begin_abstract
Pollard's \(p-1\) algorithm (1974) factors \(n\) whenever it has a prime factor
\(p\) such that \(p-1\) is *smooth* -- built only from small primes. By Fermat's little
theorem \(a^{p-1}\equiv1\pmod p\), so if we raise \(a\) to a highly composite exponent
\(M\) that is a multiple of \(p-1\), then \(a^M-1\) is divisible by \(p\), and
\(\gcd(a^M-1,n)\) hands us \(p\). It costs almost nothing when it works, and its
existence is precisely why cryptographic primes are chosen so that \(p-1\) has a *large*
prime factor. This report drives =datamunge='s =algorithms::pollard_p_minus_1=, verified to
split smooth composites, and shows it failing on a safe-prime modulus.
#+end_abstract

* Ride the smooth order

Pick a base \(a\) (say 2) and an exponent \(M=\operatorname{lcm}(1,2,\dots,B)\) for a
*smoothness bound* \(B\). Compute \(a^M\bmod n\) by raising through \(a\leftarrow
a^j\) for \(j=2,\dots,B\). If some prime factor \(p\mid n\) has \((p-1)\mid M\) -- true
exactly when \(p-1\) is \(B\)-smooth -- then \(a^M\equiv1\pmod p\), so \(p\mid
a^M-1\), and

\[ \gcd(a^M-1,\ n) \]

is a nontrivial factor (as long as *not every* factor went smooth at once, which is why we test
the gcd as \(M\) grows and stop at the first split). The method's reach is set by \(B\):
raise \(B\) and more factors become findable, at proportional cost. It is defeated by a
*safe prime* \(p=2q+1\) with \(q\) prime, since then \(p-1=2q\) needs \(B\ge q\) --
enormous.

* Algorithm

#+begin_example
POLLARD-P-1(n, B):
  a <- 2
  for j = 2 .. B:
      a <- a^j mod n
      g <- gcd(a - 1, n)
      if 1 < g < n: return g          # p-1 divided the exponent so far
      if g == n: return FAIL          # all factors smoothed at once
  return FAIL
#+end_example

* Worked example: a smooth factor found, a safe prime resisting

We factor \(n=1009\cdot2003\) (both \(p-1\) smooth) and watch the smallest bound \(B\)
that succeeds; then we try \(n'=2039\cdot2063\) whose primes are *safe-prime-like*
(\(p-1=2\times\text{large prime}\)) and see it resist small bounds.

#+name: pm-run
#+begin_src c++ :eval no
    const std::uint64_t n_smooth = 1009ULL * 2003ULL;   // 1008=2^4*3^2*7 (7-smooth), 2002=2*7*11*13
    const std::uint64_t n_safe   = 2039ULL * 2063ULL;   // 2038=2*1019, 2062=2*1031 (both hard)

    std::cout << "=== smooth case n = 1009*2003 = " << n_smooth << " ===\n";
    const std::uint64_t f = pollard_p_minus_1(n_smooth, 20);
    std::cout << "B=20 -> factor " << f << " (n/f = " << (f ? n_smooth / f : 0) << ")\n\n";

    std::cout << "=== safe-prime case n = 2039*2063 = " << n_safe << " ===\n";
    std::cout << "B=50 -> " << (pollard_p_minus_1(n_safe, 50) ? "found" : "FAILED")
              << ", B=1100 -> factor " << pollard_p_minus_1(n_safe, 1100) << "\n\n";

    // Success (1) vs bound B, for both moduli.
    std::vector<double> bs, s_smooth, s_safe;
    std::cout << "B     smooth-n   safe-n\n";
    for (int B = 2; B <= 40; ++B) {
        const int a = pollard_p_minus_1(n_smooth, B) ? 1 : 0;
        const int b = pollard_p_minus_1(n_safe, B) ? 1 : 0;
        bs.push_back(B); s_smooth.push_back(a); s_safe.push_back(b);
        if (B % 4 == 0) std::printf("%-4d  %-9d  %d\n", B, a, b);
    }

    auto plot = RPlot::create();
    plot.line(bs, s_smooth, "smooth", RGB{5, 150, 105}, 2.0);
    plot.points(bs, s_smooth, "smooth", RGB{5, 150, 105}, 5.0);
    plot.line(bs, s_safe, "safe", RGB{220, 38, 38}, 2.0);
    plot.points(bs, s_safe, "safe", RGB{220, 38, 38}, 5.0);
    plot.legend({"smooth p-1 (factored)", "safe-prime p-1 (resists)"}, {{5, 150, 105}, {220, 38, 38}});
    plot.title("Pollard p-1 succeeds once B reaches the largest prime in p-1")
        .x_label("smoothness bound B").y_label("factor found (1 = yes)").background({250, 250, 252});
    plot.save_svg("build/org/pollard_p_minus_1.svg");
    std::cout << "\nwrote pollard_p_minus_1.svg\n";
#+end_src

The smooth modulus falls to a bound as small as \(B=7\) (the largest prime dividing
\(1008\)), while the safe-prime modulus resists every small bound and yields only once
\(B\) reaches \(\sim1019\). Same algorithm, same base -- the outcome depends entirely on
whether *some* \(p-1\) is smooth.

The green "smooth" curve jumps to 1 (factored) at a tiny bound and stays there; the red
"safe" curve sits flat at 0 across the whole plotted range, needing a bound far larger than
shown. That gap is the entire security argument for choosing primes with a large factor in
\(p-1\): it turns this near-free attack into an infeasible one.
