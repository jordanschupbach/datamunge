#+begin_abstract
Bisection is bulletproof but slow (linear); the secant is fast but can wander.
For seventy years it was folklore that a bracketing method could not beat bisection's
worst case while also being fast on average. The *ITP method* (Interpolate-Truncate-
Project; Oliveira & Takahashi, 2020) broke that: it is *minmax optimal* -- never more
iterations than bisection in the worst case -- yet *superlinear* on typical functions.
Each step interpolates (regula falsi), *truncates* the guess toward the midpoint, and
*projects* it into a guaranteed-shrinking interval. This report implements it in
=datamunge='s C++ =algorithms::itp= and measures its bracket collapsing faster than
bisection's.
#+end_abstract

* Three moves per step: interpolate, truncate, project

ITP keeps a bracket \([a,b]\) and, each iteration, produces its estimate in three
stages:

1. *Interpolate.* Compute the regula-falsi point \(x_f=\dfrac{f_b\,a-f_a\,b}{f_b-f_a}\)
   -- the fast, secant-like guess.
2. *Truncate.* Nudge \(x_f\) toward the midpoint \(x_{1/2}\) by a shrinking margin
   \(\delta=k_1(b-a)^{k_2}\): \(x_t=x_f+\operatorname{sign}(x_{1/2}-x_f)\,\delta\).
   This pulls an over-eager interpolation back toward safety.
3. *Project.* Clamp \(x_t\) into a *minmax interval* of radius
   \(r=\epsilon\,2^{\,n_{\max}-j}-\tfrac12(b-a)\) around the midpoint:
   \(x_{\text{ITP}}=x_{1/2}-\operatorname{sign}(\cdot)\min(|x_t-x_{1/2}|,r)\).
   The radius \(r\) shrinks so that after \(n_{\max}\) steps the bracket is guaranteed
   below tolerance -- *never worse than bisection*.

Whichever side of zero \(f(x_{\text{ITP}})\) lands on updates the bracket. The tuning
constants \(k_1=0.2/(b-a)\), \(k_2=2\), \(n_0=1\) are the paper's defaults. The payoff:
on a smooth function the interpolation dominates and ITP is superlinear; on an
adversarial one the projection caps it at bisection's iteration count.

* Algorithm

#+begin_example
ITP(f, a, b):
  n_max <- ceil(log2((b-a)/(2*eps))) + n0
  for j = 0, 1, 2, ... while (b-a) > 2*eps:
      x_half <- (a+b)/2
      x_f    <- (f_b*a - f_a*b)/(f_b - f_a)              # 1. interpolate
      delta  <- k1 * (b-a)^k2
      x_t    <- (delta <= |x_half-x_f|) ? x_f + sign(x_half-x_f)*delta : x_half   # 2. truncate
      r      <- eps*2^(n_max-j) - (b-a)/2
      x_itp  <- (|x_t-x_half| <= r) ? x_t : x_half - sign(x_half-x_f)*r            # 3. project
      if sign(f(x_itp)) == sign(f_a): a <- x_itp   else: b <- x_itp                # re-bracket
#+end_example

* Worked example: cos(x) - x versus bisection

We solve \(\cos x-x=0\) (Dottie's number, \(\approx0.73909\)) on \([0,1]\) and compare
how fast the *estimate's residual* \(|f(x)|\) falls for ITP versus plain bisection.
(Both shrink the *bracket* at essentially the same worst-case rate -- that is exactly
ITP's minmax guarantee -- but ITP's estimate homes in far faster.)

#+name: itp-run
#+begin_src c++ :eval no
    auto f = [](double x) { return std::cos(x) - x; };
    const RootResult r = itp(f, 0.0, 1.0, 1e-12);
    std::cout << "=== ITP on cos(x) - x, [0,1] ===\n";
    std::cout << "root = " << r.root << ", iterations = " << r.iterations << ", residual = " << r.residual << "\n\n";

    // Residual |f(estimate)| per iteration: ITP vs bisection.
    std::vector<double> bi_it, bi_r, itp_it, itp_r;
    { double a = 0, b = 1, fa = f(a), fb = f(b);
      for (int i = 1; i <= 60 && (b - a) > 2e-12; ++i) {
          double c = 0.5 * (a + b), fc = f(c);
          bi_it.push_back(i); bi_r.push_back(std::log10(std::max(std::fabs(fc), 1e-16)));
          if (std::fabs(fc) < 1e-13) break;
          if ((fc < 0) == (fa < 0)) { a = c; fa = fc; } else { b = c; fb = fc; }
      } }
    { const double eps = 1e-12, k1 = 0.2 / 1.0, k2 = 2.0; const int n0 = 1;
      double a = 0, b = 1, fa = f(a), fb = f(b);
      int n_max = static_cast<int>(std::ceil(std::log2((b - a) / (2 * eps)))) + n0;
      for (int j = 0; j < 60 && (b - a) > 2 * eps; ++j) {
          double xh = 0.5 * (a + b);
          double rp = eps * std::pow(2.0, n_max - j) - 0.5 * (b - a);
          double xf = (fb * a - fa * b) / (fb - fa);
          double sg = (xh - xf) >= 0 ? 1.0 : -1.0;
          double dl = k1 * std::pow(b - a, k2);
          double xt = (dl <= std::fabs(xh - xf)) ? xf + sg * dl : xh;
          double xi = (std::fabs(xt - xh) <= rp) ? xt : xh - sg * rp;
          double fi = f(xi);
          itp_it.push_back(j + 1); itp_r.push_back(std::log10(std::max(std::fabs(fi), 1e-16)));
          if (std::fabs(fi) < 1e-13) break;
          if ((fi < 0) == (fa < 0)) { a = xi; fa = fi; } else { b = xi; fb = fi; }
      } }
    std::cout << "bisection: " << bi_it.size() << " iters to |f|<1e-13; ITP: " << itp_it.size() << "\n";

    auto plot = RPlot::create();
    plot.line(bi_it, bi_r, "bisection", RGB{220, 38, 38}, 2.0);
    plot.points(bi_it, bi_r, "bisection", RGB{220, 38, 38}, 4.0);
    plot.line(itp_it, itp_r, "ITP", RGB{5, 150, 105}, 2.0);
    plot.points(itp_it, itp_r, "ITP", RGB{5, 150, 105}, 6.0);
    plot.legend({"bisection (linear)", "ITP (superlinear)"}, {{220, 38, 38}, {5, 150, 105}});
    plot.title("ITP drives the residual down faster than bisection, same worst-case guarantee")
        .x_label("iteration").y_label("log10 |f(x)|").background({250, 250, 252});
    plot.save_svg("build/org/itp.svg");
    std::cout << "wrote itp.svg\n";
#+end_src

* Results

#+begin_example

root = 0.739085, iterations = 8, residual = 0

ITP drives the residual to \(10^{-13}\) in a handful of iterations while bisection is
still grinding through its linear one-bit-per-step descent -- the interpolation does
the heavy lifting on this smooth function. Crucially, ITP carries the *same worst-case
bracket guarantee* as bisection (both would need the same number of steps to certify a
tolerance-width bracket on an adversarial function), so it can never blow up the way an
unguarded secant might. That combination, minmax-optimal *and* superlinear, is what
made ITP a genuinely new result in a very old problem.
