#+begin_abstract
*Shortest-Remaining-Time* (SRT, preemptive shortest-job-first) always runs the ready process
with the least *remaining* work, preempting the current job the instant a shorter one
arrives. It is *optimal for average waiting time* over all scheduling policies, at the cost
of more context switches and, like all shortest-first schemes, possible starvation of long
jobs. This report implements it in =datamunge='s C++ =algorithms::shortest_remaining_time= as
a literate program: every number and figure comes from one compiled binary. We run the
classic four-process example, draw the preempting timeline, and report waiting and turnaround
times.
#+end_abstract

* Preempt on a shorter arrival

At every instant SRT compares the remaining time of the running job against every newly
ready job; if some job has less work left, it preempts. This is the preemptive refinement of
shortest-job-next, and the same rearrangement argument shows it is optimal for mean waiting
time -- now over *all* schedulers, because preemption lets a late-arriving short job jump
ahead of a long one already in progress. The price is context-switch overhead and starvation:
a steady stream of short jobs can indefinitely postpone a long one.

#include <datamunge/algorithms/cpu_scheduling.hpp>

#include <cstddef>
#include <iostream>
#include <string>
#include <vector>

using namespace datamunge::algorithms;
using namespace datamunge::plot;

// Draw a Gantt chart: one horizontal row per process id, a colored box per run slice.
inline void draw_gantt(const ScheduleResult& r, std::size_t nproc, const char* path) {
    static const RGB palette[] = {{37,99,235},{220,38,38},{22,163,74},{202,138,4},{147,51,234}};
    RPlot p = RPlot::create();
    for (const auto& g : r.gantt) {
        double y = static_cast<double>(g.id);
        p.polygon({(double)g.start,(double)g.end,(double)g.end,(double)g.start},
                  {y-0.4, y-0.4, y+0.4, y+0.4}, palette[g.id % 5], true);
    }
    std::vector<double> ax, ay;
    for (std::size_t i = 0; i < nproc; ++i) { ax.push_back(0.0); ay.push_back((double)i); }
    p.points(ax, ay, "", {0,0,0}, 0.1);
    p.save_svg(path);
}
#+end_src

#+begin_example
SRT(processes):
    at each time unit t:
        ready = arrived, unfinished processes
        i = ready process with least remaining time (ties: arrival)
        run i for one unit; if remaining[i]==0 record completion[i]
    (a shorter arrival preempts the running job automatically)
#+end_example

* A worked example

The classic four-process instance: arrivals 0, 1, 2, 3 with bursts 8, 4, 9, 5.

* Results

#+begin_example
=== Shortest-remaining-time ===
arrivals/bursts: P0(a0,b8) P1(a1,b4) P2(a2,b9) P3(a3,b5)

execution timeline (merged slices):
  [0,1) P0
  [1,5) P1
  [5,10) P3
  [10,17) P0
  [17,26) P2

proc  completion  turnaround  waiting
  P0        17          17         9
  P1        5          4         0
  P2        26          24         15
  P3        10          7         2
average waiting = 6.5, average turnaround = 13
#+end_example

P0 starts alone, but the moment the shorter P1 arrives at \(t=1\) it is preempted; P1 runs to
completion, then the scheduler picks the shortest remaining job among those waiting (P3, then
P0, then P2). The result -- an average waiting time of 6.5 -- is the minimum achievable by any
scheduler on this workload, which is exactly the optimality guarantee of shortest-remaining-time.
Compared with the non-preemptive shortest-job-next, preemption lets the short P1 skip ahead of
the long P0 instead of waiting for it to finish.

* Character and relatives

SRT is optimal for mean waiting time but impractical in pure form: it needs known burst
lengths and preempts frequently. Real systems approximate it with *multilevel feedback
queues* that infer job length from observed behavior (short, I/O-bound jobs bubble to high
priority; CPU-bound jobs sink), capturing most of SRT's benefit while bounding starvation. The
non-preemptive *shortest-job-next* trades optimality for fewer switches, and *round-robin*
abandons burst-awareness entirely for fairness.

* Complexity

\(O(T\cdot n)\) for a horizon of \(T\) time units and \(n\) processes in this unit-step
simulation; an event-driven implementation with a remaining-time priority queue runs in
\(O(k\log n)\) where \(k\) is the number of preemption/arrival events.
