#+begin_abstract
Apriori generates and tests candidate itemsets; Eclat intersects tidsets.
*FP-growth* (Han, Pei & Yin 2000) does neither -- it *compresses the entire
database into a tree* and mines that tree recursively, generating no candidates
at all. The frequent-pattern tree (FP-tree) stores every transaction as a path
from the root, with shared prefixes merged and node counts recording how many
transactions traverse each edge; frequent patterns are then read off by walking
the paths that end at each item -- its *conditional pattern base* -- and mining the
smaller conditional trees they induce. Because common prefixes collapse into
shared paths, dense databases compress dramatically and are mined in two passes.
This report implements it in =datamunge='s C++
=algorithms::fp_growth_frequent_itemsets= as a literate program: every number
below comes from one compiled binary. We mine the same grocery database as the
Apriori and Eclat reports and confirm the three agree.
#+end_abstract

* The frequent-pattern tree

FP-growth makes two passes over the data. The first counts item frequencies,
discards infrequent items, and fixes an order on the survivors -- by *descending*
frequency, so the most common items sit near the root and share the most. The
second pass inserts each transaction: its frequent items, sorted into that order,
are threaded from the root downward, creating nodes where needed and incrementing
a count on each node passed. Transactions sharing a prefix share the corresponding
path, so the tree is a lossless, compressed picture of the database. A *header
table* links, for each item, all the nodes carrying it, so every occurrence can be
reached quickly.

For our grocery database (with =milk= and =bread= most frequent) the tree looks
schematically like:

#+begin_example
             (root)
            /      \
        milk:5      beer:1        <- items ordered by descending frequency
        /    \         \
   bread:3  butter:1  diapers:1
      |
   butter:3   ...
#+end_example

(the exact shape depends on the frequency order and ties; the compiled program
below mines it rather than drawing it).

#+name: fpgrowth-includes
#+begin_src c++ :eval no
#include <datamunge/algorithms/association_rules.hpp>
#include <datamunge/plot/plot.hpp>

#include <cstddef>
#include <iostream>
#include <string>
#include <vector>

using namespace datamunge::algorithms;
using namespace datamunge::plot;

static std::string name_set(const std::vector<std::size_t>& items) {
    static const char* names[] = {"bread", "milk", "butter", "beer", "diapers"};
    std::string        s = "{";
    for (std::size_t i = 0; i < items.size(); ++i) s += (i ? ", " : "") + std::string(names[items[i]]);
    return s + "}";
}
#+end_src

* Mining by conditional pattern bases

With the tree built, FP-growth mines it recursively, one item at a time, working
from the least frequent item upward. For a target item \(x\):

1. Its *support* is the sum of counts over all header-table nodes for \(x\); emit
   \(\{x\}\cup\text{prefix}\) as frequent.
2. Its *conditional pattern base* is the multiset of prefix paths leading to each
   \(x\)-node, each weighted by that node's count -- these are the transactions
   "conditioned on containing \(x\)".
3. Build a *conditional FP-tree* from that base (re-counting frequencies within
   it, keeping only items still frequent) and recurse, prepending \(x\) to the
   prefix.

No candidate itemsets are ever enumerated: the tree structure hands frequent
patterns directly to the recursion. This is FP-growth's central advantage over
Apriori's generate-and-test loop.

** Pseudocode

#+begin_example
FPGrowth(transactions, minsup):
    build FP-tree T (2 passes: count+order frequent items, then insert)
    return FPMine(T, prefix = {})

FPMine(T, prefix):
    for each item x in T's header (least frequent first):
        support = sum of counts of x's nodes
        emit  prefix + x   with support
        base = { (path from x-node up to root, node.count) : each x-node }
        Tx = build conditional FP-tree from base with minsup
        if Tx not empty: FPMine(Tx, prefix + x)
#+end_example

* A worked example

We mine the eight-basket grocery database (bread, milk, butter, beer, diapers) at
\(\text{minsup}=2\), list the frequent itemsets, and confirm the result is
identical to Apriori's and Eclat's.

#+name: fpgrowth-run
#+begin_src c++ :eval no
    std::vector<std::vector<std::size_t>> txns = {
        {0, 1, 2}, {0, 1}, {1, 2}, {0, 1, 2}, {3, 4}, {0, 3, 4}, {3, 4}, {0, 1, 2, 3}};

    auto freq  = fp_growth_frequent_itemsets(txns, 2);
    auto aprio = apriori_frequent_itemsets(txns, 2);

    std::cout << "=== FP-growth on 8 grocery baskets (minsup = 2) ===\n";
    std::cout << freq.size() << " frequent itemsets:\n";
    for (const auto& fs : freq) std::cout << "  " << name_set(fs.items) << "  support " << fs.support << '\n';

    bool same = freq.size() == aprio.size();
    for (std::size_t i = 0; same && i < freq.size(); ++i)
        same = (freq[i].items == aprio[i].items) && (freq[i].support == aprio[i].support);
    std::cout << "\nidentical to Apriori's output: " << (same ? "yes" : "no") << '\n';

    // Conditional pattern base of the least-frequent item, diapers, illustrated by hand:
    // diapers occurs in transactions {4,5,6}; the items co-occurring with it are beer (x3).
    std::cout << "\nconditional pattern base of {diapers}: beer appears in all 3 -> {beer,diapers} freq\n";

    // Figure: support of every frequent itemset FP-growth returns.
    std::vector<double>      heights;
    std::vector<std::string> labels;
    for (const auto& fs : freq) {
        heights.push_back(static_cast<double>(fs.support));
        std::string s = name_set(fs.items);
        labels.push_back(s.substr(1, s.size() - 2));
    }
    RPlot p = RPlot::barplot(heights, labels, "support", {147, 51, 234});
    p.save_svg("build/org/fp_growth_supports.svg");
    std::cout << "\nwrote build/org/fp_growth_supports.svg\n";
#+end_src

* Why FP-growth scales

FP-growth's advantage grows with the database. Two passes build the tree; after
that, all mining happens on the compact tree and its (smaller) conditional trees,
never on the raw transactions. On dense data with many shared prefixes the tree
is far smaller than the database, and avoiding candidate generation sidesteps
Apriori's combinatorial blow-up. The costs are implementation complexity and the
memory for the tree and its header links; when the tree does not fit in memory,
partitioning or disk-based variants (and the vertical Eclat approach) become
attractive. All three algorithms in this trio are, by construction, guaranteed to
return the same frequent-itemset collection -- they are different routes to the
same summit.

* Complexity

The two database passes are \(O(N\cdot w)\) for \(N\) transactions of size up to
\(w\). Mining cost is output-sensitive in the number of frequent itemsets, with
recursion depth bounded by the longest frequent pattern; memory is dominated by
the FP-tree, which is at most the total size of the (frequent-filtered)
transactions and usually far less thanks to prefix sharing.
