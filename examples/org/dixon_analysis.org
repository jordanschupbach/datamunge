#+begin_abstract
The idea behind every modern factoring record -- the quadratic sieve, the number field sieve --
is a *congruence of squares*: if \(X^2\equiv Y^2\pmod n\) with \(X\not\equiv\pm Y\), then
\(\gcd(X-Y,n)\) is a nontrivial factor. *Dixon's algorithm* (1981) is the clean prototype:
find integers whose squares mod \(n\) are *smooth* over a small factor base, then combine a
subset -- chosen by linear algebra over \(\mathrm{GF}(2)\) -- so their product is a perfect
square on both sides. This report drives =datamunge='s =algorithms::dixon_factor=, verified to
split composites, and shows the smooth relations accumulating.
#+end_abstract

* Smooth squares, then a GF(2) dependency

Fix a *factor base* of the first \(k\) primes. Scan \(x=\lceil\sqrt n\rceil,\dots\) and
compute \(q=x^2\bmod n\); keep \(x\) only if \(q\) is *smooth* -- it factors entirely
over the base. Record its exponent vector, and reduce it mod 2 to a parity vector over the
\(k\) base primes. Collect \(k+1\) such relations and a *linear dependency over
\(\mathrm{GF}(2)\)* is guaranteed: some subset of the parity vectors sums to zero. For that
subset,

\[
X=\prod x_i \bmod n, \qquad Y=\prod_{\text{primes } p}p^{\frac12\sum e_p}\bmod n,
\]

satisfies \(X^2\equiv\prod q_i\equiv Y^2\pmod n\) -- because every prime's total exponent is
even, so the right side is a genuine square. Then \(\gcd(X-Y,n)\) is a factor (nontrivial
about half the time; other dependencies are tried otherwise). The subset is found by Gaussian
elimination over \(\mathrm{GF}(2)\). Dixon picks its smooth \(x\) at *random/by scanning*;
the sieve methods differ only in finding smooth values far faster, which is what pushed
factoring to hundreds of digits.

* Algorithm

#+begin_example
DIXON(n, factor base of k primes):
  scan x from ceil(sqrt n):
      q <- x^2 mod n
      if q is smooth over the base: record x and q's exponent-parity vector
      stop after k+1 relations
  find a subset with GF(2) parity sum = 0 (Gaussian elimination)
  X <- product of the x's;  Y <- product of primes^(half the summed exponents)
  return gcd(X - Y, n)   (try another dependency if trivial)
#+end_example

* Worked example: splitting composites, and smooth-relation density

We factor a few composites, then -- for one of them -- count how the smooth relations
accumulate as we scan more values of \(x\) (their density is what governs the running time).

#+name: dx-run
#+begin_src c++ :eval no
    for (std::uint64_t n : {8051ULL, 15347ULL, 92434447ULL, 16843009ULL}) {
        const std::uint64_t f = dixon_factor(n, 30);
        std::cout << n << " -> " << f << " x " << (f ? n / f : 0)
                  << (f ? "" : " (not found)") << "\n";
    }
    std::cout << "\n";

    // Smooth-relation accumulation for n = 92434447 with a 30-prime factor base.
    const std::uint64_t n = 92434447ULL;
    std::vector<std::uint64_t> base;
    for (std::uint64_t c = 2; base.size() < 30; ++c) {
        bool pr = true;
        for (std::uint64_t p : base) { if (p * p > c) break; if (c % p == 0) { pr = false; break; } }
        if (pr) base.push_back(c);
    }
    auto isqrt = [](std::uint64_t v) { std::uint64_t r = (std::uint64_t)std::sqrt((double)v); while (r * r > v) --r; while ((r + 1) * (r + 1) <= v) ++r; return r; };

    std::vector<double> scanned, found;
    long long smooth = 0;
    const std::uint64_t start = isqrt(n) + 1;
    for (std::uint64_t i = 0; i < 4000; ++i) {
        const std::uint64_t x = start + i;
        std::uint64_t q = (std::uint64_t)(( __uint128_t)x * x % n);
        std::uint64_t r = q;
        for (std::uint64_t p : base) while (r % p == 0) r /= p;
        if (q != 0 && r == 1) ++smooth;
        if (i % 100 == 99) { scanned.push_back(i + 1); found.push_back((double)smooth); }
    }
    std::cout << "n = " << n << ": " << smooth << " smooth relations in 4000 scanned x (base of 30 primes)\n";

    auto plot = RPlot::create();
    plot.line(scanned, found, "smooth", RGB{124, 58, 237}, 2.0);
    plot.points(scanned, found, "smooth", RGB{124, 58, 237}, 4.0);
    plot.legend({"cumulative smooth relations"}, {{124, 58, 237}});
    plot.title("Dixon collects smooth squares steadily as x is scanned")
        .x_label("values of x scanned").y_label("smooth relations found").background({250, 250, 252});
    plot.save_svg("build/org/dixon.svg");
    std::cout << "wrote dixon.svg\n";
#+end_src

* Results

Dixon splits each composite into true factors -- including the eight-digit \(92434447\) and
\(16843009=257\cdot65537\) (a product of Fermat primes) -- by assembling a congruence of
squares from smooth relations. The accumulation plot shows those smooth values arriving at a
steady rate as \(x\) is scanned; once more than the factor-base's worth have been gathered,
a \(\mathrm{GF}(2)\) dependency is guaranteed.

The purple line climbs roughly linearly: smooth squares appear at a fixed density that depends
on the factor base and the size of \(n\). Speeding up *that* collection -- finding smooth
values without dividing each one -- is the single improvement that turns Dixon into the
quadratic and number field sieves, and factoring from a curiosity into a threat to RSA.
