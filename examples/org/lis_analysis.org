#+begin_abstract
Given a sequence of numbers, how long is the longest run -- picking items in order,
skipping freely -- that strictly increases? The *longest increasing subsequence*
(LIS) problem appears in patience card games, in ranking and airplane-boarding
analyses, and (via Schensted's theorem) in the combinatorics of Young tableaux. A
naive dynamic program is \(O(n^2)\); *patience sorting* solves it in
\(O(n\log n)\) by binary-searching each element into a set of "piles". This report
implements it in =datamunge='s C++ =algorithms::longest_increasing_subsequence=,
which reconstructs an actual subsequence (not just its length), works a 16-element
example whose LIS has length 6, and plots the recovered increasing chain.
#+end_abstract

* Patience sorting

Deal the numbers one at a time onto piles under one rule: a number goes on the
leftmost pile whose current top is \(\ge\) it, or starts a new pile to the right
if none qualifies. The number of piles at the end equals the LIS length. Because
pile tops are always increasing left to right, "the leftmost pile whose top is
\(\ge x\)" is found by *binary search*, giving \(O(n\log n)\).

Concretely we keep an array =tail=, where =tail[k]= is the smallest value that can
end an increasing subsequence of length \(k+1\) seen so far (equivalently, the top
of pile \(k\)). For each \(x\) we binary-search the first =tail[k] >= x=; if none,
\(x\) extends the longest run and appends a new pile, otherwise it replaces that
pile's top (a smaller tail is always at least as useful). Storing, for each
element, the index of the previous pile's top when it was placed gives predecessor
links, from which an actual LIS is reconstructed by following the links back from
the last pile.

* Algorithm

#+begin_example
LIS(a):                               # returns one longest strictly increasing subsequence
  tail <- [] ; prev <- [-1]*n
  for i in 0..n-1:
      k <- first index with a[tail[k]] >= a[i]      # binary search (strict increase)
      if k > 0: prev[i] <- tail[k-1]
      if k == len(tail): tail.append(i)
      else:              tail[k] <- i
  # reconstruct from the last pile back through predecessors
  L <- [] ; i <- tail.last
  while i != -1: L.prepend(a[i]); i <- prev[i]
  return L
#+end_example

* Worked example

Take the interleaved sequence

: 0 8 4 12 2 10 6 14 1 9 5 13 3 11 7 15

which is built so that its LIS has length 6 (for instance =0 4 6 9 13 15= or
=0 2 6 9 11 15=). The program recovers one such subsequence and reports its
length.

#+name: lis-run
#+begin_src c++ :eval no
    const std::vector<int> a = {0, 8, 4, 12, 2, 10, 6, 14, 1, 9, 5, 13, 3, 11, 7, 15};
    const std::vector<int> lis = longest_increasing_subsequence(a);

    std::cout << "=== Longest increasing subsequence ===\n";
    std::cout << "sequence:";
    for (int x : a) std::cout << " " << x;
    std::cout << "\nLIS     :";
    for (int x : lis) std::cout << " " << x;
    std::cout << "  (length " << lis.size() << ")\n";

    // Plot the sequence and highlight the recovered increasing chain.
    auto plot = RPlot::create();
    std::vector<double> ax, ay;
    for (std::size_t i = 0; i < a.size(); ++i) { ax.push_back(static_cast<double>(i)); ay.push_back(a[i]); }
    plot.points(ax, ay, "sequence", RGB{148, 163, 184}, 8.0);

    // Recover the indices of the LIS by matching values greedily left to right.
    std::vector<double> lx, ly;
    std::size_t next = 0;
    for (std::size_t i = 0; i < a.size() && next < lis.size(); ++i)
        if (a[i] == lis[next]) { lx.push_back(static_cast<double>(i)); ly.push_back(static_cast<double>(a[i])); ++next; }
    plot.line(lx, ly, "LIS", RGB{220, 38, 38}, 2.0);
    plot.points(lx, ly, "LIS elements", RGB{220, 38, 38}, 11.0);
    plot.legend({"sequence", "LIS"}, {{148, 163, 184}, {220, 38, 38}});
    plot.title("Longest increasing subsequence (length 6)")
        .x_label("index").y_label("value").background({250, 250, 252});
    plot.save_svg("build/org/lis.svg");
    std::cout << "\nwrote lis.svg\n";
#+end_src

* Results

#+begin_example
=== Longest increasing subsequence ===
sequence: 0 8 4 12 2 10 6 14 1 9 5 13 3 11 7 15
LIS     : 0 2 6 9 11 15  (length 6)

wrote lis.svg
#+end_example

The recovered subsequence strictly increases, is a subsequence of the input, and
has length 6 -- the maximum. Patience sorting finds it with one binary search per
element, so the whole computation is \(O(n\log n)\) rather than the \(O(n^2)\) of
the naive pairwise dynamic program.
