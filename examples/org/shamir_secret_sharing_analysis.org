#+begin_abstract
How do you split a master key among five officers so that /any three/ can recover it but
/any two/ learn nothing? Shamir's 1979 scheme answers this with a single fact from algebra:
a degree \(k-1\) polynomial is pinned down by exactly \(k\) points, and by no fewer. Hide
the secret as the constant term of a random such polynomial, hand each participant one
point, and the threshold falls out for free. This report implements the scheme in
=datamunge='s =algorithms::shamir_split= / =shamir_combine= as a literate program: we split
a secret into six shares, reconstruct it from several different three-share subsets, and
show that two shares leave it undetermined.
#+end_abstract

* A polynomial through the secret

Work in a prime field \(\mathbb{Z}_p\). To share secret \(s\) with threshold \(k\), pick
random coefficients \(a_1,\dots,a_{k-1}\) and form

\[
  P(x) = s + a_1 x + a_2 x^2 + \dots + a_{k-1}x^{k-1} \pmod p,
\]

so \(P(0)=s\). Give participant \(i\) the point \((i, P(i))\) for \(i=1,\dots,n\). Because a
degree \(k-1\) polynomial is uniquely determined by any \(k\) of its points, any \(k\)
shares recover \(P\) -- and hence \(s=P(0)\) -- by *Lagrange interpolation at zero*:

\[
  s = P(0) = \sum_{i} y_i \prod_{j\ne i}\frac{x_j}{x_j - x_i}\pmod p .
\]

With only \(k-1\) shares the interpolation is underdetermined: for /every/ candidate secret
there is exactly one polynomial of degree \(k-1\) through those points plus \((0,\text{that
secret})\), so all secrets stay equally likely. That is *information-theoretic* security --
it does not rest on any computational hardness assumption.

** Pseudocode

#+begin_example
Split(secret s, n, threshold k, prime p):
    pick random a[1..k-1] in [0, p)
    for i in 1..n:
        P = s + a[1]*i + a[2]*i^2 + ... + a[k-1]*i^(k-1)  mod p
        share[i] = (i, P)
    return shares

Combine(shares, p):           # any k shares
    s = 0
    for each share i with point (xi, yi):
        num = product of xj   for j != i
        den = product of (xj - xi) for j != i
        s += yi * num * inverse(den mod p)   mod p    # Lagrange basis at x = 0
    return s
#+end_example

* A worked example

We share the secret \(1234\) into six shares with threshold three over the prime field
\(\mathbb{Z}_{2087}\). We then reconstruct from three /different/ three-share subsets (all
must return 1234), and show that a two-share subset returns some unrelated value -- proof
that two officers hold nothing usable.

#+name: shamir-run
#+begin_src c++ :eval no
    const std::uint64_t prime = 2087;
    const std::uint64_t secret = 1234;
    const std::vector<std::uint64_t> coeffs = {166, 94};  // threshold k = 3
    auto shares = shamir_split(secret, 6, coeffs, prime);

    std::cout << "=== Six shares of secret " << secret << " (k = 3, p = " << prime << ") ===\n";
    for (const auto& sh : shares)
        std::cout << "  share (" << sh.x << ", " << sh.y << ")\n";

    std::cout << "\n=== Reconstruct from different 3-share subsets ===\n";
    std::vector<std::vector<int>> subsets = {{0, 1, 2}, {0, 2, 4}, {1, 3, 5}, {2, 4, 5}};
    std::vector<double> recon, xs;
    for (std::size_t t = 0; t < subsets.size(); ++t) {
        std::vector<SecretShare> pick;
        for (int idx : subsets[t]) pick.push_back(shares[idx]);
        std::uint64_t r = shamir_combine(pick, prime);
        std::cout << "  shares {" << subsets[t][0] + 1 << "," << subsets[t][1] + 1 << ","
                  << subsets[t][2] + 1 << "} -> " << r << "\n";
        xs.push_back(static_cast<double>(t + 1));
        recon.push_back(static_cast<double>(r));
    }

    std::cout << "\n=== Below threshold: only 2 shares ===\n";
    std::vector<SecretShare> two = {shares[0], shares[1]};
    std::uint64_t bad = shamir_combine(two, prime);
    std::cout << "  shares {1,2} -> " << bad << "  (not the secret; two shares determine nothing)\n";

    // Plot: reconstructed value from each 3-subset, all landing on the secret line.
    std::vector<std::string> labels;
    for (std::size_t t = 0; t < subsets.size(); ++t) labels.push_back("subset " + std::to_string(t + 1));
    RPlot p = RPlot::barplot(recon, labels, "Reconstructed secret from four different 3-share subsets", {16, 122, 87});
    p.abline_h(static_cast<double>(secret), {220, 38, 38}, 1.5);  // the true secret
    p.save_svg("build/org/shamir_reconstruct.svg");
    std::cout << "\nwrote build/org/shamir_reconstruct.svg\n";
#+end_src

* Uses and cautions

Shamir sharing underpins key escrow, hardware-wallet backups, threshold signatures, and
distributed custody where no single party should hold a secret alone. Practical notes: use
a large prime (or \(\mathrm{GF}(2^8)\) byte-wise) so the secret fits and shares reveal
nothing; draw the coefficients from a *cryptographic* RNG (this report fixes them only for
reproducibility); the basic scheme is not *verifiable*, so a malicious participant can
submit a bad share and corrupt the reconstruction -- verifiable secret sharing (Feldman,
Pedersen) adds commitments to detect that.

* Complexity

Splitting is \(O(nk)\) field operations; reconstruction from \(k\) shares is \(O(k^2)\)
via Lagrange interpolation, with a modular inverse per term.
