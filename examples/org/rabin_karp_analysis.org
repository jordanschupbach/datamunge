#+begin_abstract
How do you find every place a short /pattern/ appears inside a long /text/
without re-inspecting every character of every candidate window? Karp and
Rabin (1987) answered with a hash: treat each length-\(m\) window of the text
as an \(m\)-digit number in some base, reduce it modulo a large prime, and
compare that single number against the pattern's hash. The trick is that the
hash of the next window follows from the current one in constant time -- drop
the leading digit, shift up by the base, add the new digit -- so a whole text
is scanned in expected \(O(n+m)\) time. A hash equality only /suggests/ a match,
because two different strings can collide modulo the prime, so a matching
window's characters are verified before it is reported; this keeps the results
exact while collisions merely cost an occasional wasted comparison. This report
implements the method in =datamunge='s C++ =algorithms::rabin_karp_search= and
presents it as a literate program: every number and figure below is produced by
a single compiled binary. A deliberately small, hand-checkable example --
searching for =aba= in =abababbb= with base \(10\) modulo \(101\) -- shows the
rolling hash gliding across six windows, the two genuine overlapping matches at
positions \(0\) and \(2\), and a /spurious/ collision at the trailing =bbb=
window whose hash equals the pattern's yet whose characters do not, exactly the
case verification exists to catch.
#+end_abstract

* The exact string-matching problem

Given a =text= of length \(n\) and a =pattern= of length \(m \le n\), the
exact string-matching problem asks for every start index \(s\) such that
=text[s .. s+m-1]= equals =pattern= character for character. Occurrences may
/overlap/: in =aaaa= the pattern =aa= starts at \(0\), \(1\), and \(2\). The
obvious algorithm slides the pattern over the text and compares up to \(m\)
characters at each of the \(n-m+1\) positions, costing \(O(n\,m)\) in the worst
case. Rabin-Karp keeps that worst case but makes the /expected/ cost linear by
replacing most character-by-character comparisons with a single integer
comparison of hashes.

=datamunge= exposes the search as =rabin_karp_search(text, pattern)=, returning
the sorted vector of start indices. By convention the empty pattern is taken to
occur at every position \(\{0, 1, \dots, n\}\), mirroring
=std::string::find("")=.

* The rolling hash

Fix a base \(b\) (naturally \(256\), one value per byte) and a large prime
modulus \(p\). Map each length-\(m\) window \(w = c_0 c_1 \cdots c_{m-1}\) to the
integer it spells in base \(b\), reduced modulo \(p\):

\[
H(w) \;=\; \Big( c_0\,b^{m-1} + c_1\,b^{m-2} + \cdots + c_{m-1}\,b^{0} \Big) \bmod p .
\]

The pattern is hashed the same way. If the window and pattern hashes differ, the
strings certainly differ and the window is skipped instantly. The point of the
scheme is that consecutive windows share \(m-1\) characters, so their hashes are
related. Writing \(h_s\) for the hash of the window starting at \(s\), sliding
one character to the right subtracts the leading digit's contribution, shifts
the remaining digits up by one place (multiply by \(b\)), and adds the incoming
digit:

\[
h_{s+1} \;=\; \Big( \big(h_s - c_s\,b^{m-1}\big)\,b + c_{s+m} \Big) \bmod p ,
\]

which is \(O(1)\) work once \(b^{m-1} \bmod p\) has been precomputed. So after an
\(O(m)\) warm-up to hash the pattern and the first window, the whole text is
swept with one multiply-add per position.

#+begin_example
RABIN-KARP(text, pattern):
  n <- len(text);  m <- len(pattern)
  if m == 0: return {0, 1, ..., n}         # empty pattern occurs everywhere
  if m > n:  return {}                      # pattern cannot fit

  high <- b^(m-1) mod p                     # weight of the leading digit
  ph <- 0;  wh <- 0                         # pattern hash, window hash
  for i in 0 .. m-1:                        # Horner evaluation of both hashes
      ph <- (ph*b + pattern[i]) mod p
      wh <- (wh*b + text[i])    mod p

  matches <- empty list
  for s in 0 .. n-m:
      if wh == ph and text[s .. s+m-1] == pattern:   # verify to reject collisions
          append s to matches
      if s < n-m:                                    # slide the window in O(1)
          wh <- ((wh - text[s]*high) * b + text[s+m]) mod p
  return matches
#+end_example

** Why hash equality is only a hint

Reducing modulo \(p\) is a many-to-one map: there are vastly more strings than
residues, so distinct windows can share a hash -- a /spurious collision/. Hence
\(h_s = H(\text{pattern})\) does not prove a match; it only marks the window as a
/candidate/. The algorithm therefore verifies the actual characters before
recording a hit, which is what makes the output exact. With a good \(p\) a random
window collides with probability \(\approx 1/p\), so verifications almost always
confirm and the expected running time is \(O(n+m)\). In the worst case -- an
adversarial text, or a tiny modulus -- every window is a candidate and every
verification costs \(O(m)\), recovering the naive \(O(n\,m)\) bound. The library
uses \(b = 256\) and the prime \(p = 1{,}000{,}000{,}007\) to make that worst
case vanishingly unlikely in practice.

* Example: searching =aba= in =abababbb=

To make the arithmetic checkable by hand we use a deliberately small base
\(b = 10\) and modulus \(p = 101\) for the /displayed/ window hashes (the library
itself keeps its robust large modulus). We map =a= \(\to 1\) and =b= \(\to 2\),
so \(H(\text{=aba=}) = 1\cdot 100 + 2\cdot 10 + 1 = 121 \equiv 20 \pmod{101}\).
Sliding across =abababbb= there are six windows. The two =aba= windows (at
\(0\) and \(2\)) hash to \(20\) and verify; the trailing =bbb= window hashes to
\(2\cdot 100 + 2\cdot 10 + 2 = 222 \equiv 20 \pmod{101}\) too -- a genuine
collision with the pattern's hash -- but its characters differ, so verification
rejects it. The authoritative match positions come from
=rabin_karp_search=, which uses the large-modulus hash internally.

#+name: rk-run
#+begin_src c++ :eval no
    const std::string text = "abababbb";
    const std::string pattern = "aba";
    const long long B = 10, P = 101; // small, hand-checkable base/modulus for the printed hashes
    const std::size_t m = pattern.size();

    auto hash_of = [&](const std::string& s) {
        long long h = 0;
        for (char c : s) h = (h * B + (c - 'a' + 1)) % P; // a -> 1, b -> 2, ...
        return h;
    };
    const long long ph = hash_of(pattern);

    std::cout << "=== Rabin-Karp: searching for \"" << pattern << "\" in \"" << text << "\" ===\n";
    std::cout << "base b = " << B << ", modulus p = " << P
              << " (small values for a hand-checkable illustration)\n";
    std::cout << "pattern hash = " << ph << "\n\n";

    std::vector<double> xs, hs, mx, my; // window index, window hash, and the verified-match subset
    for (std::size_t k = 0; k + m <= text.size(); ++k) {
        const std::string w = text.substr(k, m);
        const long long h = hash_of(w);
        const bool hit = (h == ph);
        const bool verified = hit && (w == pattern);
        xs.push_back(static_cast<double>(k));
        hs.push_back(static_cast<double>(h));
        std::cout << "window " << k << ": \"" << w << "\" hash=" << h;
        if (!hit)
            std::cout << " -> no\n";
        else if (verified) {
            std::cout << " (==pattern) -> MATCH\n";
            mx.push_back(static_cast<double>(k));
            my.push_back(static_cast<double>(h));
        } else
            std::cout << " (==pattern) -> spurious (chars differ)\n";
    }

    const auto pos = rabin_karp_search(text, pattern); // authoritative, large-modulus search
    std::cout << "\nverified match positions (datamunge::rabin_karp_search):";
    for (const std::size_t p : pos) std::cout << " " << p;
    std::cout << "\nmatch count: " << pos.size() << "\n";

    auto plot = RPlot::create();
    plot.lines(xs, hs, "", {37, 99, 235}, 1.5);
    plot.points(xs, hs, "window hash", {37, 99, 235}, 6.0);
    plot.points(mx, my, "verified match", {22, 163, 74}, 10.0);
    plot.abline_h(static_cast<double>(ph), {220, 38, 38}, 1.5);
    plot.title("Rolling hash per window (red = pattern hash; windows on it are candidates)")
        .x_label("window start index").y_label("window hash (base 10, mod 101)")
        .background({250, 250, 252});
    plot.save_svg("build/org/rabin_karp_hashes.svg");
    std::cout << "\nwrote rabin_karp_hashes.svg\n";
#+end_src

#+end_example

The window hashes trace out \(20, 10, 20, 10, 21, 20\) as the frame slides one
character at a time -- each computed from its predecessor by the constant-time
subtract-shift-add update, never by re-reading the window. Three windows land on
the pattern's hash of \(20\): the two =aba= windows at positions \(0\) and \(2\),
which verify and are genuine (overlapping) matches, and the trailing =bbb=
window at position \(5\), whose hash collides with the pattern's purely by the
arithmetic of \(\bmod 101\) yet whose characters plainly differ. That last
window is exactly why the algorithm verifies before reporting: hashing narrows
the field to candidates, and a single character comparison certifies each one.
The =rabin_karp_search= call, using the library's large modulus internally,
returns precisely the two true positions.
