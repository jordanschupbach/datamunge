#+begin_abstract
Multiplying two numbers is *convolving* their digit sequences, and the convolution theorem turns a
convolution into a cheap pointwise product once both operands are carried into transform space. The
Schonhage-Strassen algorithm (1971) exploits this with a fast transform over a ring chosen so the
arithmetic is exact, multiplying two \(n\)-digit numbers in \(O(n\log n\log\log n)\) -- the method
behind serious big-number libraries. This report drives =datamunge='s =algorithms::ntt_mul=, a
*number-theoretic transform* realisation of the same idea, verified against the library's Karatsuba
multiplier and shown to scale like \(n\log n\).
#+end_abstract

* Multiplication is convolution

Write the operands as polynomials in the base, \(a=A(10)=\sum a_i 10^i\) and \(b=B(10)\). Then
\(ab=(A\cdot B)(10)\), and the coefficients of the product polynomial are the *convolution*

\[ (A * B)_k=\sum_{i+j=k} a_i\,b_j. \]

Computed directly this is the \(O(n^2)\) schoolbook sum. The convolution theorem says instead

\[ A * B=\mathcal{T}^{-1}\big(\mathcal{T}(A)\cdot\mathcal{T}(B)\big), \]

where \(\mathcal{T}\) is a transform that diagonalises convolution into a *pointwise* product. Using
a fast transform, \(\mathcal{T}\) and \(\mathcal{T}^{-1}\) cost \(O(n\log n)\) and the pointwise
product \(O(n)\), so the whole multiplication is \(O(n\log n)\) up to the cost of the transform's
arithmetic. Schonhage and Strassen take \(\mathcal{T}\) to be an FFT over the Fermat ring
\(\mathbb{Z}/(2^{2^k}+1)\), making every operation exact; we use the closely related *number-theoretic
transform* over the prime field \(\mathbb{Z}/p\) with \(p=998244353\), whose \(2^{23}\)-th roots of
unity give an exact, integer-only FFT and thus a round-off-free convolution. A final carry pass turns
the convolution coefficients back into decimal digits.

* Algorithm

#+begin_example
NTT-MULTIPLY(a, b):
  A, B <- digit vectors of a, b, zero-padded to a power of two >= |a|+|b|
  NTT(A); NTT(B)                       # forward transform, O(n log n)
  for k: C[k] = A[k] * B[k] mod p      # pointwise product, O(n)
  INVERSE-NTT(C)                       # back to coefficients, O(n log n)
  propagate base-10 carries through C
  return C as a decimal string
#+end_example

The transform is the iterative radix-2 Cooley-Tukey butterfly with the twiddle factor a power of a
primitive root of \(p\); the inverse uses the inverse root and a final scaling by \(n^{-1}\bmod p\).

* Worked example: a big product, and n log n scaling

We multiply two large integers, confirm against Karatsuba, and plot the transform's \(n\log n\) work
against the quadratic schoolbook cost.

#+name: ss-run
#+begin_src c++ :eval no
    const std::string a = "12345678901234567890123456789012345678901234567890";
    const std::string b = "98765432109876543210987654321098765432109876543210";
    const std::string prod = ntt_mul(a, b);
    std::cout << "=== NTT (Schonhage-Strassen-style) multiplication ===\n";
    std::cout << "product has " << prod.size() << " digits\n";
    std::cout << "matches Karatsuba multiplier: " << (prod == karatsuba_multiply(a, b) ? "yes" : "no") << "\n";
    std::cout << "first 40 digits: " << prod.substr(0, 40) << "...\n";
    std::cout << "R11 squared = " << ntt_mul("11111111111", "11111111111") << "\n\n";

    std::cout << "transform work n*log2(n)  vs  schoolbook n^2:\n";
    std::vector<double> nx, nlogn, quad;
    for (int n = 8; n <= 1024; n *= 2) {
        nx.push_back(n);
        nlogn.push_back(static_cast<double>(n) * std::log2((double)n));
        quad.push_back(static_cast<double>(n) * n);
        std::printf("n=%-5d  n log n=%-10.0f  n^2=%-12.0f  ratio=%.0fx\n",
                    n, (double)n * std::log2((double)n), (double)n * n,
                    ((double)n * n) / ((double)n * std::log2((double)n)));
    }

    auto plot = RPlot::create();
    plot.line(nx, quad, "q", RGB{220, 38, 38}, 2.0);
    plot.line(nx, nlogn, "n", RGB{124, 58, 237}, 2.0);
    plot.legend({"schoolbook  n^2", "NTT  n log n"}, {{220, 38, 38}, {124, 58, 237}});
    plot.title("The transform turns quadratic multiplication into n log n")
        .x_label("operand length n (digits)").y_label("work units").background({250, 250, 252});
    plot.save_svg("build/org/schonhage_strassen.svg");
    std::cout << "wrote schonhage_strassen.svg\n";
#+end_src

The hundred-digit product matches the independent Karatsuba multiplier exactly -- the NTT convolution
is round-off free because every operation happens in the exact field \(\mathbb{Z}/p\). The
work-unit table makes the asymptotic case plainly: by a thousand digits the transform does on the
order of a hundred times less work than the quadratic method, and the gap widens without bound.

The near-flat \(n\log n\) curve barely lifts off the axis while the quadratic curve explodes. That
separation is why every arbitrary-precision library switches to a transform-based multiply once the
operands grow past a few thousand digits -- Karatsuba and Toom-Cook rule the middle sizes, but the
transform owns the tail.
