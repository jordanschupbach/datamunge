#+begin_abstract
Fibonacci coding represents a positive integer using *Zeckendorf's theorem*: every positive
integer is a unique sum of *non-consecutive* Fibonacci numbers. The code writes one bit per
Fibonacci number (smallest first) marking which are used, then appends a terminating \(1\).
Because no two consecutive Fibonacci numbers appear, the only place two \(1\)s sit adjacent is
that terminator -- so \(11\) is an unambiguous end marker, making the code *self-delimiting* and
unusually *robust to bit errors*: a corrupted bit cannot desynchronize the stream past the next
\(11\). This report runs it with =datamunge='s =algorithms::fibonacci_encode= as a literate
program: every number and figure comes from one compiled binary.
#+end_abstract

* Zeckendorf digits plus a delimiter

To encode \(n\), greedily subtract the largest Fibonacci number \(\le n\), repeat, and mark the
used ones -- Zeckendorf's theorem guarantees this representation exists, is unique, and uses no
two consecutive Fibonacci numbers. Writing the marks from the smallest Fibonacci upward gives a
bit string ending in the highest used position (a \(1\)); appending one more \(1\) produces the
tell-tale \(11\). The decoder simply reads bits, summing the corresponding Fibonacci numbers,
until it meets \(11\). The codeword length is about \(\log_\varphi n\approx 1.44\log_2 n\) bits
(\(\varphi\) the golden ratio) -- slightly longer than the tightest universal codes, bought back
in error resilience.

#+begin_example
Fibonacci(n):
    greedily write n as a sum of non-consecutive Fibonacci numbers (Zeckendorf)
    emit one bit per Fibonacci number (smallest first): 1 if used
    emit a terminating 1        # adjacent to the top 1 -> the "11" delimiter

* A worked example

We show a few codewords (note each ends in \(11\)), verify a round trip, and compare codeword
length against order-0 Exp-Golomb.

#+name: fc-run
#+begin_src c++ :eval no
    std::cout << "=== Fibonacci codewords (Zeckendorf + '11' delimiter) ===\n";
    for (std::uint64_t n : {1ull, 2ull, 3ull, 4ull, 10ull, 20ull, 50ull, 100ull})
        std::cout << "  " << n << " -> " << fib_code(n) << "\n";

    std::vector<std::uint64_t> vals = {1, 2, 3, 4, 7, 10, 50, 100, 1000, 100000};
    auto bits = fibonacci_encode(vals);
    std::cout << "\nround trip over sample values: "
              << (fibonacci_decode(bits) == vals ? "ok" : "FAIL") << "\n";

    std::cout << "\nvalue : Fibonacci bits : Exp-Golomb0 bits\n";
    std::vector<double> xs, flen, elen;

        std::cout << "  " << n << "  :   " << fib_len(n) << "   :   " << eg_len(n) << "\n";
        xs.push_back(n); flen.push_back(fib_len(n)); elen.push_back(eg_len(n));
    }

    RPlot p = RPlot::create();

Every codeword ends in the \(11\) delimiter, and no interior pair of \(1\)s appears, which is
what makes the code self-synchronizing -- corruption is confined to at most the two codewords
around an error. The length comparison is striking: Fibonacci coding is not only robust but
actually *more compact* than order-0 Exp-Golomb here, asymptotically about \(1.44\log_2 n\) bits
versus \(2\log_2 n\) (24 vs 33 bits at 65536). So on this range it wins on both fronts -- fewer
bits *and* error confinement -- which is why it is attractive for storing sorted-integer
differences and for transmission over noisy channels lacking heavier error correction.

* Character and relatives

Fibonacci coding is prized less for compactness than for *robustness*: its \(11\) delimiter makes
it self-synchronizing, so it appears where bitstreams face errors without a separate framing
layer. It sits in the *universal code* family with *Elias* and *Exponential-Golomb* codes
(companion report); higher-order Fibonacci codes (using higher-order Fibonacci-like sequences)
trade a longer forbidden pattern for shorter codewords. For pure compression of a known
distribution, arithmetic or Golomb coding (companion reports) is tighter.

* Complexity

\(O(\log n)\) time and bits per value -- proportional to the number of Fibonacci numbers below
\(n\), which is \(\Theta(\log n)\).
