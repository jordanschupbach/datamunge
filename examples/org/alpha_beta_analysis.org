#+begin_abstract
Minimax finds the value of a game position under optimal play -- but it evaluates *every*
leaf of the game tree, which grows as @math{b^d} for branching factor @math{b} and depth
@math{d}. *Alpha-beta pruning* returns the *exact same value* while skipping branches that
provably cannot change it: once one player has a move good enough that the opponent would
never permit the current line, the rest of that line is irrelevant. With good move ordering
it examines only @math{O(b^{d/2})} leaves -- effectively *doubling the searchable depth*.
This report drives =datamunge='s =algorithms::alpha_beta=, verified to agree with minimax,
and measures the leaves it prunes.
#+end_abstract

* The window that closes

Alpha-beta carries two bounds down the tree: @math{\alpha}, the best value the maximizer can
already guarantee, and @math{\beta}, the best the minimizer can already hold it to. At a
*max* node, as soon as a child's value reaches @math{\beta}, the *minimizer above* would
never enter this node (it already has a line at most @math{\beta}), so the remaining children
are skipped -- a *beta cutoff*. Symmetrically a *min* node cuts off once a child drops to
@math{\alpha}. The value returned is *identical* to minimax's; only the useless work is
removed.

The payoff depends entirely on *move ordering*. In the worst order (best moves last) nothing
is pruned and you pay the full @math{b^d}. In the best order (best moves first) the count
collapses to @math{2b^{d/2}-1} -- the square root of the tree -- which is why real engines
spend so much effort ordering moves. Random ordering, as here, lands in between: substantial
pruning, though short of the ideal.

* Algorithm

#+begin_example
ALPHA-BETA(node, maximizing, alpha, beta):
  if node is a leaf: return node.value
  if maximizing:
      best <- -inf
      for child: best <- max(best, ALPHA-BETA(child, false, alpha, beta))
                 alpha <- max(alpha, best)
                 if alpha >= beta: break        # beta cutoff
      return best
  else (minimizing): symmetric, with a beta update and an alpha cutoff
#+end_example

* Worked example: agreement with minimax, and leaves pruned

We build random game trees, confirm alpha-beta returns exactly minimax's value, and plot how
many leaves each evaluates as depth grows (branching factor 3), against the @math{b^d} and
best-case @math{b^{d/2}} references.

#+name: ab-run
#+begin_src c++ :eval no
    std::mt19937 rng(20240728);
    std::function<GameNode(int, int)> make_tree = [&](int depth, int b) {
        GameNode n;
        if (depth == 0) { n.leaf = true; n.value = std::uniform_int_distribution<int>(-99, 99)(rng); return n; }
        for (int i = 0; i < b; ++i) n.children.push_back(make_tree(depth - 1, b));
        return n;
    };

    const GameNode demo = make_tree(4, 3);
    const GameResult mm = minimax(demo, true), ab = alpha_beta(demo, true);
    std::cout << "=== depth-4, branching-3 game tree (81 leaves) ===\n";
    std::cout << "minimax value    = " << mm.value << ", leaves = " << mm.leaves_evaluated << "\n";
    std::cout << "alpha-beta value = " << ab.value << ", leaves = " << ab.leaves_evaluated
              << "  (same value: " << (mm.value == ab.value ? "yes" : "no") << ")\n\n";

    const int b = 3;
    std::vector<double> ds, full, pruned, ideal;
    std::cout << "depth   minimax leaves   alpha-beta leaves (avg)\n";
    for (int d = 1; d <= 8; ++d) {
        long long mmsum = 0, absum = 0; const int trials = 40;
        for (int t = 0; t < trials; ++t) {
            const GameNode tree = make_tree(d, b);
            mmsum += minimax(tree, true).leaves_evaluated;
            absum += alpha_beta(tree, true).leaves_evaluated;
        }
        const double mmavg = static_cast<double>(mmsum) / trials, abavg = static_cast<double>(absum) / trials;
        ds.push_back(d); full.push_back(std::log10(mmavg)); pruned.push_back(std::log10(abavg));
        ideal.push_back(std::log10(std::pow(b, d / 2.0)));
        if (d % 2 == 0) std::printf("%-6d  %-15.0f  %.0f\n", d, mmavg, abavg);
    }

    auto plot = RPlot::create();
    plot.line(ds, full, "minimax", RGB{220, 38, 38}, 2.0);
    plot.points(ds, full, "minimax", RGB{220, 38, 38}, 5.0);
    plot.line(ds, pruned, "alpha-beta", RGB{37, 99, 235}, 2.0);
    plot.points(ds, pruned, "alpha-beta", RGB{37, 99, 235}, 6.0);
    plot.line(ds, ideal, "best case", RGB{5, 150, 105}, 2.0);
    plot.legend({"minimax b^d", "alpha-beta (random order)", "best case b^(d/2)"},
                {{220, 38, 38}, {37, 99, 235}, {5, 150, 105}});
    plot.title("Alpha-beta evaluates far fewer leaves than minimax (b = 3)")
        .x_label("tree depth d").y_label("log10 leaves evaluated").background({250, 250, 252});
    plot.save_svg("build/org/alpha_beta.svg");
    std::cout << "\nwrote alpha_beta.svg\n";
#+end_src

Alpha-beta returns exactly minimax's value on every tree -- it is not an approximation -- yet
evaluates markedly fewer leaves, and the gap grows with depth. Even with the *random* move
ordering used here, the blue curve sits well below the red @math{b^d} minimax line, trending
toward the green best-case @math{b^{d/2}}.

The three lines tell the story: minimax pays the full exponential (red), the theoretical
best case is its square root (green), and alpha-beta with random ordering (blue) falls
between -- closer to the ideal as depth grows. Ordering moves to push that blue line down
onto the green one is precisely what a competitive game engine spends its cleverness on.
