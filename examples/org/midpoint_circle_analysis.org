#+begin_abstract
Drawing a circle on a pixel grid without trigonometry or square roots is the circle
analogue of Bresenham's line: the *midpoint circle algorithm* walks a single 45-degree
octant with an integer *decision variable* that tests whether the true circle passes
above or below the midpoint between the two candidate cells, and mirrors each plotted
cell into the other seven octants by symmetry. This report implements it in
=datamunge='s C++ =algorithms::midpoint_circle= as a literate program: every number and
figure comes from one compiled binary. We rasterize a circle and confirm every plotted
cell lies within a pixel of the true radius.
#+end_abstract

* Eight-way symmetry and the decision variable

A circle is symmetric across both axes and both diagonals, so the eight points
\((\pm x,\pm y)\) and \((\pm y,\pm x)\) all lie on it. Computing just the octant from
\((r,0)\) to the diagonal suffices. Along it \(x\) starts at \(r\), \(y\) at 0; a decision
variable \(d\) (initialized \(1-r\)) decides at each step whether to keep \(x\) or
decrement it, updated with only integer additions. This avoids the \(\sqrt{r^2-y^2}\)
that a naive circle would need.

** Pseudocode

#+begin_example
MidpointCircle(cx, cy, r):
    x = r;  y = 0;  d = 1 - r
    while x >= y:
        plot the 8 symmetric points of (x, y)
        y += 1
        if d < 0: d += 2*y + 1
        else:     x -= 1;  d += 2*(y - x) + 1
#+end_example

* A worked example

#+name: mc-run
#+begin_src c++ :eval no
    const int r   = 12;
    auto      pts = midpoint_circle(0, 0, r);
    std::cout << "=== Midpoint circle, radius " << r << " ===\n";
    std::cout << "cells plotted: " << pts.size() << " (with 8-way symmetry)\n";
    double max_err = 0.0;
    for (const auto& [x, y] : pts)
        max_err = std::max(max_err, std::fabs(std::sqrt(double(x * x + y * y)) - r));
    std::cout << "max |distance-from-center - r|: " << max_err << " (< 1 pixel)\n";

    std::vector<double> px, py;
    for (const auto& [x, y] : pts) { px.push_back(x); py.push_back(y); }
    RPlot p = RPlot::create();
    p.points(px, py, "circle cells", {37, 99, 235}, 6.0);
    p.save_svg("build/org/midpoint_circle.svg");
    std::cout << "\nwrote build/org/midpoint_circle.svg\n";
#+end_src

* Results

#+begin_example
=== Midpoint circle, radius 12 ===
cells plotted: 72 (with 8-way symmetry)
max |distance-from-center - r|: 0.369317 (< 1 pixel)
#+end_example

Every plotted cell lies less than one pixel from the true radius, and the scatter forms
a clean circle -- generated by computing one octant and reflecting it eight ways, using
only integer additions. The 8-way symmetry is why the cell count is a small multiple of
the octant length.

* Relatives

The same integer-decision idea extends to ellipses (with two regions where the slope
crosses 45 degrees) and, with a coverage term, to *antialiased* circles. Filled disks
come from drawing horizontal spans between the symmetric points. It is the circle member
of the Bresenham family of pure-integer rasterizers.

* Complexity

\(O(r)\) time -- the octant has \(O(r)\) cells, each \(O(1)\) to compute and reflect --
and \(O(1)\) state.
