#+begin_abstract
A contour map draws lines of constant value -- coastlines on a bathymetry grid, isobars on a
weather map, the boundary of a region in an image. *Marching squares* extracts those lines
from a scalar field sampled on a grid: it visits each cell, classifies its four corners
against the threshold, and emits interpolated line segments. This report implements it in
=datamunge='s =algorithms::marching_squares= as a literate program: we contour a radial field
and show the extracted segments trace a circle at the chosen iso-radius.
#+end_abstract

* Sixteen cases, one interpolation

For a threshold \(\tau\), classify each of a cell's four corners as *above* or *below*
\(\tau\), giving a 4-bit *case index* (16 possibilities). The contour crosses every edge that
joins an above corner to a below one, at the point where linear interpolation hits \(\tau\):
\[
  x_{\text{cross}} = x_a + \frac{\tau - f_a}{f_b - f_a}(x_b - x_a).
\]
The case index selects which crossings to connect: 14 cases give a single segment, and the
two *saddle* cases (opposite corners above) give two. Concatenating the segments of all cells
yields the contour. The method is embarrassingly parallel (each cell is independent) and is
the 2D form of marching cubes; its only subtlety is the saddle ambiguity, which this
implementation resolves by a fixed convention.

** Pseudocode

#+begin_example
marching_squares(grid, iso):
    for each cell (r,c):
        idx = bits( TL>=iso, TR>=iso, BR>=iso, BL>=iso )
        if idx in {0, 15}: continue                 # wholly above or below
        for each edge joining an above corner to a below corner:
            place crossing point by linear interpolation to iso
        connect crossings per idx  (2 segments for the saddle cases 5 and 10)
    return all segments
#+end_example

* A worked example

We sample \(f(x,y)=\sqrt{(x-10)^2+(y-10)^2}\) (distance from the grid centre) on a 21x21
grid and extract the \(\tau=6\) contour. The segments should trace the circle of radius 6.

#+name: ms-run
#+begin_src c++ :eval no
    const int N = 21;
    std::vector<std::vector<double>> grid(N, std::vector<double>(N));
    for (int r = 0; r < N; ++r)
        for (int c = 0; c < N; ++c)
            grid[r][c] = std::sqrt((c - 10.0)*(c - 10.0) + (r - 10.0)*(r - 10.0));

    auto segs = marching_squares(grid, 6.0);
    std::cout << "=== Marching squares on a radial field, iso = 6 ===\n";
    std::cout << "segments extracted: " << segs.size() << "\n";

    double max_err = 0, mean_err = 0;
    for (const auto& s : segs) {
        double mx = 0.5*(s[0]+s[2]) - 10.0, my = 0.5*(s[1]+s[3]) - 10.0;
        double e = std::fabs(std::sqrt(mx*mx + my*my) - 6.0);
        max_err = std::max(max_err, e); mean_err += e;
    }
    mean_err /= segs.size();
    std::cout << "segment-midpoint distance from radius 6: mean " << mean_err
              << ", max " << max_err << "\n";

    // Plot the contour segments.
    RPlot p = RPlot::create();
    std::vector<double> x0, y0, x1, y1;
    for (const auto& s : segs) { x0.push_back(s[0]); y0.push_back(s[1]); x1.push_back(s[2]); y1.push_back(s[3]); }
    p.segments(x0, y0, x1, y1, {37, 99, 235}, 2.0);
    p.save_svg("build/org/marching_squares_contour.svg");
    std::cout << "wrote build/org/marching_squares_contour.svg\n";
#+end_src

* Uses and cautions

Marching squares is the workhorse behind contour plots, GIS coastline and elevation-line
extraction, and 2D region-boundary tracing. Caveats: the *saddle* cases are genuinely
ambiguous (two ways to connect), so different conventions give different topology at those
cells; finer grids reduce interpolation error but cost more cells; and the segments come out
unordered, so applications needing closed polygons must stitch them. The 3D analogue,
marching cubes, applies the same idea to voxels with a 256-case table.

* Complexity

\(O(\text{cells})\) time -- one constant-time classification and interpolation per cell -- and
\(O(1)\) memory beyond the output segments.
