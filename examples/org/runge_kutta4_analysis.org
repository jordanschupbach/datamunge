#+begin_abstract
Euler uses one slope per step and earns first-order accuracy. The *classical fourth-order
Runge-Kutta method* (Runge 1895, Kutta 1901) uses *four* carefully placed slope
evaluations -- at the start, twice at the midpoint, and at the end -- and blends them so
that error terms cancel through fourth order. The result is the workhorse of scientific
computing: *explicit*, self-starting, and @math{O(h^4)} accurate, so halving the step
cuts the error roughly *sixteen-fold*. This report implements it in =datamunge='s C++
=algorithms::runge_kutta4=, verifies it against exact solutions, and puts its convergence
slope side by side with Euler's.
#+end_abstract

* Four slopes, weighted like Simpson's rule

One RK4 step samples the derivative four times:

\[
\begin{aligned}
k_1 &= f(t_n,\,y_n), & k_2 &= f\!\left(t_n+\tfrac{h}{2},\, y_n+\tfrac{h}{2}k_1\right),\\
k_3 &= f\!\left(t_n+\tfrac{h}{2},\, y_n+\tfrac{h}{2}k_2\right), & k_4 &= f(t_n+h,\, y_n+h\,k_3),
\end{aligned}
\]

then combines them with Simpson-like weights

\[ y_{n+1} = y_n + \frac{h}{6}\,(k_1 + 2k_2 + 2k_3 + k_4). \]

The two midpoint samples @math{k_2,k_3} and the endpoint @math{k_4} let the update match
the Taylor expansion of the true solution through the @math{h^4} term, so the *local*
error is @math{O(h^5)} and the *global* error @math{O(h^4)}. That is the sweet spot RK4
is famous for: four function evaluations per step -- four times Euler's cost -- but an
error that falls as the *fourth power* of the step, so for any real accuracy target RK4
needs dramatically fewer, larger steps than Euler.

* Algorithm

#+begin_example
RK4(f, y0, t0, t1, steps):
  h <- (t1 - t0)/steps;  y <- y0;  t <- t0
  repeat steps times:
      k1 <- f(t,          y)
      k2 <- f(t + h/2,     y + (h/2) k1)
      k3 <- f(t + h/2,     y + (h/2) k2)
      k4 <- f(t + h,       y + h    k3)
      y  <- y + (h/6)(k1 + 2 k2 + 2 k3 + k4)
      t  <- t + h;  record (t, y)
  return trajectory
#+end_example

* Worked example: convergence order, RK4 versus Euler

We integrate @math{y'=-y} (exact @math{e^{-1}} at @math{t=1}) at a range of step sizes
and plot the final error against @math{h} on log-log axes. Euler's points should fall on
a line of slope 1; RK4's on a line of slope 4 -- until they hit the floating-point floor.

#+name: rk-run
#+begin_src c++ :eval no
    auto f = [](double, const std::vector<double>& y) { return std::vector<double>{-y[0]}; };
    const double exact = std::exp(-1.0);

    // Sanity: RK4 solves y' = y to Euler's number very accurately with few steps.
    auto grow = [](double, const std::vector<double>& y) { return std::vector<double>{y[0]}; };
    std::cout << "=== RK4 on y' = y, 20 steps over [0,1] ===\n";
    std::cout << "RK4 e ~ " << runge_kutta4(grow, {1.0}, 0.0, 1.0, 20).y.back()[0]
              << ", true e = " << std::exp(1.0) << "\n\n";

    std::cout << "steps    h         Euler error    RK4 error\n";
    std::vector<double> logh, e_err, r_err;
    for (int steps = 4; steps <= 256; steps *= 2) {
        const double h  = 1.0 / steps;
        const double ee = std::fabs(euler_method(f, {1.0}, 0.0, 1.0, steps).y.back()[0] - exact);
        const double re = std::fabs(runge_kutta4(f, {1.0}, 0.0, 1.0, steps).y.back()[0] - exact);
        std::printf("%5d    %.5f   %.4e    %.4e\n", steps, h, ee, re);
        logh.push_back(std::log10(h));
        e_err.push_back(std::log10(ee));
        r_err.push_back(std::log10(std::max(re, 1e-16)));
    }

    // Empirical slopes (order) from the first two points.
    const double euler_order = (e_err[0] - e_err[1]) / (logh[0] - logh[1]);
    const double rk_order    = (r_err[0] - r_err[1]) / (logh[0] - logh[1]);
    std::cout << "\nempirical order: Euler ~ " << euler_order << ", RK4 ~ " << rk_order << "\n";

    auto plot = RPlot::create();
    plot.line(logh, e_err, "Euler", RGB{220, 38, 38}, 2.0);
    plot.points(logh, e_err, "Euler", RGB{220, 38, 38}, 6.0);
    plot.line(logh, r_err, "RK4", RGB{37, 99, 235}, 2.0);
    plot.points(logh, r_err, "RK4", RGB{37, 99, 235}, 6.0);
    plot.legend({"Euler (slope ~1)", "RK4 (slope ~4)"}, {{220, 38, 38}, {37, 99, 235}});
    plot.title("Error vs step size (log-log): RK4's slope is 4, Euler's is 1")
        .x_label("log10 h").y_label("log10 final error").background({250, 250, 252});
    plot.save_svg("build/org/runge_kutta4.svg");
    std::cout << "wrote runge_kutta4.svg\n";
#+end_src

At every step size RK4's error is orders of magnitude below Euler's, and the empirical
slopes confirm the theory: Euler's error falls like @math{h^1}, RK4's like @math{h^4}.
By @math{256} steps RK4 has already run into the @math{\sim10^{-16}} floating-point floor
-- it is as accurate as double precision allows -- while Euler is still crawling down at
one digit per halving.

On log-log axes both errors are straight lines, but with very different slopes: Euler's
gentle slope-1 descent versus RK4's steep slope-4 plunge (until it flattens at the
machine floor). That steepness is the practical meaning of "fourth order" -- a few extra
slope evaluations per step turn into a completely different accuracy regime.
