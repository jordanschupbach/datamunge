#+begin_abstract
We fit a regularized, second-order gradient boosting classifier -- the
XGBoost algorithm (Chen & Guestrin, 2016) -- to Fisher's (1936) iris data
using =datamunge='s C++ =stats::XGBoostClassifier=, and report it as a
literate program: every fragment below is a real, compiled, executed chunk
of the single C++ binary that produced every number and figure in this
document. Using the same 100-round budget as the classic gradient boosting
companion report but a Newton (second-order) update instead of a plain
gradient step, this model reaches a training deviance of 0.0288 -- more
than three times lower than the companion GBM report's 0.0900 at the same
round count. A sweep over the L2 regularization parameter $\lambda$
produces a clean, textbook regularization curve: training accuracy holds
at 99.33-100.00% for $\lambda$ up to about 10, then collapses to 96.67% by
$\lambda = 50$, with training deviance rising more than 3.6-fold over the
same range -- a sharper, cleaner illustration of over-regularization than
any hyperparameter sweep in this project's other five reports produced. We
derive the second-order Taylor approximation to the loss, the closed-form
regularized leaf weight, the regularized split-gain criterion, and
gain-based feature importance from first principles, connect each to the
corresponding library call, and close by placing this method directly
against its closest relative, the classic gradient boosting companion
report.
#+end_abstract

* Introduction

This project has now fit five classifiers to the same 150 iris flowers --
[[file:lda_iris_analysis.org][=lda_iris_analysis.org=]],
[[file:svm_iris_analysis.org][=svm_iris_analysis.org=]],
[[file:dt_iris_analysis.org][=dt_iris_analysis.org=]],
[[file:rf_iris_analysis.org][=rf_iris_analysis.org=]], and
[[file:gbm_iris_analysis.org][=gbm_iris_analysis.org=]] -- and this report
adds a sixth that is, in one specific sense, the smallest possible step
away from the fifth: XGBoost fits the same kind of thing (an additive
ensemble of shallow trees, one per class per round, each correcting the
last) that the GBM companion report already covers, but changes /how/ each
round's trees are fit and /what/ keeps them from overfitting. Where
classic gradient boosting takes one gradient-descent step per round,
XGBoost takes a full Newton step -- using both the gradient /and/ the
curvature (Hessian) of the loss -- and where classic gradient boosting's
only real defense against overfitting is a small learning rate, XGBoost
adds three more knobs (L2, L1, and a minimum-gain threshold) directly
inside the formula that decides both how a leaf is weighted and whether a
split is worth making at all.

As with its companions, this document is a /literate program/: prose and
source are interleaved in reading order, and a single "assembling the
program" step (§3.3.8) weaves every named chunk below into one =.cpp= file,
compiles it, and runs it. Every number and figure from §4 onward is that
program's literal output.

§2 derives the second-order Taylor approximation to the loss, the
resulting closed-form regularized leaf weight, the regularized split-gain
criterion, and gain-based feature importance, each tied to the specific
library call that implements it. §3 describes the program chunk by chunk.
§4 reports the fitted model, its training deviance curve, feature
importance, a sweep over the L2 regularization parameter, and a
side-by-side look at the decision boundary under light versus heavy
regularization. §5 compares this report directly against its closest
relative, the classic gradient boosting report, and places all six methods

* Background: Regularized, Second-Order Boosting

** Setup and notation

As in the other classification companion reports: $n = 150$ flowers,
$p = 4$ measurements $x_i \in \mathbb{R}^4$, and $y_i \in \{1, \dots, K\}$,
$K = 3$, labeling one of the three species.

** Second-order (Newton) boosting

The GBM companion report's §2.2 fits each round's trees to the /negative
gradient/ of the loss -- a first-order, steepest-descent approximation.
XGBoost instead expands the loss to /second/ order around the current
prediction $F(x)$: for a new tree $f$,
$L(y, F+f) \approx L(y,F) + g f(x) + \tfrac12 h f(x)^2$, where $g$ is the
gradient and $h$ is the /Hessian/ (second derivative) of the loss with
respect to the current prediction. This quadratic is exactly solvable in
closed form for the best value of $f(x)$ at every leaf, which is what
turns "fit a tree to point downhill" (GBM) into "fit a tree using the
locally-optimal Newton step, including curvature information" (XGBoost) --
the same distinction between gradient descent and Newton's method that
appears throughout numerical optimization, applied here to fitting each
round's tree rather than to a single parameter update.

** Gradient and Hessian for multiclass softmax

As in the GBM companion report, =datamunge= maintains one score $F_k(x)$
per class and converts them to probabilities by softmax
$p_k(x) = \exp(F_k(x)) / \sum_j \exp(F_j(x))$. The gradient of the
multinomial deviance with respect to $F_k(x_i)$ is
$g_{ik} = p_{ik} - y_{ik}$ -- the same one-hot-minus-probability quantity
the GBM report calls a pseudo-residual -- and the Hessian is
$h_{ik} = p_{ik}(1 - p_{ik})$, the standard diagonal approximation to the
true (dense, $K \times K$) softmax Hessian, used here because computing the
exact cross-class Hessian for every row would be far more expensive for
comparatively little practical benefit. Both are computed fresh every
round from the /current/ ensemble's predictions, exactly as in GBM.

** The regularized objective and the optimal leaf weight

For a leaf whose rows have accumulated gradient $G = \sum_i g_i$ and
Hessian $H = \sum_i h_i$, the second-order approximation reduces the
leaf's contribution to the loss to a simple quadratic in its weight $w$:
$G w + \tfrac12 (H + \lambda) w^2 + \alpha |w|$, where $\lambda$
(=XGBoostClassifierOptions::lambda=) is an L2 penalty directly on the leaf
weight and $\alpha$ (=alpha=) is an L1 penalty. Minimizing this quadratic
gives a closed-form optimal weight,

\[
w^* = -\frac{\mathrm{softthresh}(G, \alpha)}{H + \lambda} , \qquad
\mathrm{softthresh}(G, \alpha) = \mathrm{sign}(G) \max(|G| - \alpha, 0) ,
\]

matching =detail::XGBoostTree='s =leaf_weight()= exactly. Larger $\lambda$
shrinks every leaf's weight toward zero regardless of how much data
supports it (smoothing the whole tree); nonzero $\alpha$ can drive a
leaf's weight to /exactly/ zero once $|G| \leq \alpha$ (a sparsifying
effect L2 alone cannot produce). This report's primary model uses the
library default $\lambda = 1$, $\alpha = 0$; §4.4 sweeps $\lambda$
directly.

** The regularized split gain and gamma

Candidate splits are scored by how much they improve the same regularized
objective. Writing $\mathrm{score}(G,H) = \mathrm{softthresh}(G,\alpha)^2 /
(H + \lambda)$ (twice the negated optimal loss at a node), a candidate
split into left/right children is scored by

\[
\mathrm{Gain} = \tfrac12 \big(\mathrm{score}(G_L,H_L) +
\mathrm{score}(G_R,H_R) - \mathrm{score}(G,H)\big) - \gamma ,
\]

matching =detail::XGBoostTree='s split search exactly. $\gamma$
(=gamma=, default 0 here) is a flat minimum-improvement threshold: a split
that doesn't clear it is refused outright, regardless of how many rows it
would affect -- a third, structural form of regularization (pruning by
required gain) alongside $\lambda$'s leaf-weight shrinkage and $\alpha$'s
leaf-weight sparsification.

** Row and column subsampling

=subsample= and =colsample_bytree= (both left at their default of 1.0 in
this report's primary model) optionally restrict each tree to a random
subset of rows or predictors respectively -- the same bagging-flavored
randomness the random forest companion report's bootstrap sampling and
=max_features= use, layered on top of boosting rather than replacing it.

** Feature importance

=feature_importance()= sums the regularized gain (§2.5, /not/ Gini,
entropy, or plain SSE decrease) contributed by every split on each
predictor across every tree in every round, normalized to sum to 1. This
differs subtly from the GBM companion report's SSE-based importance:
XGBoost's importance already has $\lambda$, $\alpha$, and $\gamma$'s
regularization baked directly into every split's credited gain, so a
predictor's importance here reflects its /regularized/ usefulness, not
just how much raw variance it happened to explain.

** Prediction

As in the GBM companion report, a new point's final class scores after all
$M$ rounds are converted to probabilities by softmax, in
=predict_detail()='s =probability= field -- the same confidence semantics
as GBM's, since both methods produce an additive ensemble of scores read
out the same way; §4.7 compares the actual numbers the two reports produce
for the identical four flowers.

** What we will report

Given the fit, we report the model's own summary (feature importance,
training accuracy, and the deviance trajectory), a confusion matrix, a
classification plot marking misclassified points directly, the training
deviance curve, a sweep over $\lambda$, and -- reduced to two predictors
purely for visualization, the same caveat every companion report makes
about its own 2-D view -- a side-by-side decision-region comparison under
light versus heavy L2 regularization.

* Data and Methods

** The data

As in every companion report: =datamunge::datasets::iris()= returns
Fisher's 150 flowers -- 50 each of /setosa/, /versicolor/, /virginica/ --
measured on =Sepal.Length=, =Sepal.Width=, =Petal.Length=, =Petal.Width=
(cm), with no missing values.

** Software

The entire analysis is one C++ program against =datamunge=:
=dstruct::DataFrame= for the data, the formula-driven
=stats::XGBoostClassifier= for every model in this report (built
internally from the regularized =detail::XGBoostTree=, distinct from the
plain =DecisionTreeRegressor= the GBM companion report's trees use), and
=plot::RPlot=/=plot::RLayout= for every figure. No external plotting or
statistics package is used.

** Program, presented as a literate whole

*** Lambda sensitivity

Refit at six values of $\lambda$ spanning four orders of magnitude,
holding =n_trees= fixed at 100, tracking both final training deviance and
training accuracy -- the direct analogue of the SVM companion report's
cost sweep, but for L2 regularization strength instead of margin
tolerance.

#+name: xgb-lambda-sensitivity
#+begin_src c++ :eval no
    {
        const std::vector<double> lambdas =
            {0.01, 0.1, 1.0, 10.0, 50.0, 100.0};
        std::vector<double> log_lambda, accs, devs;
        std::cout << "\nLambda sensitivity (n_trees=100):\n";
        std::cout << std::setw(10) << "lambda" << std::setw(12) << "accuracy"
                   << std::setw(12) << "deviance\n";
        for (const double lam : lambdas) {
            XGBoostClassifierOptions opts;
            opts.lambda = lam;
            XGBoostClassifier m(iris, kFormula, opts);
            const double acc = m.training_accuracy() * 100.0;
            const double dev = m.training_deviance().back();
            log_lambda.push_back(std::log10(lam));
            accs.push_back(acc);
            devs.push_back(dev);
            std::cout << std::setw(10) << std::fixed << std::setprecision(2)
                       << lam << std::setw(11) << acc << "%"
                       << std::setw(12) << std::setprecision(4) << dev
                       << "\n";
        }
        auto acc_plot = RPlot::plot(log_lambda, accs, "b", "accuracy",
                                     {37, 99, 235});
        acc_plot.title("Training Accuracy vs Lambda")
            .x_label("log10(lambda)").y_label("training accuracy (%)")
            .background({250, 250, 252});
        auto dev_plot2 = RPlot::plot(log_lambda, devs, "b", "deviance",
                                      {220, 38, 38});
        dev_plot2.title("Final Deviance vs Lambda")
            .x_label("log10(lambda)").y_label("training deviance")
            .background({250, 250, 252});
        auto layout = RLayout::create(1, 2);
        layout.add(acc_plot);
        layout.add(dev_plot2);
        layout.save_svg("build/org/xgb_iris_lambda_sensitivity.svg");
        std::cout << "wrote xgb_iris_lambda_sensitivity.svg\n";
    }
#+end_src

*** Decision regions: light versus heavy regularization

As in the decision-tree, random-forest, and GBM companion reports,
=plot_decision_regions= only accepts a model with /exactly/ two
predictors, so we fit two separate 2-predictor models purely to draw this
figure -- one at the library default $\lambda = 1$, one heavily
regularized at $\lambda = 50$ -- to see §2.4's shrinkage effect directly on
a boundary rather than only in a table of numbers.

#+name: xgb-decision-regions
#+begin_src c++ :eval no
    {
        XGBoostClassifier light(iris, "Species ~ Petal.Length + Petal.Width");
        XGBoostClassifierOptions heavy_opts;
        heavy_opts.lambda = 50.0;
        XGBoostClassifier heavy(iris, "Species ~ Petal.Length + Petal.Width",
                                 heavy_opts);

        auto light_plot = light.plot_decision_regions("Petal.Length",
                                                        "Petal.Width");
        light_plot.title("lambda = 1 (default)").background({250, 250, 252});

                                                        "Petal.Width");

lightly-regularized one on the left -- shrinking every leaf's weight
toward zero doesn't just hurt accuracy in the abstract, it concretely
simplifies the boundary the ensemble is willing to draw, the same
qualitative story the SVM companion report's cost sweep tells about margin
width, applied here to boosted trees instead of a kernel margin.

* Discussion

**XGBoost versus classic gradient boosting, directly.** These two reports
share almost everything -- the same additive, sequential, one-tree-per-
class-per-round structure, the same softmax/multinomial-deviance loss, the
same missing built-in held-out check -- and differ in exactly the ways §2
predicted: a Newton step instead of a gradient step, three explicit
regularization knobs ($\lambda$, $\alpha$, $\gamma$) built directly into
the leaf-weight and split-gain formulas instead of relying on learning
rate and tree depth alone, and gain-based rather than SSE-based feature
importance. On this small, clean dataset, the practical upshot is that
XGBoost reaches a substantially lower training deviance in the same number
of rounds -- but, per §4.7, that same tighter fit also means its
confidence on the one genuinely ambiguous flower in this project's
recurring four-flower test set is the highest of any of the six methods
in this project, which is worth treating as a caution rather than a
straightforward improvement.

**Is XGBoost's extra confidence deserved?** Every method in this project
that has a resubstitution-only accuracy figure (LDA, SVM, the single
decision tree, GBM, and this report) has had to caveat it as potentially
optimistic; only the random forest companion report's out-of-bag estimate
actually checks that optimism against anything. XGBoost's characteristic
behavior -- converging to a tighter fit, faster, than plain gradient
boosting -- makes that caveat /more/ pressing here, not less: a model that
fits its own training data even more confidently, with no held-out check
at all in this configuration, is exactly the situation where a
practitioner should reach for cross-validation before trusting the
headline accuracy figure, regardless of how clean the deviance curve
looks.

**Six methods, one dataset, one recurring lesson.** Every one of this
project's six classifier reports lands in the 95-100% range on these 150
flowers, and every method's genuine errors (where it reports any at all)
fall in the same /versicolor//virginica/ overlap. That convergence, one
more time, is evidence about the /data/ -- a small region of real
biological similarity between two species -- and not a ranking of the six
methods against each other; each report in this series has, in its own
way, arrived at the same conclusion from a completely different
mathematical starting point.

* Conclusion

A 100-round, regularized, second-order gradient boosting classifier, fit
with =datamunge='s C++ =stats::XGBoostClassifier=, reaches a training
deviance of 0.0288 on Fisher's three iris species -- more than three times
lower than the classic gradient boosting companion report's 0.0900 at the
same round budget -- and a sweep over its L2 regularization parameter
produces this project's cleanest over-regularization curve, with training
accuracy holding steady up to $\lambda \approx 10$ before collapsing by
$\lambda = 50$. Read against its closest relative, this report's real
contribution is isolating exactly what changes between "boosting" and
"regularized, second-order boosting": the leaf-weight and split-gain
formulas gain three explicit regularization terms, and the resulting model
converges faster and more confidently -- confidence that, absent any
built-in held-out check, is exactly what should be verified rather than
simply trusted. As with its companions, this entire report is reproducible
end to end via =just org-example xgb_iris_analysis=, which re-executes
§3.3.8's assembly block -- and therefore every number and figure above --
from the =datamunge= source tree.
