#+begin_abstract
The "textbook" one-pass variance formula, \(\operatorname{Var}=\overline{x^2}-\bar
x^2\), is a numerical trap: for data with a large mean and small spread it subtracts
two huge, nearly equal numbers and loses all precision -- it can even report a
*negative* variance. *Welford's algorithm* (1962) computes exactly the same mean and
variance in a single pass while staying accurate, by updating running estimates
from each new value instead of accumulating giant sums. This report implements it
in =datamunge='s C++ =algorithms::OnlineVariance= (and its covariance extension) as a
literate program: every number and figure comes from one compiled binary. We show
the naive formula catastrophically failing as the data's offset grows while Welford
stays exact, and demonstrate the mergeable, streaming, and covariance forms.
#+end_abstract

* Two one-pass formulas, one stable

Both the naive and Welford methods make a single pass, but they accumulate very
different quantities. The *naive* method keeps \(\sum x_i\) and \(\sum x_i^2\) and
forms
\[
  \operatorname{Var} = \frac{\sum x_i^2}{n} - \Big(\frac{\sum x_i}{n}\Big)^2.
\]
When the mean is large, \(\sum x_i^2\) and \(n\bar x^2\) are both enormous and nearly
equal, so their difference suffers *catastrophic cancellation*: the small true
variance is swamped by floating-point rounding of the big sums.

*Welford's* method keeps the running mean \(\bar x_n\) and the sum of squared
deviations \(M_{2,n}=\sum_{i\le n}(x_i-\bar x_n)^2\), updated per value:
\[
  \bar x_n = \bar x_{n-1} + \frac{x_n - \bar x_{n-1}}{n},\qquad
  M_{2,n} = M_{2,n-1} + (x_n - \bar x_{n-1})(x_n - \bar x_n).
\]
Then the population variance is \(M_2/n\) and the sample variance \(M_2/(n-1)\). The
increments involve only *deviations from the current mean* -- never the large raw
sums -- so no cancellation occurs.

** Pseudocode

#+begin_example
Welford:
    n = 0; mean = 0; M2 = 0
    for each x:
        n += 1
        delta = x - mean
        mean += delta / n
        M2   += delta * (x - mean)      # (x - old_mean)*(x - new_mean)
    population_variance = M2 / n
    sample_variance     = M2 / (n - 1)
#+end_example

The accumulators also *merge*: two partial \((n,\bar x,M_2)\) triples combine in
closed form (Chan et al.), enabling parallel and chunked reduction.

* A worked example: cancellation as the offset grows

We fix a data set of unit-variance noise and add a growing constant offset
\(10^k\). We compute the sample variance three ways -- a reference two-pass, the
naive one-pass formula, and Welford -- and track each one-pass method's relative
error against the reference as the offset explodes.

#+name: ov-run
#+begin_src c++ :eval no
    std::mt19937_64                  rng(1);
    std::normal_distribution<double> g(0.0, 1.0);
    std::vector<double>              base(10000);
    for (double& x : base) x = g(rng);  // ~ N(0,1)

    std::cout << "=== Variance under a growing offset (true variance ~ 1) ===\n";
    std::cout << "offset      two-pass     naive one-pass   Welford\n";
    std::vector<double> off_x, naive_err, welford_err;
    for (int k = 0; k <= 9; ++k) {
        double offset = std::pow(10.0, k);
        std::vector<double> data(base.size());
        for (std::size_t i = 0; i < base.size(); ++i) data[i] = base[i] + offset;

        // Reference two-pass.
        double mean = 0.0;
        for (double x : data) mean += x;
        mean /= data.size();
        double ss = 0.0;
        for (double x : data) ss += (x - mean) * (x - mean);
        double two_pass = ss / (data.size() - 1);

        // Naive one-pass (sum and sum of squares).
        double s = 0.0, s2 = 0.0;
        for (double x : data) { s += x; s2 += x * x; }
        double nmean = s / data.size();
        double naive = (s2 - data.size() * nmean * nmean) / (data.size() - 1);

        // Welford.
        OnlineVariance ov;
        for (double x : data) ov.add(x);
        double welford = ov.sample_variance();

        printf("1e%d   %12.6f   %14.6f   %10.6f\n", k, two_pass, naive, welford);
        off_x.push_back(k);
        naive_err.push_back(std::abs(naive - two_pass) / two_pass + 1e-18);
        welford_err.push_back(std::abs(welford - two_pass) / two_pass + 1e-18);
    }

    // Covariance/correlation demo.
    OnlineCovariance oc;
    for (int i = 0; i < 5000; ++i) {
        double x = g(rng);
        oc.add(x, 3.0 * x + 0.5 * g(rng));
    }
    std::cout << "\nstreaming covariance demo: cov=" << oc.sample_covariance()
              << "  correlation=" << oc.correlation() << "  (y = 3x + noise)\n";

    // Figure: relative error vs offset (log scale) for naive vs Welford.
    RPlot p = RPlot::create();
    std::vector<double> naive_log, welford_log;
    for (double e : naive_err) naive_log.push_back(std::log10(e));
    for (double e : welford_err) welford_log.push_back(std::log10(e));
    p.line(off_x, naive_log, "naive", {220, 38, 38}, 2.5);
    p.points(off_x, naive_log, "", {220, 38, 38}, 4.0);
    p.line(off_x, welford_log, "Welford", {22, 163, 74}, 2.5);
    p.points(off_x, welford_log, "", {22, 163, 74}, 4.0);
    p.legend({"naive one-pass", "Welford"}, {{220, 38, 38}, {22, 163, 74}});
    p.save_svg("build/org/online_variance_error.svg");
    std::cout << "\nwrote build/org/online_variance_error.svg\n";
#+end_src

At small offsets all three agree, but as the offset grows the naive formula's
relative error climbs by orders of magnitude -- by an offset of \(10^8\)-\(10^9\) it
has lost most or all of its significant digits (the plotted \(\log_{10}\) error
rises steeply), and it can return a nonsensically small or negative variance.
Welford's method, working only with deviations from the running mean, stays correct
to near machine precision throughout. The streaming covariance recovers the
planted relationship \(y=3x+\text{noise}\).

* Why this matters, and relatives

The lesson is practical: never compute variance as "mean of squares minus square
of mean" on real data with a nonzero baseline (sensor readings, timestamps,
prices). Welford's method is the standard fix, and its properties make it broadly
useful: it is *online* (update as data streams in, no storage), *stable* (no
cancellation), and *mergeable* (combine partial results from parallel workers or
data chunks). The same running-moments idea extends to higher moments (skewness,
kurtosis) via Terriberry's formulas and to the running covariance shown here, which
is the basis of streaming correlation and incremental PCA.

* Complexity

Welford is \(O(1)\) work and \(O(1)\) memory per element -- a running count, mean, and
\(M_2\) -- versus the naive method's identical cost but ruined accuracy. The merge is
\(O(1)\). Nothing is stored, so it handles unbounded streams.
