#+begin_abstract
The *discrete logarithm* problem -- find \(x\) with \(g^x\equiv h\pmod p\) -- is easy
to state and (believed) hard to solve, which is why it underpins Diffie-Hellman key
exchange and much of public-key cryptography. Brute force tries every exponent,
\(O(p)\) work. *Shanks's baby-step giant-step* algorithm cuts this to
\(O(\sqrt p)\) time and space by a *meet-in-the-middle* trick. This report
implements it in =datamunge='s C++ =algorithms::baby_step_giant_step=, solves
\(2^x\equiv 17\pmod{101}\), and plots the collision between the baby steps and the
giant steps that pins down \(x\).
#+end_abstract

* Splitting the exponent

Write the unknown exponent as \(x = i\,m + j\) with \(m=\lceil\sqrt{p-1}\rceil\)
and \(0\le j < m\). Then \(g^x=h\) becomes

\[
g^{j} \equiv h\cdot\bigl(g^{-m}\bigr)^{i} \pmod p .
\]

The left side depends only on \(j\), the right only on \(i\). So:

- *baby steps*: tabulate \(g^{j}\bmod p\) for every \(j\in[0,m)\) in a hash table;
- *giant steps*: for \(i=0,1,2,\dots\), compute \(h\cdot(g^{-m})^{i}\) and look it up
  in the table.

The first match gives \(j\) and \(i\), hence \(x=im+j\). Both loops run about
\(\sqrt{p}\) times, so the total work is \(O(\sqrt p)\) -- a square-root speedup
bought with \(O(\sqrt p)\) memory for the table. If \(h\) is not in the subgroup
generated by \(g\), no match occurs and the algorithm reports that no logarithm
exists.

* Algorithm

#+begin_example
BABY-STEP-GIANT-STEP(g, h, p):
  m <- ceil(sqrt(p - 1))
  table <- { g^j mod p : j  for j in 0..m-1 }      # baby steps
  factor <- g^(-m) mod p                            # = g^(p-1-m)
  gamma <- h
  for i in 0 .. m:                                  # giant steps
      if gamma in table: return i*m + table[gamma]
      gamma <- gamma * factor mod p
  return NONE
#+end_example

* Worked example: solve 2^x = 17 (mod 101)

Here \(p=101\), so \(m=\lceil\sqrt{100}\rceil=10\). We tabulate \(2^0,\dots,2^{9}\)
(the baby steps), then step \(h=17\) by the giant stride \(2^{-10}\) until we land
on a tabulated value. The program reports \(x\), verifies \(2^x\equiv 17\), and
records the collision for the figure.

#+name: bs-run
#+begin_src c++ :eval no
    const std::uint64_t g = 2, h = 17, p = 101;
    const DiscreteLog r = baby_step_giant_step(g, h, p);

    auto powmod = [](std::uint64_t b, std::uint64_t e, std::uint64_t m) {
        std::uint64_t out = 1; b %= m;
        while (e) { if (e & 1) out = out * b % m; b = b * b % m; e >>= 1; }
        return out;
    };

    std::cout << "=== Baby-step giant-step: 2^x = 17 (mod 101) ===\n";
    if (r.exists)
        std::cout << "x = " << r.exponent << "   (check 2^" << r.exponent << " mod 101 = "
                  << powmod(g, r.exponent, p) << ")\n";
    else
        std::cout << "no discrete logarithm exists\n";

    const std::uint64_t m = static_cast<std::uint64_t>(std::ceil(std::sqrt(static_cast<double>(p - 1))));
    // Baby steps.
    std::unordered_map<std::uint64_t, std::uint64_t> table;
    std::vector<double> baby_val, baby_row, baby_lab;
    std::uint64_t e = 1;
    for (std::uint64_t j = 0; j < m; ++j) {
        table.emplace(e, j);
        baby_val.push_back(static_cast<double>(e)); baby_row.push_back(1.0); baby_lab.push_back(static_cast<double>(j));
        e = e * g % p;
    }
    // Giant steps until collision.
    const std::uint64_t factor = powmod(g, p - 1 - m, p);
    std::vector<double> giant_val, giant_row, giant_lab;
    std::uint64_t gamma = h; std::uint64_t collide = 0; bool found = false;
    for (std::uint64_t i = 0; i <= m; ++i) {
        giant_val.push_back(static_cast<double>(gamma)); giant_row.push_back(0.0); giant_lab.push_back(static_cast<double>(i));
        if (!found && table.count(gamma)) { collide = gamma; found = true; }
        if (found) break;
        gamma = gamma * factor % p;
    }
    std::cout << "m = " << m << ", baby steps 2^0..2^" << m - 1 << ", collision residue = " << collide << "\n";

    auto plot = RPlot::create();
    plot.points(baby_val, baby_row, "baby: g^j", RGB{37, 99, 235}, 8.0);
    plot.points(giant_val, giant_row, "giant: h*g^-mi", RGB{220, 38, 38}, 8.0);
    if (found) plot.segments({static_cast<double>(collide)}, {0.0}, {static_cast<double>(collide)}, {1.0}, RGB{202, 138, 4}, 2.0);
    for (std::size_t k = 0; k < baby_val.size(); ++k)
        plot.text(baby_val[k], 1.12, std::to_string(static_cast<int>(baby_lab[k])), RGB{37, 99, 235}, 10.0);
    for (std::size_t k = 0; k < giant_val.size(); ++k)
        plot.text(giant_val[k], -0.12, std::to_string(static_cast<int>(giant_lab[k])), RGB{220, 38, 38}, 10.0);
    plot.legend({"baby steps (index j)", "giant steps (index i)"}, {{37, 99, 235}, {220, 38, 38}});
    plot.title("Baby-step giant-step: collision at residue where a baby meets a giant")
        .x_label("residue mod 101").y_label("").background({250, 250, 252});
    plot.y_limits(-0.5, 1.6);
    plot.save_svg("build/org/baby_step_giant_step.svg");
    std::cout << "wrote baby_step_giant_step.svg\n";
#+end_src

The algorithm recovers the exponent and the check \(2^x\bmod 101 = 17\) confirms
it. Only about \(\sqrt{100}=10\) baby steps and a handful of giant steps were
needed, versus up to 100 for brute force -- the square-root speedup that
meet-in-the-middle buys.
