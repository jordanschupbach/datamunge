#+begin_abstract
Exact nearest-neighbor search in a k-d tree backtracks into every branch that *might* hold a closer point;
in high dimensions that degrades to scanning nearly everything. *Best Bin First* (Beis & Lowe, 1997)
trades a sliver of accuracy for a large speedup: it visits the tree's bins in order of their distance to
the query using a priority queue, and *stops after a fixed budget* of examined points. This report drives
=datamunge='s =geometry::BestBinFirst=, verified to return the exact neighbor with an unbounded budget
and a very close one on a small budget, and shows the work it saves.
#+end_abstract

* Visit the closest bins first, then stop

A k-d tree splits space by alternating axis-aligned planes. Exact search descends to the leaf containing
the query, then unwinds, re-entering any sibling subtree whose splitting plane is closer than the current
best -- potentially many subtrees. Best Bin First changes the *order and the stopping rule*:

1. Maintain a priority queue of unexplored subtrees, keyed by the distance from the query to the subtree's
   bounding boundary (a lower bound on the distance to any point inside it).
2. Repeatedly pop the *closest* subtree, descend it to a leaf, and push the sibling branches encountered
   along the way with their boundary distances.
3. Stop after examining a fixed number \(L\) of points, returning the best found so far.

Because the most promising bins are searched first, the true nearest neighbor is usually found within the
first few examined points; the budget \(L\) caps the worst case. With \(L\) unbounded the queue empties
only after every potentially-closer bin is checked, so the result is *exact*; with small \(L\) it is
approximate but typically within a whisker of exact, at a fraction of the cost. This budgeted search is
what makes k-d trees usable for the high-dimensional descriptor matching in computer vision (it was
introduced for SIFT).

* Algorithm

#+begin_example
BBF-NEAREST(query, max_search):
  push (0, root) onto a min-priority-queue keyed by boundary distance
  best = infinity
  while the queue is nonempty:
      (bd, node) = pop the closest bin;  if bd > best: break
      descend from node to a leaf:
          update best with each point on the way
          if examined == max_search: return best
          push the far branch keyed by its boundary distance
  return best
#+end_example

* Worked example: exactness and work saved

We confirm that with a generous budget BBF matches brute-force nearest neighbor, then measure how many
points it actually examines to find the exact neighbor as the dataset grows -- far fewer than the
brute-force scan.

#+name: bbf-run
#+begin_src c++ :eval no
    std::mt19937_64 rng(1);
    std::uniform_real_distribution<double> u(-50, 50);

    std::cout << "=== Best Bin First ===\n";
    // Exactness check against brute force on 3000 points.
    {
        std::vector<Point2D> pts;
        for (int i = 0; i < 3000; ++i) pts.push_back({u(rng), u(rng)});
        BestBinFirst bbf(pts);
        auto brute = [&](const Point2D& q) { int bi = 0; double bd = 1e300; for (std::size_t i = 0; i < pts.size(); ++i) { const double dx = q.x - pts[i].x, dy = q.y - pts[i].y, d = dx * dx + dy * dy; if (d < bd) { bd = d; bi = (int)i; } } return bi; };
        int exact = 0; const int Q = 1000;
        for (int t = 0; t < Q; ++t) { const Point2D q{u(rng), u(rng)}; if (bbf.nearest(q, (int)pts.size() + 1) == brute(q)) ++exact; }
        std::printf("unbounded budget: exact for %d / %d queries\n", exact, Q);
    }

    // Points examined to find the exact NN, versus dataset size.
    std::vector<double> ns, examined, brute_cost;
    for (int n : {500, 1000, 2000, 4000, 8000, 16000}) {
        std::vector<Point2D> pts;
        for (int i = 0; i < n; ++i) pts.push_back({u(rng), u(rng)});
        BestBinFirst bbf(pts);
        double sum = 0; const int Q = 400;
        for (int t = 0; t < Q; ++t) { const Point2D q{u(rng), u(rng)}; sum += bbf.nearest_counted(q, n + 1).examined; }
        ns.push_back(n); examined.push_back(sum / Q); brute_cost.push_back(n);
    }
    std::cout << "      n    BBF examined   brute-force scan\n";
    for (std::size_t i = 0; i < ns.size(); ++i)
        std::printf("  %6.0f      %8.1f        %8.0f\n", ns[i], examined[i], brute_cost[i]);

    auto plot = RPlot::create();
    plot.line(ns, brute_cost, "brute", RGB{220, 120, 120}, 2.0);
    plot.points(ns, brute_cost, "brute", RGB{220, 120, 120}, 5.0);
    plot.line(ns, examined, "bbf", RGB{37, 99, 235}, 2.2);
    plot.points(ns, examined, "bbf", RGB{37, 99, 235}, 5.0);
    plot.legend({"brute-force scan (n)", "BBF points examined"}, {{220, 120, 120}, {37, 99, 235}});
    plot.title("BBF finds the exact neighbor while examining far fewer points than a scan")
        .x_label("dataset size n").y_label("points examined").background({250, 250, 252});
    plot.save_svg("build/org/best_bin_first.svg");
    std::cout << "\nwrote best_bin_first.svg\n";
#+end_src

With an unbounded budget BBF reproduces the brute-force nearest neighbor exactly, yet the number of points
it must examine to do so grows far more slowly than the dataset -- a scan touches every point while BBF
touches a small, slowly-growing fraction.

The red brute-force line climbs linearly with the dataset while the blue BBF curve stays low and nearly
flat: ordering the search by bin distance lets it find and confirm the true neighbor after inspecting only
a handful of the most promising points. Capping that inspection turns the exact search into a fast
approximate one -- the trade that keeps nearest-neighbor matching tractable in the high-dimensional
feature spaces of vision and retrieval.
