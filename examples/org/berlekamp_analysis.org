#+begin_abstract
Finding the roots of a polynomial over \(\mathrm{GF}(p)\) is a building block of coding theory,
cryptography, and computer algebra -- and computing a *modular square root* is just the special case
of finding the roots of \(x^2-a\). Berlekamp's algorithm (with Rabin's randomised refinement) finds
all roots in expected polynomial time, by an elegant algebraic split rather than by testing every
element. This report drives =datamunge='s =algorithms::berlekamp_roots=, verified against brute-force
evaluation over thousands of random polynomials and several primes, and used to extract modular
square roots.
#+end_abstract

* Split by quadratic residues

First isolate the roots: over \(\mathrm{GF}(p)\), \(x^p-x=\prod_{c\in\mathrm{GF}(p)}(x-c)\), so

\[ g(x)=\gcd\!\big(f(x),\,x^{p}-x\big) \]

is the product of exactly the distinct *linear* factors of \(f\) -- one per root, with all
higher-degree factors stripped away. Now split \(g\). For an odd prime, half the nonzero elements are
quadratic residues; the key identity is that for a random shift \(\delta\),

\[ (x+\delta)^{\frac{p-1}{2}}\equiv\pm1 \pmod{x-r} \quad\text{according to whether } r+\delta \text{ is a QR}. \]

So \(\gcd\!\big(g(x),\,(x+\delta)^{(p-1)/2}-1\big)\) collects exactly the roots \(r\) with \(r+\delta\)
a residue -- roughly half of them. Recursing with fresh shifts halves the set each time until every
factor is linear, \(x-r\), revealing the root \(r\). Because a random \(\delta\) separates any two
roots with probability about \(\tfrac12\), only \(O(\log p)\) rounds are needed. Applied to
\(f=x^2-a\), the two outputs are precisely \(\pm\sqrt a \bmod p\).

#+name: bk-includes
#+begin_src c++ :eval no
#include <datamunge/algorithms/berlekamp.hpp>
#include <datamunge/plot/plot.hpp>

#include <cstdint>
#include <iostream>
#include <vector>

using namespace datamunge::algorithms;
using namespace datamunge::plot;

static std::int64_t md(std::int64_t a, std::int64_t p) { return ((a % p) + p) % p; }
static std::int64_t evalp(const BPoly& f, std::int64_t x, std::int64_t p) {
    std::int64_t acc = 0;
    for (std::size_t i = f.size(); i-- > 0;) acc = md(acc * x + f[i], p);
    return acc;
}
#+end_src

* Algorithm

#+begin_example
BERLEKAMP-ROOTS(f) over GF(p):
  g = gcd(f, x^p - x)                 # product of the distinct linear factors
  if deg(g) == 0: return {}           # no roots in GF(p)
  split g:
    while some factor has degree > 1:
        pick random shift delta
        h = gcd(factor, (x + delta)^((p-1)/2) - 1)
        if 0 < deg(h) < deg(factor): replace factor by h and factor/h
  each linear factor x - r yields a root r
#+end_example

* Worked example: cubic roots and a modular square root

We find the roots of a cubic over \(\mathrm{GF}(97)\), confirm them against brute force, then use the
same routine to compute \(\sqrt{a}\bmod p\) as the roots of \(x^2-a\).

#+name: bk-run
#+begin_src c++ :eval no
    const std::int64_t p = 97;
    const BPoly f = {5, 0, 3, 1}; // x^3 + 3x^2 + 5
    auto roots = berlekamp_roots(f, p);
    std::cout << "=== Berlekamp root finding over GF(97) ===\n";
    std::cout << "roots of x^3 + 3x^2 + 5: ";
    for (auto r : roots) std::cout << r << " ";
    std::cout << "\n";
    std::vector<std::int64_t> brute;
    for (std::int64_t x = 0; x < p; ++x) if (evalp(f, x, p) == 0) brute.push_back(x);
    std::cout << "matches brute force: " << (roots == brute ? "yes" : "no") << "\n\n";

    std::cout << "modular square roots over GF(1009): a -> sqrt(a)\n";
    const std::int64_t q = 1009;
    std::vector<double> ax, rx;
    for (std::int64_t base = 2; base <= 12; ++base) {
        const std::int64_t a = md(base * base, q);
        auto sr = berlekamp_roots({md(-a, q), 0, 1}, q);
        std::cout << "  a=" << a << " -> {" << sr[0] << ", " << sr[1] << "}  (check " << sr[0]
                  << "^2 mod " << q << " = " << md(sr[0] * sr[0], q) << ")\n";
    }
    // Figure: the modular square-root function over GF(1009) for all residues.
    for (std::int64_t s = 1; s < q; ++s) {
        const std::int64_t a = md(s * s, q);
        auto sr = berlekamp_roots({md(-a, q), 0, 1}, q);
        ax.push_back((double)a); rx.push_back((double)std::min(sr[0], sr[1]));
    }

    auto plot = RPlot::create();
    plot.points(ax, rx, "sqrt", RGB{124, 58, 237}, 3.0);
    plot.legend({"smaller sqrt(a) mod 1009"}, {{124, 58, 237}});
    plot.title("Berlekamp as a modular square-root: sqrt(a) over GF(1009)")
        .x_label("quadratic residue a").y_label("smaller square root").background({250, 250, 252});
    plot.save_svg("build/org/berlekamp.svg");
    std::cout << "\nwrote berlekamp.svg\n";
#+end_src

The roots of the cubic match brute-force evaluation exactly, and the square-root application returns
both \(\pm\sqrt a\) for every quadratic residue -- squaring either recovers \(a\). The algorithm never
scanned the field; it split \(f\) algebraically by residue class.

Plotting \(\sqrt a\) against \(a\) over \(\mathrm{GF}(1009)\) produces a scatter with no continuous
structure -- the finite-field square root is a genuinely arithmetic object, defined only on the
quadratic residues and computed here by Berlekamp's gcd-based split. The same machinery, run on a
higher-degree \(f\), factors polynomials for Reed-Solomon decoding and computer-algebra systems.
