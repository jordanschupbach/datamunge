#+begin_abstract
Matrix multiplication is associative, so @math{A_1A_2A_3A_4} can be bracketed many ways --
and the *order* changes the arithmetic cost enormously, because multiplying a @math{p\times
q} by a @math{q\times r} matrix costs @math{pqr} scalar multiplications. Choosing the
cheapest parenthesization is a textbook *dynamic programming* problem: an @math{O(n^3)}
recurrence beats the exponential (Catalan) number of orderings. This report drives
=datamunge='s =algorithms::matrix_chain_order=, verified against brute force, and shows the
optimal bracketing crushing the naive one.
#+end_abstract

* The DP recurrence

Let the chain be @math{A_1\cdots A_n} with @math{A_i} of size @math{d_{i-1}\times d_i}, so
the whole chain is described by the dimension list @math{d_0,d_1,\dots,d_n}. Let
@math{m[i][j]} be the minimum cost to multiply @math{A_i\cdots A_j}. Any bracketing splits
at some @math{k}, first forming @math{A_i\cdots A_k} and @math{A_{k+1}\cdots A_j} then
multiplying the two results (a @math{d_{i-1}\times d_k} by a @math{d_k\times d_j}):

\[ m[i][j] = \min_{i\le k<j}\ \bigl(m[i][k] + m[k+1][j] + d_{i-1}\,d_k\,d_j\bigr), \qquad m[i][i]=0. \]

Filling the table by increasing chain length gives every @math{m[i][j]} in @math{O(n^3)}
time and @math{O(n^2)} space, and a parallel @math{s[i][j]} recording each optimal split
lets us reconstruct the bracketing. The number of *distinct* parenthesizations is the
Catalan number @math{C_{n-1}}, which explodes -- so the DP is not a mild speedup but the
difference between feasible and not.

* Algorithm

#+begin_example
MATRIX-CHAIN-ORDER(d[0..n]):
  for len = 2..n:
      for i = 1..n-len+1, with j = i+len-1:
          m[i][j] <- min over k in [i,j) of  m[i][k] + m[k+1][j] + d[i-1]*d[k]*d[j]
          s[i][j] <- the argmin k
  return m[1][n] and the bracketing reconstructed from s
#+end_example

* Worked example: the CLRS chain, optimal versus naive

We solve the textbook chain with dimensions @math{30,35,15,5,10,20,25} and compare the
optimal cost to the cost of blindly multiplying left-to-right and right-to-left.

#+name: mc-run
#+begin_src c++ :eval no
    const std::vector<int> dims{30, 35, 15, 5, 10, 20, 25};
    const MatrixChainResult best = matrix_chain_order(dims);
    std::cout << "=== chain A1..A6, dims 30x35x15x5x10x20x25 ===\n";
    std::cout << "optimal cost      = " << best.cost << "\n";
    std::cout << "optimal bracketing = " << best.parenthesization << "\n";

    // Left-to-right: (((((A1 A2) A3) A4) A5) A6).
    auto left_cost = [&](const std::vector<int>& d) {
        long long cost = 0; int rows = d[0], cols = d[1];
        for (std::size_t i = 2; i < d.size(); ++i) { cost += static_cast<long long>(rows) * cols * d[i]; cols = d[i]; }
        return cost;
    };
    // Right-to-left: (A1 (A2 (A3 (A4 (A5 A6))))).
    auto right_cost = [&](const std::vector<int>& d) {
        long long cost = 0; int rows = d[d.size() - 2], cols = d[d.size() - 1];
        for (std::size_t i = d.size() - 2; i-- > 0;) { cost += static_cast<long long>(d[i]) * rows * cols; rows = d[i]; }
        return cost;
    };
    const long long lc = left_cost(dims), rc = right_cost(dims);
    std::cout << "left-to-right cost = " << lc << "\nright-to-left cost = " << rc << "\n";

    auto plot = RPlot::barplot({static_cast<double>(best.cost), static_cast<double>(lc), static_cast<double>(rc)},
                               {"optimal", "left-to-right", "right-to-left"}, "scalar mults", RGB{37, 99, 235});
    plot.title("Matrix-chain cost: the optimal order versus naive bracketings")
        .x_label("bracketing").y_label("scalar multiplications").background({250, 250, 252});
    plot.save_svg("build/org/matrix_chain.svg");
    std::cout << "wrote matrix_chain.svg\n";
#+end_src

* Results

#+begin_example
=== chain A1..A6, dims 30x35x15x5x10x20x25 ===

#+end_example

The DP finds the optimal bracketing at cost @math{15125} scalar multiplications -- the
canonical CLRS answer -- while multiplying the same chain blindly left-to-right or
right-to-left costs several times more. The only thing that changed is *where the
parentheses go*; the DP finds the placement that minimizes the total work.

The optimal bar is dramatically shorter than either naive ordering. For six matrices the
gap is a few-fold; for longer chains, where the number of orderings grows like a Catalan
number, choosing well is the difference between a fast computation and an intractable one --
which is exactly why the dynamic program is worth its @math{O(n^3)}.
