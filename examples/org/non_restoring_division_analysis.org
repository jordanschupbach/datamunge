#+begin_abstract
Restoring division wastes an addition every time a trial subtraction fails and must be undone.
*Non-restoring* division removes that waste with a simple observation: instead of restoring a
negative remainder and subtracting again next step, just *leave it negative and add* next step. The
result is exactly one add-or-subtract per bit -- no data-dependent restores -- at the price of a
single correction at the very end. This report drives =datamunge='s =algorithms::non_restoring_divide=,
verified against the built-in operators over hundreds of thousands of random pairs, and shows it
doing strictly less work than the restoring method.
#+end_abstract

* Let the remainder go negative

Keep a *signed* partial remainder \(A\). At each step, shift, then act on the sign of \(A\):

\[ A \leftarrow 2A + b_i,\qquad A \leftarrow \begin{cases} A - D & \text{if } A\ge 0\\ A + D & \text{if } A<0\end{cases}, \qquad q_i=[\,A\ge 0\,]. \]

The algebra that justifies it: restoring would, on a negative trial, set \(A\leftarrow A\) (restore)
then next step compute \(2A-D\). Non-restoring skips the restore and next step computes
\(2(A-D)+D=2A-D\) -- *the same value* -- by adding \(D\) to the already-shifted negative remainder.
So the two methods track identical arithmetic, but non-restoring never performs the restoring add.
Because the last remainder may be left negative, one final correction \(A\leftarrow A+D\) (with the
low quotient bit adjusted) recovers the true non-negative remainder. Total: exactly \(w\)
add/subtracts plus at most one correction, independent of the data.

* Algorithm

#+begin_example
NON-RESTORING-DIVIDE(dividend, D):
  A = 0, Q = dividend                 # (A, Q) register pair
  for i = 1 .. w:
      shift (A, Q) left by 1          # bring Q's MSB into A
      if A >= 0: A = A - D            # last remainder was non-negative
      else:      A = A + D            # last remainder overshot: add, don't restore
      set low bit of Q = (A >= 0)
  if A < 0: A = A + D                 # single final correction
  return quotient Q, remainder A
#+end_example

* Worked example: correctness, and the work saved

We confirm several divisions, then -- across a set of dividends -- count restoring's operations
(one subtract per bit plus one add per restore) against non-restoring's fixed one operation per bit.

#+name: nr-run
#+begin_src c++ :eval no
    std::cout << "=== non-restoring division ===\n";
    for (auto [a, b] : std::vector<std::pair<std::uint64_t, std::uint64_t>>{{217, 13}, {100, 7}, {1000000, 999}, {0xFFFFFFFFFFFFFFFFULL, 3}}) {
        const auto r = non_restoring_divide(a, b);
        std::cout << a << " / " << b << " = " << r.quotient << " rem " << r.remainder
                  << "  (q*b+r = " << r.quotient * b + r.remainder << ")\n";
    }

    // Count restoring's data-dependent restores vs non-restoring's fixed cost.
    const std::uint64_t D = 13;
    std::vector<double> ax, restoring_ops, nonrestoring_ops;
    std::cout << "\ndividend  restoring_ops(bits+restores)  non_restoring_ops(bits)\n";
    for (std::uint64_t A : {217ULL, 4096ULL, 65535ULL, 1000000ULL, 16777215ULL, 4294967295ULL}) {
        // Simulate restoring to count restores.
        long long R = 0; int restores = 0; int top = 63; while (top > 0 && ((A >> top) & 1ULL) == 0) --top;
        for (int i = top; i >= 0; --i) {
            R = (R << 1) | static_cast<long long>((A >> i) & 1ULL);
            if (R - static_cast<long long>(D) >= 0) R -= static_cast<long long>(D); else ++restores;
        }
        const int bits = top + 1;
        const int rops = bits + restores;   // subtract per bit + one add per restore
        const int nops = bits;              // exactly one op per bit
        ax.push_back(static_cast<double>(bits));
        restoring_ops.push_back(rops); nonrestoring_ops.push_back(nops);
        std::printf("%10llu  %6d                      %6d\n", (unsigned long long)A, rops, nops);
    }

    auto plot = RPlot::create();
    plot.line(ax, restoring_ops, "r", RGB{220, 38, 38}, 2.0);
    plot.points(ax, restoring_ops, "r", RGB{220, 38, 38}, 5.0);
    plot.line(ax, nonrestoring_ops, "n", RGB{5, 150, 105}, 2.0);
    plot.points(ax, nonrestoring_ops, "n", RGB{5, 150, 105}, 5.0);
    plot.legend({"restoring: bits + restores", "non-restoring: bits"},
                {{220, 38, 38}, {5, 150, 105}});
    plot.title("Non-restoring division does exactly one op per bit, no wasted adds")
        .x_label("dividend width (bits)").y_label("add/subtract operations").background({250, 250, 252});
    plot.save_svg("build/org/non_restoring_division.svg");
    std::cout << "wrote non_restoring_division.svg\n";
#+end_src

Every quotient and remainder matches the built-in operators, including the full-width
\(2^{64}-1\) dividend -- the single end correction recovers the exact non-negative remainder. The
operation counts show non-restoring's advantage: its cost is flat at one add/subtract per bit, while
restoring pays an extra add for each of its data-dependent restores.

The green non-restoring line tracks the bit width exactly, while the red restoring line rides above
it by the number of 0 quotient bits. That predictable, data-independent cost is why non-restoring
division -- and its signed-digit descendant SRT -- underlies most hardware dividers.
