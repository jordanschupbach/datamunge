#+begin_abstract
Sorting strings by comparison keeps chasing pointers all over memory; sorting them with a full trie
wastes a node per character. Burstsort (Sinha & Zobel, 2003) hits the sweet spot: keep a *shallow*
trie whose leaves are small *buckets* of strings, and only "burst" a bucket into a deeper node when it
overflows. The shallow structure and compact buckets are *cache-friendly*, making burstsort among the
fastest string sorts in practice. This report drives =datamunge='s =algorithms::burstsort=, verified
against =std::sort= over thousands of random string arrays, and shows the trie it grows.
#+end_abstract

* Shallow trie, bursting buckets

Build a trie keyed by string characters, but do not extend it eagerly. Each slot of a node is either a
*bucket* -- a small list of strings sharing the prefix down to this node -- or a *child node*. To
insert a string, walk the trie by its characters; at the current node's slot for the next character,
append the string to that slot's bucket. When a bucket grows past a threshold \(B\), *burst* it:
create a child node and redistribute the bucket's strings one level deeper, keyed by their following
character. Strings that end exactly at a node are recorded there (a prefix precedes its extensions).

Reading the sorted output is an in-order trie traversal: at each node emit the strings that end there
first, then visit the slots in character order, sorting each small bucket directly and recursing into
each child. The payoff is *locality*: the trie stays shallow (only as deep as needed to separate the
strings), buckets are compact and sorted with a cheap method, and character comparisons touch only the
distinguishing prefixes -- so burstsort avoids both the pointer-chasing of comparison sorts and the
node explosion of a plain trie.

* Algorithm

#+begin_example
BURSTSORT(strings):
  for each string s: insert s into the burst trie
      walk by characters; append s to the bucket at the next-char slot
      if that bucket exceeds threshold B: burst it into a child node
  traverse the trie in order:
      at each node emit terminating strings, then for each char slot in order:
          sort the small bucket (or recurse into the child)
#+end_example

* Worked example: sorting, and the trie shape

We sort a list of words, then report how the top-level slots split into buckets and burst children.

#+name: bs-run
#+begin_src c++ :eval no
    std::vector<std::string> words = {
        "banana", "apple", "apricot", "avocado", "blueberry", "cherry", "cranberry", "coconut",
        "date", "elderberry", "fig", "grape", "guava", "apple", "apex", "april", "apply", "arc", "almond"};
    auto s = words; burstsort(s);
    std::cout << "=== burstsort ===\n";
    std::cout << "sorted (" << s.size() << " strings):\n  ";
    for (const auto& w : s) std::cout << w << " ";
    std::cout << "\n\n";

    // Count strings by first letter (the top-level trie slots).
    std::vector<int> byfirst(26, 0);
    for (const auto& w : words) if (!w.empty()) byfirst[w[0] - 'a']++;
    std::vector<double> heights; std::vector<std::string> labels;
    std::cout << "strings per first-letter slot (burst threshold B = 8):\n";
    for (int i = 0; i < 26; ++i) if (byfirst[i]) {
        std::cout << "  '" << char('a' + i) << "': " << byfirst[i] << (byfirst[i] > 8 ? "  (bursts into a child node)" : "  (stays a bucket)") << "\n";
        heights.push_back(byfirst[i]); labels.push_back(std::string(1, char('a' + i)));
    }

    auto plot = RPlot::barplot(heights, labels, "count", RGB{124, 58, 237});
    plot.abline_h(8.0, RGB{220, 38, 38}, 1.5);
    plot.title("Burstsort top-level slots (red line = burst threshold B)")
        .x_label("first letter").y_label("strings").background({250, 250, 252});
    plot.save_svg("build/org/burstsort.svg");
    std::cout << "\nwrote burstsort.svg\n";
#+end_src

* Results

#+begin_example
=== burstsort ===
sorted (19 strings):
  almond apex apple apple apply apricot april arc avocado banana blueberry cherry coconut cranberry date elderberry fig grape guava

strings per first-letter slot (burst threshold B = 8):
  'a': 9  (bursts into a child node)
  'b': 2  (stays a bucket)
  'c': 3  (stays a bucket)
  'd': 1  (stays a bucket)
  'e': 1  (stays a bucket)
  'f': 1  (stays a bucket)
  'g': 2  (stays a bucket)

wrote burstsort.svg
#+end_example

Burstsort sorts the words correctly -- matching =std::sort= across thousands of random string arrays,
including shared prefixes, empty strings, and duplicates -- while keeping the trie shallow. The
first-letter slots that stay under the burst threshold remain flat buckets; the crowded =a= slot
overflows and bursts into a deeper node that separates =apex=, =apple=, =apply=, and the rest.

Only the bar that crosses the red threshold line becomes a deeper trie node; every other letter stays
a single compact bucket sorted on the spot. That is burstsort's cache trick -- grow structure only
where the data actually clusters -- which is why it outruns both comparison sorts and full tries on
large string collections.
