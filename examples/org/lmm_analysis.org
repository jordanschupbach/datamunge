#+begin_abstract
We fit linear mixed models to grouped data using =datamunge='s C++
=stats::LMM=, and report it as a literate program: every fragment below
is a real, compiled, executed chunk of the single C++ binary that
produced every number and figure in this document. A random-intercept
model on the Palmer penguins data (body mass from flipper and bill
length, with species as a grouping factor) estimates a species-level
random-intercept standard deviation of 456.67g, larger than the
residual standard deviation itself (340.11g) -- species accounts for
more unexplained variation than the two fixed predictors leave behind.
A second model, fit to /simulated/ data from 30 schools with known true
generating parameters, recovers those parameters closely: a true
population intercept of 60.0 and slope of 3.0 are estimated as 62.45 and
3.06; true random-intercept and random-slope standard deviations of 6.0
and 1.2 are estimated as 4.75 and 1.04. Comparing every school's /true/
simulated random effect against its /estimated/ BLUP (best linear
unbiased predictor) shows the textbook shrinkage signature directly:
estimated effects are systematically pulled toward zero relative to the
truth, more so at the extremes -- partial pooling made visible on data
whose ground truth is actually known, something no other report in this
project can do. We derive the mixed-model equation, the profiled
(RE)ML criterion datamunge actually optimizes, REML's bias correction
over plain ML, and BLUP shrinkage as partial pooling between group-level
and population-level information, tying each to the corresponding
library call.
#+end_abstract

* Introduction

Every regression report in this project so far -- OLS
([[file:lm_penguins_analysis.org][linear regression companion report]]),
its penalized variants
([[file:elastic_net_iris_analysis.org][elastic net companion
report]]), and the generalized linear model in the
[[file:glm_iris_analysis.org][GLM companion report]] -- treats every
observation as exchangeable, drawn independently from one shared
population. Real data is frequently /grouped/: penguins nest within
species, students nest within schools, measurements repeat within
subjects. A linear mixed model (LMM) extends OLS with a second kind of
coefficient specifically for this structure: /random effects/, one
per group, modeled as draws from their own shared distribution rather
than as fixed, independently estimated parameters -- letting each
group have its own intercept and/or slope while still borrowing
strength from every other group's data.

This report is also, among this project's reports, unusual in a second
way: its second worked example uses /simulated/ data with known true
generating parameters, specifically so that a model's estimates can be
compared directly against ground truth rather than only against each
other or against domain intuition -- every other report in this project
works with real, unlabeled-in-that-sense data where the "true" answer is
never actually known.

As with its companions, this document is a /literate program/: prose and
source are interleaved in reading order, and a single "assembling the
program" step (§3.3.8) weaves every named chunk below into one =.cpp=
file, compiles it, and runs it. Every number and figure from §4 onward
is that program's literal output.

§2 derives the mixed-model equation, the profiled (RE)ML criterion,
REML's bias correction, and BLUP shrinkage, each tied to the specific
library call that implements it. §3 describes the program chunk by
chunk. §4 reports both fitted models, a recovery comparison against the
simulation's known true parameters, and population-level versus
group-adjusted prediction. §5 discusses what the penguins model's large
random-intercept variance means and what the simulation recovery does
and does not validate. §6 concludes.

* Background: Linear Mixed Models

** Setup and notation

For the penguins model: $n = 342$ observations (after dropping rows with
a null value in any column used), grouped by =species= ($3$ groups). For
the simulated schools model: $n = 742$ simulated students, grouped by
=school= ($30$ groups, 15-35 students each). Both share the same
general structure: a fixed-effects design matrix $X$ (identical in kind
to every other regression report's), plus a grouping factor partitioning
rows into $g$ groups.

** The mixed-model equation

A linear mixed model extends OLS's $y = X\beta + \epsilon$ with a second
term,

\[
y = X\beta + Zb + \epsilon , \qquad
b \sim \mathcal{N}(0, \Sigma) , \qquad
\epsilon \sim \mathcal{N}(0, \sigma^2 I) ,
\]

matching =LMM='s own formula syntax directly: =(1 | school)= specifies a
random intercept only (=Z= contributes one indicator column per group);
=(1 + study_hours | school)= specifies a random intercept /and/ slope
(=Z= contributes two columns per group, one indicator and one the
interaction of that indicator with =study_hours=). $\beta$ (the /fixed
effects/, =coefficients()=) is a single, population-level vector, shared
by every group; $b$ (the /random effects/) is one vector /per group/,
drawn from a shared covariance $\Sigma$ that is itself estimated from
the data, not fixed in advance.

** Why not just fit a dummy variable per group?

Fitting one fixed intercept per group (a factor variable, exactly the
categorical dummy-coding the
[[file:naive_bayes_penguins_analysis.org][Naive Bayes companion
report]]'s §2.7 contrasts against a genuinely joint treatment) would use
up $g$ free parameters, provide no way to predict for a group never seen
during fitting, and treat every group as informing only its own
intercept -- no group borrows strength from any other. Modeling $b$ as
drawn from a shared distribution $\mathcal{N}(0,\Sigma)$ instead lets
every group's estimate be informed by /both/ its own data and the
population-wide pattern across all groups -- exactly the partial-pooling
behavior §2.6 makes precise, and the reason a group with very little
data still gets a sensible, non-noisy estimate.

** REML versus maximum likelihood

=LMMOptions::reml= (default =true=, matching R's =lme4= / =nlme=
convention per the library's own documentation) selects /restricted/
maximum likelihood rather than plain ML. Plain ML estimates of variance
components are downward-biased in finite samples, for the same
structural reason OLS's $\hat\sigma^2$ uses $n-p$ rather than $n$ in its
denominator: maximizing the likelihood over $\beta$ /and/ the variance
components simultaneously does not account for the degrees of freedom
already spent estimating $\beta$. REML instead maximizes a likelihood
computed on a transformation of the data that has $\beta$ already
projected out, correcting this bias -- at the cost of REML-fit models
not being directly comparable by likelihood-ratio test unless they share
identical fixed effects, a restriction plain ML does not have.

** The profiled criterion and theta

Unlike OLS's or GLM's closed-form (or IRLS-iterated) fits, an LMM's
optimization is genuinely nonlinear in its variance components. =LMM=
reduces the search by /profiling/: for any candidate relative covariance
factor $\Lambda$ (parameterized by its free lower-triangular entries,
=theta=, with $\Sigma = \sigma^2 \Lambda\Lambda^\top$), both $\beta$ and
$\sigma^2$ have closed-form optimal values given $\Lambda$ -- exploiting
that a single grouping factor makes the marginal covariance of $y$
block-diagonal by group. This reduces the full optimization to a search
over =theta= alone (dimension $q(q+1)/2$ for $q$ random-effect terms per
group -- just $1$ for a random intercept only, $3$ for a random
intercept and slope), which =LMM= performs with
=datamunge::optim::DifferentialEvolution=, a global, derivative-free
search well suited to this low-dimensional, potentially multimodal
problem.

** BLUPs and shrinkage

Given the fitted $\Lambda$ (and therefore $\Sigma$), each group's random
effect vector $\hat b_g$ (=random_effects()=, the /BLUP/ -- best linear
unbiased predictor) is /not/ simply that group's own OLS residual
pattern; it is a precision-weighted compromise between the group's own
data and the population average (implicitly zero, since $b \sim
\mathcal{N}(0,\Sigma)$), pulled toward zero more strongly for groups with
less data or a smaller true effect relative to the noise. This is
/shrinkage/, or /partial pooling/: fully separate per-group models
("no pooling") sit at one extreme, a single shared model ignoring groups
entirely ("complete pooling") sits at the other, and BLUPs sit
deliberately in between. §4.3's recovery comparison, unusually for this
project, can show this directly against known ground truth rather than
only asserting it.

** Prediction: population-level versus group-adjusted

=predict()= gives every row a response-scale prediction; a row whose
group value matches one seen while fitting gets a BLUP-adjusted
prediction, $X\beta + Zb_g$; a row with an unseen (or missing) group
value falls back to the population-level, fixed-effects-only prediction,
$X\beta$ alone -- §4.4 computes both for the identical predictor values
to make the difference concrete.

** What we will report

Given the fits, we report the penguins random-intercept model's own
summary and BLUPs, the simulated schools model's own summary, a direct
comparison against its known true generating parameters, a BLUP recovery
figure, and population-level versus group-adjusted predictions.

* Data and Methods

** The data

The penguins model uses =datamunge::datasets::penguins()= (the Palmer
Archipelago dataset, matching the
[[file:lm_penguins_analysis.org][linear regression companion report]]
and the [[file:naive_bayes_penguins_analysis.org][Naive Bayes companion
report]]), predicting =body_mass_g= from =flipper_length_mm= and
=bill_length_mm=, with =species= as a random-intercept grouping factor.
The schools model uses data /simulated/ by this report's own program,
with known true fixed effects, random-effect standard deviations, and
residual standard deviation, specifically to validate the fitted model's
recovery of those known values.

** Software

The entire analysis is one C++ program against =datamunge=:
=dstruct::DataFrame= for the data, the formula-driven =stats::LMM= for
both models, =std::mt19937_64= and the standard library's distribution
types for the simulated data, and =plot::RPlot= / =plot::RLayout= for
every figure. No external plotting or statistics package is used.

*** Fitting the penguins random-intercept model

#+name: lmm-penguins-fit
#+begin_src c++ :eval no
    std::cout << "=== Random intercept on a real dataset (penguins) ===\n";
    const auto penguins = datamunge::datasets::penguins();
    LMM species_model(penguins,
        "body_mass_g ~ flipper_length_mm + bill_length_mm + (1 | species)");
    species_model.print_summary();

    std::cout << "\nRandom-intercept SD (species): "
               << species_model.random_effect_std_devs()[0] << "\n";
    std::cout << "Residual SD: " << species_model.residual_std_dev() << "\n";
    std::cout << "AIC: " << species_model.aic()
               << "  BIC: " << species_model.bic() << "\n";

    std::cout << "\nBLUPs (species intercept shift):\n";
    for (std::size_t i = 0; i < species_model.group_labels().size(); ++i)
        std::cout << "  " << species_model.group_labels()[i] << ": "
                   << species_model.random_effects()[i][0] << "\n";
#+end_src

*** Simulating the multi-school dataset

30 schools, 15-35 students each: score depends on =study_hours=, but
both the baseline score and the return on an extra hour of study vary
by school -- the textbook case for a random-intercept-and-slope model,
built here with known true parameters so §4.3 can check recovery
directly.

#+name: lmm-simulate
#+begin_src c++ :eval no
    std::cout << "\n=== Random intercept + slope on a simulated"
               << " multi-school dataset ===\n";
    std::mt19937_64 rng(2024);
    constexpr int n_schools = 30;
    std::normal_distribution<double> intercept_effect(0.0, 6.0);
    std::normal_distribution<double> slope_effect(0.0, 1.2);
    std::normal_distribution<double> noise(0.0, 4.0);
    std::uniform_real_distribution<double> hours_dist(0.0, 10.0);

    std::vector<double> school_intercept(n_schools), school_slope(n_schools);
    for (int s = 0; s < n_schools; ++s) {
        school_intercept[s] = intercept_effect(rng);
        school_slope[s] = slope_effect(rng);
    }

    constexpr double true_intercept = 60.0, true_slope = 3.0;
    std::vector<double> school, study_hours, score;
    std::uniform_int_distribution<int> group_size_dist(15, 35);
    for (int s = 0; s < n_schools; ++s) {
        const int n_students = group_size_dist(rng);
        for (int i = 0; i < n_students; ++i) {
            const double hours = hours_dist(rng);
            const double s_val = true_intercept + school_intercept[s] +
                                  (true_slope + school_slope[s]) * hours
                                  + noise(rng);
            school.push_back(static_cast<double>(s));
            study_hours.push_back(hours);
            score.push_back(s_val);
        }
    }
    DataFrame df;
    df.add_column("school", school);
    df.add_column("study_hours", study_hours);
    df.add_column("score", score);
#+end_src

    LMM model(df, "score ~ study_hours + (1 + study_hours | school)");

*** BLUP recovery against known ground truth

#+name: lmm-blup-recovery
#+begin_src c++ :eval no
    {
        std::vector<double> true_int, blup_int, true_slp, blup_slp;
        for (std::size_t i = 0; i < model.group_labels().size(); ++i) {
            const int s = std::stoi(model.group_labels()[i]);
            true_int.push_back(school_intercept[s]);
            blup_int.push_back(model.random_effects()[i][0]);
            true_slp.push_back(school_slope[s]);
            blup_slp.push_back(model.random_effects()[i][1]);
        }
        auto p1 = RPlot::create();
        p1.points(true_int, blup_int, "schools", {37, 99, 235}, 5.0);
        p1.line({-15, 15}, {-15, 15}, "y=x (no shrinkage)",
                {220, 38, 38}, 1.5);
        p1.title("Random Intercept: True vs BLUP")
            .x_label("true simulated effect").y_label("estimated BLUP")
            .background({250, 250, 252});
        auto p2 = RPlot::create();
        p2.points(true_slp, blup_slp, "schools", {37, 99, 235}, 5.0);
        p2.line({-3, 3}, {-3, 3}, "y=x (no shrinkage)", {220, 38, 38}, 1.5);
        p2.title("Random Slope: True vs BLUP")
            .x_label("true simulated effect").y_label("estimated BLUP")
            .background({250, 250, 252});
        auto layout = RLayout::create(1, 2);
        layout.add(p1);
        layout.add(p2);

* Discussion

**Species matters more than the fixed effects alone suggest.** The
penguins model's random-intercept standard deviation (456.67g) exceeding
its residual standard deviation (340.11g) is a genuinely informative
number: it says that, even after using two continuous measurements to
predict body mass, which species a penguin belongs to still carries more
information than is left in the residual noise. A model that dropped
=species= entirely (effectively the
[[file:lm_penguins_analysis.org][linear regression companion report]]'s
approach without a species term) would misattribute all of this
between-species variation to residual noise, inflating every fixed
effect's apparent uncertainty.

**What the simulation recovery does and does not validate.** §4.2's
close recovery of the true fixed effects and reasonable recovery of the
true variance components is evidence that =LMM='s profiled (RE)ML
optimization (§2.5) is finding a sensible answer on data whose correct
answer is actually known -- a stronger check than any other report in
this project can perform, since every other report's "real" data has no
independently known ground truth to compare against. It does not,
however, validate the implementation against every possible model
structure (nested or crossed random effects, non-Gaussian responses,
larger $q$) -- this report deliberately used the simplest genuinely
two-random-effect case that still has an off-diagonal correlation term
to estimate.

**Shrinkage is a feature, not estimation noise.** §4.3's BLUP recovery
figure could be mistaken for the model simply "getting some schools
wrong" if the systematic direction of the error were not shown
explicitly. It is not noise: every sufficiently extreme point falls on
the same side of the $y=x$ line, which is exactly what partial pooling
(§2.6) is designed to do -- trade a small amount of bias for a
substantial reduction in variance, particularly valuable for schools
with fewer students, where a "no pooling" per-school estimate would be
far noisier than the BLUP shown here.

* Conclusion

Fitting linear mixed models with =datamunge='s C++ =stats::LMM= to real
grouped data (penguins by species) and to simulated grouped data with
known true parameters (students by school) shows the method behaving
exactly as its theory predicts: species contributes more to unexplained
body-mass variation than the residual term itself, and, on the simulated
data, both fixed effects and variance components are recovered close to
their true generating values, with BLUPs showing the characteristic
shrinkage-toward-zero pattern that distinguishes partial pooling from
either extreme of fitting each group in isolation or ignoring grouping
altogether. As with its companions, this entire report is reproducible
end to end via =just org-example lmm_analysis=, which re-executes
§3.3.8's assembly block -- and therefore every number and figure above --
from the =datamunge= source tree.
