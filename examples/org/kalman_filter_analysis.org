* Introduction

Every filter in this report solves the same underlying problem: given a
sequence of noisy measurements of a system that evolves over time,
estimate its true, hidden state at every step -- and do so *online*,
processing one measurement at a time rather than needing the whole
sequence in advance. This is a different inferential setting from every
other report in this project: not a static dataset fit once, but a
system whose state estimate is continuously updated as new data arrives,
with an explicit model of how the state itself evolves between
observations.

For the special case where that evolution and the observation process
are both linear with Gaussian noise, the classical =KalmanFilter= is the
provably optimal (minimum-mean-squared-error) linear estimator -- exact,
not an approximation. Every other filter in this report exists to handle
some way that assumption can fail or some property the plain Kalman
filter lacks: the Extended and Unscented Kalman Filters handle
*nonlinear* dynamics or observations two different ways; the
=InformationFilter= reparameterizes the identical linear estimator for a
different computational advantage (additive sensor fusion); the Ensemble
Kalman Filter and particle filter drop the Gaussian assumption (or, for
EnKF, drop it approximately) in exchange for scaling via Monte Carlo
sampling instead of matrix algebra; and the alpha-beta (and
alpha-beta-gamma) trackers strip out the covariance bookkeeping entirely
in exchange for a much cheaper, fixed-gain update.

As with its companions, this document is a /literate program/: prose and
source are interleaved in reading order, and a single "assembling the
program" step (§3.3.6) weaves every named chunk below into one =.cpp=
file, compiles it, and runs it. Every number and figure from §4 onward is
that program's literal output.

§2 derives every filter's update equations, each tied to the specific
library call that implements it. §3 describes the program chunk by
chunk. §4 reports the results of all seven filters alongside three
figures. §5 discusses what the RTS smoother's error reduction, the
multiple nonlinear filters' agreement, and the alpha-beta filter's
position/velocity convergence gap each reveal. §6 concludes.

* Background: The Kalman Filter Family

** The shared model: a constant-velocity target

Every filter in this report tracks the same running example: a target
moving at (near-)constant velocity, whose position alone is observed
with noise. Its state is $x = (\text{position}, \text{velocity})$,
evolving by $x_k = F x_{k-1} + w_k$ with

$$F = \begin{pmatrix}1 & \Delta t\\0 & 1\end{pmatrix}, \qquad
w_k \sim N(0, Q)$$

(position advances by velocity $\times\,\Delta t$ each step, velocity
otherwise constant apart from small process noise $Q$), observed via
$z_k = H x_k + v_k$ with $H = (1, 0)$ (only position is measured) and
$v_k \sim N(0, R)$. This exact $(F, H, Q, R)$ pair, plus a nonlinear
sensor variant introduced in §2.4, is reused across every filter below,
letting every method's result be compared directly against both the
simulated ground truth and each other.

** The linear Kalman filter

=KalmanFilter= alternates two steps every timestep. The *predict* (time
update) step propagates the state estimate and its covariance forward
through the dynamics with no new information:

$$\hat{x}_{k|k-1} = F\hat{x}_{k-1|k-1}, \qquad
P_{k|k-1} = F P_{k-1|k-1} F^\top + Q$$

The *update* (measurement update) step then corrects that prediction
using the new observation $z_k$, via the innovation
$y = z_k - H\hat{x}_{k|k-1}$, innovation covariance
$S = HP_{k|k-1}H^\top + R$, and Kalman gain $K = P_{k|k-1}H^\top S^{-1}$:

$$\hat{x}_{k|k} = \hat{x}_{k|k-1} + Ky, \qquad
P_{k|k} = (I - KH)P_{k|k-1}$$

=datamunge='s implementation uses this textbook form (not the more
numerically robust Joseph-form covariance update), matching the
project's general preference for the direct textbook formula. This
recursion is provably the minimum-mean-squared-error linear estimator
for exactly this linear-Gaussian model -- not an approximation, unlike
every nonlinear filter below.

** The RTS smoother

=KalmanFilter::smooth()= runs the ordinary forward filter first, then a
backward Rauch-Tung-Striebel pass that revisits every earlier estimate
once the *entire* sequence is available, using the smoother gain
$C_i = P_{i|i}F^\top P_{i+1|i}^{-1}$:

$$\hat{x}_{i|N} = \hat{x}_{i|i} + C_i(\hat{x}_{i+1|N} - \hat{x}_{i+1|i}), \qquad
P_{i|N} = P_{i|i} + C_i(P_{i+1|N} - P_{i+1|i})C_i^\top$$

Because every smoothed estimate incorporates information from
observations *after* time $i$ as well as before it, the smoothed
covariance is never larger than the filtered one at the same point --
the smoother is always at least as accurate as the causal filter, at
the cost of not being usable online (the full sequence must already be
in hand).

** Nonlinear generalizations: EKF and UKF

When \(f\)/\(h\) (the dynamics/observation functions) are nonlinear, no
exact linear-Gaussian recursion exists. =ExtendedKalmanFilter=
linearizes $f$ and $h$ about the current state estimate at every step,
via a numerically-computed Jacobian (central finite differences,
=detail::numerical_jacobian=, so callers never hand-derive analytic
derivatives), and otherwise runs the identical predict/update algebra as
=KalmanFilter= with that local linearization standing in for \(F\)/\(H\).
=UnscentedKalmanFilter= instead propagates a small deterministic set of
$2n+1$ "sigma points" through the *true* nonlinear \(f\)/\(h\) directly (no
Jacobian at all), then reconstructs the predicted mean and covariance
from the propagated points' weighted statistics -- capturing curvature
to at least second order, generally more accurate than EKF's
first-order linearization for strongly nonlinear models, at the cost of
$2n+1$ function evaluations per step instead of one. Both exactly
reproduce =KalmanFilter='s result whenever \(f\)/\(h\) happen to be linear.

** The information filter: an algebraic dual

=InformationFilter= tracks the *information matrix* $Y = P^{-1}$ and
*information vector* $y = Yx$ instead of $(x, P)$ directly. Its
measurement update becomes purely additive,

$$Y \mathrel{+}= H^\top R^{-1} H, \qquad y \mathrel{+}= H^\top R^{-1} z$$

with no matrix inversion at all -- the classical advantage of this form
is that fusing several independent sensors, or distributing a filter
across nodes that each see part of the measurement stream, reduces to
summing information contributions. The time-update step has no equally
simple additive form for a general $F$, so =datamunge='s implementation
converts to covariance form for predict, then back to information form
-- mathematically exact, producing results *identical* to
=KalmanFilter= given the same model, since the two are the same
estimator in a different parameterization, not an approximation of one
another.

** Monte Carlo filters: EnKF and the particle filter

=EnsembleKalmanFilter= represents the state distribution as a finite
ensemble of sample state vectors rather than an explicit mean/covariance
pair, propagating each member through the true nonlinear $f$ (plus
sampled process noise) and estimating the covariances the Kalman update
needs from the ensemble's own sample statistics. Its stochastic
("perturbed observations") update adds an *independently* sampled
$N(0,R)$ draw to each member's own copy of $z$ before correcting it --
perturbing the observation per member, rather than applying one shared
correction to the whole ensemble, is what keeps the ensemble's spread
statistically consistent after the update instead of collapsing it.
Like UKF, EnKF needs no Jacobian; unlike UKF, its cost scales with
ensemble size rather than state dimension squared/cubed, the classical
reason it is preferred for very high-dimensional states (e.g.
geophysical data assimilation).

=ParticleFilter= drops the Gaussian assumption entirely: it represents
the full posterior as a weighted swarm of particles, reweighting each
by its observation likelihood ($\propto\exp(-\tfrac{1}{2}(z-h(x))^\top
R^{-1}(z-h(x)))$) and resampling the swarm from the resulting weighted
distribution every step (unconditional multinomial resampling, simpler
than an adaptive effective-sample-size-triggered scheme). This is the
fully general member of the family -- correct even for strongly
non-Gaussian or multimodal posteriors where every Gaussian-belief filter
above can fail -- at the cost of needing many particles in high
dimensions (the "curse of dimensionality" for particle filters), which
is why EnKF is usually preferred once the Gaussian approximation is
acceptable.

** Fixed-gain trackers: alpha-beta and alpha-beta-gamma

=AlphaBetaFilter= uses the identical predict/correct structure as
=KalmanFilter= restricted to this report's constant-velocity model, but
with *fixed* gains $\alpha$ (position correction) and $\beta$ (velocity
correction) instead of a covariance-driven Kalman gain:

$$x_{\text{pred}} = x + v\,\Delta t, \qquad
\text{residual} = z - x_{\text{pred}}, \qquad
x \leftarrow x_{\text{pred}} + \alpha\cdot\text{residual}, \qquad
v \leftarrow v + \frac{\beta}{\Delta t}\cdot\text{residual}$$

This is exactly the steady-state behavior a 1D constant-velocity
=KalmanFilter= converges to once its covariance stops changing, with all
the covariance bookkeeping stripped out -- far cheaper per step (no
matrices at all), at the cost of not adapting to changing noise
conditions the way a real Kalman gain does.
=AlphaBetaGammaFilter= is the same idea one derivative order higher (a
3-state "g-h-k" filter tracking position, velocity, and acceleration
with a third fixed gain $\gamma$). An arbitrary $(\alpha,\beta,\gamma)$
triple can leave this recursion oscillating rather than converging --
a real property of the g-h-k recursion's own stability, not a tuning
nicety -- so this report's gains are chosen to satisfy the filter's
stability relation ($\gamma$ small relative to $\beta^2/\alpha$).

* Data and Methods

** The data

All filters track a simulated constant-velocity target (true velocity
$2.0$ per timestep, 50 steps) with Gaussian measurement noise (SD $2.0$)
added to the position-only observation -- chosen specifically because a
known, exact true trajectory lets every filter's estimate be checked
directly against ground truth. §4.2 and §4.3 additionally use a
deliberately nonlinear, but strictly monotonic, sensor model
($h(x)=2x+\sin(x)$, derivative $2+\cos(x)\ge1>0$ everywhere) -- monotonic
specifically to avoid a sign ambiguity a symmetric nonlinear sensor
(e.g. $\sqrt{x^2+c}$) would otherwise introduce, which would make EKF/UKF
convergence a test of tie-breaking behavior rather than of the
approximation quality this report is actually interested in.

** Software

All computation uses =datamunge='s C++ =filter= module --
=KalmanFilter=, =ExtendedKalmanFilter=, =UnscentedKalmanFilter=,
=InformationFilter=, =EnsembleKalmanFilter=, =ParticleFilter=,
=AlphaBetaFilter=, and =AlphaBetaGammaFilter= -- together with
=filter::VectorFunction= (the director-enabled interface every
nonlinear filter's \(f\)/\(h\) implements) and =plot::RPlot= for
visualization.

namespace {

struct LinearFn : VectorFunction {
    std::vector<std::vector<double>> M;
    explicit LinearFn(std::vector<std::vector<double>> m) : M(std::move(m)) {}
    std::vector<double> evaluate(const std::vector<double>& x) override {
        std::vector<double> out(M.size(), 0.0);
        for (std::size_t i = 0; i < M.size(); ++i)
            for (std::size_t j = 0; j < x.size(); ++j) out[i] += M[i][j] * x[j];
        return out;
    }
};

struct MonotonicSensor : VectorFunction {
    std::vector<double> evaluate(const std::vector<double>& x) override {
        return {2.0 * x[0] + std::sin(x[0])};
    }
};

std::vector<double> column(const std::vector<KalmanState>& states,
                            std::size_t dim) {
    std::vector<double> out;
    out.reserve(states.size());
    for (const auto& s : states) out.push_back(s.x[dim]);
    return out;
}

} // namespace

($2.113$) both land close to the true values ($100.000$ and $2.000$),
well within the noise expected from measurements with SD $2.0$. The RTS
smoother's MSE ($0.416$) is roughly a third of the forward-only filtered
MSE ($1.206$), confirming §2.3's prediction directly: incorporating
information from the whole sequence, not just data up to each point,
produces a strictly more accurate estimate at every earlier timestep.

* Discussion

**A smoother's error reduction is not free accuracy from nowhere --
it is the direct, quantifiable value of information the causal filter
did not yet have.** §4.1's roughly threefold MSE reduction from
filtering to smoothing is the same quantity in every application of an
RTS smoother: exactly how much a causal estimate improves once future
observations become available to inform it. This is why the smoother
is unusable online (by definition, "future" observations do not yet
exist during real-time operation) but is the right choice whenever a
sequence is analyzed after the fact -- offline trajectory reconstruction,
retrospective sensor calibration, or (as here) evaluating how much
better an estimate *could* have been with the same data, a useful
benchmark even when only the causal filter is deployable in production.

**Four structurally unrelated approximation strategies converging to
the same answer is a much stronger validation than any one of them
looking reasonable in isolation.** EKF's local linearization, UKF's
deterministic sigma points, EnKF's stochastic ensemble, and the
particle filter's fully general weighted swarm share almost nothing in
their internal mechanics -- yet all four land within a narrow band of
each other and of the true trajectory in §4.2 and §4.3. Had only one filter been
tested, a systematic bug producing a plausible-looking but wrong answer
would be much harder to rule out; four independently-derived methods
agreeing is close to as strong a correctness check as this report's
methodology can offer without an external ground-truth oracle.

**A fixed-gain filter's state components can converge at genuinely
different rates, which a covariance-driven Kalman gain cannot exhibit
in the same way.** §4.4's split result -- good position tracking,
poor velocity convergence, both from the same filter at the same
timestep -- is a direct structural consequence of §2.7's fixed gains:
$\alpha$ and $\beta$ are chosen once and never adapt, so whatever rate
of convergence they happen to produce for each state component is
whatever it is, regardless of how much evidence has accumulated. A real
=KalmanFilter=, by contrast, has a *time-varying* gain driven by its own
covariance $P$, which automatically shifts more correction toward
whichever component is least well-determined at each step -- exactly
the adaptivity §2.7 identifies as the fixed-gain tracker's principal
tradeoff for its much lower per-step cost. This is worth remembering
whenever a fixed-gain filter's output "looks fine" on the visible
output quantity (here, position): an internal state the caller isn't
directly plotting (here, velocity) may be far less converged than that
visible agreement would suggest.

* Conclusion

Tracking a simulated constant-velocity target with every member of
=datamunge='s C++ =filter= family confirms each filter's own theoretical
property directly: the RTS smoother roughly halves the forward filter's
MSE by using the whole sequence; the information filter matches the
Kalman filter's result to near machine precision, confirming algebraic
equivalence rather than approximation; EKF, UKF, EnKF, and the particle
filter -- four structurally unrelated nonlinear approximation strategies
-- all converge to within a narrow band of each other and the truth on a
mildly nonlinear sensor model; and the alpha-beta filter's fixed gains
produce a real, visualized gap between good position tracking and poor
velocity convergence at the same timestep, a genuine property of
fixed-gain filtering rather than a bug. As with its companions, this
entire report is reproducible end to end via
=just org-example kalman_filter_analysis=, which re-executes §3.3.6's
assembly block -- and therefore every number and figure above -- from the
=datamunge= source tree.
