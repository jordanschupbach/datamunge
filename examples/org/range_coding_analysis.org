#+begin_abstract
Range coding is arithmetic coding viewed as narrowing an integer *range* instead of a
\([0,1)\) interval, renormalized a *byte* at a time rather than a bit at a time. Each symbol
scales the range by its probability and shifts the low end; when the range shrinks enough, the
settled top byte is shifted out. Byte-wise renormalization makes it fast, and Subbotin's
*carry-free* variant sidesteps the carry propagation that complicates a naive coder. It achieves
the same near-entropy compression as arithmetic coding and is the entropy backend of LZMA. This
report runs the carry-free range coder with =datamunge='s =algorithms::range_encode= as a
literate program: every number and figure comes from one compiled binary.
#+end_abstract

* Narrow the range, shift out settled bytes

Maintain a 32-bit \(\text{low}\) and \(\text{range}\). To encode symbol \(s\): divide the range
by the total frequency, advance \(\text{low}\) by the symbol's cumulative frequency times that
quotient, and multiply the range by the symbol's frequency -- the arithmetic-coding interval
update, in integers. Then *renormalize*: while the top byte of \(\text{low}\) is settled (the
interval no longer straddles a byte boundary), output it and shift both \(\text{low}\) and
\(\text{range}\) left by 8. The carry-free trick forces a renormalization when the range gets too
small even if the top byte has not settled, capping any pending carry -- so no carry ever
propagates back through already-emitted bytes.

** Pseudocode

#+begin_example
encode(symbols, freq):
    low = 0, range = 0xFFFFFFFF
    for each symbol s:
        range /= total
        low   += cum[s] * range
        range *= freq[s]
        while top byte settled (or range too small): output (low >> 24); low <<= 8; range <<= 8
    flush the 4 bytes of low
#+end_example

* A worked example

A skewed four-symbol source (frequencies 50:20:20:10). We encode messages of growing length and
watch the achieved *bits per symbol* fall toward the Shannon entropy.

#+name: rg-run
#+begin_src c++ :eval no
    std::vector<std::uint32_t> freq = {50, 20, 20, 10};
    double total = 100.0, entropy = 0.0;
    for (auto f : freq) if (f) entropy -= (f / total) * std::log2(f / total);

    std::cout << "=== Range coding (freq 50:20:20:10) ===\n";
    std::cout << "Shannon entropy: " << entropy << " bits/symbol\n\n";

    std::vector<int> pattern;
    for (int i = 0; i < 50; ++i) pattern.push_back(0);
    for (int i = 0; i < 20; ++i) pattern.push_back(1);
    for (int i = 0; i < 20; ++i) pattern.push_back(2);
    for (int i = 0; i < 10; ++i) pattern.push_back(3);

    std::vector<double> lengths, bps;
    std::cout << "symbols : bytes : bits/symbol\n";
    for (int reps = 1; reps <= 12; ++reps) {
        std::vector<int> msg;
        for (int r = 0; r < reps; ++r) msg.insert(msg.end(), pattern.begin(), pattern.end());
        auto   bytes = range_encode(msg, freq);
        bool   ok    = range_decode(bytes, freq, (int)msg.size()) == msg;
        double bp    = bytes.size() * 8.0 / msg.size();
        std::cout << "  " << msg.size() << "   :  " << bytes.size() << "  :  " << bp
                  << (ok ? "" : "  (DECODE ERROR)") << "\n";
        lengths.push_back(msg.size()); bps.push_back(bp);
    }

    RPlot p = RPlot::create();
    p.line(lengths, bps, "range bits/symbol", {37, 99, 235}, 2.0);
    p.points(lengths, bps, "", {37, 99, 235}, 4.0);
    p.abline_h(entropy, {22, 163, 74}, 1.5);
    p.legend({"range bits/symbol", "entropy"}, {{37, 99, 235}, {22, 163, 74}});
    p.save_svg("build/org/range_coding.svg");
    std::cout << "\nwrote build/org/range_coding.svg\n";
#+end_src

The achieved bits per symbol fall toward the Shannon entropy (about 1.76 bits/symbol here) as
the message grows and the fixed 4-byte flush amortizes -- the same near-optimal compression an
arithmetic coder gives, reached with byte-wise instead of bit-wise renormalization. Every message
decoded back exactly, confirming the carry-free coder is lossless. The byte granularity costs a
tiny constant overhead versus a bit-exact arithmetic coder but runs faster, which is why range
coding is the entropy stage of production compressors.

* Character and relatives

Range coding and *arithmetic coding* (companion report) are the same algorithm at heart -- both
narrow an interval by symbol probabilities -- differing only in renormalization granularity and
carry handling; range coding's byte orientation and patent-avoidance history made it popular in
*LZMA* (7-Zip), *bzip2*'s successors, and many game and media codecs. Modern designs increasingly
use *asymmetric numeral systems* (ANS), which match range-coding compression at higher speed. All
three dominate *Huffman* coding on skewed and adaptive sources.

* Complexity

\(O(1)\) integer operations per symbol (a divide, a multiply, and the renormalization loop), so
\(O(n)\) for an \(n\)-symbol message; the output approaches \(nH/8\) bytes for entropy \(H\).
