#+begin_abstract
To magnify an image or read a value between the samples of a function tabulated on a grid, you
interpolate. Bilinear interpolation blends the four surrounding samples with linear weights -- cheap, but
visibly kinked and only first-order. *Bicubic* interpolation blends the surrounding \(4\times4\)
neighborhood with a piecewise-cubic kernel, giving a \(C^1\), third-order-accurate surface that passes
through the samples and reproduces bilinear functions exactly. This report drives =datamunge='s
=algorithms::bicubic_interpolate=, verified to interpolate grid nodes exactly, to be exact for bilinear
functions, and to beat bilinear on smooth data, and shows a coarse grid resampled smoothly.
#+end_abstract

* A separable cubic kernel

Bicubic interpolation is convolution with Keys' *cubic convolution* kernel

\[ w(t)=\begin{cases}(a+2)|t|^3-(a+3)|t|^2+1 & |t|\le 1,\\[2pt] a|t|^3-5a|t|^2+8a|t|-4a & 1<|t|<2,\\[2pt]0 & \text{otherwise},\end{cases} \]

with \(a=-\tfrac12\), the value that makes the scheme third-order accurate. The kernel is *separable*:
the weight for a 2-D neighbor at offset \((m,n)\) is \(w(t_x-m)\,w(t_y-n)\), where \((t_x,t_y)\) is the
query's fractional position inside its grid cell. So the interpolated value is

\[ f(x,y)\approx\sum_{m=-1}^{2}\sum_{n=-1}^{2} w(t_x-m)\,w(t_y-n)\;z_{\,i+m,\,j+n}, \]

a weighted sum over the \(4\times4\) block around the cell. Because \(w(0)=1\) and \(w(k)=0\) for nonzero
integers \(k\), the interpolant reproduces the samples exactly at grid nodes; because the weights sum to
one and reproduce linear terms, it is exact for any bilinear function \(a+bx+cy+dxy\) in the grid
interior. Away from the samples it is much smoother than bilinear -- continuous in value and first
derivative -- which is why bicubic is the default quality setting for image and texture magnification.
(At the border the \(4\times4\) stencil is completed by clamping to the edge samples.)

* Algorithm

#+begin_example
BICUBIC(xs, ys, z, x, y):                  # uniform grid, z row-major
  ix = floor((x - xs[0]) / hx);  tx = fractional part
  iy = floor((y - ys[0]) / hy);  ty = fractional part
  result = 0
  for m in -1..2:
      for n in -1..2:
          result += w(tx - m) * w(ty - n) * z[clamp(ix+m), clamp(iy+n)]
  return result                            # w = Keys cubic kernel, a = -1/2
#+end_example

* Worked example: resampling a coarse grid

We sample a smooth bump on a coarse \(9\times9\) grid, then read a dense profile across it with both
bicubic and bilinear interpolation and compare their errors against the true function.

#+name: bc-run
#+begin_src c++ :eval no
    auto f = [](double x, double y) { return std::exp(-0.15 * (x * x + y * y)) * std::cos(0.7 * (x + y)); };
    std::vector<double> xs, ys;
    for (int i = 0; i < 9; ++i) xs.push_back(i * 0.6 - 2.4);
    for (int j = 0; j < 9; ++j) ys.push_back(j * 0.6 - 2.4);
    std::vector<double> z(xs.size() * ys.size());
    for (std::size_t i = 0; i < xs.size(); ++i)
        for (std::size_t j = 0; j < ys.size(); ++j) z[i * ys.size() + j] = f(xs[i], ys[j]);

    std::cout << "=== Bicubic interpolation ===\n";
    std::cout << "9x9 grid, spacing 0.6.  Node check at (xs[3], ys[5]):\n";
    std::printf("  bicubic = %.10f   truth = %.10f\n", bicubic_interpolate(xs, ys, z, xs[3], ys[5]),
                f(xs[3], ys[5]));

    // Dense profile along the line y = 0.3, and interpolation errors there.
    std::vector<double> px, truth, bic, bil;
    double bic_err = 0, bil_err = 0;
    const double y0 = 0.3;
    for (double x = -2.2; x <= 2.2; x += 0.05) {
        const double t = f(x, y0), b = bicubic_interpolate(xs, ys, z, x, y0);
        // bilinear along the same line for comparison
        const long   ix = static_cast<long>((x - xs[0]) / 0.6), iy = static_cast<long>((y0 - ys[0]) / 0.6);
        const double tx = (x - xs[ix]) / 0.6, ty = (y0 - ys[iy]) / 0.6, ny = ys.size();
        const double bl = (1 - tx) * (1 - ty) * z[ix * (long)ny + iy] + tx * (1 - ty) * z[(ix + 1) * (long)ny + iy] +
                          (1 - tx) * ty * z[ix * (long)ny + (iy + 1)] + tx * ty * z[(ix + 1) * (long)ny + (iy + 1)];
        px.push_back(x); truth.push_back(t); bic.push_back(b); bil.push_back(bl);
        bic_err = std::max(bic_err, std::fabs(b - t));
        bil_err = std::max(bil_err, std::fabs(bl - t));
    }
    std::printf("max error along y=%.1f:  bicubic %.3e   bilinear %.3e\n", y0, bic_err, bil_err);

    auto plot = RPlot::create();
    plot.line(px, truth, "truth", RGB{30, 30, 30}, 2.5);
    plot.line(px, bic, "bicubic", RGB{37, 99, 235}, 1.8);
    plot.line(px, bil, "bilinear", RGB{220, 120, 120}, 1.5);
    plot.legend({"true function", "bicubic", "bilinear"}, {{30, 30, 30}, {37, 99, 235}, {220, 120, 120}});
    plot.title("Bicubic tracks the smooth function; bilinear kinks between samples")
        .x_label("x  (y = 0.3)").y_label("value").background({250, 250, 252});
    plot.save_svg("build/org/bicubic_interpolation.svg");
    std::cout << "\nwrote bicubic_interpolation.svg\n";
#+end_src

At the grid node the bicubic value equals the sample exactly, and along the dense profile its maximum
error is far below bilinear's -- the third-order kernel captures curvature that piecewise-linear blending
cannot.

The bicubic curve rides on top of the true function; the bilinear reconstruction sags between samples
with visible kinks at each node. That smoothness is the payoff of widening the stencil from \(2\times2\)
to \(4\times4\) and weighting it with a cubic kernel -- the same reason bicubic is the workhorse behind
image resizing and height-field sampling.
