#+begin_abstract
The *finite difference method* is the oldest and most direct way to solve a differential
equation numerically: replace each derivative by a difference quotient on a grid, and the
differential equation becomes a system of linear equations. For the 1-D Poisson problem
\(-u''=f\) with fixed boundary values, that system is *tridiagonal* and solves in \(O(n)\) by the
Thomas algorithm, with error \(O(h^2)\). This report drives =datamunge='s
=algorithms::finite_difference_poisson=, verified against an exact solution, and shows the error
shrinking as the grid refines.
#+end_abstract

* Central differences on a grid

Place \(n\) interior points \(x_i=ih\) with spacing \(h=1/(n+1)\). The central second difference

\[ u''(x_i)\approx\frac{u_{i-1}-2u_i+u_{i+1}}{h^2} \]

is second-order accurate. Substituting into \(-u''=f\) at every interior point gives one equation
per unknown:

\[ \frac{-u_{i-1}+2u_i-u_{i+1}}{h^2}=f(x_i), \]

with the known boundary values \(u_0=\alpha,\ u_{n+1}=\beta\) moved to the right-hand side of the
first and last equations. The result is a *symmetric tridiagonal* system \(A\mathbf{u}=\mathbf{d}\)
with \(2/h^2\) on the diagonal and \(-1/h^2\) off it. Because it is tridiagonal, the *Thomas
algorithm* (Gaussian elimination specialised to three bands) solves it in a single forward and
backward sweep, \(O(n)\) time and memory -- no general matrix factorization needed. Refining the
grid halves \(h\) and *quarters* the \(O(h^2)\) error.

* Algorithm

#+begin_example
FINITE-DIFFERENCE-POISSON(f, alpha, beta, n):
  h <- 1/(n+1)
  build tridiagonal system: diag 2/h^2, off-diag -1/h^2, rhs f(x_i)
  fold boundary values alpha, beta into the first/last rhs
  solve with the Thomas algorithm (O(n))
  return u at all grid points
#+end_example

* Worked example: a known solution and the O(h^2) error

We solve \(-u''=\pi^2\sin(\pi x)\), \(u(0)=u(1)=0\), whose exact solution is \(\sin(\pi x)\),
comparing the numerical profile and measuring the error as the grid refines.

#+name: fd-run
#+begin_src c++ :eval no
    auto f = [](double x) { return M_PI * M_PI * std::sin(M_PI * x); };
    const int n = 19;
    const std::vector<double> u = finite_difference_poisson(f, 0.0, 0.0, n);

    std::vector<double> gx, gy, ex, ey;
    const double h = 1.0 / (n + 1);
    for (int i = 0; i <= n + 1; ++i) { gx.push_back(i * h); gy.push_back(u[i]); }
    for (int i = 0; i <= 200; ++i) { const double x = i / 200.0; ex.push_back(x); ey.push_back(std::sin(M_PI * x)); }

    std::cout << "=== -u'' = pi^2 sin(pi x), u(0)=u(1)=0, exact = sin(pi x) ===\n";
    std::cout << "n      h          max |error|\n";
    for (int nn : {9, 19, 39, 79, 159}) {
        const auto uu = finite_difference_poisson(f, 0.0, 0.0, nn);
        const double hh = 1.0 / (nn + 1); double err = 0;
        for (int i = 0; i <= nn + 1; ++i) err = std::max(err, std::fabs(uu[i] - std::sin(M_PI * i * hh)));
        std::printf("%-6d %.6f   %.3e\n", nn, hh, err);
    }

    auto plot = RPlot::create();
    plot.line(ex, ey, "exact", RGB{16, 185, 129}, 2.0);
    plot.points(gx, gy, "finite difference", RGB{220, 38, 38}, 6.0);
    plot.legend({"exact sin(pi x)", "finite difference (n=19)"}, {{16, 185, 129}, {220, 38, 38}});
    plot.title("Finite difference solution of the Poisson BVP sits on the exact curve")
        .x_label("x").y_label("u(x)").background({250, 250, 252});
    plot.save_svg("build/org/finite_difference.svg");
    std::cout << "\nwrote finite_difference.svg\n";
#+end_src

Even with nineteen interior points the numerical solution sits essentially on top of the exact
\(\sin(\pi x)\), and the error table shows the promised second order: each refinement (halving
\(h\)) cuts the maximum error by about four. The differential equation has been turned into a
tridiagonal matrix and solved exactly up to discretisation error.

The red grid values lie right on the green exact curve -- the central-difference stencil captures
the smooth solution faithfully. Doubling the grid would pull them four times closer still. This
same discretise-and-solve recipe, in two and three dimensions, is the backbone of computational
physics; the tridiagonal 1-D case is where it all starts.
