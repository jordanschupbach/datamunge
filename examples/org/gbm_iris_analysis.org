#+begin_abstract
We fit a multinomial gradient boosting classifier -- 100 rounds of shallow
regression trees, one per class per round -- to Fisher's (1936) iris data
using =datamunge='s C++ =stats::GBMClassifier=, and report it as a literate
program: every fragment below is a real, compiled, executed chunk of the
single C++ binary that produced every number and figure in this document.
Unlike the random forest companion report's parallel, independent trees,
gradient boosting fits trees /sequentially/, each one correcting the
current ensemble's mistakes, and the training multinomial deviance falls
monotonically from 1.0354 after round 1 to 0.0900 after round 100 -- a
curve unavailable from any of this project's other four classifier
reports. The fitted model reaches 100.00% training accuracy with no
built-in held-out estimate to temper it (unlike the random forest
companion's out-of-bag accuracy), a real limitation this report is
explicit about. We derive additive functional gradient descent, the
multinomial-deviance pseudo-residuals each round's trees target, the
learning-rate/shrinkage tradeoff, and ensemble feature importance from
first principles, connect each to the corresponding library call, and
close by placing bagging and boosting -- this project's two tree-ensemble
methods -- directly side by side.
#+end_abstract

* Introduction

This project's tree-based reports so far have gone from one greedy
decision tree
([[file:dt_iris_analysis.org][=dt_iris_analysis.org=]]) to a bagged forest
of 100 independent such trees
([[file:rf_iris_analysis.org][=rf_iris_analysis.org=]]), voting in
parallel and never influencing one another. Gradient boosting takes the
opposite approach to combining many weak trees: fit them one at a time, in
sequence, and have each new tree target specifically what the ensemble so
far has gotten wrong. Where bagging's goal is reducing variance by
averaging decorrelated trees, boosting's goal is reducing /bias/ by
having each round directly attack the current model's residual error --
different mechanisms, both arriving at strong ensembles from the same
building block. This report, together with the two companion reports
below it (LDA and SVM
-- [[file:lda_iris_analysis.org][=lda_iris_analysis.org=]] and
[[file:svm_iris_analysis.org][=svm_iris_analysis.org=]]) -- completes a
five-method comparison on the same 150 flowers.

As with its companions, this document is a /literate program/: prose and
source are interleaved in reading order, and a single "assembling the
program" step (§3.3.9) weaves every named chunk below into one =.cpp= file,
compiles it, and runs it. Every number and figure from §4 onward is that
program's literal output.

§2 derives additive functional gradient descent, the multinomial-deviance
pseudo-residuals each boosting round targets, the learning-rate/shrinkage
tradeoff, and ensemble feature importance, each tied to the specific
library call that implements it. §3 describes the program chunk by chunk.
§4 reports the fitted model, its training deviance curve, feature
importance, a learning-rate sweep, and a side-by-side look at the decision
boundary after 5 rounds versus 100. §5 places bagging and boosting side by
side and discusses what this method's own summary can and cannot tell us.
§6 concludes.

* Background: Gradient Boosting

** Setup and notation

As in the other classification companion reports: $n = 150$ flowers,
$p = 4$ measurements $x_i \in \mathbb{R}^4$, and $y_i \in \{1, \dots, K\}$,
$K = 3$, labeling one of the three species.

** Additive modeling and functional gradient descent

Rather than fitting one model once (LDA, SVM) or averaging many
/independent/ models (the random forest companion report), gradient
boosting builds one model as a running sum,
$F_k(x) = \sum_{m=1}^{M} \eta \, f_{m,k}(x)$, adding one new shallow tree
$f_{m,k}$ per round $m$ per class $k$, and never revisiting a tree once
fit. Each new tree is chosen to point the ensemble's predictions in the
direction that most reduces the training loss right now -- "gradient
descent," except each descent step is itself an entire regression tree
rather than a numeric update to a parameter vector (Friedman, 2001). This
is exactly why boosting rounds must run in order and why, unlike bagging,
tree $m+1$ genuinely depends on every tree fit before it.

** Multinomial deviance and pseudo-residuals

For $K$-class classification, =datamunge= maintains one running score
$F_k(x)$ per class and converts them to probabilities by softmax,
$p_k(x) = \exp(F_k(x)) / \sum_{j=1}^K \exp(F_j(x))$, and measures fit with
multinomial deviance (negative log-likelihood),
$L = -\sum_i \sum_k y_{ik} \log p_k(x_i)$, where $y_{ik}$ is 1 if flower
$i$ is class $k$ and 0 otherwise. The negative gradient of $L$ with
respect to $F_k(x_i)$ works out to exactly $y_{ik} - p_k(x_i)$ -- the
one-hot class indicator minus the model's /current/ predicted probability
-- which is precisely the =GBMClassifierPrediction=-adjacent quantity each
round's $K$ trees are fit to (one =DecisionTreeRegressor= per class,
regressing directly on this pseudo-residual). A flower the model is
already confident and correct about has a pseudo-residual near zero and
contributes almost nothing to the next round's trees; a flower the model
is getting badly wrong has a large pseudo-residual and dominates what the
next round learns.

** The additive update and the learning rate

After fitting round $m$'s $K$ trees, every class score updates as
$F_k(x) \leftarrow F_k(x) + \eta \, f_{m,k}(x)$, where
$\eta$ = =GBMClassifierOptions::learning_rate= (default 0.1) shrinks each
round's contribution before adding it in. A smaller $\eta$ means any one
round can only nudge the ensemble a little, so reaching a given training
deviance needs more rounds (=n_trees=) -- but that slower, more cautious
path is also usually the one that generalizes better, exactly the same
"more conservative now, better later" tradeoff the SVM companion report's
cost parameter and the random forest companion report's tree count both
embody in their own ways. §4.4 measures this directly by sweeping $\eta$
at a fixed =n_trees=.

** Stochastic subsampling

=GBMClassifierOptions::subsample= (default 1.0, unmodified in this
report's primary model) optionally fits each round's trees on a random
fraction of the training rows rather than all of them -- Friedman's (2002)
/stochastic/ gradient boosting. Like the random forest companion report's
bootstrap sampling, this adds randomness across rounds that can reduce
overfitting and speed up fitting; unlike bagging, it does not, by itself,
give a free out-of-bag accuracy estimate the way §2.4 of the random forest
report describes, since boosting's rounds are not independent draws in the
same sense.

** Monitoring convergence

Because each round is fit specifically to reduce the /current/ training
loss, =training_deviance()= -- one number per completed round -- should
fall monotonically on the training set as fitting proceeds, and
=plot_training_deviance()= draws exactly that curve. No other classifier
report in this project has an equivalent per-iteration convergence
diagnostic: LDA and SVM solve one optimization problem in a single step,
a lone decision tree is grown once, and a random forest's trees are
independent of each other rather than forming a sequence at all.

** Feature importance

As in the decision-tree and random-forest companion reports, every split
anywhere in every round's trees credits its impurity decrease to whichever
predictor it split on. Because each per-class model here is a
=DecisionTreeRegressor= fit to a continuous pseudo-residual rather than a
=DecisionTreeClassifier= fit to a class label, the relevant impurity is
SSE (sum of squared errors) reduction rather than Gini or entropy;
=feature_importance()= averages that credit across every tree in every
round and renormalizes to sum to 1.

** Prediction

A new point's final class scores $F_k(x)$ after all $M$ rounds are
converted to probabilities by the same softmax used during fitting, given
directly in =predict_detail()='s =probability= field. This is a fifth
distinct notion of "confidence" across this project's classifier reports
-- smoothly valued like LDA's Bayes posterior, but built from an additive
ensemble of trees rather than a Gaussian model, and unlike a single
decision tree's leaf-frequency probabilities, not constrained to whatever
fractions happen to be achievable at one particular leaf.

** What we will report

Given the fit, we report the forest's own summary (feature importance,
training accuracy, and the deviance trajectory), a confusion matrix, a
classification plot marking misclassified points directly, the training
deviance curve itself, a sweep over the learning rate, and -- reduced to
two predictors purely for visualization, the same caveat every companion
report makes about its own 2-D view -- a side-by-side decision-region
comparison after 5 boosting rounds versus 100.

* Data and Methods

** The data

As in every companion report: =datamunge::datasets::iris()= returns
Fisher's 150 flowers -- 50 each of /setosa/, /versicolor/, /virginica/ --
measured on =Sepal.Length=, =Sepal.Width=, =Petal.Length=, =Petal.Width=
(cm), with no missing values.

** Software

The entire analysis is one C++ program against =datamunge=:
=dstruct::DataFrame= for the data, the formula-driven
=stats::GBMClassifier= for every model in this report (built internally
from =stats::DecisionTreeRegressor=), and =plot::RPlot=/=plot::RLayout=
for every figure -- including the deviance curve, classification plot, and
decision regions, which the classifier itself knows how to draw. No
external plotting or statistics package is used.

*** Learning-rate sensitivity

Refit at six learning rates spanning two orders of magnitude, holding
=n_trees= fixed at 100, tracking both final training deviance and training
accuracy.

#+name: gbm-lr-sensitivity
#+begin_src c++ :eval no
    {
        const std::vector<double> rates =
            {0.01, 0.05, 0.1, 0.3, 0.5, 1.0};
        std::vector<double> rate_x, accs, devs;
        std::cout << "\nLearning-rate sensitivity (n_trees=100):\n";
        std::cout << std::setw(10) << "rate" << std::setw(12) << "accuracy"
                   << std::setw(12) << "deviance\n";
        for (const double lr : rates) {
            GBMClassifierOptions opts;
            opts.learning_rate = lr;
            GBMClassifier m(iris, kFormula, opts);
            const double acc = m.training_accuracy() * 100.0;
            const double dev = m.training_deviance().back();
            rate_x.push_back(lr);
            accs.push_back(acc);
            devs.push_back(dev);
            std::cout << std::setw(10) << std::fixed << std::setprecision(2)
                       << lr << std::setw(11) << acc << "%"
                       << std::setw(12) << std::setprecision(4) << dev
                       << "\n";
        }
        auto acc_plot = RPlot::plot(rate_x, accs, "b", "accuracy",
                                     {37, 99, 235});
        acc_plot.title("Training Accuracy vs Learning Rate")
            .x_label("learning_rate").y_label("training accuracy (%)")
            .background({250, 250, 252});
        auto dev_plot2 = RPlot::plot(rate_x, devs, "b", "deviance",
                                      {220, 38, 38});
        dev_plot2.title("Final Deviance vs Learning Rate")
            .x_label("learning_rate").y_label("training deviance")
            .background({250, 250, 252});
        auto layout = RLayout::create(1, 2);
        layout.add(acc_plot);
        layout.add(dev_plot2);
        layout.save_svg("build/org/gbm_iris_lr_sensitivity.svg");
        std::cout << "wrote gbm_iris_lr_sensitivity.svg\n";
    }
#+end_src

a learning rate this large would more typically start overshooting rather
than simply converging faster.

Even the three unambiguous flowers get posteriors around 0.92-0.93 rather
than the near-exact 1.0000 the LDA, single-tree, and random-forest
companion reports all report for their own unambiguous cases -- a direct
consequence of softmax over finite, shrunk (=learning_rate= = 0.1) additive
scores never fully saturating to certainty the way a Bayes posterior or a
majority-vote fraction can. The fourth, deliberately ambiguous flower gets
87.73% /virginica/ against 9.64% /versicolor/ -- still confidently
/virginica/, but visibly less certain than the other three, exactly the
graded signal a genuinely ambiguous case should produce.

* Discussion

**Bagging versus boosting, directly.** This report and the random forest
companion report share a base learner (a shallow CART tree) and differ in
exactly one idea: fit many trees independently and average them (bagging),
or fit trees one at a time, each correcting the last (boosting). That
single difference explains nearly every contrast between the two reports:
the random forest's trees can be fit in any order or even in parallel,
while this report's cannot; the random forest gets a free, near-unbiased
accuracy estimate from out-of-bag rows, while this report has no
equivalent without deliberately holding out data; and the random forest's
feature importance is comparatively evenly spread by design (via
=max_features=), while this report's tracks even more closely with the
single decision tree's petal-dominated, near-zero-elsewhere pattern, since
nothing here restricts what any one round's trees can see.

**The missing safety net.** §4.2 raised this report's central limitation
directly: 100.00% training accuracy, with nothing in this configuration
comparable to the random forest's out-of-bag figure to check it against.
That is not a flaw specific to gradient boosting -- =subsample= < 1
(§2.5) could in principle support something similar -- but as configured
here (the library default, =subsample= = 1.0), this report's training
accuracy carries exactly the same resubstitution-optimism caveat the LDA,
SVM, and single-decision-tree companion reports all had to raise, and
which the random forest companion report was the only one able to
resolve with an actual number instead of a caveat.

**Five methods, one dataset.** Across all five reports in this project,
every method reaches somewhere in the 95-100% range on these 150 flowers
(LDA 98.00%, SVM 97.33%, one tree 97.33%, forest 95.33% out-of-bag, this
model's ungrounded 100.00%), and every method's errors -- where it has
verifiable held-out-style errors at all -- cluster in the exact same
/versicolor//virginica/ overlap. Five structurally different algorithms
converging on the same answer, and the same residual difficulty, is
itself evidence that this dataset's remaining uncertainty is a property of
the flowers, not of any one modeling choice.

* Conclusion

A 100-round multinomial gradient boosting classifier, fit with
=datamunge='s C++ =stats::GBMClassifier=, drives training multinomial
deviance down by a factor of 11.5 over its 100 rounds and reaches perfect
training accuracy on Fisher's three iris species, with feature importance
once again dominated by petal measurements. A learning-rate sweep shows
faster convergence at higher $\eta$ with no instability on this
particular (small, clean) dataset, and a direct 5-rounds-versus-100
comparison shows boosting's defining incremental refinement, even though
most of the improvement had already happened by round 5. Read against the
random forest companion report, this report's real contribution is
showing what bagging and boosting share (the same tree base learner, both
outperforming a single tree) and where they genuinely differ (parallel and
self-validating versus sequential and, as configured here, without a
built-in check on its own confident training accuracy). As with its
companions, this entire report is reproducible end to end via
=just org-example gbm_iris_analysis=, which re-executes §3.3.9's assembly
block -- and therefore every number and figure above -- from the
=datamunge= source tree.
