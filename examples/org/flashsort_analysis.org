#+begin_abstract
Comparison sorts need \(\Omega(n\log n)\); *distribution* sorts sidestep the bound by using the values
themselves as addresses. Flashsort (Neubert, 1998) classifies each element into one of \(m\approx
0.43\,n\) buckets by a linear map of its value, permutes the array into bucket order in place, and
finishes with a short insertion sort. On uniformly distributed data it runs in *linear* expected time
with negligible extra memory. This report drives =datamunge='s =algorithms::flashsort=, verified
against =std::sort= over thousands of random arrays (integers and doubles), and shows the bucket
distribution it builds.
#+end_abstract

* Classify, permute in place, then insertion sort

Find the minimum and maximum, and choose \(m\) classes. Map a value \(v\) to a class by a linear
interpolation between the extremes:

\[ k(v)=\Big\lfloor (m-1)\,\frac{v-\min}{\max-\min}\Big\rfloor\in\{0,\dots,m-1\}. \]

Count how many elements fall in each class and take a prefix sum, so class \(k\) owns a known
contiguous range of the array. Then *permute in place*: follow cycle leaders, repeatedly taking an
out-of-place element and swapping it into the current end of its class's range, until every element
sits inside its class. Because elements are now grouped by value into small, ordered ranges, a final
*insertion sort* -- cheap since each element is close to its final position -- completes the order. The
expected cost is \(O(n)\) when the data is roughly uniform (each class gets \(O(1)\) elements); a
skewed distribution enlarges some classes and pushes the insertion-sort tail toward \(O(n^2)\), the
price of the distribution assumption.

* Algorithm

#+begin_example
FLASHSORT(a):
  find min and max; choose m ~ 0.43 n classes
  k(v) = floor((m-1) (v-min)/(max-min))
  count class sizes; prefix-sum into range boundaries L[]
  permute in place: cycle out-of-place elements into their class range
  insertion-sort the (now nearly-ordered) array
#+end_example

* Worked example: sorting, and the bucket distribution

We sort a scrambled array, then classify a uniform sample into buckets and plot the class sizes -- flat
for uniform data, which is when Flashsort runs in linear time.

#+name: fl-run
#+begin_src c++ :eval no
    std::vector<int> a = {29, 4, 17, 88, 41, 6, 73, 50, 12, 95, 33, 61, 8, 24, 77};
    auto s = a; flashsort(s);
    std::cout << "=== flashsort ===\n";
    std::cout << "input:  "; for (int x : a) std::cout << x << " "; std::cout << "\n";
    std::cout << "sorted: "; for (int x : s) std::cout << x << " "; std::cout << "\n\n";

    // Bucket sizes for a uniform sample.
    std::mt19937_64 rng(11);
    std::uniform_int_distribution<int> d(0, 9999);
    const int n = 2000;
    std::vector<int> sample(n); for (auto& x : sample) x = d(rng);
    const int mn = *std::min_element(sample.begin(), sample.end());
    const int mx = *std::max_element(sample.begin(), sample.end());
    const int m = std::max(2, (int)(0.43 * n));
    const int nbars = 20; // aggregate the m classes into 20 display bins
    std::vector<double> counts(nbars, 0);
    for (int x : sample) { int bin = (int)((double)(nbars - 1) * (x - mn) / (double)(mx - mn)); counts[bin]++; }
    std::cout << "classes m = " << m << "; showing " << nbars << " aggregated bins\n";
    std::vector<std::string> labels; for (int i = 0; i < nbars; ++i) labels.push_back(std::to_string(i));

    flashsort(sample);
    std::cout << "sorted 2000 uniform samples: " << (std::is_sorted(sample.begin(), sample.end()) ? "ok" : "FAIL") << "\n";

    auto plot = RPlot::barplot(counts, labels, "count", RGB{234, 88, 12});
    plot.title("Flashsort class distribution for uniform data (roughly flat)")
        .x_label("value bin").y_label("elements").background({250, 250, 252});
    plot.save_svg("build/org/flashsort.svg");
    std::cout << "wrote flashsort.svg\n";
#+end_src

* Results

#+begin_example
=== flashsort ===
input:  29 4 17 88 41 6 73 50 12 95 33 61 8 24 77
sorted: 4 6 8 12 17 24 29 33 41 50 61 73 77 88 95

classes m = 860; showing 20 aggregated bins
sorted 2000 uniform samples: ok
wrote flashsort.svg
#+end_example

Flashsort produces a correctly sorted array -- matching =std::sort= across the test suite for both
integers and doubles -- by classifying values into buckets rather than comparing them. For the uniform
sample the class sizes are roughly equal, the balanced distribution that gives the linear-time
behaviour.

The bars are near-uniform in height: uniform input spreads evenly across the value classes, so each
class holds only a handful of elements and the finishing insertion sort has almost nothing to do. That
even spread is exactly the condition under which Flashsort beats \(O(n\log n)\) -- and a lopsided,
clustered distribution is exactly when it does not.
