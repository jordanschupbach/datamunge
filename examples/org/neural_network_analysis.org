#+begin_abstract
We implement a feed-forward neural network -- a multi-layer perceptron
(MLP) -- trained by backpropagation with mini-batch stochastic gradient
descent, in =datamunge='s C++ =stats::MLPClassifier=, and report it as a
literate program: every fragment below is a real, compiled, executed chunk
of the single C++ binary that produced every number and figure in this
document. A neural network stacks simple units -- each an affine map
followed by a nonlinearity -- so that hidden layers /learn features/ that
render a problem linearly separable, letting the network fit decision
boundaries no linear model can express. We demonstrate this on the
canonical case that motivated the field: XOR, where a linear classifier is
provably stuck -- here converging to exactly the chance floor, a training
accuracy of 0.4983 at a cross-entropy of 0.6931 (which is \(\ln 2\) to four
decimals, the loss of uniform guessing) -- while adding a single hidden
layer of eight units drives training accuracy to 1.0000 at a loss of
0.0108. On two interleaving half-moons, a linear classifier reaches only
89.33% test accuracy with its straight boundary, while a two-hidden-layer
network (354 parameters) learns a curved boundary and classifies the held-
out set perfectly. A capacity sweep shows the decisive jump is from /zero/
hidden layers to /one/ (89.33% to 100%), not from small to large -- even
four hidden units suffice, while sixteenfold more parameters add nothing
on this task. The training loss curve falls smoothly from 0.62 toward zero,
the visible trace of gradient descent at work. On real iris data the
network classifies species from two petal measurements at 91.11% held-out
accuracy. Throughout, the same class with an /empty/ hidden-layer list
reduces exactly to multinomial logistic regression, making "a neural
network is a stack of logistic regressions with learned features between
them" concrete rather than metaphorical. We derive the forward pass, the
softmax/cross-entropy objective, the backpropagation gradient, the
mini-batch SGD update, and the linear special case, tying each to the
corresponding library call.

* Introduction

Every classifier in this project so far draws its decision boundary in a
fixed way: [[file:glm_iris_analysis.org][logistic regression]] and a
linear [[file:svm_iris_analysis.org][SVM]] draw straight lines, the
[[file:kernel_pca_iris_analysis.org][kernel]] methods draw curves fixed in
advance by the choice of kernel, and [[file:dt_iris_analysis.org][decision
trees]] draw axis-aligned steps. A feed-forward neural network is
different in kind: it /learns/ the shape of its own boundary from the data,
by learning intermediate features. This is what lets it solve problems
that defeat every linear method -- most famously XOR, four points arranged
so that no straight line can separate the two classes, the example whose
apparent impossibility for a single-layer "perceptron" stalled the field
for a decade until backpropagation through /hidden/ layers resolved it.

The mechanism is a stack of simple layers. Each layer takes the previous
layer's output, applies an affine map (a matrix of weights plus a bias),
and passes the result through a nonlinear activation function. A single
such layer is just linear regression or logistic regression; but /composed/,
with nonlinearities between them, the layers build up increasingly
expressive features, and a network with even one hidden layer can
approximate any continuous function. The weights are learned by gradient
descent, with the gradient computed efficiently by /backpropagation/ -- the
chain rule applied layer by layer from the output back to the input. This
report builds that machinery from scratch and shows it working.

As with its companions, this document is a /literate program/: prose and
source are interleaved in reading order, and a single "assembling the
program" step (§3.5.8) weaves every named chunk below into one =.cpp= file,
compiles it, and runs it. Every number and figure from §4 onward is that
program's literal output.

§2 derives the feed-forward architecture, the softmax/cross-entropy
objective, why hidden layers overcome linear inseparability,
backpropagation, the SGD training loop, and the linear special case -- each
tied to the specific piece of =MLPClassifier= that implements it. §3
describes the program chunk by chunk. §4 reports the XOR capacity result,
the two-moons boundary with its figures, the training loss curve, a
capacity sweep, and a real-data iris fit. §5 discusses what neural networks
buy and what they cost. §6 concludes.

* Background: Feed-Forward Neural Networks

** Setup and notation

We observe \(n\) labeled examples with predictors \(x_i \in \mathbb{R}^p\)
and a categorical response in one of \(K\) classes. =MLPClassifier= takes
them through the same formula interface as the other classifiers
(=MLPClassifier(data, "Species ~ Petal.Length + Petal.Width")=) and
standardizes the predictors. The network is a sequence of /layers/ of
widths \(p = n_0, n_1, \ldots, n_{L} = K\), where the \(n_1, \ldots,
n_{L-1}\) are the hidden layers (=MLPClassifierOptions::hidden_layer_sizes=).

** The feed-forward architecture

Writing \(a^{(0)} = x\) for the (standardized) input, each layer \(l = 1,
\ldots, L\) computes an affine map followed by an elementwise nonlinearity:

\[
z^{(l)} = W^{(l)} a^{(l-1)} + b^{(l)}, \qquad
a^{(l)} = \sigma\!\bigl(z^{(l)}\bigr),
\]

with weight matrix \(W^{(l)} \in \mathbb{R}^{n_l \times n_{l-1}}\) and bias
\(b^{(l)} \in \mathbb{R}^{n_l}\) (=weights_= and =biases_= in the source).
The hidden activation \(\sigma\) is =MLPClassifierOptions::activation=, one
of

\[
\sigma_{\text{relu}}(z) = \max(0, z), \quad
\sigma_{\text{tanh}}(z) = \tanh z, \quad
\sigma_{\text{sigmoid}}(z) = \frac{1}{1 + e^{-z}} ,
\]

and =architecture()= reports the full width sequence, =n_parameters()= the
total count of weights and biases. Composing affine maps through these
nonlinearities is what gives the network its expressive power: without
\(\sigma\), a stack of affine maps would collapse into a single affine map,
and the network could do no more than a linear model.

** The softmax output and cross-entropy loss

The final layer produces one score per class, converted to a probability
distribution by the /softmax/,

\[
\hat{p}_k = \frac{e^{z^{(L)}_k}}{\sum_{j=1}^{K} e^{z^{(L)}_j}} ,
\]

and the network is trained to minimize the /cross-entropy/ between these
predicted probabilities and the true one-hot labels,

\[
\mathcal{L} = -\frac{1}{n}\sum_{i=1}^{n} \log \hat{p}_{i, y_i} ,
\]

the negative log-likelihood of the correct class. This is exactly the
multinomial logistic loss, now applied on top of the learned features
\(a^{(L-1)}\) rather than the raw inputs. =loss_curve()= records this
quantity after each epoch; a network guessing uniformly scores \(\ln K\)
(for two classes, \(\ln 2 \approx 0.6931\)), the floor §4.1 finds a linear
model stuck at on XOR.

** Why hidden layers: nonlinear separability

A linear classifier partitions the input space with a single hyperplane,
so it can only solve problems that are /linearly separable/. XOR is the
minimal counterexample: with classes at the corners \((0,0), (1,1)\) versus
\((0,1), (1,0)\), no straight line separates them, and both classes share
the same centroid, so a linear model has literally no usable direction --
its best is to guess, scoring \(\ln 2\). A hidden layer removes this
ceiling by first mapping the inputs into a new feature space in which the
classes /become/ linearly separable; the output layer then draws its
hyperplane there, which pulls back to a curved boundary in the original
space. The universal approximation theorem (Cybenko 1989; Hornik 1991)
makes the general statement: a network with a single sufficiently wide
hidden layer can approximate any continuous function to arbitrary accuracy.
§4.1 and §4.2 exhibit both the failure of the linear model and the success
of the hidden-layer network directly.

** Backpropagation: computing the gradient

Training needs the gradient of \(\mathcal{L}\) with respect to every weight
and bias. Backpropagation computes it by the chain rule, sweeping backward
from the output. The softmax-with-cross-entropy output has an especially
clean gradient: the error signal at the output layer is simply the
predicted minus the true distribution,

\[
\delta^{(L)} = \hat{p} - \mathbf{1}_{y} ,
\]

and it propagates to earlier layers through the transposed weights and the
activation's derivative,

\[
\delta^{(l)} = \bigl(W^{(l+1)\top} \delta^{(l+1)}\bigr) \odot
   \sigma'\!\bigl(z^{(l)}\bigr) ,
\]

where \(\odot\) is elementwise multiplication. Each layer's parameter
gradients then follow immediately from its own error signal and input,

\[
\frac{\partial \mathcal{L}}{\partial W^{(l)}} = \delta^{(l)}
   \, a^{(l-1)\top}, \qquad
\frac{\partial \mathcal{L}}{\partial b^{(l)}} = \delta^{(l)} .
\]

=MLPClassifier::fit= implements exactly this recursion: a forward pass
caches every \(z^{(l)}\) and \(a^{(l)}\), then a backward pass accumulates
these gradients over a mini-batch. The efficiency of reusing the cached
forward quantities -- rather than perturbing each weight numerically -- is
what makes training large networks feasible at all.

** Training: mini-batch stochastic gradient descent

The parameters are updated by gradient descent on mini-batches of the data.
For each batch, =fit= averages the backpropagated gradients and steps every
parameter downhill,

\[
W^{(l)} \leftarrow W^{(l)} - \eta \Bigl( \overline{\nabla_{W^{(l)}}
   \mathcal{L}} + \lambda\, W^{(l)} \Bigr) ,
\]

with learning rate \(\eta\) (=learning_rate=), an optional \(L_2\) weight
penalty \(\lambda\) (=l2=), and =batch_size= examples per step (0 meaning
full-batch). One pass over all the data is an /epoch/, repeated
=max_epochs= times, with the data reshuffled each epoch. Weights are
initialized randomly -- He-scaled for ReLU, Xavier-scaled otherwise, from
=seed= -- since starting them all equal would keep every unit in a layer
identical forever. The whole procedure is deterministic given the seed.

** The linear special case

With =hidden_layer_sizes= empty there are no hidden layers at all: the
network is just \(\hat{p} = \operatorname{softmax}(W x + b)\), which /is/
multinomial logistic regression. So the MLP contains the linear classifier
as its degenerate zero-hidden-layer case, and comparing the two (as §4.1,
§4.2 and §4.4 do) isolates exactly what the hidden layers contribute:
nothing about the code path changes except whether learned features sit
between the input and the softmax.

** What we will report

Given the fits, we report the XOR capacity gap between a linear model and a
hidden-layer network, the two-moons boundary with linear-versus-MLP
decision-region figures and held-out accuracies, the training loss curve, a
network-capacity sweep, and a real-data iris classification with its
confusion matrix and decision regions.

* Data and Methods

** XOR

The canonical non-linearly-separable problem: 150 points jittered around
each of the four corners \((0,0), (0,1), (1,0), (1,1)\), labeled by parity
(the two "even" corners one class, the two "odd" corners the other). Since
XOR is about /representational capacity/ -- can the model fit the pattern
at all? -- we train on the full, class-balanced dataset with full-batch
gradient descent and report training accuracy, the honest measure of
whether the boundary can even be drawn.

** Two interleaving moons

A harder, more realistic nonlinear problem: two half-circles ("moons")
offset and interleaved so their boundary is a smooth curve, 250 points per
moon with Gaussian noise. Here generalization matters, so we split 70/30
into training and held-out test sets and report test accuracy, plus the
decision-region figures that show the boundary each model draws.

** The iris data

=datamunge::datasets::iris()= supplies Fisher's 150 flowers; we classify
=Species= from =Petal.Length= and =Petal.Width= (two predictors, so the
decision regions can be drawn), again on a 70/30 train/test split.

** Software

The entire analysis is one C++ program against =datamunge=:
=dstruct::DataFrame= for the data, =stats::MLPClassifier= for the model,
and =plot::RPlot= for every figure. No external machine-learning package is
used.

// Build a two-column-plus-label DataFrame.
static DataFrame make_df(const std::vector<double>& x, const std::vector<double>& y,
                         const std::vector<std::string>& label) {
    DataFrame d;
    d.add_column("x", x);
    d.add_column("y", y);
    d.add_column("class", label);
    return d;
}

// Shuffle indices (seeded) and split rows into train/test DataFrames.
static void split(const std::vector<double>& x, const std::vector<double>& y, const std::vector<std::string>& label,
                  double train_frac, unsigned seed, DataFrame& train, DataFrame& test) {
    const std::size_t n = x.size();
    std::vector<std::size_t> idx(n);
    std::iota(idx.begin(), idx.end(), 0);
    std::mt19937_64 rng(seed);
    std::shuffle(idx.begin(), idx.end(), rng);
    const std::size_t n_train = static_cast<std::size_t>(train_frac * n);
    std::vector<double> xtr, ytr, xte, yte;
    std::vector<std::string> ltr, lte;
    for (std::size_t i = 0; i < n; ++i) {
        if (i < n_train) { xtr.push_back(x[idx[i]]); ytr.push_back(y[idx[i]]); ltr.push_back(label[idx[i]]); }
        else            { xte.push_back(x[idx[i]]); yte.push_back(y[idx[i]]); lte.push_back(label[idx[i]]); }
    }
    train = make_df(xtr, ytr, ltr);
    test  = make_df(xte, yte, lte);
}

#+begin_src c++ :eval no
    std::cout << "=== XOR: the problem a linear classifier cannot solve ===\n";
    // XOR is about representational capacity, not generalization -- can the model even FIT the
    // pattern? -- so we report training accuracy on the full, class-balanced dataset (150 points at
    // each of the four corners), with full-batch gradient descent for a deterministic answer.
    {
        const std::size_t per = 150;
        std::mt19937_64 rng(1);
        std::normal_distribution<double> jitter(0.0, 0.12);
        std::vector<double> x, y;
        std::vector<std::string> label;
        const int corners[4][2] = {{0, 0}, {0, 1}, {1, 0}, {1, 1}};
        for (auto& c : corners)
            for (std::size_t i = 0; i < per; ++i) {
                x.push_back(c[0] + jitter(rng));
                y.push_back(c[1] + jitter(rng));
                label.push_back((c[0] ^ c[1]) ? "B" : "A");  // XOR
            }
        DataFrame xor_data = make_df(x, y, label);
        MLPClassifier linear(xor_data, "class ~ x + y", MLPClassifierOptions{{}, "tanh", 0.1, 800, 0, 0.0, 7});
        MLPClassifier mlp(xor_data, "class ~ x + y", MLPClassifierOptions{{8}, "tanh", 0.1, 800, 0, 0.0, 7});
        std::cout << "linear (no hidden layer): training accuracy " << linear.training_accuracy()
                  << ", final loss " << linear.loss_curve().back() << " (ln 2 = " << std::log(2.0)
                  << ", the no-signal floor)\n";
        std::cout << "MLP (one hidden layer of 8): training accuracy " << mlp.training_accuracy()
                  << ", final loss " << mlp.loss_curve().back() << "\n";
    }

* Results

** XOR: one hidden layer breaks the linear ceiling

#+begin_example
linear (no hidden layer): training accuracy 0.4983, final loss 0.6931 (ln 2 = 0.6931, the no-signal floor)
MLP (one hidden layer of 8): training accuracy 1.0000, final loss 0.0108
#+end_example

This is the whole argument for hidden layers in two lines. The linear model
-- the network with no hidden layer, i.e. plain multinomial logistic
regression (§2.7) -- cannot fit XOR at all: it converges to a training
accuracy of 0.4983 (a coin flip) at a cross-entropy of 0.6931, which is
\(\ln 2\) to four decimals -- /exactly/ the loss of predicting 50/50 on
every point, the provable floor for a model with no usable linear
direction (§2.4). Inserting a single hidden layer of eight units changes
the story completely: training accuracy 1.0000, loss 0.0108. The hidden
units learn a feature representation in which the four XOR clusters become
linearly separable, and the output layer then trivially separates them --
the failure that once seemed to doom neural networks, resolved by the one
architectural change backpropagation made trainable.

** How much network is enough?

#+begin_example
architecture                params  test accuracy
none (linear)                    6          0.8933
one hidden: 4                   22          1.0000
one hidden: 16                  82          1.0000
two hidden: 16,16              354          1.0000
two hidden: 64,64             4482          1.0000
#+end_example

The capacity sweep locates where the value actually is: the decisive jump
is from /zero/ hidden layers to /one/ (0.8933 to 1.0000), not from a small
network to a large one. A single hidden layer of just four units -- 22
parameters -- already classifies the moons perfectly, and multiplying the
parameter count more than two-hundred-fold (to the 4482 of a 64-64 network)
adds exactly nothing on this task. The lesson is the practical counterpart
of the universal approximation theorem (§2.4): what matters first is
/having/ a hidden layer at all, so the model can bend; how big it needs to
be is a secondary, problem-dependent question, and bigger is not
automatically better.

* Discussion

**Hidden layers learn features; that is the whole idea.** §4.1 is the
thesis in miniature: a linear model on XOR is not merely worse than a
network, it is at the /chance floor/ (\(\ln 2\)), because the problem has no
linear signal to find -- and one hidden layer takes it to perfect. The
hidden units do not draw the final boundary; they learn a new coordinate
system in which the old, impossible problem becomes linearly separable, and
the output layer -- an ordinary logistic regression (§2.7) -- finishes the
job there. Everything a neural network does beyond a linear model is this
one idea, applied in stack.

**Depth and width are means, not ends.** §4.4 is a useful corrective to the
instinct that more network is better. On the moons, the entire gain came
from the /first/ hidden layer; four units sufficed, and 4482 parameters did
no better than 22. Real problems demand more capacity than this toy one
does, but the principle holds: capacity should be matched to the problem,
and the sharp, reliable win is qualitative (linear to nonlinear), not the
marginal returns of ever-larger models -- which, past the point of fitting
the data, buy only a greater risk of overfitting and a larger training
bill.

**Backpropagation is what makes it practical.** The forward pass (§2.2) and
the loss (§2.3) define /what/ the network computes, but it is
backpropagation (§2.5) that makes learning feasible: by reusing cached
forward quantities and sweeping the chain rule backward once, it computes
the gradient of every one of the (here up to 4482) parameters in a single
pass, rather than perturbing each in turn. This report's networks train in
a blink because of it; the same algorithm, unchanged in essence, is what
trains models a billion times larger. The MLP here is deliberately small
and transparent, but it is the genuine article -- affine layers,
nonlinearities, softmax, cross-entropy, and backpropagation -- and every
number above came from that machinery running end to end.

* Conclusion

Implementing a feed-forward neural network in =datamunge='s C++
=stats::MLPClassifier= and training it by backpropagation, we reproduce the
result that founded the field: on XOR a linear model sits exactly at the
chance floor (training accuracy 0.4983, cross-entropy 0.6931 = \(\ln 2\)),
while a single eight-unit hidden layer reaches 1.0000. On two interleaving
moons the network learns a curved decision boundary a linear model cannot,
lifting held-out accuracy from 89.33% to 100%, and a capacity sweep shows
the decisive step is from zero hidden layers to one -- four hidden units
suffice, and two-hundred-fold more parameters add nothing. The training
loss falls smoothly toward zero as gradient descent proceeds, and on real
iris data the network classifies species at 91.11% held-out accuracy, its
only errors on the two species every method in this project finds
overlapping. With an empty hidden-layer list the same class is exactly
multinomial logistic regression, making precise what the hidden layers add.

=just org-example neural_network_analysis=, which re-executes §3.5.8's
assembly block -- and therefore every number and figure above -- from the
=datamunge= source tree.
