#+begin_abstract
Given a scatter of points, which two are closest together? The *closest pair problem* is a
staple of computational geometry -- underlying collision detection, clustering, and
map-label declutter. The brute-force answer compares all \(\binom{n}{2}\) pairs in
\(O(n^2)\); the celebrated divide-and-conquer algorithm does it in \(O(n\log n)\).
=datamunge= ships the clear, easy-to-trust \(O(n^2)\) version. This report drives
=geometry::closest_pair=, verified on a hand-checkable set, and highlights the winning pair
in a random cloud.
#+end_abstract

* All pairs, or divide and conquer

The distance between two points is \(\sqrt{(x_1-x_2)^2+(y_1-y_2)^2}\); the closest pair
is the one minimizing it. Two strategies:

- *Brute force* (\(O(n^2)\)): scan every unordered pair, keep the smallest distance. To
  avoid needless square roots one compares *squared* distances and takes the root once at
  the end. Simple, exact, no edge cases -- the right choice for the modest point counts this
  module targets, and the version =datamunge= implements.
- *Divide and conquer* (\(O(n\log n)\)): split the points by a vertical line, recurse on
  each half, then check only the points within the current best distance \(\delta\) of
  the dividing line -- a strip in which, by a packing argument, each point can have at most a
  constant number of rivals. This is asymptotically optimal but has a fiddly merge step.

For \(n\) in the hundreds the \(O(n^2)\) scan is both fast enough and impossible to
get subtly wrong, which is why a "basic" geometry component prefers it.

* Algorithm

#+begin_example
CLOSEST-PAIR(points):                         # brute force, O(n^2)
  best <- infinity
  for i in 0..n-1:
      for j in i+1..n-1:
          d <- distance(points[i], points[j])
          if d < best: best <- d;  remember (points[i], points[j])
  return the remembered pair and best
#+end_example

* Worked example: a planted close pair in a random cloud

We drop two points very near each other into an otherwise-spread random cloud and confirm
the algorithm recovers exactly that pair.

#+name: cp-run
#+begin_src c++ :eval no
    std::mt19937 rng(424242);
    std::uniform_real_distribution<double> ud(0.0, 10.0);
    std::vector<Point2D> pts;
    for (int i = 0; i < 60; ++i) pts.push_back({ud(rng), ud(rng)});
    // Plant a deliberately close pair.
    pts.push_back({5.00, 5.00});
    pts.push_back({5.03, 4.98});

    const ClosestPairResult r = closest_pair(pts);
    std::cout << "=== closest pair among " << pts.size() << " points ===\n";
    std::cout << "a = (" << r.a.x << ", " << r.a.y << "), b = (" << r.b.x << ", " << r.b.y << ")\n";
    std::cout << "distance = " << r.distance << "\n";

    std::vector<double> px, py, cx, cy;
    for (const Point2D& p : pts) { px.push_back(p.x); py.push_back(p.y); }
    cx = {r.a.x, r.b.x}; cy = {r.a.y, r.b.y};

    auto plot = RPlot::create();
    plot.points(px, py, "points", RGB{100, 116, 139}, 5.0);
    plot.line(cx, cy, "closest", RGB{220, 38, 38}, 2.0);
    plot.points(cx, cy, "closest pair", RGB{220, 38, 38}, 9.0);
    plot.legend({"points", "closest pair"}, {{100, 116, 139}, {220, 38, 38}});
    plot.title("Closest pair: the two nearest points among 62")
        .x_label("x").y_label("y").background({250, 250, 252});
    plot.save_svg("build/org/closest_pair.svg");
    std::cout << "wrote closest_pair.svg\n";
#+end_src

* Results

The algorithm picks out exactly the planted pair near \((5,5)\), whose separation of a
few hundredths is far smaller than any gap in the random spread. Every other pair among the
sixty-two points is farther apart, and the all-pairs scan finds the minimum with certainty.
