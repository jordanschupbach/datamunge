#+begin_abstract
The oldest way to factor an integer is also the most obvious: try dividing by \(2\), then
\(3\), then \(5\), and so on, peeling off each prime factor as you find it. *Trial
division* needs no cleverness and always works, but its cost grows like \(\sqrt{n}\) -- fine
for small numbers or for stripping the small factors off a big one before a sharper method
takes over, hopeless for the large semiprimes cryptography relies on. This report drives
=datamunge='s =algorithms::trial_division_factorize=, verified to reproduce known
factorizations, and measures its \(\sqrt{n}\) effort.
#+end_abstract

* Divide, divide out, repeat

To factor \(n\): while \(2\) divides \(n\), record \(2\) and halve; then try odd
candidates \(d=3,5,7,\dots\). Whenever \(d\mid n\), record \(d\) and divide it out
(with full multiplicity) before moving on -- so each recorded factor is automatically *prime*,
since any composite candidate's prime parts were already removed. The loop can stop once
\(d^2>n\): whatever remains above \(\sqrt{n}\) has no divisor \(\le\sqrt{n}\) and is
itself prime. Hence the work is \(O(\sqrt{n})\) in the worst case (a prime, or a semiprime
whose smaller factor is near \(\sqrt{n}\)). That square-root wall is why trial division is a
*preprocessing* step -- clearing out small factors -- rather than a general factorer.

* Algorithm

#+begin_example
TRIAL-DIVISION(n):
  while n even: record 2; n <- n/2
  for d = 3, 5, 7, ... while d*d <= n:
      while d divides n: record d; n <- n/d
  if n > 1: record n            # the remaining prime
  return the recorded factors
#+end_example

* Worked example: factorizations, and the sqrt(n) cost

We factor a few integers by hand-check, then count the trial divisors tested to factor
semiprimes of growing size (worst case for trial division).

#+name: td-run
#+begin_src c++ :eval no
    for (std::uint64_t n : {360ULL, 1001ULL, 2027ULL, 1000000007ULL}) {
        std::cout << n << " = ";
        const auto f = trial_division_factorize(n);
        for (std::size_t i = 0; i < f.size(); ++i) std::cout << (i ? " x " : "") << f[i];
        if (f.size() == 1) std::cout << " (prime)";
        std::cout << "\n";
    }
    std::cout << "\n";

    // Instrumented divisor count for semiprimes p*q with p ~ q ~ sqrt(n).
    auto count_divisions = [](std::uint64_t n) {
        long long steps = 0;
        while (n % 2 == 0) { ++steps; n /= 2; }
        for (std::uint64_t d = 3; d * d <= n; d += 2) { ++steps; while (n % d == 0) n /= d; }
        return steps;
    };

    std::cout << "semiprime          sqrt(n)      trial divisors\n";
    std::vector<double> sq, steps;
    const std::uint64_t primes[] = {101, 331, 1009, 3167, 10007, 31627, 100003};
    for (std::uint64_t p : primes) {
        const std::uint64_t n = p * p; // worst case: factor near sqrt(n)
        const long long s = count_divisions(n);
        sq.push_back(std::sqrt(static_cast<double>(n)));
        steps.push_back(static_cast<double>(s));
        std::printf("%-18llu %-12.0f %lld\n", (unsigned long long)n, std::sqrt((double)n), s);
    }

    auto plot = RPlot::create();
    plot.line(sq, steps, "steps", RGB{37, 99, 235}, 2.0);
    plot.points(sq, steps, "steps", RGB{37, 99, 235}, 6.0);
    plot.legend({"trial divisors tested"}, {{37, 99, 235}});
    plot.title("Trial division cost grows linearly with sqrt(n)")
        .x_label("sqrt(n)").y_label("divisor candidates tested").background({250, 250, 252});
    plot.save_svg("build/org/trial_division.svg");
    std::cout << "\nwrote trial_division.svg\n";
#+end_src

Each number is factored correctly into primes -- \(360=2^3\cdot3^2\cdot5\), the
ten-digit \(1000000007\) confirmed prime -- and the divisor-count table shows the cost
tracking \(\sqrt{n}\): the number of candidates tested to factor \(p^2\) is essentially
\(p/2=\tfrac12\sqrt{n}\) (only odd \(d\) are tried after the factor of two).

The step count is a straight line against \(\sqrt{n}\) -- linear, confirming the
\(O(\sqrt{n})\) worst case. Since \(\sqrt{n}\) still doubles in bits for every two bits
added to \(n\), this line becomes an exponential wall in the *number of digits*: exactly
why factoring hard semiprimes needs the subexponential methods in the companion reports.
