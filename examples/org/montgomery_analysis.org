#+begin_abstract
Public-key cryptography does *millions* of modular multiplications under one fixed modulus, and
the @c mod operation -- a hardware division -- is the bottleneck. *Montgomery reduction*
(Peter Montgomery, 1985) removes it. By representing numbers in a scaled "Montgomery domain"
(everything times \(R=2^{64}\bmod n\)), it reduces a product using only *multiplies, adds, and
a shift by \(R\)* -- no division by \(n\) at all. This report drives =datamunge='s
=algorithms::montgomery_multiply=, verified to reproduce ordinary modular multiplication over
hundreds of thousands of cases, and uses it to run a toy RSA round-trip.
#+end_abstract

* REDC: reduce with a shift, not a divide

Choose \(R=2^{64}\) (coprime to the odd modulus \(n\)). *Montgomery reduction* @c REDC(T)
computes \(T R^{-1}\bmod n\) for \(T<nR\) as

#+begin_example
m <- (T mod R) * n' mod R        # n' = -n^{-1} mod R, precomputed once
t <- (T + m*n) / R               # exact: T + m*n is divisible by R, so this is a shift
if t >= n: t <- t - n
#+end_example

Every operation is a multiply, an add, or a shift by \(R\) (a free truncation of the low 64
bits) -- the division by \(n\) has vanished. To multiply \(a\cdot b\bmod n\), transform into
the domain (\(\bar a = aR\bmod n\)) and Montgomery-multiply; @c montgomery_multiply here does
both transforms so it returns the ordinary \(a\cdot b\bmod n\). The precomputations
(\(n'=-n^{-1}\bmod R\) via a Newton iteration mod \(2^k\), and \(R^2\bmod n\)) are done once per
modulus, after which each modular multiply is division-free -- the reason every fast RSA/ECC
implementation runs in Montgomery form.

* Algorithm

#+begin_example
MONTGOMERY-MULTIPLY(a, b, n):        # n odd, R = 2^64
  n'  <- -n^{-1} mod R              (Newton's iteration, once per modulus)
  R2  <- R^2 mod n                  (once per modulus)
  aR  <- REDC(a * R2)              # a in Montgomery domain
  return REDC(aR * b)              # = a*b mod n, no division by n
#+end_example

* Worked example: correctness, and a toy RSA round-trip

We confirm Montgomery multiplication matches ordinary modular multiplication, then use it as the
multiply inside modular exponentiation to encrypt and decrypt with a toy RSA key.

#+name: mg-run
#+begin_src c++ :eval no
    // Montgomery modular exponentiation: same square-and-multiply, division-free multiply.
    auto mont_powmod = [](std::uint64_t base, std::uint64_t e, std::uint64_t n) {
        std::uint64_t r = 1 % n; base %= n;
        while (e) { if (e & 1) r = montgomery_multiply(r, base, n); base = montgomery_multiply(base, base, n); e >>= 1; }
        return r;
    };

    std::cout << "=== correctness spot checks ===\n";
    for (auto t : {std::tuple{123ULL, 456ULL, 1000003ULL}, std::tuple{9999ULL, 8888ULL, 100000007ULL}}) {
        const auto [a, b, n] = t;
        std::cout << a << "*" << b << " mod " << n << " = " << montgomery_multiply(a, b, n)
                  << " (naive " << (a * b) % n << ")\n";
    }

    // Toy RSA: p=61, q=53, n=3233, phi=3120, e=17, d=2753.
    const std::uint64_t n = 3233, e = 17, d = 2753, msg = 123;
    const std::uint64_t cipher = mont_powmod(msg, e, n);
    const std::uint64_t back   = mont_powmod(cipher, d, n);
    std::cout << "\n=== toy RSA (n=3233, e=17, d=2753) ===\n";
    std::cout << "message  m = " << msg << "\nencrypt  c = m^e mod n = " << cipher
              << "\ndecrypt  m = c^d mod n = " << back << "  (round-trip " << (back == msg ? "OK" : "FAIL") << ")\n";

    // Figure: primitive-op mix of one modular multiply -- Montgomery trades the divide for multiplies.
    auto plot = RPlot::barplot({1, 1, 3, 0}, {"naive: mul", "naive: DIV", "mont: mul", "mont: DIV"},
                               "ops", RGB{37, 99, 235});
    plot.title("Per modular multiply: naive needs a division, Montgomery needs none")
        .x_label("operation").y_label("count per modular multiply").background({250, 250, 252});
    plot.save_svg("build/org/montgomery.svg");
    std::cout << "\nwrote montgomery.svg\n";
#+end_src

Montgomery multiplication reproduces ordinary modular multiplication exactly, and dropped in as
the multiply inside exponentiation it encrypts \(123\) and decrypts it back to \(123\) -- a full
RSA round-trip with *no division by the modulus anywhere in the hot loop*. The precomputed
\(n'\) and \(R^2\) are the one-time price for that.

The bars make the trade concrete: a naive modular multiply pays for one 128-by-64-bit division
(red), the slowest integer operation on most CPUs; Montgomery spends a couple of extra
multiplies instead and *zero* divisions. Across the millions of multiplies in an RSA
exponentiation, replacing every division with multiplies is a large net win.
