#+begin_abstract
*Earliest-Deadline-First* (EDF) is the optimal single-processor scheduler for periodic
real-time tasks: at every instant it runs the ready job whose absolute deadline is nearest.
For tasks with implicit deadlines it meets every deadline *if and only if* the total
utilization \(U=\sum_i C_i/T_i\le 1\) -- it can use the processor fully, unlike fixed-priority
schemes. This report implements the utilization test and a preemptive timeline in
=datamunge='s C++ =algorithms::edf_simulate= as a literate program: every number and figure
comes from one compiled binary. We schedule three periodic tasks over their hyperperiod and
confirm no deadline is missed.
#+end_abstract

* Nearest deadline wins

Task \(\tau_i\) releases a job every \(T_i\) units needing \(C_i\) units of CPU, due by its
next release. EDF assigns each *job* a dynamic priority equal to its absolute deadline and
always runs the ready job with the smallest one, preempting as needed. Liu & Layland proved
EDF is optimal: if any scheduler can meet all deadlines, EDF does, and for implicit deadlines
this happens exactly when
\[
  U=\sum_i \frac{C_i}{T_i}\le 1.
\]
So EDF achieves 100% utilization -- its advantage over rate-monotonic, whose fixed priorities
cap guaranteed utilization at \(\approx 0.69\).

#include <datamunge/algorithms/realtime_scheduling.hpp>
#include <datamunge/plot/plot.hpp>

#include <cstddef>
#include <iostream>
#include <string>
#include <vector>

using namespace datamunge::algorithms;
using namespace datamunge::plot;

// Draw a real-time timeline: one row per task, a colored box per executed unit (idle skipped).
inline void draw_timeline(const RTScheduleResult& r, std::size_t ntask, const char* path) {
    static const RGB palette[] = {{37,99,235},{220,38,38},{22,163,74},{202,138,4},{147,51,234}};
    RPlot p = RPlot::create();
    for (const auto& s : r.timeline) {
        if (s.id == static_cast<std::size_t>(-1)) continue;  // idle
        double y = static_cast<double>(s.id);
        p.polygon({(double)s.start,(double)s.end,(double)s.end,(double)s.start},
                  {y-0.4, y-0.4, y+0.4, y+0.4}, palette[s.id % 5], true);
    }
    std::vector<double> ax, ay;
    for (std::size_t i = 0; i < ntask; ++i) { ax.push_back(0.0); ay.push_back((double)i); }
    p.points(ax, ay, "", {0,0,0}, 0.1);
    p.save_svg(path);
}
#+end_src

** Pseudocode

#+begin_example
EDF (at each time unit t):
    for each task: if t mod T_i == 0, release a job with deadline t+T_i and work C_i
    among ready jobs pick the one with the smallest absolute deadline
    run it for one unit
    (schedulable for implicit deadlines iff sum C_i/T_i <= 1)
#+end_example

* A worked example

Three tasks: \((T,C)=(4,1),(6,2),(8,2)\). Utilization is \(1/4+2/6+2/8\). The hyperperiod
(lcm of periods) is 24; we simulate over it.

With utilization \(U\approx 0.83\le 1\), EDF meets every deadline over the whole hyperperiod:
whenever a task with a nearer deadline becomes ready it takes the CPU, and the idle slots show
the ~17% of the processor the workload leaves free. A rate-monotonic scheduler's sufficient
bound for three tasks is only \(\approx 0.78\), below this utilization -- so EDF schedules a
workload that the fixed-priority guarantee cannot certify, illustrating its higher achievable
utilization.

* Character and relatives

EDF's full-utilization optimality makes it attractive, but it has drawbacks: under *overload*
(\(U>1\)) it degrades badly -- a *domino effect* where one missed deadline cascades -- whereas
fixed-priority rate-monotonic degrades predictably (only low-priority tasks miss). EDF also
needs dynamic-priority support and is harder to analyze for tasks that share resources
(requiring protocols like Stack Resource Policy). Real-time operating systems therefore often
prefer *rate-monotonic* (companion report) for its simplicity and predictability, reserving
EDF for workloads that need the extra utilization.

* Complexity

The unit-step simulation is \(O(H\cdot n)\) for hyperperiod \(H\) and \(n\) tasks; an
event-driven EDF with a deadline-ordered ready queue runs in \(O(k\log n)\) for \(k\)
scheduling events.
