#+begin_abstract
The Gauss-Legendre iteration doubles the correct digits of \(\pi\) at every step; the *Borwein brothers'
quartic algorithm* does better still, *quadrupling* them. Each iteration multiplies the number of correct
digits by four, so two steps already exhaust double precision and a handful would reach millions of
digits in exact arithmetic. This report drives =datamunge='s =algorithms::borwein_pi=, verified to reach
\(\pi\) to the last representable bit in three steps, and shows the error collapsing quartically.
#+end_abstract

* A quartically convergent iteration for 1/pi

Borwein's algorithm (1987) seeds

\[ y_0=\sqrt2-1,\qquad a_0=6-4\sqrt2, \]

and iterates

\[ y_{k+1}=\frac{1-(1-y_k^4)^{1/4}}{1+(1-y_k^4)^{1/4}},\qquad
   a_{k+1}=a_k(1+y_{k+1})^4-2^{2k+3}\,y_{k+1}\bigl(1+y_{k+1}+y_{k+1}^2\bigr). \]

The sequence \(a_k\) converges to \(1/\pi\), and the convergence is *quartic*: the error obeys
\(a_{k+1}-\tfrac1\pi=O\!\bigl((a_k-\tfrac1\pi)^4\bigr)\), so the number of correct digits roughly
quadruples per step. The cost per iteration is a few multiplications and one fourth root (two square
roots), independent of the precision, so the total work to reach \(N\) digits is dominated by the last
one or two iterations -- the same reason AGM-type algorithms are the method of choice for record
\(\pi\) computations. In IEEE double precision there are only about 16 digits to win, so the estimate
locks onto \(\pi\) after two or three iterations and cannot improve further; the algorithm's real power
shows in an arbitrary-precision setting, but even here the quartic collapse of the error is plain to see.

* Algorithm

#+begin_example
BORWEIN-PI(iterations):
  y = sqrt(2) - 1;  a = 6 - 4 sqrt(2)
  for k = 0 .. iterations-1:
      r = (1 - y^4)^(1/4)
      y = (1 - r) / (1 + r)
      a = a (1 + y)^4 - 2^(2k+3) y (1 + y + y^2)
  return 1 / a                              # -> pi
#+end_example

* Worked example: the error, step by step

We print each iterate's estimate and its error against the library's \(\pi\), then plot the error on a
logarithmic axis to expose the quartic rate.

#+name: bw-run
#+begin_src c++ :eval no
    std::cout << "=== Borwein quartic algorithm for pi ===\n";
    const auto seq = borwein_pi_sequence(4);
    std::cout << "  k      estimate                 |error|\n";
    for (std::size_t k = 0; k < seq.size(); ++k)
        std::printf("  %zu   %.16f   %.3e\n", k, seq[k], std::fabs(seq[k] - M_PI));

    std::vector<double> it, err;
    for (std::size_t k = 0; k < seq.size(); ++k) {
        it.push_back(static_cast<double>(k));
        err.push_back(std::max(1e-17, std::fabs(seq[k] - M_PI)));
    }

    auto plot = RPlot::create();
    plot.line(it, err, "e", RGB{190, 24, 93}, 2.2);
    plot.points(it, err, "e", RGB{190, 24, 93}, 6.0);
    plot.legend({"|error| in pi"}, {{190, 24, 93}});
    plot.title("Borwein quadruples the correct digits each step (log-scale error)")
        .x_label("iteration").y_label("absolute error").background({250, 250, 252});
    plot.save_svg("build/org/borwein_pi.svg");
    std::cout << "\nwrote borwein_pi.svg\n";
#+end_src

From a seed good to less than one digit, one iteration reaches eight correct digits and the second
saturates double precision -- the error dropping from \(10^{-1}\) to \(10^{-9}\) to the \(10^{-15}\) floor,
a textbook quartic cascade.

On the logarithmic axis the error plunges almost vertically before flattening at the double-precision
floor around \(10^{-15}\) -- there are simply no more bits to gain. In arbitrary precision the same
iteration would keep quadrupling the digit count, which is why quartic AGM-style algorithms, not
term-by-term series, hold the records for computing \(\pi\).
