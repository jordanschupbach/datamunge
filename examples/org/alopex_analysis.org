#+begin_abstract
Most learning rules need a gradient. *ALOPEX* (Harth & Tzanakou 1974) needs only
the *cost*. It perturbs every parameter at once and adjusts each one using the
*correlation* between its last change and the resulting change in the cost, plus a
dose of noise controlled by a temperature. Increase a parameter and the cost went
up? Make a decrease more likely next time. This makes ALOPEX a biologically
plausible, derivative-free optimizer for noisy, non-differentiable, or black-box
objectives. This report implements it in =datamunge='s C++
=algorithms::alopex_minimize= as a literate program: every number and figure comes
from one compiled binary. We minimize a two-dimensional objective from a poor
starting point and watch the cost fall as the correlation signal steers the search.
#+end_abstract

* The correlation update

For a cost \(E(w)\) over parameters \(w\), ALOPEX keeps the previous change
\(\Delta w_i\) and the previous cost change \(\Delta E\), and forms the *correlation*
\(C_i = \Delta w_i\,\Delta E\). For *minimization* it then moves each parameter
\(+\delta\) with probability
\[
  p_i = \frac{1}{1 + e^{\,C_i/T}},
\]
and \(-\delta\) otherwise. When \(C_i>0\) (raising \(w_i\) last time raised the cost)
\(p_i<\tfrac12\), so a decrease is favored; when \(C_i<0\) the move that lowered the
cost is repeated. The temperature \(T\) sets the exploration: large \(T\) makes moves
near-random (escaping local minima), small \(T\) makes them near-deterministic
(exploiting the correlation). Annealing \(T\) downward gives global-then-local search.

** Pseudocode

#+begin_example
ALOPEX(cost, w0):
    w = w0;  dw = 0;  dE = 0
    repeat:
        for each i:
            C_i = dw_i * dE                       # correlation
            p_i = 1 / (1 + exp(C_i / T))          # P(move +delta)
            step_i = (rand < p_i) ? +delta : -delta
            w_i += step_i;  dw_i = step_i
        newcost = cost(w)
        dE = newcost - oldcost;  oldcost = newcost
        anneal T
    return best w seen
#+end_example

* A worked example

We minimize \(E(x, y) = (x-3)^2 + (y+2)^2\) -- a bowl with minimum at \((3, -2)\) --
starting from the origin, using no derivatives.

#+name: alopex-run
#+begin_src c++ :eval no
    auto cost = [](const std::vector<double>& w) {
        return (w[0] - 3.0) * (w[0] - 3.0) + (w[1] + 2.0) * (w[1] + 2.0);
    };

    AlopexParameters params;
    params.step        = 0.05;
    params.temperature = 0.0;  // auto-scale from the correlation magnitude
    params.iterations  = 3000;
    params.seed        = 7;

    AlopexResult r = alopex_minimize(cost, 2, {0.0, 0.0}, params);

    std::cout << "=== ALOPEX minimizing (x-3)^2 + (y+2)^2 ===\n";
    std::cout << "start: (0, 0), cost " << cost({0.0, 0.0}) << '\n';
    std::cout << "best found: (" << r.best_parameters[0] << ", " << r.best_parameters[1] << ")  cost "
              << r.best_cost << "   (true optimum (3, -2), cost 0)\n";

    // Figure: cost history (log scale) -- the search descending the bowl.
    std::vector<double> it_x, logc;
    for (std::size_t i = 0; i < r.cost_history.size(); ++i) {
        it_x.push_back(static_cast<double>(i));
        logc.push_back(std::log10(r.cost_history[i] + 1e-9));
    }
    RPlot p = RPlot::create();
    p.line(it_x, logc, "log10(cost)", {37, 99, 235}, 1.5);
    p.save_svg("build/org/alopex_cost.svg");
    std::cout << "\nwrote build/org/alopex_cost.svg\n";
#+end_src

* Results

=== ALOPEX minimizing (x-3)^2 + (y+2)^2 ===
start: (0, 0), cost 13
best found: (3, -2)  cost 7.88861e-30   (true optimum (3, -2), cost 0)
#+end_example

From the origin, ALOPEX drives the cost down to the true minimum at
\((3, -2)\) using only cost evaluations -- no gradient, no model of the objective.
The cost history (log scale) shows the characteristic noisy descent: a rapid early
drop as the correlation signal aligns the moves with the downhill direction, then a
jittery plateau where the fixed step size and residual exploration keep the search
bouncing near the optimum.

* Character and relatives

ALOPEX's appeal is that it needs *nothing but the objective value*, updates all
parameters simultaneously (natural for parallel hardware), and its stochasticity
lets it escape shallow local minima -- properties it shares with simulated annealing
and evolutionary strategies, and that motivated its use as a model of biological
adaptation and for training non-differentiable systems. Its costs are the usual
gradient-free ones: many function evaluations, sensitivity to the step size and
temperature schedule, and jitter around the optimum that a decaying step size (or a
final local polish) removes. It sits in the same family as SPSA and finite-
difference stochastic approximation.

* Complexity

Each iteration is one cost evaluation plus \(O(d)\) work over the \(d\) parameters,
so a run is \(O(\text{iterations}\cdot(d + \text{cost eval}))\). Memory is \(O(d)\).
