We fit two Bayesian models with =datamunge='s C++ =bayes= module -- a
Normal-Normal conjugate model with a known closed-form posterior, and a

report it as a literate program: every fragment below is a real,

dual-averaging step-size adaptation, and NUTS's recursive trajectory

* Introduction

Every classical inference report in this project so far -- including the
[[file:hypothesis_tests_analysis.org][hypothesis tests companion
report]] -- has asked a frequentist question: given the data, how
surprising is a fixed null hypothesis, or what single point estimate
best explains it? Bayesian inference asks a different question
entirely: given a *prior* belief about a parameter and the data actually
observed, what is the full *posterior distribution* over that parameter?
The answer is not a point estimate or a \(p\)-value but an entire
probability distribution, and =datamunge='s =bayes= module provides three
increasingly general ways to characterize it: find its single most
probable point (MAP), draw correlated samples from it via simulated
Hamiltonian dynamics (HMC), or draw samples via the same dynamics with
an automatically tuned trajectory length (NUTS) -- the algorithm behind
Stan's default sampler.

This report's organizing device is a model with a *known answer*: the
Normal-Normal conjugate model in §4.1 has an exact, closed-form posterior
derivable in three lines of algebra, so every one of the three inference
methods can be checked directly against ground truth rather than only
against each other. §4.2 then applies the same three methods (MAP and
NUTS; HMC is dropped there since NUTS strictly dominates it in practice,
as §2.5 explains) to a real model with no closed form -- Bayesian
logistic regression -- and compares the result against the frequentist
maximum-likelihood fit already familiar from the
[[file:glm_iris_analysis.org][GLM companion report]].

As with its companions, this document is a /literate program/: prose and
source are interleaved in reading order, and a single "assembling the
program" step (§3.3.6) weaves every named chunk below into one =.cpp=
file, compiles it, and runs it. Every number and figure from §4 onward is
that program's literal output.

§2 derives the Bayesian inference problem, MAP estimation, Hamiltonian
dynamics, the leapfrog integrator, dual-averaging adaptation, and NUTS's
trajectory doubling, each tied to the specific library call that
implements it. §3 describes the program chunk by chunk. §4 reports the
results of both models alongside three figures. §5 discusses what
checking against a closed-form posterior actually buys us, and what the
logistic regression's separation behavior means. §6 concludes.

* Background: Bayesian Inference via MAP, HMC, and NUTS

** The Bayesian inference problem

Given data $y$ and a parameter vector $\theta$ with prior density
$p(\theta)$ and likelihood $p(y\mid\theta)$, Bayes' theorem gives the
posterior

$$p(\theta \mid y) = \frac{p(y\mid\theta)\,p(\theta)}{p(y)}
\propto p(y\mid\theta)\,p(\theta)$$

The normalizing constant $p(y) = \int p(y\mid\theta)p(\theta)\,d\theta$
is, for all but the simplest models, an intractable integral -- this is
the central computational obstacle of Bayesian inference, and MAP, HMC,
and NUTS each sidestep it differently. All three work directly with the
unnormalized *log-posterior density*

$$\ell(\theta) = \log p(y\mid\theta) + \log p(\theta) = \log p(\theta\mid y) + \text{const}$$

which is all that is needed: MAP maximizes it, and HMC/NUTS sample
proportionally to its exponential without ever computing the
normalizing constant. In =datamunge=, a model is written declaratively
as exactly this sum of log-density terms via =bayes::AutodiffModel=,
which wraps a lambda over =autodiff::Var= (the same reverse-mode
automatic-differentiation type used throughout the project's
optimization-based reports) as an =optim::DifferentiableFunction=,
giving MAP/HMC/NUTS access to both $\ell(\theta)$ and its exact gradient
$\nabla_\theta\,\ell(\theta)$ via the same =Tape::backward()= mechanism.
=bayes::distributions.hpp= supplies a small library of log-density
functions (=normal_lpdf=, =bernoulli_logit_lpmf=, =cauchy_lpdf=,
=gamma_lpdf=, ...) written in this differentiable style -- writing a
model is structurally identical to writing a sequence of Stan's
tilde-notation sampling statements (=parameter distributed as
distribution(...)=), just as ordinary C++.

** MAP: the posterior mode via L-BFGS

=bayes::MAP= finds $\hat\theta_{\text{MAP}} = \arg\max_\theta\,\ell(\theta)$
using =optim::LBFGS=, the same quasi-Newton optimizer used for
maximum-likelihood fitting elsewhere in this project (e.g. GLM's IRLS
inner loop) -- the only difference is that $\ell(\theta)$ here includes a
prior term. MAP is the Bayesian analog of Stan's =optimizing()=: fast, a
single point, and exact for any model whose posterior is genuinely
unimodal and well-approximated locally by a quadratic (true for the
Normal-Normal conjugate model in §4.1 by construction, and often a
reasonable approximation elsewhere) -- but MAP reports no measure of
posterior *uncertainty* at all, which is the entire reason HMC and NUTS
exist.

** Hamiltonian Monte Carlo

HMC characterizes the full posterior by drawing correlated samples from
it. It does so by introducing an auxiliary momentum variable $p$ with
the same dimension as $\theta$, defining a fictitious physical system
with Hamiltonian

$$H(\theta, p) = -\ell(\theta) + \frac{1}{2}p^\top M^{-1} p$$

($-\ell(\theta)$ plays the role of potential energy, and the quadratic
term in $p$ the role of kinetic energy under mass matrix $M$;
=datamunge='s implementation uses an identity mass matrix). Each
iteration draws a fresh momentum $p\sim N(0, M)$, simulates Hamiltonian
dynamics forward using the *leapfrog integrator* -- a symplectic,
time-reversible discretization that alternates half-step momentum
updates with full-step position updates,

$$p_{t+\epsilon/2} = p_t + \frac{\epsilon}{2}\nabla_\theta\,\ell(\theta_t), \quad
\theta_{t+\epsilon} = \theta_t + \epsilon\, M^{-1} p_{t+\epsilon/2}, \quad
p_{t+\epsilon} = p_{t+\epsilon/2} + \frac{\epsilon}{2}\nabla_\theta\,\ell(\theta_{t+\epsilon})$$

for =num_leapfrog_steps= steps of size $\epsilon$ -- and then accepts or
rejects the resulting proposal with a Metropolis correction on
$H(\theta,p)$ that corrects for the leapfrog integrator's small
discretization error. Because the proposal follows the posterior's own
gradient rather than a naive random walk, HMC explores a
high-dimensional posterior far more efficiently than a
gradient-free Metropolis sampler (the subject of the forthcoming
Bayesian sampling companion report) -- at the cost of needing a good
step size $\epsilon$ and trajectory length (=num_leapfrog_steps=
$\times\ \epsilon$), which =bayes::HMC= tunes only partially: the step
size adapts automatically during warmup via dual averaging (below), but
the number of leapfrog steps is a fixed hyperparameter the user must
choose, exactly the parameter NUTS removes.

** Dual-averaging step-size adaptation

Both =HMC= and =NUTS= adapt $\epsilon$ during the =num_warmup= iterations
using the Nesterov dual-averaging scheme of Hoffman & Gelman (2014),
targeting a specified Metropolis acceptance rate (=target_accept_rate=,
default 0.8 -- the theoretically motivated optimum for HMC-family
samplers). Too large an $\epsilon$ makes the leapfrog discretization
error large, rejecting most proposals; too small wastes computation
taking tiny steps. Dual averaging treats this as a stochastic
approximation problem, nudging $\log\epsilon$ toward the value whose
long-run average acceptance rate matches the target, and *freezes*
$\epsilon$ at the end of warmup -- =final_step_size= in both
=HMCResult= and =NUTSResult= reports exactly what was found.

** NUTS: automatically choosing the trajectory length

=bayes::NUTS= removes HMC's remaining hand-tuned hyperparameter --
trajectory length -- by growing the leapfrog trajectory dynamically.
Starting from the current point, it doubles the trajectory by extending
either forward or backward in simulated time, building a binary tree of
leapfrog states, and stops doubling as soon as continuing would make the
trajectory start turning back on itself -- a "U-turn," detected when the
angle between the direction of travel and the momentum indicates the
endpoints are no longer separating. This is the efficient
slice-sampling formulation (Hoffman & Gelman 2014, Algorithm 3): a slice
variable restricts the proposal to states within a valid Hamiltonian
energy band, and the final sample is drawn uniformly from the valid
leapfrog states the doubling procedure visited. =max_tree_depth= caps
the doubling at $2^{\text{max\_tree\_depth}}$ leapfrog steps per
iteration as a safety bound. A trajectory is flagged as a *divergence*
(=num_divergences= in =NUTSResult=) if the Hamiltonian drifts by more
than =max_delta_error= from its starting value during any single
leapfrog step -- a diagnostic signal that the posterior's local geometry
(typically its curvature) is too extreme for the current step size to
resolve accurately, worth checking whenever it is nonzero even though a
handful of divergences out of thousands of iterations rarely
invalidates the overall fit.

** What we will report

§4.1 fits the Normal-Normal conjugate model with MAP, HMC, and NUTS and
checks every result against the closed-form posterior directly, with a
density-histogram overlay and a trace plot as the two supporting
figures. §4.2 fits Bayesian logistic regression on iris with MAP and
NUTS and compares the fitted probability curve against the GLM
companion report's maximum-likelihood fit, with a third figure

* Data and Methods

** The data

The conjugate model (§4.1) uses ten small simulated measurements
($y = \{2.1, 1.8, 2.5, 2.0, 1.9, 2.3, 2.2, 1.7, 2.4, 1.95\}$) chosen
specifically because their exact posterior is a closed-form calculation
-- the point of this section is validating the inference machinery, not
studying the data itself. The logistic regression (§4.2) uses the iris
dataset restricted to versicolor and virginica (100 flowers), already
used for exactly this classification problem via maximum likelihood in
the [[file:glm_iris_analysis.org][GLM companion report]], letting this
report's Bayesian fit be compared directly against that report's
frequentist one.

** Software

All computation uses =datamunge='s C++ =bayes= module --
=bayes::AutodiffModel=, =bayes::MAP=, =bayes::HMC=, =bayes::NUTS=, and
the =normal_lpdf= / =bernoulli_logit_lpmf= log-density helpers from
=bayes::distributions.hpp= -- together with =autodiff::Tape= and
=autodiff::Var= for gradients and =stats::GLM= for the frequentist
comparison fit. Unlike the
DataFrame-and-formula-based classes used in most other reports in this
project, a Bayesian model here is written directly as a C++ lambda
returning an =autodiff::Var= log-density, matching the way Stan models
are written as a sequence of distribution statements rather than as a
formula string.

namespace {

void print_vec(const std::vector<double>& v) {
    std::cout << "[";
    for (std::size_t i = 0; i < v.size(); ++i) std::cout << (i ? ", " : "") << v[i];
    std::cout << "]";
}

double mean_of(const std::vector<std::vector<double>>& samples, std::size_t dim) {
    double s = 0.0;
    for (const auto& row : samples) s += row[dim];
    return s / static_cast<double>(samples.size());
}

double sd_of(const std::vector<std::vector<double>>& samples, std::size_t dim,
             double mean) {
    double s = 0.0;
    for (const auto& row : samples) {
        const double d = row[dim] - mean;
        s += d * d;
    }
    return std::sqrt(s / static_cast<double>(samples.size() - 1));
}

} // namespace

*** The conjugate model: exact posterior, MAP, HMC, and NUTS

#+name: bayes-conjugate-setup
#+begin_src c++ :eval no
    std::cout << "=== Normal-Normal conjugate model:"
                 " MAP, HMC, NUTS vs. the exact posterior ===\n";
    const std::vector<double> y{2.1, 1.8, 2.5, 2.0, 1.9, 2.3, 2.2, 1.7, 2.4, 1.95};
    constexpr double sigma = 1.0, mu0 = 0.0, tau0 = 5.0;

    double sum_y = 0.0;
    for (const double v : y) sum_y += v;
    const double n = static_cast<double>(y.size());
    const double precision_post = 1.0 / (tau0 * tau0) + n / (sigma * sigma);
    const double exact_mean =
        (mu0 / (tau0 * tau0) + sum_y / (sigma * sigma)) / precision_post;
    const double exact_sd = std::sqrt(1.0 / precision_post);
    std::cout << "Exact posterior: N(" << exact_mean << ", " << exact_sd << "^2)\n\n";

    AutodiffModel conjugate_model([&](Tape&, const std::vector<Var>& params) {
        Var lp = normal_lpdf(params[0], mu0, tau0);
        for (const double yi : y) lp = lp + normal_lpdf(yi, params[0], sigma);
        return lp;
    });
#+end_src

The exact posterior mean/SD above come directly from the standard
conjugate-update formula for a Normal likelihood with known variance and
a Normal prior (§2.1's normalizing-constant obstacle disappears entirely
in this special case, since the posterior is available in closed form) --
this is the ground truth every inference method below is checked
against.

Note that =RPlot::curve()= (used elsewhere in this project to plot a
mathematical function directly) is a *static factory* method like
=RPlot::boxplot()= / =RPlot::hist()=, not a chainable instance method like
=RPlot::lines()= -- calling it on an existing plot object returns a
*brand-new*, independent =RPlot= rather than adding a series to the one
already built. This report evaluates the exact posterior density at 200
points directly and adds it via =RPlot::lines()= instead, exactly the
technique the [[file:hypothesis_tests_analysis.org][hypothesis tests
report]]'s own boxplot fix (a genuine library bug, unlike this one) grew
out of the same kind of careful figure-by-figure verification.

    AutodiffModel logistic_model([&](Tape&, const std::vector<Var>& params) {
        Var lp = normal_lpdf(params[0], 0.0, 10.0) + normal_lpdf(params[1], 0.0, 10.0);
        for (std::size_t i = 0; i < petal_length.size(); ++i) {
            const Var eta = params[0] + params[1] * petal_length[i];
            lp = lp + bernoulli_logit_lpmf(is_virginica[i], eta);
        }
        return lp;
    });
    std::vector<double> map_coords{0.0, 0.0};
    {

* Results

** The conjugate model: MAP, HMC, and NUTS vs. the exact posterior

#+begin_example
Exact posterior: N(2.0767, 0.3156^2)

MAP:  mu = 2.0767 (log-posterior = -12.1145)
HMC:  mu ~ N(2.0737, 0.3129^2), accept rate = 0.7898, step size = 0.4452
NUTS: mu ~ N(2.0813, 0.3076^2), accept rate = 0.8369, step size = 0.4156,
  divergences = 1
#+end_example

MAP recovers the exact posterior mode to all four displayed decimal
places -- expected, since the conjugate posterior is exactly Gaussian
and L-BFGS finds the mode of a smooth unimodal function essentially
exactly. Both sampling methods land close to the true mean ($2.0767$)
and SD ($0.3156$): HMC's $2.0737/0.3129$ and NUTS's $2.0813/0.3076$ each
differ from the truth by at most about 0.008 in the mean and 0.005 in
the SD, well within the Monte Carlo error expected from 4000 samples of
a distribution with SD $\approx0.31$. Both samplers report a healthy
acceptance rate close to their 0.8 target (dual averaging did its job:
=final_step_size= landed at $0.4452$ for HMC and $0.4156$ for NUTS, both
found automatically from the same =initial_step_size=0.3= starting
point). NUTS reports a single divergence out of 4000 post-warmup
iterations -- negligible on its own, and unsurprising given this model's
smooth, well-behaved single-parameter posterior; a much higher
divergence count would be the diagnostic signal to actually worry about.

[[file:../../build/org/bayes_posterior_density.svg]]

The overlay makes the numerical agreement visually immediate: the
density histogram built directly from the 4000 NUTS samples tracks the
exact red posterior curve essentially everywhere, including in both
tails.

#+ATTR_HTML: :alt Trace plot of the NUTS post-warmup samples for mu :width 100%
[[file:../../build/org/bayes_nuts_trace.svg]]

The trace plot shows the classic "fuzzy caterpillar" signature of a
well-mixing chain: the sampled values oscillate rapidly and evenly
around the posterior mean with no visible trend, drift, or sustained
excursion to one side -- exactly what NUTS's automatic trajectory-length
tuning (§2.5) is designed to produce, and a useful visual diagnostic to
compare against on future models whose posteriors are not available in
closed form to check against directly.

** Bayesian logistic regression vs. GLM's maximum likelihood

#+begin_example
GLM MLE:        [-43.7809, 9.0020]
Bayes MAP:      [-26.5388, 5.4588] (weak Normal(0, 10) priors)
Bayes NUTS mean: [-27.8953, 5.7351] (posterior mean, accept rate = 0.8450)
#+end_example

=Petal.Length= alone nearly separates versicolor from virginica, the
same near-separation the
[[file:glm_iris_analysis.org][GLM companion report]] discusses for a
different predictor pair -- and the unregularized MLE responds exactly
as separation theory predicts, with its slope coefficient (9.0020)
roughly 60% larger than either Bayesian estimate. The weak
$N(0,10)$ prior added no strong outside information (a slope of $\pm10$
is still an enormous log-odds change per centimeter of petal length),
yet it visibly pulls both the MAP mode (5.4588) and the NUTS posterior
mean (5.7351) back from the MLE's inflated value. MAP and NUTS agree
closely with each other (5.4588 vs. 5.7351), consistent with §4.1's
finding that this posterior's mode and mean are close together for a
reasonably well-behaved (here, two-dimensional but still smooth and
unimodal) posterior.

#+ATTR_HTML: :alt Fitted probability curves comparing the GLM maximum-likelihood fit against the Bayes MAP and NUTS posterior-mean fits :width 100%
[[file:../../build/org/bayes_logistic_curves.svg]]

The fitted curves make the regularization effect directly visible: the
red MLE curve is noticeably steeper -- closer to a step function -- than
the blue MAP and green NUTS-mean curves, which sit almost exactly on top
of each other and rise more gradually through the same crossover region.
This is the geometric signature of near-separation: with no prior to
resist it, the MLE's slope grows without real bound as the data get
closer to perfectly separable, while even a weak prior anchors the
Bayesian fit to a finite, more conservative estimate.

* Discussion

**Checking against a closed-form posterior is worth the extra
derivation effort every time it's available.** §4.1's conjugate model
exists purely as a validation device: because its exact posterior is
three lines of algebra, every number MAP/HMC/NUTS produced could be
checked directly, not just against each other. This is a much stronger
test than the more common practice of checking that multiple samplers
merely *agree with each other* -- two samplers can agree while both being
wrong (a shared bug, a shared bias from insufficient warmup, ...), but
agreement with an independently-derived exact answer rules that out.
Whenever a model's structure permits a closed-form or otherwise
independently verifiable posterior (even an approximate one, e.g. a
large-sample normal approximation to a GLM's likelihood), it is worth
deriving before trusting a sampler's output on a harder version of the
same model.

**MAP and posterior-mean estimates coinciding is itself informative, not
just convenient.** §4.2's Bayes MAP (5.4588) and NUTS posterior mean
(5.7351) landed close together, which is exactly what should happen
when a posterior is reasonably close to Gaussian (mode = mean for an
exact Gaussian, and approximately so for a mildly asymmetric one) --
the same property that makes MAP a fast, useful proxy for full posterior
sampling in appropriate models, and a reasonable warning sign to watch
for divergence between the two on models with heavier-tailed, more
skewed, or multimodal posteriors, where MAP's single point can badly
misrepresent the distribution's central tendency.

**Regularization from a prior and regularization from a penalty term are
the same computation, seen from two different framings.** §4.2's
weakly-informative $N(0,10)$ prior visibly shrinking the logistic
regression's coefficients is mathematically identical to adding an
$L_2$ (ridge) penalty to the negative log-likelihood -- the log-density
of a Gaussian prior is, up to a constant, exactly a quadratic penalty
term. This connects directly to the
[[file:elastic_net_iris_analysis.org][Elastic Net companion report]]'s
frequentist regularization story: the same numerical phenomenon (a
penalized/prior-informed fit shrinking coefficients relative to an
unregularized MLE) is reachable from either the Bayesian or the
penalized-likelihood framing, and near-separation is one of the clearest
settings where the practical benefit of doing so -- a finite, interpretable
coefficient instead of one racing toward $\pm\infty$ -- is visible in a
single fitted curve.

* Conclusion

Fitting a Normal-Normal conjugate model with =datamunge='s C++
=bayes::MAP=, =bayes::HMC=, and =bayes::NUTS= reproduces the model's
exact closed-form posterior to within Monte Carlo error on every metric
checked -- mean, SD, and (via direct histogram overlay) the full
density shape -- validating all three inference methods against ground
truth rather than only against each other. Applying the same MAP and
NUTS machinery to a real Bayesian logistic regression on iris surfaces a
genuine, expected regularization effect: near-perfect separation by
=Petal.Length= inflates the unregularized MLE's slope coefficient well
beyond both Bayesian estimates under a merely weakly-informative prior,
visible directly in the fitted probability curves. As with its
companions, this entire report is reproducible end to end via
=just org-example bayesian_modeling_analysis=, which re-executes
§3.3.6's assembly block -- and therefore every number and figure above --
from the =datamunge= source tree.
