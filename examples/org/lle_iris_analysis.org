#+begin_abstract
We fit Locally Linear Embedding (Roweis & Saul, 2000) to Fisher's (1936)
iris measurements using =datamunge='s C++ =stats::LLE=, and report it as
a literate program: every fragment below is a real, compiled, executed
chunk of the single C++ binary that produced every number and figure in
this document. =Species= is withheld entirely from the fit. Fitting
with =n_neighbors= set to =10= surfaces a genuine complication this
project has previously hit: iris's \(k\)-nearest-neighbor graph is
/disconnected/, splitting into a 50-point /setosa/ component and a
100-point /versicolor/+/virginica/ component -- confirmed two
independent ways, by =eigenvalues()='s own tail (the two smallest
values, 5.8722e-10 and 8.2772e-17, sit below a first non-trivial value
of 3.2669e-09) and by an independently-written union-find cross-check
over the same \(k\)-nearest-neighbor adjacency (also 2 components,
matching =LLE='s internally reported "Discarded trivial eigenvalue(s):
2" exactly). The consequence is not the naive failure mode of one
species collapsing to a point: because the reconstruction-weight matrix
\(W\) is exactly block-diagonal across disconnected components, each
embedding dimension turns out to be supported entirely on /one/
component and identically zero on the other -- =versicolor= and
=virginica= sit at =mean(d1)= of =0.0000= with =var(d1)= of
=0.0000e+00=, while /setosa/ sits at =mean(d2)= of =0.0000= with
=var(d2)= of =0.0000e+00=, an exact "cross" structure we derive
directly from the block-diagonal argument in §2.4, not merely observe.
On a synthetic Swiss roll (\(n=400\), seed 42, the shared ground-truth
construction used across this report series), LLE recovers the true
angular parameter \(t\) far better than PCA or MDS on the identical 3D
data -- best correlation 0.7153 at =n_neighbors= set to =8=, versus
0.0215 for PCA and 0.2426 for MDS -- but the recovery is imperfect and,
honestly reported, /non-monotonic/ in =n_neighbors= (0.7153 at 8,
0.1188 at 12, 0.1999 at 20), not the clean textbook "too few, just
right, too many" curve. We derive the local reconstruction-weight
optimization, its closed-form per-point solution, the Rayleigh-quotient
argument for the embedding step, and the disconnected-graph extension
of the trivial-eigenvalue argument, tying each to the corresponding
library call.

* Introduction

Every report in this project's manifold-learning series asks some
version of the same question the [[file:pca_iris_analysis.org][companion
PCA report]] and the [[file:mds_iris_analysis.org][companion MDS
report]] already ask: given only a set of observations in a
higher-dimensional feature space, can we find a faithful low-dimensional
representation? PCA answers this by preserving /global/ linear variance;
classical MDS by preserving /global/ pairwise distances. Locally Linear
Embedding (LLE) takes a structurally different approach: it never looks
at global distances or variance at all, only at how each point relates
to its immediate neighbors, and asks for a low-dimensional embedding
that reproduces those purely /local/ relationships as faithfully as
possible. This locality is precisely what lets LLE unfold genuinely
nonlinear manifolds -- surfaces that fold or curl through a
higher-dimensional space -- that PCA and MDS, both fundamentally
straight-line-distance methods, cannot.

As with its companion reports, this document is a /literate program/:
prose and source are interleaved in reading order, and a single
"assembling the program" step (§3.4.11) weaves every named chunk below
into one =.cpp= file, compiles it, and runs it. Every number and figure
from §4 onward is that program's literal output.

§2 derives the local reconstruction-weight optimization and its
closed-form solution, the Rayleigh-quotient argument for turning fixed
weights into an embedding, and -- because this report's own iris
experiment demonstrates it concretely -- the extension of the "discard
the trivial eigenvalue" argument to a /disconnected/ neighbor graph. §3
describes the program chunk by chunk, including the shared-brief Swiss
roll construction. §4 reports the iris eigenvalue/connected-component
diagnostic, the resulting embedding's block structure, and the
Swiss-roll unrolling comparison against PCA and MDS. §5 discusses what
the disconnection finding does and does not mean for using LLE in
practice, and is honest about the Swiss-roll sweep's non-monotonic
result. §6 concludes.

* Background: Locally Linear Embedding

** Setup and notation

\(n = 150\) flowers, \(p = 4\) predictors (\(x_i \in \mathbb{R}^4\):
=Sepal.Length=, =Sepal.Width=, =Petal.Length=, =Petal.Width=) -- and, as
in the [[file:pca_iris_analysis.org][PCA]] and
[[file:mds_iris_analysis.org][MDS]] companion reports, no response
variable at all during fitting. =Species= is retained separately in this
report's own code and used only afterward to color the embedding scatter
and compute per-species diagnostics, never passed to the =LLE=
constructor.

** Local reconstruction weights

For each point \(x_i\), =LLE::fit= finds its =LLEOptions::n_neighbors=
(\(k\)) nearest neighbors under the chosen =DistanceMetric= (Euclidean
by default), then solves for the weights that best reconstruct \(x_i\)
as a linear combination of just those neighbors,

\[
\min_{W} \sum_{i=1}^n \Big\lVert x_i - \sum_{j} W_{ij} x_j \Big\rVert^2
\qquad \text{s.t.} \quad \sum_j W_{ij} = 1, \quad W_{ij} = 0 \text{ for } j \notin N(i) ,
\]

where \(N(i)\) is \(x_i\)'s neighbor set. The sum-to-one constraint
makes the reconstruction invariant to translating, rotating, or
rescaling the neighborhood, which is exactly why the resulting weights
can later be reused, unchanged, in a lower-dimensional embedding space
(§2.3): they describe the neighborhood's local /shape/, not its
absolute position or the ambient dimensionality it happens to live in.

For a fixed \(i\) this is a small, closed-form problem. Writing
\(\eta_1, \ldots, \eta_k\) for \(x_i\)'s \(k\) neighbors and the
/local Gram matrix/

\[
C_{ab} = (x_i - \eta_a) \cdot (x_i - \eta_b), \qquad a, b = 1, \ldots, k ,
\]

the constrained least-squares solution is \(w = C^{-1}\mathbf{1}\),
renormalized so its entries sum to 1. =LLE::fit= computes exactly this:
it builds \(C\) directly (the same dot-product form above), adds a
small diagonal regularizer =LLEOptions::regularization= times
\(\mathrm{trace}(C)/k\) (a /fraction/ of the local Gram matrix's own
trace, not an absolute value -- needed whenever \(k\) exceeds the local
intrinsic dimensionality, which makes \(C\) singular or near-singular),
solves \(Cw = \mathbf{1}\) via =linalg::lu(C).solve(ones)=, and
renormalizes \(w\) to sum to 1. The resulting sparse \(n \times n\)
matrix \(W\) (nonzero only at each point's own \(k\) neighbors) is the
complete "local shape" summary that the embedding step below preserves.

** From weights to embedding: a Rayleigh-quotient argument

With \(W\) now fixed, LLE looks for embedded coordinates
\(y_1, \ldots, y_n \in \mathbb{R}^d\) (\(d = \) =LLEOptions::n_components=)
that are reconstructed by the /same/ weights just as well as the
originals were,

\[
\min_{Y} \sum_{i=1}^n \Big\lVert y_i - \sum_j W_{ij} y_j \Big\rVert^2
= \min_{Y} \operatorname{tr}\!\big(Y^\top M Y\big), \qquad M = (I - W)^\top (I - W) ,
\]

subject to constraints that remove the embedding's inherent translation
and rotation/scale indeterminacy (centering the \(y_i\) at the origin,
and requiring \(Y^\top Y\) proportional to the identity). This is a
standard Rayleigh-quotient minimization: by the Rayleigh-Ritz theorem,
the columns of \(Y\) that minimize \(\operatorname{tr}(Y^\top M Y)\)
subject to an orthonormality constraint are exactly \(M\)'s eigenvectors
corresponding to its /smallest/ eigenvalues. =LLE::fit= computes this
directly, eigendecomposing \(M\) via the same =linalg::jacobi_eigen=
solver the [[file:pca_iris_analysis.org][PCA]] and
[[file:mds_iris_analysis.org][MDS]] reports use (=eigenvalues()=
returns the full descending spectrum, length \(n\)).

** The trivial eigenvalue(s) and graph disconnection

\(M\)'s /smallest/ eigenvalue is always (near) zero: because every row of
\(W\) sums to 1, \(M\mathbf{1} = (I-W)^\top(I-W)\mathbf{1} =
(I-W)^\top(\mathbf{1}-\mathbf{1}) = 0\), so the all-constant vector
\(\mathbf{1}\) is an exact null eigenvector. Including it in the
embedding would assign every point the same coordinate on that axis --
useless -- so the classical LLE derivation discards this one trivial
eigenvalue/eigenvector and keeps the next \(d\) smallest.

This argument silently assumes the \(k\)-nearest-neighbor graph is
/connected/. When it is not -- exactly the situation §4.1 finds for
iris -- the argument extends cleanly, and is worth walking through
because this report's own experiment gives a concrete instance of it.
If the neighbor graph splits into components \(S_1, \ldots, S_c\), then
because each point's neighbors (by construction of the \(k\)-NN graph)
lie only within its own component, \(W\) is exactly block-diagonal, one
block per component -- and so is \(M = (I-W)^\top(I-W)\). For /each/
block \(M_{(S_r)}\), the same row-sums-to-1 argument applies /within
that block/: the vector that is 1 on \(S_r\) and 0 elsewhere is an exact
null eigenvector of the whole \(M\) (it is annihilated within its own
block by the argument above, and \(M\) has no cross-block entries to
disturb the zero outside the block). So a graph with \(c\) connected
components produces /exactly \(c\)/ trivial near-zero eigenvalues, not
one -- and discarding only one, as the connected-graph derivation
assumes, would leave a second exactly-null eigenvector inside the
retained span. =LLE::fit= handles this by counting connected components
of the (undirected closure of the) \(k\)-NN graph via union-find and
discarding /that many/ trailing eigenvalues instead of always exactly
one (=discarded_trivial_count_= in the header's own documentation).
§4.1 verifies this discarded count against an independently-written
union-find cross-check, and §4.2 verifies a further, more specific
consequence of the block-diagonal structure: since each surviving
embedding eigenvector is itself a genuine (non-trivial) eigenvector of
one block's own sub-matrix and exactly zero on every other block, each
retained embedding /dimension/ ends up supported entirely on a single
connected component.

** What we will report

Given the fit, we report the iris eigenvalue tail and an independent
connected-component cross-check, the resulting embedding's per-species
mean/variance structure (confirming the block-diagonal argument just
derived, not merely a "no collapse" check), an embedding scatter, and a
Swiss-roll =n_neighbors= sweep compared against PCA and MDS on the
identical 3D data.

* Data and Methods

** The data

As in every companion report: =datamunge::datasets::iris()= returns
Fisher's 150 flowers -- 50 each of /setosa/, /versicolor/, /virginica/ --
measured on =Sepal.Length=, =Sepal.Width=, =Petal.Length=, =Petal.Width=
(cm), with no missing values. All four measurements are used as LLE
features throughout; =Species= is withheld from the constructor and used
only for the exploratory diagnostics and the embedding figure.

** A synthetic ground truth: the Swiss roll

Iris alone cannot demonstrate manifold learning's actual value
proposition, since it is already close to linearly structured. §4.3
instead generates the classic "Swiss roll": \(n = 400\) points seeded
uniformly at random (=std::mt19937_64=, seed 42),

\[
t_i = 1.5\pi (1 + 2 u_i), \qquad h_i = 21 u_i', \qquad
x_i = t_i \cos t_i, \quad y_i = h_i, \quad z_i = t_i \sin t_i ,
\]

with \(u_i, u_i' \sim \mathrm{Uniform}(0,1)\) independently drawn. Only
the 3D observed coordinates (=x=, =y=, =z=) are given to LLE/PCA/MDS as
features; \(t\) (the true position /along/ the roll) and \(h\) (the true
height) are withheld and used only afterward, in §4.3, to color a figure
and to compute a real correlation between each method's recovered
embedding and the true parametrization.

** Software

The entire analysis is one C++ program against =datamunge=:
=dstruct::DataFrame= for the data, =stats::LLE= (and, for §4.3's
comparison, =stats::PCA= and =stats::MDS=) for the models, and
=plot::RPlot= for every figure. No external plotting or statistics
package is used.

// Independent connected-component cross-check over a k-NN graph built
// directly from a feature matrix (does NOT reuse any LLE-internal state) --
// union-find over the undirected closure of the directed k-NN adjacency.
std::size_t knn_connected_components(
    const std::vector<std::vector<double>>& X, std::size_t k,
    DistanceMetric metric) {
    const std::size_t n = X.size();
    const std::size_t p = X.front().size();
    auto dist = [&](std::size_t i, std::size_t j) {
        double sum = 0.0;
        if (metric == DistanceMetric::Euclidean) {
            for (std::size_t f = 0; f < p; ++f) {
                const double d = X[i][f] - X[j][f];
                sum += d * d;
            }
            return std::sqrt(sum);
        }
        for (std::size_t f = 0; f < p; ++f)
            sum += std::abs(X[i][f] - X[j][f]);
        return sum;
    };
    std::vector<std::size_t> parent(n);
    for (std::size_t i = 0; i < n; ++i) parent[i] = i;
    std::function<std::size_t(std::size_t)> find = [&](std::size_t x) {
        while (parent[x] != x) {
            parent[x] = parent[parent[x]];
            x = parent[x];
        }
        return x;
    };
    for (std::size_t i = 0; i < n; ++i) {
        std::vector<std::size_t> idx;
        idx.reserve(n - 1);
        for (std::size_t j = 0; j < n; ++j)
            if (j != i) idx.push_back(j);
        std::partial_sort(
            idx.begin(), idx.begin() + static_cast<std::ptrdiff_t>(k),
            idx.end(),
            [&](std::size_t a, std::size_t b) { return dist(i, a) <
                                                        dist(i, b); });
        for (std::size_t tt = 0; tt < k; ++tt) {
            const std::size_t j = idx[tt];
            const std::size_t ri = find(i), rj = find(j);
            if (ri != rj) parent[ri] = rj;
        }
    }
    std::vector<bool> is_root(n, false);
    std::size_t comps = 0;
    for (std::size_t i = 0; i < n; ++i) {
        const std::size_t r = find(i);
        if (!is_root[r]) {
            is_root[r] = true;
            ++comps;
        }
    }
    return comps;
}

double pearson(const std::vector<double>& a, const std::vector<double>& b) {
    const std::size_t n = a.size();
    double ma = 0.0, mb = 0.0;
    for (std::size_t i = 0; i < n; ++i) {
        ma += a[i];
        mb += b[i];
    }
    ma /= n;
    mb /= n;
    double num = 0.0, da = 0.0, db = 0.0;
    for (std::size_t i = 0; i < n; ++i) {
        num += (a[i] - ma) * (b[i] - mb);
        da += (a[i] - ma) * (a[i] - ma);
        db += (b[i] - mb) * (b[i] - mb);
    }
    return num / std::sqrt(da * db);
}

// Best-of (axis assignment x sign) correlation between a 2D embedding and
// (t, height), allowing for the well-known LLE/MDS/PCA indeterminacy up to
// rotation/reflection/axis-permutation.
struct RollCorr {
    double corr_t;
    double corr_height;
};
RollCorr best_roll_correlation(const std::vector<double>& d0,
                                const std::vector<double>& d1,
                                const std::vector<double>& t,
                                const std::vector<double>& height) {
    const double c_00 = std::abs(pearson(d0, t));
    const double c_01 = std::abs(pearson(d0, height));
    const double c_10 = std::abs(pearson(d1, t));
    const double c_11 = std::abs(pearson(d1, height));
    // assignment A: d0->t, d1->height ; assignment B: d0->height, d1->t
    if (c_00 + c_11 >= c_01 + c_10) return {c_00, c_11};
    return {c_10, c_01};
}

    std::uniform_real_distribution<double> u(0.0, 1.0);

        y[i] = height[i];
        z[i] = t[i] * std::sin(t[i]);

    DataFrame roll;
    roll.add_column("x", x);

#+end_example

At =n_neighbors= set to =10=, iris's \(k\)-nearest-neighbor graph is
disconnected, and =LLE= itself reports discarding /two/ trivial
eigenvalues rather than the naive-derivation default of one. Two
independent numbers agree that this is the right count: an
independently-written union-find cross-check over the same 4-feature
\(k\)-NN adjacency (built without touching any =LLE=-internal state, per
§3.4.1) also finds exactly 2 connected components, and the eigenvalue
spectrum's own tail shows a genuine break -- the two smallest values
(=eigenvalues()[149]=8.277178e-17=, essentially machine-precision zero,
and =eigenvalues()[148]=5.872186e-10=) sit below the next value up
(=eigenvalues()[147]=3.266911e-09=), consistent with §2.4's derivation
that a \(c\)-component graph produces exactly \(c\) trivial eigenvalues.
Refitting at =n_neighbors= set to =20= (double the default) reproduces
the same finding -- 2 connected components, 2 discarded trivial
eigenvalues -- confirming this is a real property of iris's local
neighborhood structure around the /setosa//non-setosa boundary, not an
artifact of one particular =n_neighbors= choice.

** Iris: how the disconnection shapes the embedding

#+begin_example
Per-species embedded-coordinate mean / variance:
     species     n    mean(d1)     var(d1)    mean(d2)    var(d2)
      setosa    50     -0.0000  2.0000e-02      0.0000  0.0000e+00
  versicolor    50      0.0000  0.0000e+00      0.0159  2.1254e-03
   virginica    50      0.0000  0.0000e+00      0.1197  3.2843e-03
#+end_example

This is a more precise picture than "no species collapses to a single
point" -- it is exactly what §2.4's block-diagonal argument predicts.
=versicolor= and =virginica= sit at =mean(d1)= of =0.0000= with
=var(d1)= of =0.0000e+00= (not merely small: identically zero to the
printed precision), while /setosa/ sits at =mean(d2)= of =0.0000= with
=var(d2)= of =0.0000e+00=. Dimension 1 is entirely the setosa \(k\)-NN
block's own leading non-trivial eigenvector -- zero everywhere outside
that block -- and dimension 2 is entirely the versicolor+virginica
block's; each species' internal shape variation shows up /only/ on the
one axis its own component owns (/setosa/'s =var(d1)= of =2.0000e-02=;
the other two components' =var(d2)= of 2.1254e-03 and 3.2843e-03
respectively), never on the other axis. The resulting embedding (below)
is therefore a "cross" shape -- points scattered along one axis or the
other, never off both simultaneously -- rather than a genuine 2D
unfolding /or/ the naive-bug single-point collapse this project has
previously hit and fixed elsewhere.

Even though =Species= was never given to =LLE::fit=, the two axes still

LLE at its best setting here (=n_neighbors= set to =8=) reaches a
correlation of 0.7153 with the true \(t\), well above both PCA's
0.0215 and MDS's 0.2426 on the /identical/ 3D data -- both, as
expected, largely fail to recover \(t\) at all, for the same
straight-line-distance-cuts-through-the-coils reason the companion
[[file:isomap_iris_analysis.org][Isomap report]] documents in more
depth. That much matches the textbook story: a genuinely local method
recovers structure the two global, straight-line-distance methods
cannot.

What does /not/ match the textbook story, reported honestly rather than
smoothed over, is the =n_neighbors= sweep's shape. LLE folklore predicts
a roughly unimodal curve -- too few neighbors fragments the local
neighborhoods, too many loses the "local" linearity assumption and
degrades toward global, PCA-like behavior -- peaking somewhere in the
middle. This run instead shows =corr_t= /falling/ from 0.7153 at
=n_neighbors= set to =8= to 0.1188 at =12=, then partially
/recovering/ to 0.1999 at =20=, which is neither monotonic nor a clean
single peak. =corr_height= moves in the opposite direction (0.4458,
0.8064, 0.6457), suggesting the two embedding axes are trading off which
one best tracks \(t\) versus \(h\) rather than both jointly improving or
degrading together -- plausible given the Rayleigh-quotient argument in
§2.3 gives no guarantee about which of the two nearly-degenerate
smallest non-trivial eigenvalues ends up more aligned with either
ground-truth coordinate at any particular =n_neighbors=. We report this
as a real, data-specific instability rather than force it into the
textbook narrative.

* Discussion

**The disconnection finding is a genuine property of iris, not a bug.**
§4.1's two independent counts (the eigenvalue-tail break and the
union-find cross-check) agreeing at exactly 2, at both =n_neighbors= set
to =10= and =20=, rules out either being a fluke of one particular run.
§2.4's derivation explains /why/ this happens mechanically -- a
disconnected \(k\)-NN graph forces \(W\), and therefore \(M\), into
block-diagonal form, and each block contributes its own trivial null
eigenvector -- and §4.2's per-species mean/variance table confirms the
/further/, more specific consequence that derivation predicts: each
retained embedding dimension is supported on exactly one component. This
is a sharper, more mechanistic finding than simply checking "does any
species collapse to a point" (the check this report's assignment brief
originally asked for) -- the actual answer is that /neither/ species
collapses, but the two-species-versus-one-species partition still
constrains the embedding's geometry into an axis-locked cross rather
than a free 2D scatter.

**Practical implication for using =n_neighbors= on data resembling
iris.** A practitioner naively trusting a 2D LLE scatter of a
disconnected dataset could easily over-read the "cross" pattern §4.2
shows as two informative coordinates, when actually only one coordinate
is doing any work for any given point. Checking =eigenvalues()='s tail
for a genuine gap (as done here) -- or, more robustly, an independent
connected-component count over the same \(k\)-NN graph, since a gap can
be subtle when component sizes/local densities differ substantially -- is
cheap and catches this before it is mistaken for real 2D structure.

**The Swiss-roll result is a genuine, if qualified, success for LLE over
PCA/MDS.** 0.7153 versus 0.0215/0.2426 is not a small difference, and it
is exactly the kind of gap the shared brief's ground-truth construction
is designed to expose: a method that looks at local neighborhoods only
can recover a folded coordinate a global, straight-line-distance method
structurally cannot. But 0.7153 is also well short of a clean "fully
unrolled" result (which would put =corr_t= near 1.0), and the sweep's
non-monotonic behavior across =n_neighbors= (§4.3) means this report
cannot respectably claim LLE reliably and predictably improves with more
carefully tuned neighbors on this exact dataset and sample size -- a
genuinely honest limitation, not a forced negative result, and worth
recording alongside the positive comparison against PCA/MDS.

* Conclusion

Fitting Locally Linear Embedding with =datamunge='s C++ =stats::LLE= to
Fisher's iris measurements -- with =Species= withheld throughout -- shows
a real, previously-hard-won complication: at the default
=n_neighbors= set to =10= (and, confirmed separately, at =20=), iris's
\(k\)-nearest-neighbor graph is disconnected into a 50-point /setosa/
component and a 100-point /versicolor/+/virginica/ component. =LLE=
correctly discards two trivial eigenvalues rather than the
naive-derivation default of one, verified against an independent
union-find cross-check, and the resulting embedding shows the exact
block-diagonal signature §2.4 derives: each retained dimension is
supported on exactly one component and identically zero on the other.
On the shared-brief
Swiss roll (\(n=400\), seed 42), LLE at its best setting
(=n_neighbors= set to =8=) recovers the true angular parameter far
better than PCA or MDS on the identical 3D data (0.7153 versus 0.0215
and 0.2426), a genuine demonstration of LLE's local-neighborhood
advantage -- but the recovery is imperfect and non-monotonic across
=n_neighbors=, an honest limitation rather than a forced textbook
narrative. As with its companions, this entire report is reproducible
end to end via =just org-example lle_iris_analysis=, which re-executes
§3.4.11's assembly block -- and therefore every number and figure above
-- from the =datamunge= source tree.
