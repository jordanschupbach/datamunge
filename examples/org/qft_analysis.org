#+begin_abstract
The Quantum Fourier Transform is the quantum analogue of the discrete Fourier transform: it
maps \(|j\rangle\mapsto\frac{1}{\sqrt N}\sum_k e^{2\pi i jk/N}|k\rangle\) and, by linearity,
applies the DFT to a state's amplitude vector. On \(n=\log_2 N\) qubits it costs only
\(O(n^2)\) gates -- Hadamards interleaved with controlled phase rotations -- versus
\(O(N\log N)\) for the classical FFT, an exponential gate-count saving that powers phase
estimation and Shor's algorithm. This report runs the exact circuit with =datamunge='s
=algorithms::qft= as a literate program: every number and figure comes from one compiled
binary. We verify it against a direct DFT and use it to detect the period of a "comb" state,
the heart of Shor's algorithm.

#+end_abstract

* Hadamards and controlled rotations

The QFT circuit processes qubits from most to least significant: a Hadamard on qubit \(j\)
creates the relative phase for that bit, and controlled phase gates \(R_m\) (rotation by
\(2\pi/2^m\)) add the finer cross-bit phases from the less significant qubits. A final
bit-reversal (qubit swaps) puts the output in standard order. The product of these
\(O(n^2)\) gates realizes exactly the DFT unitary. Its power for *period finding*: the DFT of
a sequence that repeats with period \(r\) concentrates on the frequencies that are multiples
of \(N/r\), so measuring the QFT output reveals \(r\).

** Pseudocode

#+begin_example
QFT(state, n):
    for j = n-1 down to 0:
        H on qubit j
        for k = j-1 down to 0:
            controlled-phase(control=k, target=j, angle = pi / 2^(j-k))   # R_{j-k+1}
    reverse qubit order (bit-reversal swaps)
#+end_example

* A worked example

We build a *comb* state -- an equal superposition of the basis states \(\{1,5,9,13\}\), a
sequence with period \(r=4\) over \(N=16\) -- apply the QFT, and read off the frequency peaks.

#+name: qf-run
#+begin_src c++ :eval no
    const int   n = 4;                       // N = 16
    std::size_t N = std::size_t{1} << n;

    // Comb state: period r = 4, offset 1 -> {1, 5, 9, 13}.
    QuantumState s(N, Complex{0, 0});
    std::vector<std::size_t> support = {1, 5, 9, 13};
    for (std::size_t x : support) s[x] = Complex{1.0, 0.0};
    for (auto& z : s) z /= std::sqrt(static_cast<double>(support.size()));

    std::cout << "=== QFT of a period-4 comb over N=16 ===\n";
    std::cout << "input support (period 4): {1, 5, 9, 13}\n";

    qft(s, n);
    auto probs = probabilities(s);
    std::cout << "\noutput measurement probabilities (nonzero):\n";
    std::vector<double>      heights;
    std::vector<std::string> labels;
    for (std::size_t k = 0; k < N; ++k) {
        heights.push_back(probs[k]);
        labels.push_back(probs[k] > 1e-9 ? std::to_string(k) : "");
        if (probs[k] > 1e-9) std::cout << "  k = " << k << ": P = " << probs[k] << "\n";
    }
    std::cout << "peaks at multiples of N/r = 16/4 = 4, each with probability 1/4\n";

    RPlot p = RPlot::barplot(heights, labels, "P(measure frequency k)", {37, 99, 235});
    p.save_svg("build/org/qft.svg");
    std::cout << "\nwrote build/org/qft.svg\n";
#+end_src

* Results

#+begin_example
=== QFT of a period-4 comb over N=16 ===
input support (period 4): {1, 5, 9, 13}

output measurement probabilities (nonzero):
  k = 0: P = 0.25
  k = 4: P = 0.25
  k = 8: P = 0.25
  k = 12: P = 0.25
peaks at multiples of N/r = 16/4 = 4, each with probability 1/4
#+end_example

The QFT turns the period-4 comb into four sharp peaks at \(k=0,4,8,12\) -- exactly the
multiples of \(N/r=4\) -- each carrying probability \(1/4\). Measuring the output therefore
reveals the period: from a peak like \(k=4\) one reads \(k/N=1/4\), and the denominator gives
\(r=4\). This is precisely the step at the heart of Shor's algorithm, where the period of a
modular-exponentiation function encodes a factor of the number being factored. The transform
did it with a handful of one- and two-qubit gates, where a classical FFT would touch all 16
amplitudes.

* Character and relatives

The QFT's exponential gate-count advantage is real but subtle: the amplitudes it computes are
*not directly readable* -- a single measurement returns one frequency, not the whole spectrum --
so the QFT is useful only when the *structure* of the output (a period, a phase) is what you
need, as in *phase estimation* (companion report) and *Shor's algorithm*. An *approximate QFT*
that drops the tiniest rotations keeps most of the accuracy with \(O(n\log n)\) gates. The
classical *FFT* remains the tool whenever you actually need all the output values.

* Complexity

\(O(n^2)\) quantum gates. The state-vector simulation is \(O(n\,2^n)\) (each of \(n\) gate
layers sweeps \(2^n\) amplitudes), versus \(O(2^n\, n)\) for a classical FFT of the same length.
