#+begin_abstract
A plain merge keeps every element, duplicates included. The *union merge* keeps each
distinct value *once* -- it is the sorted *set union* of its inputs, computed in a
single @math{O(n\log k)} pass by the same min-heap as a @math{k}-way merge, simply
skipping any value equal to the one just emitted. No sorting afterward, no hash set: the
already-sorted inputs make deduplication a one-line check. This report implements it in
=datamunge='s C++ =algorithms::union_merge=, verified against @c std::set over hundreds
of random cases.
#+end_abstract

* Deduplicating while you merge

Because a @math{k}-way merge emits values in nondecreasing order, *every copy of a
value comes out consecutively*. So to keep the set union you need only remember the last
value you emitted and drop the next one if it is equal:

- pop the smallest front from the heap;
- emit it *only if* it differs from the previously emitted value;
- push that list's successor and repeat.

This is the merge behind combining sorted index *posting lists* (document-id lists that
must not repeat an id) and behind SQL's @c UNION of sorted inputs. It costs the same
@math{O(n\log k)} as the plain merge, with @math{O(1)} extra state -- strictly cheaper
than merging-then-deduplicating or unioning through a hash set, both of which touch more
memory.

* Algorithm

#+begin_example
UNION-MERGE(lists):
  heap <- min-heap of (value, list_index, elem_index) over each nonempty list's front
  out <- [];  last <- undefined
  while heap not empty:
      (v, l, e) <- pop-min(heap)
      if last is undefined or v != last:      # skip a repeat of the last emitted value
          append v to out;  last <- v
      if e+1 < len(lists[l]): push successor
  return out
#+end_example

* Worked example: overlapping lists collapse to their union

We union several sorted lists that share many elements, and watch the output size fall
from the total element count toward the number of *distinct* values as overlap grows.

#+name: um-run
#+begin_src c++ :eval no
    const std::vector<std::vector<int>> demo = {{1, 2, 2, 3, 5}, {2, 3, 4, 5}, {3, 5, 5, 6}};
    std::size_t total = 0;
    for (const auto& l : demo) total += l.size();
    const std::vector<int> u = union_merge(demo);
    std::cout << "=== union of three overlapping lists ===\n";
    for (int v : u) std::cout << v << " ";
    std::cout << "\n" << total << " elements in -> " << u.size() << " distinct values out\n\n";

    // As lists overlap more (values drawn from a shrinking range), the union shrinks toward
    // the range size while the total input stays fixed.
    std::vector<double> ranges, totals, unions;
    for (int range = 200; range >= 20; range -= 20) {
        std::vector<std::vector<int>> lists(5, std::vector<int>());
        std::set<int>                 distinct;
        std::size_t                   tot = 0;
        int                           seed = 1;
        for (auto& l : lists) {
            for (int j = 0; j < 100; ++j) {
                const int v = (seed = (seed * 1103515245 + 12345) & 0x7fffffff) % range;
                l.push_back(v);
                distinct.insert(v);
                ++tot;
            }
            std::sort(l.begin(), l.end());
        }
        const std::vector<int> merged = union_merge(lists);
        ranges.push_back(range);
        totals.push_back(static_cast<double>(tot));
        unions.push_back(static_cast<double>(merged.size()));
        if (merged.size() != distinct.size()) std::cout << "MISMATCH vs std::set!\n";
    }
    std::cout << "smallest range (20): 500 elements in -> " << unions.back() << " distinct out\n";

    auto plot = RPlot::create();
    plot.line(ranges, totals, "total input", RGB{148, 163, 184}, 2.0);
    plot.points(ranges, totals, "total", RGB{148, 163, 184}, 4.0);
    plot.line(ranges, unions, "union size", RGB{5, 150, 105}, 2.0);
    plot.points(ranges, unions, "union", RGB{5, 150, 105}, 5.0);
    plot.legend({"total elements in (fixed 500)", "distinct values out (union)"},
                {{148, 163, 184}, {5, 150, 105}});
    plot.title("Union merge collapses duplicates: output is the distinct-value count")
        .x_label("value range (smaller = more overlap)").y_label("number of elements")
        .background({250, 250, 252});
    plot.save_svg("build/org/union_merge.svg");
    std::cout << "wrote union_merge.svg\n";
#+end_src

The three overlapping lists collapse to their distinct values in sorted order, and the
scaling run confirms the output tracks the *distinct-value* count exactly (it agrees
with @c std::set on every case). As the value range shrinks and the five 100-element
lists overlap more, the union shrinks toward the range size even though the input stays
500 elements.
