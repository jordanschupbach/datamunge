#+begin_abstract
For Newton's equations of motion @math{x''=a(x)}, accuracy per step is not the whole
story -- what matters over a long simulation is whether *energy* is conserved. A generic
integrator like forward Euler slowly pumps energy in (or bleeds it out), so an orbit
spirals away over time. *Velocity Verlet* is *symplectic*: it preserves the geometric
structure of Hamiltonian flow, so energy merely *oscillates within a bounded band* for
millions of steps. This report implements it in =datamunge='s C++
=algorithms::velocity_verlet=, verifies it against the harmonic oscillator, and contrasts
its flat energy with forward Euler's relentless drift.
#+end_abstract

* Drift, kick, and time-reversibility

Velocity Verlet advances position and velocity in a specific interleaved order:

\[
x_{n+1} = x_n + v_n h + \tfrac12 a_n h^2, \qquad
a_{n+1} = a(x_{n+1}), \qquad
v_{n+1} = v_n + \tfrac12 (a_n + a_{n+1})\, h.
\]

Position advances using the current acceleration (the "drift"), the acceleration is
recomputed at the new position, and velocity advances using the *average* of the old and
new accelerations (the "kick"). This is second-order accurate, needs just *one* force
evaluation per step, and is *time-reversible* -- run it backward and you retrace your
steps exactly. Those properties make it *symplectic*: it exactly conserves a slightly
perturbed "shadow" energy, so the true energy stays within a bounded band forever instead
of drifting. That is why molecular dynamics and orbital mechanics are built on Verlet,
not on Euler or even RK4 (which is more accurate per step but *not* symplectic, so its
energy slowly drifts too).

* Algorithm

#+begin_example
VELOCITY-VERLET(a, x0, v0, t0, t1, steps):
  h <- (t1 - t0)/steps;  x <- x0;  v <- v0;  acc <- a(x)
  repeat steps times:
      x   <- x + v*h + 0.5*acc*h^2      # drift using current acceleration
      acc_new <- a(x)                    # force at the new position
      v   <- v + 0.5*(acc + acc_new)*h   # kick using the average acceleration
      acc <- acc_new;  record (x, v)
  return trajectory
#+end_example

* Worked example: the harmonic oscillator over many periods

We integrate @math{x''=-x} (energy @math{E=\tfrac12(v^2+x^2)}, exactly conserved for the
true solution @math{x=\cos t}) from @math{x_0=1,\ v_0=0} over @math{50} time units, and
track the energy for velocity Verlet against forward Euler applied to the same system.

#+name: vl-run
#+begin_src c++ :eval no
    auto accel = [](const std::vector<double>& x) { return std::vector<double>{-x[0]}; };
    const double t1 = 50.0;
    const int    steps = 2000;

    const VerletSolution vv = velocity_verlet(accel, {1.0}, {0.0}, 0.0, t1, steps);

    // Forward Euler on the same oscillator written as a first-order system z = (x, v).
    auto sho = [](double, const std::vector<double>& z) { return std::vector<double>{z[1], -z[0]}; };
    const OdeSolution fe = euler_method(sho, {1.0, 0.0}, 0.0, t1, steps);

    auto energy2 = [](double x, double v) { return 0.5 * (v * v + x * x); };

    std::vector<double> tv, ev, tf, ef;
    for (std::size_t i = 0; i < vv.t.size(); ++i) { tv.push_back(vv.t[i]); ev.push_back(energy2(vv.x[i][0], vv.v[i][0])); }
    for (std::size_t i = 0; i < fe.t.size(); ++i) { tf.push_back(fe.t[i]); ef.push_back(energy2(fe.y[i][0], fe.y[i][1])); }

    double vmin = ev[0], vmax = ev[0];
    for (double e : ev) { vmin = std::min(vmin, e); vmax = std::max(vmax, e); }
    std::cout << "=== harmonic oscillator, " << steps << " steps over [0,50] ===\n";
    std::cout << "Verlet energy stays in [" << vmin << ", " << vmax << "] (start 0.5)\n";
    std::cout << "forward Euler energy grew from " << ef.front() << " to " << ef.back() << "\n";
    std::cout << "Verlet x(50) = " << vv.x.back()[0] << ", exact cos(50) = " << std::cos(50.0) << "\n\n";

    auto plot = RPlot::create();
    plot.line(tf, ef, "forward Euler", RGB{220, 38, 38}, 2.0);
    plot.line(tv, ev, "velocity Verlet", RGB{37, 99, 235}, 2.0);
    plot.legend({"forward Euler (energy drifts up)", "velocity Verlet (energy bounded)"},
                {{220, 38, 38}, {37, 99, 235}});
    plot.title("Harmonic oscillator energy: Verlet stays flat, Euler drifts away")
        .x_label("t").y_label("energy  (v^2 + x^2)/2").background({250, 250, 252});
    plot.save_svg("build/org/verlet.svg");
    std::cout << "wrote verlet.svg\n";
#+end_src

* Results

Over fifty time units -- about eight oscillations -- velocity Verlet's energy stays
pinned in a razor-thin band around its starting value @math{0.5}, and its position still
matches @math{\cos t} closely. Forward Euler, integrating the *same* equations at the
*same* step size, steadily injects energy: its amplitude swells and the energy climbs
without bound. Neither method is exact, but only Verlet respects the conservation law.

The blue Verlet energy line is essentially flat; the red forward-Euler line ramps
steadily upward. That divergence -- tiny per step, ruinous over many -- is why long
dynamical simulations use symplectic integrators: keeping the *qualitative* physics
(bounded energy, closed orbits) matters more than shaving the per-step error, and Verlet
delivers it for one force evaluation per step.
