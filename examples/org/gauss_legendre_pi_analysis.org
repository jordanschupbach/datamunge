#+begin_abstract
Most series for \(\pi\) add a fixed number of digits per term. The *Gauss-Legendre
algorithm* does far better: built on the *arithmetic-geometric mean*, it *doubles*
the number of correct digits every iteration -- *quadratic* convergence -- so a
handful of steps reaches millions of digits (given enough precision). This report
implements it in =datamunge='s C++ =algorithms::gauss_legendre_pi=, watches the
error square itself each step, and reaches full double precision in four iterations.
#+end_abstract

* The arithmetic-geometric mean

Gauss studied the iteration that replaces a pair \((a,b)\) by its arithmetic mean
\((a+b)/2\) and geometric mean \(\sqrt{ab}\); the two converge -- *quadratically* --
to a common limit, the AGM. Legendre connected the AGM to elliptic integrals, and
hence to \(\pi\). The algorithm keeps \(a,b\) plus a correction \(t\) and a power
\(p\):

\[
a_{n+1}=\frac{a_n+b_n}{2},\quad b_{n+1}=\sqrt{a_n b_n},\quad
t_{n+1}=t_n-p_n(a_n-a_{n+1})^2,\quad p_{n+1}=2p_n,
\]

from \(a_0=1,\ b_0=1/\sqrt2,\ t_0=1/4,\ p_0=1\), and returns

\[
\pi\approx\frac{(a_{n}+b_{n})^2}{4\,t_{n}} .
\]

Because the AGM converges quadratically, the number of correct digits roughly
doubles per iteration: 1, 3, 8, 19, 41, ... So four iterations already exceed the
~16 digits a =double= holds; going further requires arbitrary-precision arithmetic.

* Algorithm

#+begin_example
GAUSS-LEGENDRE(iterations):
  a, b, t, p <- 1, 1/sqrt(2), 1/4, 1
  repeat iterations times:
      a' <- (a + b) / 2
      b  <- sqrt(a * b)
      t  <- t - p * (a - a')^2
      a  <- a'
      p  <- 2p
  return (a + b)^2 / (4t)
#+end_example

* Worked example: error squaring each step

We print the estimate after each of the first few iterations alongside its error,
to watch the digit count double until double precision runs out.

#+name: gl-run
#+begin_src c++ :eval no
    std::cout << std::setprecision(16);
    std::cout << "=== Gauss-Legendre: pi by AGM ===\n";
    std::vector<double> its, logerr;
    for (int i = 1; i <= 6; ++i) {
        const double est = gauss_legendre_pi(i);
        const double err = std::fabs(est - PI);
        std::cout << "  iter " << i << ": " << est << "   error " << err << "\n";
        its.push_back(i); logerr.push_back(std::log10(std::max(err, 1e-17)));
    }

    auto plot = RPlot::create();
    plot.line(its, logerr, "log10 error", RGB{37, 99, 235}, 2.0);
    plot.points(its, logerr, "log10 error", RGB{37, 99, 235}, 8.0);
    plot.title("Gauss-Legendre: log10 error halves-squared each iteration")
        .x_label("iteration").y_label("log10 |estimate - pi|").background({250, 250, 252});
    plot.save_svg("build/org/gauss_legendre_pi.svg");
    std::cout << "\nwrote gauss_legendre_pi.svg\n";
#+end_src

The error drops from about \(10^{-3}\) to \(10^{-8}\) to below \(10^{-15}\) in
successive iterations -- each step roughly squares the previous error, the
signature of quadratic convergence. By iteration four the estimate is correct to
the last bit a =double= can store, and further iterations cannot improve it without
more precision.

The \(\log_{10}\) error plunges in a steepening curve -- not a straight line (that
would be linear convergence) but one whose slope keeps increasing, because each
iteration doubles the number of correct digits. The floor near \(-16\) is double
precision itself, the point past which only arbitrary-precision arithmetic reveals
new digits of \(\pi\).
