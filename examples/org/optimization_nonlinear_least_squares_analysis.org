parameters $(A,k,c)=(5,0.7,1)$, starting from the deliberately poor
guess $(1,0.1,0)$, =LevenbergMarquardt= recovers
$(5.046416,0.718982,1.018157)$ in 11 iterations (12 total
=residuals()= calls), driving the objective (=datamunge='s convention
$0.5\sum r_k^2$) from an initial =49.909912= down to a final
=0.285027= -- consistent with the added noise's own variance, not a
fitting failure. The first three of those 11 iterations are *rejected*
(the trial step's SSE rises before the damping term grows enough to
tame it), giving a genuinely non-monotonic convergence curve, exactly
the behavior the accept/reject-and-rescale-damping strategy is
supposed to produce. A harder logistic-growth problem
($L/(1+\exp(-k(t-t_0)))$, true $(L,k,t_0)=(10,1.5,5)$), started from an
even worse guess $(1,0.1,0)$ (initial objective =902.273049=), still
converges in 18 iterations to $(9.966641,1.582894,5.013407)$, with 12
accepted and 6 rejected steps. Reading the =.cpp= source directly (not
just its header) turns up two concrete, checkable implementation
details worth stating plainly: the normal-equation solve is a
hand-rolled dense Gaussian elimination with *no* partial pivoting
(despite that being an easy, standard addition), and the damping update
uses Levenberg's original flat additive form ($A_{pp}\mathrel{+}=
\lambda$) rather than Marquardt's later scale-invariant diagonal form
($A_{pp}\mathrel{+}=\lambda A_{pp}$).

* Introduction

Every other report in this series assumes an objective that returns a
single scalar -- =ArbitraryFunction::evaluate()=, possibly plus a
gradient or a Hessian. Nonlinear curve fitting has a different, richer
shape: the quantity being minimized is always a sum of squared
*residuals*, one per data point, and knowing each residual's own
gradient (a row of the Jacobian $\partial r_k/\partial\theta_p$)
lets an optimizer do much better than treating the sum as an opaque
scalar objective. =datamunge::optim= captures this with a fourth,
free-standing function-type interface, =ResidualFunction=
(=function_types.hpp=), deliberately *not* derived from
=ArbitraryFunction= or =DifferentiableFunction= at all:

#+begin_src c++ :eval no
class ResidualFunction {
public:
    virtual ~ResidualFunction() = default;
    virtual std::vector<double> residuals(
        const std::vector<double>& coordinates) = 0;
    virtual std::vector<std::vector<double>> jacobian(
        const std::vector<double>& coordinates) = 0;
};
#+end_src

=residuals()= returns $r(\theta) = [\text{model}(\theta;x_i) - y_i]_i$
and =jacobian()= returns the matrix of $\partial r_k/\partial\theta_p$
(rows indexed by data point, columns by parameter). The single
optimizer this report exercises, =LevenbergMarquardt=, consumes exactly
this interface, using both the residual vector and its Jacobian at
every iteration to build and solve a locally-linearized least-squares
problem -- the classic Levenberg-Marquardt algorithm, derived precisely
in §2 and checked against the real =.cpp= source line by line, not
against a generic textbook description.

This document is a /literate program/, like its companions in this
series: prose and source are interleaved in reading order, and a single
"assembling the program" step (§3.4.7) weaves every named chunk below
into one =.cpp= file, compiles it, and runs it. Every number and figure
from §4 onward is that program's literal output.

* Background: Gauss-Newton and Levenberg-Marquardt

** Linearizing the residuals: Gauss-Newton

Nonlinear least squares minimizes $f(\theta) = \frac{1}{2}\sum_k
r_k(\theta)^2$ over parameters $\theta$. Near a current estimate
$\theta$, each residual can be linearized in a small step $\delta$:

$$r(\theta+\delta) \approx r(\theta) + J\delta$$

where $J$ is the Jacobian, $J_{kp} = \partial r_k/\partial\theta_p$.
Substituting this linear model into $\frac{1}{2}\lVert
r(\theta)+J\delta\rVert^2$ and minimizing over $\delta$ (setting the
gradient with respect to $\delta$ to zero) gives the *normal equations*
of the Gauss-Newton method,

$$J^\top J\,\delta = -J^\top r.$$

This is exactly one step of Newton's method applied to $f$, but using
only first-derivative information: $J^\top J$ approximates the true
Hessian of $f$ by dropping the curvature-of-the-residuals term that a
full Hessian would include, which is cheap to compute and, near a good
fit (small residuals), an excellent approximation. Far from a good fit,
or when $J^\top J$ is singular or near-singular (redundant or weakly
identified parameters), the Gauss-Newton step can be a poor -- even
uphill -- direction.

** Levenberg's damping

Levenberg (1944) fixes this by adding a damping term to the normal
equations:

$$(J^\top J + \lambda I)\,\delta = -J^\top r.$$

As $\lambda\to 0$ this recovers the Gauss-Newton step exactly (fast,
locally quadratic convergence near a good fit); as $\lambda\to\infty$
the step direction rotates toward $-J^\top r/\lambda$, i.e. plain
gradient descent on $f$ with a shrinking step size (small, cautious,
robust far from the solution). $\lambda$ is adapted every iteration by
whether the resulting step actually improved the objective: an
accepted step means the local quadratic model was trustworthy, so
$\lambda$ shrinks, moving the next step closer to the fast Gauss-Newton
direction; a rejected step means the model was not trustworthy at this
$\lambda$, so $\lambda$ grows, moving the next step closer to safe
gradient descent. Marquardt (1963) later refined this by replacing the
isotropic $\lambda I$ with $\lambda\,\text{diag}(J^\top J)$ -- damping
each parameter in proportion to its own curvature, which makes the
method far less sensitive to parameters living on very different
numeric scales.

** What the real =.cpp= source actually does

=LevenbergMarquardtOptions= (=levenberg_marquardt.hpp=) has three
fields: =initial_damping= (default =1e-3=), =max_iterations= (default
=200=), and =tolerance= (default =1e-8=). Reading =levenberg_marquardt.cpp=
directly (it is dense but short enough to read as a whole) confirms
several concrete details worth stating precisely rather than assuming
the textbook version:

- =optimize()= returns $f(\theta)=\frac{1}{2}\sum_k r_k(\theta)^2$
  evaluated at the *final* accepted $\theta$ -- the same halved sum of
  squares convention used throughout this derivation, not a raw,
  un-halved SSE.
- Each iteration forms $A=J^\top J$ and $b=-J^\top r$ from a fresh call
  to =jacobian()= and the current =residuals()=, then adds damping with
  a plain loop over the diagonal that adds the damping value directly
  to each entry: $A_{pp}\mathrel{+}=\lambda$. This is Levenberg's
  original *flat additive* form, not Marquardt's scale-invariant
  $A_{pp}\mathrel{+}=\lambda A_{pp}$ variant -- a real, checkable
  implementation choice, not a simplification introduced by this
  report.
- $A\delta=b$ is solved by a hand-rolled dense Gaussian elimination
  (forward elimination row-by-row followed by back-substitution),
  written out explicitly rather than delegating to this project's own
  =linalg::= module. Reading the elimination loop closely, it performs
  *no partial pivoting whatsoever* -- there is no search for the
  largest-magnitude entry in a column before eliminating, and no row
  swap. This is a real, checkable simplification relative to the
  numerically-safer standard textbook recipe: the two synthetic
  problems in this report never hit the case where it matters (their
  $J^\top J+\lambda I$ diagonal never approaches zero at any visited
  $\theta$), but it is a genuine limitation for problems whose Jacobian
  can produce a small or zero pivot mid-elimination.
- A trial step $\theta'=\theta+\delta$ is *accepted* (the code sets
  =x= to the trial point) exactly when its objective value is strictly
  lower than the current value, in which case $\lambda$ is scaled down
  by =0.3=; otherwise the step is *rejected* (=x= is left unchanged)
  and $\lambda$ is scaled up by =10=. Critically, a rejected step is
  *not* retried at the new, larger
  $\lambda$ within the same outer iteration -- the code simply moves on
  to the next iteration (a fresh =jacobian()= call, even though
  $\theta$ did not move) and recomputes from there. This is simpler
  than the textbook backtracking-retry loop, and means a single
  "iteration" of this implementation can correspond to either an
  accepted Levenberg-Marquardt step or a wasted, no-op probe of the
  current $\lambda$.
- The loop terminates when $\lVert\delta\rVert\le$ =tolerance=, checked
  every iteration regardless of accept or reject, or after
  =max_iterations= iterations, whichever comes first.

Because =optimize()= does not expose an iteration history or a damping
trace directly, this report -- following the same pattern as
=optimization_analysis.org='s =LoggingDifferentiable= /
=LoggingArbitrary= decorators -- wraps =ResidualFunction= in a small
=LoggingResidual= class that records $0.5\sum r_k^2$ every time
=residuals()= is called, forwarding to the real objective unchanged.
Since =optimize()= calls =residuals()= exactly once before the loop
(the initial point) and exactly once per iteration (the trial step,
whether it is ultimately accepted or rejected), this log's length
equals $1+$ the number of iterations actually run, and it is possible
to recover the accept-or-reject sequence purely from the outside:
because $\theta$ (and hence
the value =v= compared against) only ever changes on an accepted step,
=v= is exactly the running minimum of the logged sequence, so a logged
value that is strictly less than the running minimum of everything
before it is an accepted step, and anything else is a rejected one.

* Data and Methods

** The data

Both problems use purely synthetic data with known ground-truth
parameters, generated with a fixed =std::mt19937_64= seed (never a
time-based seed) so every number in this report is exactly
reproducible. The first problem is exponential decay,
$y=A\exp(-kt)+c$, true parameters $(A,k,c)=(5.0,0.7,1.0)$, evaluated at
40 points $t=0,0.25,0.5,\dots,9.75$ with independent Gaussian noise
($\sigma=0.1$, seed =42=) added to each. The second is logistic growth,
$y=L/(1+\exp(-k(t-t_0)))$, true parameters $(L,k,t_0)=(10.0,1.5,5.0)$,
evaluated at 50 points $t=0,0.2,0.4,\dots,9.8$ with independent
Gaussian noise ($\sigma=0.15$, seed =43=) added to each. Both are fit
starting from the same kind of deliberately poor initial guess (small
amplitude, shallow rate, zero offset/midpoint) so that recovering the
true parameters from a genuinely bad starting point -- not merely
refining an already-close guess -- is what the results actually
demonstrate.

** Deriving each model's residual and Jacobian

For the exponential-decay model, $r_i(\theta) = A\exp(-kt_i)+c-y_i$
with $\theta=(A,k,c)$, so differentiating term by term gives

$$\frac{\partial r_i}{\partial A} = \exp(-kt_i), \qquad
\frac{\partial r_i}{\partial k} = -At_i\exp(-kt_i), \qquad
\frac{\partial r_i}{\partial c} = 1.$$

For the logistic-growth model, write $s_i =
1/(1+\exp(-k(t_i-t_0)))$ (the logistic curve's own value at $t_i$, a
number in $(0,1)$), so $r_i(\theta)=Ls_i-y_i$ with
$\theta=(L,k,t_0)$. Differentiating $s_i$ itself with respect to $k$
and $t_0$ and simplifying using $s_i(1-s_i) = \exp(-k(t_i-t_0)) /
(1+\exp(-k(t_i-t_0)))^2$ gives

$$\frac{\partial r_i}{\partial L} = s_i, \qquad
\frac{\partial r_i}{\partial k} = L(t_i-t_0)\,s_i(1-s_i), \qquad
\frac{\partial r_i}{\partial t_0} = -Lk\,s_i(1-s_i).$$

Both derivations are implemented directly in =lm-includes= below
(=ExpDecayResidual::jacobian=, =LogisticResidual::jacobian=) and, per
this series' standard of never trusting a hand-derived Jacobian
without checking it, verified numerically in §3.4.2 against a central
finite-difference approximation before either fit is run.

namespace {

class ExpDecayResidual : public ResidualFunction {
public:
    ExpDecayResidual(std::vector<double> t, std::vector<double> y)
        : t_(std::move(t)), y_(std::move(y)) {}

    std::vector<double> residuals(const std::vector<double>& theta)
        override {
        const double A = theta[0], k = theta[1], c = theta[2];
        std::vector<double> r(t_.size());
        for (std::size_t i = 0; i < t_.size(); ++i) {
            r[i] = A * std::exp(-k * t_[i]) + c - y_[i];
        }
        return r;
    }
    std::vector<std::vector<double>> jacobian(
        const std::vector<double>& theta) override {
        const double A = theta[0], k = theta[1];
        std::vector<std::vector<double>> j(t_.size(),
                                            std::vector<double>(3));
        for (std::size_t i = 0; i < t_.size(); ++i) {
            const double e = std::exp(-k * t_[i]);
            j[i][0] = e;
            j[i][1] = -A * t_[i] * e;
            j[i][2] = 1.0;
        }
        return j;
    }

private:
    std::vector<double> t_;
    std::vector<double> y_;
};

class LogisticResidual : public ResidualFunction {
public:
    LogisticResidual(std::vector<double> t, std::vector<double> y)
        : t_(std::move(t)), y_(std::move(y)) {}

    std::vector<double> residuals(const std::vector<double>& theta)
        override {
        const double L = theta[0], k = theta[1], t0 = theta[2];
        std::vector<double> r(t_.size());
        for (std::size_t i = 0; i < t_.size(); ++i) {
            const double s = 1.0 / (1.0 + std::exp(-k * (t_[i] - t0)));
            r[i] = L * s - y_[i];
        }
        return r;
    }
    std::vector<std::vector<double>> jacobian(
        const std::vector<double>& theta) override {
        const double L = theta[0], k = theta[1], t0 = theta[2];
        std::vector<std::vector<double>> j(t_.size(),
                                            std::vector<double>(3));
        for (std::size_t i = 0; i < t_.size(); ++i) {
            const double s = 1.0 / (1.0 + std::exp(-k * (t_[i] - t0)));
            j[i][0] = s;
            j[i][1] = L * (t_[i] - t0) * s * (1.0 - s);
            j[i][2] = -L * k * s * (1.0 - s);
        }
        return j;
    }

private:
    std::vector<double> t_;
    std::vector<double> y_;
};

// Logs 0.5*sum(r^2) every time residuals() is called, for building a
// convergence-curve figure (mirrors LoggingDifferentiable and
// LoggingArbitrary from optimization_analysis.org).
class LoggingResidual : public ResidualFunction {
public:
    LoggingResidual(ResidualFunction& inner, std::vector<double>& log)
        : inner_(&inner), log_(&log) {}
    std::vector<double> residuals(const std::vector<double>& x) override {
        auto r = inner_->residuals(x);
        double sse = 0.0;
        for (const double v : r) sse += 0.5 * v * v;
        log_->push_back(sse);
        return r;
    }
    std::vector<std::vector<double>> jacobian(
        const std::vector<double>& x) override {
        return inner_->jacobian(x);
    }

private:
    ResidualFunction* inner_;
    std::vector<double>* log_;
};

void print_vec(const std::vector<double>& v) {
    std::cout << "[";
    for (std::size_t i = 0; i < v.size(); ++i) {
        std::cout << (i ? ", " : "") << v[i];
    }
    std::cout << "]";
}

// Central finite-difference Jacobian check, run before either fit is
// trusted.
double max_abs_jac_diff(ResidualFunction& f, const std::vector<double>& x,
                         double h = 1e-6) {
    auto j_analytic = f.jacobian(x);
    double max_diff = 0.0;
    for (std::size_t p = 0; p < x.size(); ++p) {
        auto xp = x, xm = x;
        xp[p] += h;
        xm[p] -= h;
        auto rp = f.residuals(xp);
        auto rm = f.residuals(xm);
        for (std::size_t k = 0; k < rp.size(); ++k) {
            const double fd = (rp[k] - rm[k]) / (2 * h);
            max_diff = std::max(max_diff, std::abs(fd - j_analytic[k][p]));
        }
    }
    return max_diff;
}

    const double L_true = 10.0, k2_true = 1.5, t0_true = 5.0;
    {

        log_t.resize(N);

        std::mt19937_64 rng(43);
        std::normal_distribution<double> noise(0.0, 0.15);
        for (std::size_t i = 0; i < N; ++i) {

            log_t[i] = t;

        }

        LogisticResidual f(log_t, log_y_noisy);
        LoggingResidual lf(f, logistic_log);
        std::vector<double> theta{1.0, 0.1, 0.0};
        auto r0 = f.residuals(theta);
        double sse0 = 0.0;
        for (double v : r0) sse0 += 0.5 * v * v;

        LevenbergMarquardt lm;
        const double final_val = lm.optimize(lf, theta);

        std::cout << "initial theta (L,k,t0): [1, 0.1, 0]  initial SSE/2: "
                   << sse0 << "\n";
        std::cout << "true theta (L,k,t0):    [" << L_true << ", "
                   << k2_true << ", " << t0_true << "]\n";
        std::cout << "fitted theta (L,k,t0): ";
        print_vec(theta);
        std::cout << "\nfinal value (0.5*sum r^2): " << final_val << "\n";
        std::cout << "residuals() calls logged: " << logistic_log.size()
                   << " (= 1 initial + " << (logistic_log.size() - 1)
                   << " LM iterations)\n";

        std::size_t accepts = 0, rejects = 0;
        double running_min = logistic_log[0];
        for (std::size_t i = 1; i < logistic_log.size(); ++i) {
            if (logistic_log[i] < running_min) {
                accepts++;
                running_min = logistic_log[i];
            } else {
                rejects++;
            }
        }
        std::cout << "accepted steps: " << accepts
                   << "  rejected steps: " << rejects << "\n";
    }
#+end_src

The logistic problem is deliberately harder: the initial guess
$(L,k,t_0)=(1,0.1,0)$ is even further from the truth
$(10,1.5,5)$ in relative terms (an almost-flat curve near $y\approx0.5$
against a curve that swings from near 0 to 10 over a narrow window
centered at $t=5$), and its initial objective, =902.273049=, is roughly
18x the exponential-decay problem's initial objective despite using a
comparable number of data points and comparable noise. =LevenbergMarquardt=
still recovers $(9.966641,1.582894,5.013407)$, within about =0.08= of
true $k$ and =0.01= of true $L$ and $t_0$, in 18 iterations -- more than
the 11 the easier exponential-decay problem needed, and with a higher
rejected-step count (6, versus 3), consistent with a harder,
more nonlinear starting landscape genuinely needing more of the
cautious, gradient-descent-like behavior Levenberg's damping falls back
to when the local quadratic model is untrustworthy.

* Discussion

**Both problems' rejected steps cluster at the very start of
optimization, not randomly throughout the run.** In the
exponential-decay fit, all 3 rejects are the first 3 logged steps;
every one of the remaining 8 is accepted. This is exactly what the
\(\lambda\)-adaptation logic in §2.2 predicts: the fixed
=initial_damping= (=1e-3=) is tuned for a well-behaved local landscape,
but the deliberately bad starting
guess here is far from where that local quadratic model is accurate,
so the first few trial steps overshoot and get rejected, growing
$\lambda$ by =10x= each time until the model becomes trustworthy,
after which every further step is accepted and $\lambda$ only shrinks.
The logistic problem's larger reject count (6 of 18) fits the same
story at a harder difficulty: a more nonlinear starting landscape needs
more rounds of $\lambda$ growth before the quadratic model becomes
locally trustworthy.

**The absence of partial pivoting in the normal-equation solve is a
real, checkable simplification, not a flaw either synthetic problem in
this report happens to expose.** Both problems here have small,
well-conditioned $3\times3$ systems throughout their entire trajectory
(three parameters, dozens of data points, no near-collinear columns in
either Jacobian), so a pivot-free elimination never encounters a small
or zero diagonal entry. A residual model whose Jacobian columns become
nearly linearly dependent at some point along the optimization path
-- e.g. two parameters that are only weakly identified together, a
common occurrence in more elaborate nonlinear models -- could hit
exactly the failure mode partial pivoting exists to avoid (a near-zero
or zero pivot producing a huge or =NaN= step). This report cannot
demonstrate that failure without deliberately constructing an
ill-conditioned problem, but the absence of the safeguard is directly
visible in the source and worth stating plainly as a known limitation.

**Levenberg's flat additive damping, not Marquardt's scale-invariant
variant, means this implementation is more sensitive to the relative
scale of different parameters than the 1963 refinement would be.** Both
problems in this report were deliberately parameterized so their three
parameters ($A$, $k$, $c$ or $L$, $k$, $t_0$) sit within roughly one
order of magnitude of each other, sidestepping the scale sensitivity
$a_{pp}\mathrel{+}=\lambda$ (as opposed to
$a_{pp}\mathrel{+}=\lambda a_{pp}$) would otherwise introduce; a problem
with, say, one parameter of order $10^{-6}$ and another of order
$10^{6}$ would push the same fixed $\lambda$ to damp one parameter's
direction far more heavily than the other's relative to its own natural
scale, an effect this report's own well-scaled problems do not surface.

**A convergence curve built purely from an external logging decorator,
with no changes to the library, was sufficient to recover the full
accept/reject sequence of an algorithm whose implementation never
exposes it.** Because =v= (the value compared against every trial step)
is provably the running minimum of the logged sequence -- it only ever
decreases, and only on an accepted step -- the accept/reject flags in
§4.2 required no instrumentation inside =levenberg_marquardt.cpp=
itself, only a wrapper around =ResidualFunction::residuals()=. This is
the same technique =optimization_analysis.org= uses for its own
convergence curves, extended here to recover strictly more information
(a full accept/reject trace, not just a value trace) than that
report needed.

* Conclusion

Fitting two synthetic nonlinear curves with known ground truth from
deliberately bad starting points shows =datamunge='s
=LevenbergMarquardt= working as the derivation in §2 predicts: damping
adapts from an early run of rejected, overly-optimistic steps into a
steady run of accepted, fast-converging ones, recovering
$(5.046416,0.718982,1.018157)$ against true $(5,0.7,1)$ in 11
iterations on the easier exponential-decay problem, and
$(9.966641,1.582894,5.013407)$ against true $(10,1.5,5)$ in 18
iterations on the harder logistic-growth problem. Reading the =.cpp=
source directly surfaced two concrete, honest implementation details
worth remembering when using this class on harder problems than either
synthetic example here: the dense linear solve has no partial pivoting,
and the damping update is Levenberg's original scale-sensitive form
rather than Marquardt's later scale-invariant one. As with its
companions, this entire report is reproducible end to end via
=just org-example optimization_nonlinear_least_squares_analysis=,
which re-executes §3.4.7's assembly block -- and therefore every number
and figure above -- from the =datamunge= source tree.
