#+begin_abstract
*Shortest-Job-Next* (SJN, a.k.a. non-preemptive shortest-job-first) always dispatches the
ready process with the smallest CPU burst. Among non-preemptive schedulers it is *provably
optimal* for average waiting time -- running short jobs first minimizes the total time other
jobs spend queued. Its cost is that a long job arriving first monopolizes the CPU (the
*convoy effect*), and that burst lengths must be known or estimated. This report implements
it in =datamunge='s C++ =algorithms::shortest_job_next= as a literate program: every number
and figure comes from one compiled binary. We schedule four staggered arrivals, draw the
timeline, and report waiting and turnaround times.
#+end_abstract

* Pick the shortest ready job

Whenever the CPU becomes free, SJN scans the *arrived, unfinished* processes and starts the
one with the smallest total burst (ties broken by arrival, then id), running it to
completion. The optimality is a rearrangement argument: if a longer job ran before a shorter
one that is also ready, swapping them lowers the shorter job's completion time by more than
it raises the longer job's, so total (hence average) waiting time drops. Because it is
non-preemptive, a job already running is never interrupted -- so a long job that starts before
short ones arrive still delays them, the convoy effect.

#include <datamunge/algorithms/cpu_scheduling.hpp>

#include <cstddef>

#include <string>

using namespace datamunge::algorithms;
using namespace datamunge::plot;

// Draw a Gantt chart: one horizontal row per process id, a colored box per run slice.
inline void draw_gantt(const ScheduleResult& r, std::size_t nproc, const char* path) {
    static const RGB palette[] = {{37,99,235},{220,38,38},{22,163,74},{202,138,4},{147,51,234}};
    RPlot p = RPlot::create();
    for (const auto& g : r.gantt) {
        double y = static_cast<double>(g.id);
        p.polygon({(double)g.start,(double)g.end,(double)g.end,(double)g.start},
                  {y-0.4, y-0.4, y+0.4, y+0.4}, palette[g.id % 5], true);
    }
    std::vector<double> ax, ay;
    for (std::size_t i = 0; i < nproc; ++i) { ax.push_back(0.0); ay.push_back((double)i); }
    p.points(ax, ay, "", {0,0,0}, 0.1);
    p.save_svg(path);
}
#+end_src

** Pseudocode

#+begin_example
SJN(processes):
    while some process unfinished:
        ready = arrived, unfinished processes
        if ready empty: advance time to next arrival; continue
        i = ready process with smallest burst (ties: arrival, then id)
        run i to completion; advance time; record completion[i]
#+end_example

* A worked example

Four processes arrive at times 0, 1, 2, 3 with bursts 6, 3, 1, 4. The long job P0 is already
running when the short jobs arrive, so we see the convoy effect.

#+name: sjn-run
#+begin_src c++ :eval no
    std::vector<SchedProcess> procs = {{0,0,6},{1,1,3},{2,2,1},{3,3,4}};
    auto r = shortest_job_next(procs);

    std::cout << "=== Shortest-job-next ===\n";
    std::cout << "arrivals/bursts: P0(a0,b6) P1(a1,b3) P2(a2,b1) P3(a3,b4)\n\n";
    std::cout << "execution timeline:\n";
    for (const auto& g : r.gantt)
        std::cout << "  [" << g.start << "," << g.end << ") P" << g.id << "\n";

    std::cout << "\nproc  completion  turnaround  waiting\n";
    for (const auto& m : r.metrics)

                  << "          " << m.turnaround << "         " << m.waiting << "\n";

* Results

#+begin_example
=== Shortest-job-next ===
arrivals/bursts: P0(a0,b6) P1(a1,b3) P2(a2,b1) P3(a3,b4)

execution timeline:
  [0,6) P0
  [6,7) P2
  [7,10) P1
  [10,14) P3

proc  completion  turnaround  waiting
  P0        6          6         0
  P1        10          9         6
  P2        7          5         4
  P3        14          11         7
average waiting = 4.25, average turnaround = 7.75
#+end_example

Because the long job P0 is already on the CPU when the short jobs arrive, SJN cannot preempt
it: P0 runs to completion first, and only then does the scheduler serve the shortest waiting
job. Once P0 finishes, the tiny job P2 goes ahead of the longer P1 and P3 -- shortest-first
among those ready -- keeping the average waiting time as low as a non-preemptive scheduler can.
The preemptive companion, shortest-remaining-time, avoids the convoy effect by interrupting
P0 the moment a shorter job appears.

* Character and relatives

SJN minimizes average waiting time among non-preemptive policies but needs the (generally
unknown) burst lengths, which real systems *estimate* via an exponentially weighted average of
recent bursts. It can *starve* long jobs if short ones keep arriving. Its preemptive version,
*shortest-remaining-time* (companion report), is optimal for average waiting time over all
schedulers but switches context more often; *round-robin* ignores burst length entirely in
favor of fairness. Priority scheduling generalizes all of these by dispatching on an arbitrary
priority key rather than burst length.

* Complexity

\(O(n^2)\) in the simple form here (scan all ready processes at each of \(n\) dispatch points);
a priority queue keyed on burst reduces the selection to \(O(\log n)\) per dispatch,
\(O(n\log n)\) overall.
