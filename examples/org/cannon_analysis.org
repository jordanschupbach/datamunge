#+begin_abstract
Multiplying two \(n\times n\) matrices on a grid of processors sounds like it needs each
processor to see whole rows and columns -- expensive global communication. *Cannon's algorithm*
(1969) avoids that: it *skews* the two matrices with cyclic shifts so that, at each of \(n\)
steps, every processor holds a matching pair of blocks to multiply and accumulate, then shifts
its blocks to the *nearest neighbour*. The whole product is formed with only local, nearest-
neighbour communication and \(O(1)\) block storage per node. This report drives =datamunge='s
sequential =algorithms::cannon_matmul=, which follows the same schedule, and verifies it against
the ordinary product.
#+end_abstract

* Skew, then shift-multiply-accumulate

Lay \(A\) and \(B\) on an \(n\times n\) grid, one entry per cell. Cannon first *pre-skews* them:
row \(i\) of \(A\) is rotated left by \(i\), and column \(j\) of \(B\) is rotated up by \(j\).
After this alignment, cell \((i,j)\) holds \(A_{i,(j+i)}\) and \(B_{(i+j),j}\) -- a pair whose
product is one term of \(C_{ij}\). Then repeat \(n\) times:

1. every cell multiplies its current \(A\)- and \(B\)-block and adds to \(C_{ij}\);
2. \(A\) shifts one step left, \(B\) shifts one step up.

Over the \(n\) steps each cell sees exactly the \(n\) products \(A_{ik}B_{kj}\) that sum to
\(C_{ij}\), so the result is the exact product. The point is *communication*: no broadcasts, no
global gather -- just \(2n\) nearest-neighbour shifts of \(O(1)\)-sized blocks, which is what
makes it scale on a physical mesh. This sequential version runs the same skew-and-shift schedule
in one process.

* Algorithm

#+begin_example
CANNON(A, B, n):
  skew: A[i][j] <- A[i][(j+i) mod n];  B[i][j] <- B[(i+j) mod n][j]
  C <- 0
  repeat n times:
      C[i][j] += A[i][j] * B[i][j]                     # local multiply-accumulate
      shift A one column left; shift B one row up      # nearest-neighbour communication
  return C
#+end_example

* Worked example: correctness against the ordinary product

We multiply a small matrix by hand-check, then confirm Cannon reproduces the naive triple-loop
product across random matrices, entry for entry.

#+name: cn-run
#+begin_src c++ :eval no
    // A hand-checkable 2x2: [[1,2],[3,4]] * [[5,6],[7,8]] = [[19,22],[43,50]].
    const std::vector<double> A2{1, 2, 3, 4}, B2{5, 6, 7, 8};
    const auto C2 = cannon_matmul(A2, B2, 2);
    std::cout << "=== [[1,2],[3,4]] * [[5,6],[7,8]] ===\n";
    std::cout << "Cannon = [[" << C2[0] << "," << C2[1] << "],[" << C2[2] << "," << C2[3] << "]] (expected [[19,22],[43,50]])\n\n";

    // Random check: Cannon vs naive, scatter each entry.
    std::mt19937 rng(11);
    std::uniform_real_distribution<double> val(-5, 5);
    const int n = 7;
    std::vector<double> A(n * n), B(n * n);
    for (double& x : A) x = val(rng);
    for (double& x : B) x = val(rng);
    std::vector<double> naive(n * n, 0.0);
    for (int i = 0; i < n; ++i) for (int k = 0; k < n; ++k) for (int j = 0; j < n; ++j) naive[i * n + j] += A[i * n + k] * B[k * n + j];
    const auto C = cannon_matmul(A, B, n);

    double maxerr = 0.0;
    std::vector<double> cx, cy;
    for (int e = 0; e < n * n; ++e) { maxerr = std::max(maxerr, std::fabs(C[e] - naive[e])); cx.push_back(naive[e]); cy.push_back(C[e]); }
    std::cout << "random 7x7: max |Cannon - naive| = " << maxerr << " over all " << n * n << " entries\n";

    auto plot = RPlot::create();
    plot.points(cx, cy, "entries", RGB{37, 99, 235}, 6.0);
    plot.abline(0.0, 1.0, RGB{148, 163, 184}, 1.5);
    plot.legend({"C entry: Cannon vs naive", "y = x"}, {{37, 99, 235}, {148, 163, 184}});
    plot.title("Cannon's algorithm reproduces the product exactly (every point on y = x)")
        .x_label("naive product entry").y_label("Cannon product entry").background({250, 250, 252});
    plot.save_svg("build/org/cannon.svg");
    std::cout << "wrote cannon.svg\n";
#+end_src

The \(2\times2\) product is exactly \([[19,22],[43,50]]\), and on the random \(7\times7\) case
Cannon matches the naive triple-loop product to the last bit -- zero error across every entry.
The skew-and-shift choreography computes the same sums as the textbook algorithm, just arriving
at each \(C_{ij}\) through a rotating stream of nearest-neighbour block exchanges.
