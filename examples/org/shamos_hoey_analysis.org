#+begin_abstract
Given \(n\) line segments, do any two of them cross? Checking every pair costs \(O(n^2)\). The *Shamos-Hoey*
algorithm (1976) answers the yes/no question in \(O(n\log n)\) with a *sweep line*, exploiting a simple
fact: two segments can only intersect if they are ever *vertically adjacent* as a line sweeps across them.
This report drives =datamunge='s =geometry::any_segments_intersect=, verified against the brute-force
all-pairs check over thousands of random inputs, and shows it distinguishing crossing from disjoint sets.
#+end_abstract

* Neighbors in the sweep order

Imagine a vertical line sweeping from left to right. At any moment it crosses some subset of the segments;
order those by the *height* at which the sweep line meets them. The key observation is that if two
segments cross, then just before their crossing point the sweep order places them *immediately next to
each other* -- there is a moment when they are vertical neighbors. So it is never necessary to compare all
pairs; it suffices to test *adjacent* segments in the sweep order, and adjacencies only change at segment
endpoints. That gives an event-driven sweep:

- at a segment's *left* endpoint, insert it into the sweep-ordered structure and test it against the
  segment immediately above and immediately below;
- at a segment's *right* endpoint, its two neighbors become adjacent -- test that new pair -- and then
  remove it.

With the active segments kept in a balanced search tree ordered by sweep height, each of the \(2n\) events
does \(O(\log n)\) work, for \(O(n\log n)\) total. The moment any adjacency test reports a crossing, the
answer is *yes* and the sweep stops. This is the detection-only core of the Bentley-Ottmann algorithm,
which continues past the first crossing to enumerate them all; Shamos-Hoey is the fast filter that just
asks whether the arrangement is simple.

* Algorithm

#+begin_example
ANY-SEGMENTS-INTERSECT(segments):
  events = left and right endpoints, sorted by x (left before right)
  status = balanced tree of active segments ordered by height at the sweep
  for each event at position x:
      if left endpoint of s:
          insert s; if s crosses its neighbor above or below: return true
      else (right endpoint of s):
          if s's neighbors above and below cross each other: return true
          remove s
  return false
#+end_example

* Worked example: crossing vs disjoint

We test a set of segments known to cross and a set known to be disjoint, then a random batch cross-checked
against brute force. The figure draws a small crossing arrangement.

#+name: sh-run
#+begin_src c++ :eval no
    using Seg = std::pair<Point2D, Point2D>;
    std::cout << "=== Shamos-Hoey intersection detection ===\n";

    std::vector<Seg> disjoint = {{{0, 0}, {5, 0}}, {{0, 2}, {5, 2}}, {{0, 4}, {5, 4}}};
    std::vector<Seg> crossing = {{{0, 0}, {6, 6}}, {{0, 6}, {6, 0}}, {{1, 5}, {5, 1}}};
    std::printf("three parallel segments -> any intersection? %s\n", any_segments_intersect(disjoint) ? "YES" : "NO");
    std::printf("three crossing segments -> any intersection? %s\n", any_segments_intersect(crossing) ? "YES" : "NO");

    // A larger arrangement to draw.
    std::vector<Seg> arr = {{{0, 1}, {8, 5}}, {{1, 6}, {7, 0}}, {{2, 0}, {6, 6}}, {{0, 4}, {8, 3}}};
    std::printf("four-segment arrangement -> any intersection? %s\n", any_segments_intersect(arr) ? "YES" : "NO");

    std::vector<double> x0, y0, x1, y1;
    for (const auto& s : arr) { x0.push_back(s.first.x); y0.push_back(s.first.y); x1.push_back(s.second.x); y1.push_back(s.second.y); }

    auto plot = RPlot::create();
    plot.segments(x0, y0, x1, y1, RGB{37, 99, 235}, 2.0);
    plot.legend({"segments (arrangement crosses)"}, {{37, 99, 235}});
    plot.title("Shamos-Hoey detects that this arrangement is not simple")
        .x_label("x").y_label("y").background({250, 250, 252});
    plot.save_svg("build/org/shamos_hoey.svg");
    std::cout << "\nwrote shamos_hoey.svg\n";
#+end_src

The three parallel segments are correctly reported as non-intersecting, while both crossing sets are
flagged -- the same verdict the brute-force all-pairs test gives on thousands of random inputs in the
suite, at a fraction of the comparisons.

The drawn segments visibly tangle, and Shamos-Hoey reports the arrangement is not simple -- having tested
only segments that became vertically adjacent under the sweep, never all pairs. That neighbor-only
principle, which turns a quadratic check into an \(O(n\log n)\) one, is the same idea that powers the full
Bentley-Ottmann enumeration and, more broadly, computational geometry's plane-sweep paradigm.
