* Introduction

Every clustering, classification, and regression report in this project
asks "what does =Species= (or some other response) depend on?" This
report asks a different kind of question entirely: given only the four
numeric measurements and /no/ response at all, what are the directions
of greatest variation in the data, and how many of them do we actually
need to describe it well? =stats::PCA= answers this by eigendecomposing
the covariance (or correlation) matrix of the centered (and, by default,
standardized) features, producing an ordered set of orthogonal axes --
principal components -- each capturing as much of the remaining variance
as possible given the axes already chosen.

As with its companion reports, this document is a /literate program/:
prose and source are interleaved in reading order, and a single
"assembling the program" step (§3.3.8) weaves every named chunk below
into one =.cpp= file, compiles it, and runs it. Every number and figure
from §4 onward is that program's literal output.

§2 derives the covariance/correlation eigendecomposition, loadings,
scores, explained variance, and the truncated-reconstruction identity,
each tied to the specific =PCA= method that implements it. §3 describes
the program chunk by chunk. §4 reports the fitted components, their
loadings, a scores scatter colored by the (withheld) true species, a
scree plot, a reconstruction-error sweep, and a comparison against
unscaled PCA. §5 discusses what "explains variance" does and does not
mean for this data, and connects the reconstruction sweep back to the
scree plot. §6 concludes.

* Background: Principal Component Analysis

** Setup and notation

\(n = 150\) flowers, \(p = 4\) predictors (\(x_i \in \mathbb{R}^4\):
=Sepal.Length=, =Sepal.Width=, =Petal.Length=, =Petal.Width=) -- and, as
in the [[file:clustering_iris_analysis.org][clustering companion
report]], no response variable at all during fitting. =Species= is
retained separately in this report's own code and used only afterward to
color the scores scatter, never passed to the =PCA= constructor.

** Centering, scaling, and the covariance/correlation matrix

Write \(X \in \mathbb{R}^{n \times p}\) for the raw feature matrix.
=PCA= first centers every column to zero mean (=PCAOptions::center=,
default true):

\[
X^c_{ij} = X_{ij} - \bar{x}_j, \qquad \bar{x}_j = \frac{1}{n}\sum_{i=1}^n X_{ij} .
\]

If =PCAOptions::scale= is also true (the default here, though R's own
=prcomp= defaults it to false while documenting true as generally
recommended), each centered column is further divided by its sample
standard deviation, so every feature contributes on a comparable scale
regardless of its original units:

\[
X^s_{ij} = X^c_{ij} \, / \, s_j, \qquad s_j = \sqrt{\frac{1}{n-1}\sum_{i=1}^n (X^c_{ij})^2} .
\]

The \(p \times p\) covariance matrix of the (centered, optionally scaled)
data,

\[
C = \frac{1}{n-1} (X^s)^\top X^s ,
\]

is exactly the /correlation/ matrix of the raw features when scaling is
on, and the raw /covariance/ matrix when it is off -- §4.5 fits both and
shows they give a materially different answer for this data.

** Eigendecomposition, loadings, and scores

\(C\) is symmetric and positive semi-definite by construction, so it
admits a real eigendecomposition \(C = V \Lambda V^\top\) with
orthonormal eigenvectors \(V = [v_1, \ldots, v_p]\) (the /loadings/,
returned by =loadings()=/=component_loadings(c)=, one unit-length column
per component) and non-negative eigenvalues
\(\lambda_1 \geq \cdots \geq \lambda_p \geq 0\) (=explained_variance()=,
sorted descending). =PCA::fit= computes this via
=linalg::jacobi_eigen=, the same classical cyclic-Jacobi symmetric
eigensolver this project's =LDA= report already uses for its own
(differently-shaped) generalized eigenproblem. Each observation's
/scores/ -- its coordinates in principal-component space -- are its
centered/scaled feature vector re-expressed in the eigenvector basis,

\[
\text{scores} = X^s V ,
\]

matching =scores()=/=component_scores(c)= directly; a single row's
\(c\)-th score is the \(c\)-th principal component's numeric summary of
that flower.

** Explained variance and the scree plot

Each eigenvalue is the variance /along/ its corresponding principal
axis, so the proportion of total variance the \(c\)-th component
explains is simply

\[
\text{ratio}_c = \lambda_c \, / \, \sum_{k=1}^p \lambda_k ,
\]

matching =explained_variance_ratio()= directly, with
=cumulative_explained_variance_ratio()= its running sum. A /scree plot/
(=plot_scree()=, §4.4's figure) is just this ratio plotted as a bar per
component -- the traditional (if informal, much like the clustering
report's own elbow method) way to eyeball how many components "matter."

** Reconstruction and the Eckart-Young theorem

Because \(V\) is orthonormal (\(V V^\top = I\)), the original centered/
scaled data can be recovered /exactly/ from the full set of \(p\) scores,
\(X^s = (\text{scores}) V^\top\). Truncating to only the first \(k < p\)
components,

\[
\hat{X}^s_{(k)} = (\text{scores}_{:,1:k}) \, V_{:,1:k}^\top ,
\]

gives the /best possible/ rank-\(k\) approximation to \(X^s\) in the
least-squares sense (the Eckart-Young theorem) -- no other rank-\(k\)
matrix achieves lower reconstruction error. §4.5's sweep computes this
reconstruction directly from =scores()= and =component_loadings()= for
\(k = 1, \ldots, 4\) and reports the root-mean-square error against the
true (\(k=4\), lossless) reconstruction.

** What we will report

Given the fit, we report exploratory data (true species, for later
visual comparison), the fitted components' explained variance and
loadings, a scores scatter, a scree plot, a reconstruction-error sweep,
and a comparison against PCA fit without scaling.

* Data and Methods

** The data

As in every companion report: =datamunge::datasets::iris()= returns
Fisher's 150 flowers -- 50 each of /setosa/, /versicolor/, /virginica/ --
measured on =Sepal.Length=, =Sepal.Width=, =Petal.Length=, =Petal.Width=
(cm), with no missing values. All four measurements are used as PCA
features throughout; =Species= is withheld from the constructor and used
only for the exploratory and scores figures.

** Software

The entire analysis is one C++ program against =datamunge=:
=dstruct::DataFrame= for the data, =stats::PCA= for the model, and
=plot::RPlot= for every figure. No external plotting or statistics
package is used.

*** Reconstruction-error sweep

#+name: pca-reconstruction-sweep
#+begin_src c++ :eval no
    std::cout << "\n=== Reconstruction error vs. number of retained"
               << " components ===\n";
    {
        std::vector<double> ks, rmse_values;
        std::cout << std::setw(6) << "k" << std::setw(16) << "RMSE\n";
        for (std::size_t k = 1; k <= 4; ++k) {
            double sum_sq = 0.0;
            std::size_t count = 0;
            for (std::size_t i = 0; i < pca.observations(); ++i) {
                for (std::size_t j = 0; j < features.size(); ++j) {
                    double reconstructed = 0.0;
                    for (std::size_t c = 0; c < k; ++c)
                        reconstructed +=
                            pca.scores()(i, c) * pca.component_loadings(c)[j];
                    double original = 0.0;
                    for (std::size_t c = 0; c < features.size(); ++c)
                        original +=
                            pca.scores()(i, c) * pca.component_loadings(c)[j];
                    const double diff = original - reconstructed;
                    sum_sq += diff * diff;
                    ++count;
                }
            }
            const double rmse =
                std::sqrt(sum_sq / static_cast<double>(count));
            ks.push_back(static_cast<double>(k));
            rmse_values.push_back(rmse);
            std::cout << std::setw(6) << k << std::setw(16) << rmse << "\n";
        }
        auto recon_plot = RPlot::plot(ks, rmse_values, "b", "RMSE",
                                       {37, 99, 235});
        recon_plot.title("Reconstruction Error vs. Retained Components")
            .x_label("components retained (k)")
            .y_label("RMSE (standardized units)")
            .background({250, 250, 252});
        recon_plot.save_svg("build/org/pca_iris_reconstruction.svg");
        std::cout << "wrote pca_iris_reconstruction.svg\n";
    }
#+end_src

** Reconstruction error

#+ATTR_HTML: :alt Line plot of reconstruction RMSE against retained components :width 100%
[[file:../../build/org/pca_iris_reconstruction.svg]]

| k | RMSE (standardized units) |
|---+----------------------------|
| 1 | 0.5182 |
| 2 | 0.2039 |
| 3 | 0.0717 |
| 4 | 0.0000 |

RMSE falls monotonically and reaches exactly zero at \(k=4\), the full
rank -- the Eckart-Young identity from §2.5 made concrete: with all four
orthonormal loadings available, =scores() \(\times\) loadings()^\top=
recovers the centered/scaled data exactly, no approximation involved.
The steepest single drop, from \(k=1\) to \(k=2\) (0.52 to 0.20, a 61%
reduction), matches §4.2's own observation that PC2 alone adds another
22.85 percentage points of explained variance -- the two views (variance
explained, reconstruction error) are two sides of the same
eigendecomposition and necessarily agree.

** PCA without scaling

#+begin_example
PC1 explains 92.4619% of variance (scaled: 72.9624%)
PC1 loadings (unscaled): 0.3614 -0.0845 0.8567 0.3583
#+end_example

Fit on the raw covariance matrix instead of the correlation matrix, PC1
alone explains 92.46% of variance -- nearly all of it -- because
=Sepal.Length='s substantially larger raw numeric spread dominates the
unscaled covariance matrix regardless of whether it is actually the
"most informative" feature in any deeper sense. The unscaled PC1
loadings (0.36, -0.08, 0.86, 0.36) are also visibly different from the
scaled ones (0.52, -0.27, 0.58, 0.56): =Petal.Length= alone now
dominates (0.86), since it happens to have the largest raw variance
among the four features. This is the standard cautionary example for why
=PCAOptions::scale= defaults to true here: without it, PCA silently
answers "which feature has the largest numeric range" rather than "which
directions capture the most /shape/ variation," and the two questions
happen to have different answers for this dataset.

* Discussion

**"Explains variance" is not the same as "is biologically important."**
PC1's loadings are large for the petal measurements not because petal
size is inherently more biologically meaningful than sepal width, but
because petal measurements happen to /covary more/ across these 150
flowers. §4.5's unscaled-vs-scaled comparison makes this concrete in a
different way: change only the units-handling convention, and the same
mathematical procedure assigns "most important" to a completely
different feature (=Sepal.Length='s raw scale versus =Petal.Length='s
raw variance). Explained variance is a purely geometric, data-relative
quantity, not a domain-knowledge judgment.

**The scree plot and the reconstruction sweep are the same information,
twice.** §4.4's bar chart and §4.5's RMSE curve are computed from
entirely separate code paths in this report (one from
=explained_variance_ratio()=, one from a manual =scores() \(\times\)
loadings()^\top= reconstruction), yet they agree exactly, as §2.6's
derivation guarantees they must -- a useful sanity check when
implementing either quantity from scratch, and a reminder that "how many
components should I keep" has (at least) two equivalent framings:
variance retained, or reconstruction error tolerated.

**Two components already capture almost everything.** 95.81% cumulative
variance at \(k=2\) (§4.2) is unusually high for a "real" (if small and
well-behaved) dataset -- a direct consequence of iris's four measurements
being highly correlated with each other (all four are, after all,
different measures of the same flower's overall size and proportions),
leaving little truly independent variation for PC3 and PC4 to capture.

* Conclusion

Fitting PCA with =datamunge='s C++ =stats::PCA= to Fisher's iris
measurements -- with =Species= withheld throughout -- shows that two
components already explain 95.81% of total variance, that the first
component is essentially a general flower-size axis dominated by petal
measurements, and that a PC1-vs-PC2 scores scatter recovers the same
/setosa/-versus-overlapping-pair structure every other report in this
project finds, without ever seeing the species labels during fitting.
The reconstruction-error sweep gives a second, numerically consistent
view of the same conclusion, reaching exactly zero error at full rank as
the Eckart-Young theorem requires. Fitting again without standardizing
first changes the answer meaningfully, a concrete demonstration of why
=PCAOptions::scale= defaults to true. As with its companions, this
entire report is reproducible end to end via
=just org-example pca_iris_analysis=, which re-executes §3.3.8's
assembly block -- and therefore every number and figure above -- from
the =datamunge= source tree.
