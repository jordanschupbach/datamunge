#+begin_abstract
Like Newton-Raphson division, *Goldschmidt division* computes a quotient with only
multiplications -- but it arranges them so the two multiplies of each step are *independent*
and can execute in parallel, which is why pipelined floating-point units (and the IBM
System/360 Model 91 that introduced it) favour it. The trick: scale numerator *and*
denominator by the same factor \(f=2-D\) each step, driving the denominator \(D\to1\) while the
numerator becomes the quotient. This report drives =datamunge='s
=algorithms::goldschmidt_division=, verified against true division, and traces the quadratic
collapse of the denominator.
#+end_abstract

* Scale both, together

Write \(q=N/D\). If we multiply top and bottom by the same \(f\), the ratio is unchanged --
so we are free to choose \(f\) to push \(D\) toward 1, at which point \(N\) *is* the quotient.
Scale \(D\) into \((0,1]\) first (via the floating-point exponent), then iterate

\[ f = 2 - D, \qquad N \leftarrow N f, \qquad D \leftarrow D f. \]

If \(D=1-\delta\) then \(f=1+\delta\) and the new \(D=(1-\delta)(1+\delta)=1-\delta^2\): the
error is *squared* each step -- quadratic convergence, doubling the correct digits. The
essential difference from Newton's \(x\leftarrow x(2-Dx)\) is *data flow*: Goldschmidt's
\(Nf\) and \(Df\) depend only on the previous \(N,D,f\), not on each other, so a superscalar
unit issues them in the same cycle. Same iteration count, better hardware utilisation.

* Algorithm

#+begin_example
GOLDSCHMIDT(N, D):
  scale D into (0,1] (and N by the same power of two)
  repeat:
      f <- 2 - D
      N <- N * f          # these two multiplies are independent
      D <- D * f
  until D ~ 1
  return N
#+end_example

* Worked example: 22/7, and the denominator collapsing

We divide and check a few quotients, then trace \(|D-1|\) each step for \(D\) scaled from
\(7\), showing the quadratic descent.

#+name: gs-run
#+begin_src c++ :eval no
    for (auto pr : {std::pair{1.0, 3.0}, std::pair{22.0, 7.0}, std::pair{-5.0, 1024.0}, std::pair{2.0, 1e-6}})
        std::cout << pr.first << " / " << pr.second << " = " << goldschmidt_division(pr.first, pr.second)
                  << "  (true " << pr.first / pr.second << ")\n";
    std::cout << "\n";

    // Trace the denominator error for D scaled from 7 into [0.5,1).
    int e; const double m = std::frexp(7.0, &e); // 7 = m * 2^e
    double D = m, N = std::ldexp(22.0, -e);
    std::cout << "denominator error |D - 1| per step (dividing 22/7):\n";
    std::vector<double> it, logerr;
    for (int i = 0; i <= 6; ++i) {
        const double err = std::fabs(D - 1.0);
        it.push_back(i); logerr.push_back(std::log10(std::max(err, 1e-18)));
        std::printf("  step %d: D=%.15f  |D-1|=%.3e  (N=%.10f)\n", i, D, err, N);
        const double f = 2.0 - D; N *= f; D *= f;
    }

    auto plot = RPlot::create();
    plot.line(it, logerr, "error", RGB{37, 99, 235}, 2.0);
    plot.points(it, logerr, "error", RGB{37, 99, 235}, 7.0);
    plot.legend({"|D - 1| (denominator error)"}, {{37, 99, 235}});
    plot.title("Goldschmidt drives the denominator to 1 quadratically")
        .x_label("iteration").y_label("log10 |D - 1|").background({250, 250, 252});
    plot.save_svg("build/org/goldschmidt.svg");
    std::cout << "\nwrote goldschmidt.svg\n";
#+end_src

The quotients are correct across magnitudes, and the trace shows the denominator error being
squared each step -- \(10^{-1},10^{-2},10^{-4},10^{-8},\dots\) -- reaching machine precision in
about five iterations, exactly like Newton but with the parallel-friendly data flow.

The error plunges faster and faster on the log axis -- the steepening curve of quadratic
convergence. Newton and Goldschmidt take the same number of steps to divide; Goldschmidt's
advantage is that each step's two multiplications do not wait on one another, so real hardware
finishes them sooner.
