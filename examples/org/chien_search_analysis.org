#+begin_abstract
Reed-Solomon and BCH decoders must find the roots of an error-locator polynomial over a finite field.
*Chien search* does it by the most direct method imaginable -- try every field element -- but
arranges the arithmetic so each trial costs only one multiply per polynomial term, updating the
previous evaluation instead of recomputing it. This report drives =datamunge='s
=algorithms::chien_search=, verified against brute-force evaluation over thousands of random
polynomials and several primes, and plots the polynomial's value sweeping across \(\mathrm{GF}(p)\)
with its roots picked out where the curve touches zero.
#+end_abstract

* Evaluate everywhere, but incrementally

The nonzero elements of \(\mathrm{GF}(p)\) are exactly the powers \(g^0,g^1,\dots,g^{p-2}\) of a
*primitive root* \(g\). To find roots of \(f(x)=\sum_j c_j x^j\), Chien search evaluates \(f\) at each
\(g^i\) in turn. The trick is that moving from \(g^i\) to \(g^{i+1}\) does not require re-evaluating
from scratch: keep a running term for each coefficient,

\[ t_j^{(i)}=c_j\,(g^i)^j=c_j\,g^{ij},\qquad f(g^i)=\sum_j t_j^{(i)}, \]

and advance every term with a single multiply, \(t_j^{(i+1)}=t_j^{(i)}\cdot g^{j}\). Whenever the sum
is zero, \(g^i\) is a root (and \(x=0\) is checked separately, since it is not a power of \(g\)). Each
of the \(p-1\) steps costs \(\deg f\) multiplications, all of them the same fixed constants
\(g^j\) -- which is why the method maps so cleanly onto hardware in a decoder.

#+name: ch-includes
#+begin_src c++ :eval no
#include <datamunge/algorithms/polynomial_gf.hpp>
#include <datamunge/plot/plot.hpp>

#include <algorithm>
#include <cstdint>
#include <iostream>
#include <vector>

using namespace datamunge::algorithms;
using namespace datamunge::plot;

static std::int64_t md(std::int64_t a, std::int64_t p) { return ((a % p) + p) % p; }
static std::int64_t evalp(const GFPoly& f, std::int64_t x, std::int64_t p) {
    std::int64_t acc = 0;
    for (std::size_t i = f.size(); i-- > 0;) acc = md(acc * x + f[i], p);
    return acc;
}
#+end_src

* Algorithm

#+begin_example
CHIEN-SEARCH(f) over GF(p):
  g = primitive root of p
  roots = {}
  if f(0) == 0: roots += 0
  t[j] = c[j] for all j                 # value at g^0 = 1
  for i = 0 .. p-2:
      if sum_j t[j] == 0: roots += g^i  # f(g^i) == 0
      t[j] *= g^j for all j             # advance to g^(i+1)
  return roots
#+end_example

* Worked example over GF(13)

We factor-free search the roots of \(f(x)=x^3+2x^2+3x+4\) over \(\mathrm{GF}(13)\), confirm them
against brute force, and plot \(f\) evaluated at every field element with the roots highlighted.

#+name: ch-run
#+begin_src c++ :eval no
    const std::int64_t p = 13;
    const GFPoly f = {4, 3, 2, 1}; // x^3 + 2x^2 + 3x + 4

    std::vector<std::int64_t> roots = chien_search(f, p);
    std::sort(roots.begin(), roots.end());
    std::cout << "=== Chien search over GF(13) ===\n";
    std::cout << "f(x) = x^3 + 2x^2 + 3x + 4\n";
    std::cout << "roots found: ";
    for (std::int64_t r : roots) std::cout << r << " ";
    std::cout << "\n";

    // Brute-force check and gather the value curve.
    std::vector<std::int64_t> brute;
    std::vector<double> xs, ys;
    std::cout << "\nx   f(x) mod 13\n";
    for (std::int64_t x = 0; x < p; ++x) {
        const std::int64_t v = evalp(f, x, p);
        if (v == 0) brute.push_back(x);
        xs.push_back(static_cast<double>(x)); ys.push_back(static_cast<double>(v));
        std::printf("%2lld   %2lld%s\n", (long long)x, (long long)v, v == 0 ? "   <- root" : "");
    }
    std::cout << "matches brute force: " << (roots == brute ? "yes" : "no") << "\n";

    std::vector<double> rx, ry;
    for (std::int64_t r : roots) { rx.push_back(static_cast<double>(r)); ry.push_back(0.0); }
    auto plot = RPlot::create();
    plot.line(xs, ys, "f", RGB{37, 99, 235}, 2.0);
    plot.points(xs, ys, "f", RGB{37, 99, 235}, 5.0);
    plot.points(rx, ry, "r", RGB{220, 38, 38}, 9.0);
    plot.abline_h(0.0, RGB{100, 116, 139}, 1.0);
    plot.legend({"f(x) mod 13", "roots (f = 0)"}, {{37, 99, 235}, {220, 38, 38}});
    plot.title("Chien search: f swept across GF(13), roots where it hits zero")
        .x_label("field element x").y_label("f(x) mod 13").background({250, 250, 252});
    plot.save_svg("build/org/chien_search.svg");
    std::cout << "\nwrote chien_search.svg\n";
#+end_src

Chien search returns exactly the roots found by brute-force evaluation. The value table shows the
polynomial taking every residue as \(x\) ranges over the field, dropping to zero precisely at its
roots -- the points the search reports.

[[file:../../build/org/chien_search.svg]]

The blue value curve wanders unpredictably across the field (a finite-field polynomial has no notion
of continuity), and the red markers sit exactly where it meets the zero line. Because each field
element is tested by one constant multiply per term, the whole sweep is cheap and completely regular
-- the property that made Chien search the standard root-finder inside BCH and Reed-Solomon decoders.
