#+begin_abstract
The *0/1 knapsack problem* -- pick items of maximum value within a weight budget -- has
\(2^n\) candidate subsets, hopeless to enumerate for large \(n\). *Branch and bound*
searches the take/skip tree but computes, at each node, an *optimistic upper bound* on what
that branch could yield; if the bound cannot beat the best solution so far, the entire
subtree is *pruned* unexplored. With a good bound most of the tree vanishes, and the exact
optimum is found while visiting a tiny fraction of the \(2^n\) leaves. This report drives
=datamunge='s =algorithms::knapsack_branch_and_bound=, verified against dynamic programming,
and shows the pruning at work.
#+end_abstract

* Bound, then prune

Branch and bound is exhaustive search with a conscience. At a node we have decided some
items (current value \(v\), weight \(w\)) and face the rest. The *branch* step tries
both possibilities for the next item -- take it (if it fits) or skip it. The *bound* step
asks: even optimistically, how much could this branch reach? A tight, cheap answer is the
*fractional-knapsack* bound: sort remaining items by value density and greedily fill the
leftover capacity, allowing a fractional last item. That relaxation can only *over*-estimate
the true 0/1 optimum, so:

- if \(\text{bound(node)} \le \text{best-so-far}\), no completion of this node can improve
  the incumbent -- *prune* the whole subtree;
- otherwise recurse.

Because the bound is an upper bound, pruning never discards the true optimum, so the answer
is *exact* -- branch and bound trades the guarantee of brute force for its speed, not its
correctness. The savings depend on the instance, but are typically enormous.

* Algorithm

#+begin_example
KNAPSACK-BB(values, weights, capacity):
  sort items by value/weight descending
  best <- 0
  DFS(level, weight, value):
      best <- max(best, value)
      if bound(level, weight, value) <= best: return          # prune
      if item[level] fits: DFS(level+1, weight+w, value+v)     # take
      DFS(level+1, weight, value)                              # skip
  return best and the taking that achieved it
#+end_example

* Worked example: a small instance, then pruning as n grows

We solve a hand instance and list the chosen items, then measure how many tree nodes branch
and bound visits as \(n\) grows -- against the \(2^{n+1}\) nodes a full enumeration
would touch.

#+name: bb-run
#+begin_src c++ :eval no
    const std::vector<int> values{60, 100, 120, 40, 70};
    const std::vector<int> weights{10, 20, 30, 15, 25};
    const int cap = 50;
    const KnapsackResult r = knapsack_branch_and_bound(values, weights, cap);
    std::cout << "=== knapsack, capacity 50 ===\n";
    std::cout << "best value = " << r.value << ", nodes explored = " << r.nodes_explored << "\nchosen: ";
    for (std::size_t i = 0; i < values.size(); ++i) if (r.chosen[i]) std::cout << "item" << i << "(v" << values[i] << ",w" << weights[i] << ") ";
    std::cout << "\n\n";

    std::mt19937 rng(777);
    std::uniform_int_distribution<int> vd(1, 100), wd(1, 30);
    std::vector<double> ns, bb_nodes, brute_nodes;
    std::cout << "n     BB nodes     2^(n+1) full tree\n";
    for (int n = 4; n <= 28; n += 2) {
        std::vector<int> vv(n), ww(n);
        for (int& v : vv) v = vd(rng);
        for (int& w : ww) w = wd(rng);
        const KnapsackResult rr = knapsack_branch_and_bound(vv, ww, 5 * n);
        ns.push_back(n);
        bb_nodes.push_back(std::log10(static_cast<double>(rr.nodes_explored)));
        brute_nodes.push_back(std::log10(std::pow(2.0, n + 1)));
        if (n % 4 == 0) std::printf("%-4d  %-10lld   %.3e\n", n, rr.nodes_explored, std::pow(2.0, n + 1));
    }

    auto plot = RPlot::create();
    plot.line(ns, brute_nodes, "brute force", RGB{220, 38, 38}, 2.0);
    plot.points(ns, brute_nodes, "brute", RGB{220, 38, 38}, 5.0);
    plot.line(ns, bb_nodes, "branch and bound", RGB{37, 99, 235}, 2.0);
    plot.points(ns, bb_nodes, "B&B", RGB{37, 99, 235}, 6.0);
    plot.legend({"full enumeration 2^(n+1)", "branch & bound (measured)"}, {{220, 38, 38}, {37, 99, 235}});
    plot.title("Branch and bound visits a tiny fraction of the 2^n search tree")
        .x_label("number of items n").y_label("log10 nodes visited").background({250, 250, 252});
    plot.save_svg("build/org/branch_and_bound.svg");
    std::cout << "\nwrote branch_and_bound.svg\n";
#+end_src

The hand instance is solved to its exact optimum, listing the chosen items. As \(n\)
grows, the gap between the two curves widens fast: full enumeration's node count climbs the
straight \(2^{n+1}\) line, while branch and bound -- pruning every hopeless subtree --
stays far below it, solving instances the brute-force tree could never finish.
