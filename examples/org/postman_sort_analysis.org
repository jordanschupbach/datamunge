#+begin_abstract
A postal service does not compare addresses -- it *files* them: first by country, then within a
country by city, then by street. Postman sort applies the same *hierarchical bucketing* to keys,
sorting by the most significant digit first and recursing into each bucket on the next digit. It is
most-significant-digit (MSD) radix sort, a *non-comparison* method that runs in \(O(n\cdot d)\) for
\(d\)-digit keys, beating the comparison bound when keys are short. This report drives =datamunge='s
=algorithms::postman_sort=, verified against =std::sort= over thousands of random 32-bit arrays, and
shows the first-digit bucketing.
#+end_abstract

* Sort by the top digit, then recurse

Treat each key as a sequence of digits in some radix -- here bytes, radix 256. Bucket all keys by
their *most significant* byte into 256 bins, in one counting pass:

\[ \text{bucket}(v)=\big\lfloor v/256^{\,d-1}\big\rfloor \bmod 256. \]

A prefix sum of the bucket counts gives each bucket a contiguous slice of the array, and a stable
distribution places the keys there. Now every bucket holds keys sharing the same top byte, so *within*
a bucket the order is decided by the *remaining* bytes -- recurse into each bucket on the next byte
down. Recursion stops when a bucket has one element or the digits run out; small buckets finish with
insertion sort. Because a key is examined digit by digit rather than compared whole, the cost is
\(O(n\cdot d)\) independent of \(n\log n\) -- linear in the input size for fixed-width keys. The MSD
(top-down) order means the array is sorted as soon as the recursion completes, with no final merge,
exactly like mail sorted into ever-finer pigeonholes.

* Algorithm

#+begin_example
POSTMAN-SORT(a, shift = top byte):
  if range small or no digits left: insertion sort; return
  count keys by their byte at `shift`; prefix-sum into bucket offsets
  stably distribute keys into their buckets
  for each nonempty bucket: POSTMAN-SORT(bucket, shift - 8)
#+end_example

* Worked example: sorting, and the top-byte buckets

We sort a scrambled array, then bucket a sample by its most significant byte and plot the distribution
that the first recursion level produces.

#+name: pm-run
#+begin_src c++ :eval no
    std::vector<std::uint32_t> a = {300000, 12, 9000000, 42, 300500, 12, 8000123, 500, 9000001, 77};
    auto s = a; postman_sort(s);
    std::cout << "=== postman sort (MSD radix) ===\n";
    std::cout << "input:  "; for (auto x : a) std::cout << x << " "; std::cout << "\n";
    std::cout << "sorted: "; for (auto x : s) std::cout << x << " "; std::cout << "\n\n";

    // First-byte bucket distribution for a uniform 32-bit sample.
    std::mt19937_64 rng(22);
    const int n = 8000;
    std::vector<int> counts(16, 0); // aggregate 256 top-byte buckets into 16 bins
    for (int i = 0; i < n; ++i) { std::uint32_t v = (std::uint32_t)rng(); counts[(v >> 24) / 16]++; }
    std::vector<double> heights; std::vector<std::string> labels;
    std::cout << "top-byte buckets (16 aggregated bins) for " << n << " uniform keys:\n";
    for (int i = 0; i < 16; ++i) { heights.push_back(counts[i]); labels.push_back(std::to_string(i)); }
    std::printf("  min bin=%d  max bin=%d  ideal=%d\n", *std::min_element(counts.begin(), counts.end()), *std::max_element(counts.begin(), counts.end()), n / 16);

    auto plot = RPlot::barplot(heights, labels, "count", RGB{234, 88, 12});
    plot.title("Postman sort: top-byte bucket distribution for uniform 32-bit keys")
        .x_label("top-byte bin").y_label("keys").background({250, 250, 252});
    plot.save_svg("build/org/postman_sort.svg");
    std::cout << "\nwrote postman_sort.svg\n";
#+end_src

Postman sort files the keys into order -- matching =std::sort= across thousands of random 32-bit
arrays -- by digit rather than by comparison. For uniform keys the top-byte buckets are nearly equal,
so each recursion level does balanced work.

The near-flat bucket profile is the postal metaphor made literal: uniform keys spread evenly across
the first sorting stage, and each bucket is refiled on the next digit until every pigeonhole holds a
single item. That digit-at-a-time filing is why radix methods beat comparison sorts on fixed-width
keys -- and why the post office never compares two addresses to decide which comes first.
