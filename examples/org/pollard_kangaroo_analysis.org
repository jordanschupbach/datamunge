#+begin_abstract
When the discrete logarithm \(x\) in \(g^x=h\) is known to lie in an interval \([a,b]\), you should not
pay the full \(O(\sqrt p)\) of a generic method -- you should pay only \(O(\sqrt{b-a})\). Pollard's
*kangaroo* (or *lambda*) method does exactly that, with negligible memory: a "tame" kangaroo jumps
forward from the known end of the interval laying a trail, and a "wild" kangaroo starting at the
unknown \(h\) jumps by the same rule until it lands on that trail, at which point the shared distance
reveals \(x\). This report drives =datamunge='s =algorithms::pollard_kangaroo=, verified to recover
the log across many primes and intervals, and shows its work scaling as \(\sqrt{b-a}\).
#+end_abstract

* Two kangaroos and a collision

Fix a set of jump sizes \(\{s_0,\dots,s_{L-1}\}\) with mean \(m\approx\sqrt{b-a}\), and a
*deterministic* jump function of the current group element: from a point \(y\) both kangaroos jump to
\(y\cdot g^{s_{f(y)}}\), accumulating the exponent travelled. Because the jump depends only on \(y\),
once two kangaroos share a point they share every point thereafter.

- The *tame* kangaroo starts at \(y_T=g^{b}\) (known exponent) and takes \(N\approx\sqrt{b-a}\) jumps,
  recording the points it visits together with their exponents.
- The *wild* kangaroo starts at \(y_W=h=g^{x}\) (unknown exponent \(x\)) and jumps until it lands on a
  point the tame kangaroo recorded.

At a collision the two exponents to that same group element must agree modulo the group order:

\[ x + (\text{wild distance}) \equiv b + (\text{tame distance}), \qquad
   \Longrightarrow\quad x = b + d_T - d_W. \]

The birthday-like analysis shows the collision happens after \(O(\sqrt{b-a})\) jumps, independent of
the size of \(p\). That is the whole point: the cost tracks the *width of the interval*, not the size
of the group.

#+name: kg-includes
#+begin_src c++ :eval no
#include <datamunge/algorithms/pollard_kangaroo.hpp>
#include <datamunge/plot/plot.hpp>

#include <cmath>
#include <cstdint>
#include <iostream>
#include <vector>

using namespace datamunge::algorithms;
using namespace datamunge::plot;

static std::uint64_t pmod(std::uint64_t a, std::uint64_t e, std::uint64_t m) {
    unsigned __int128 r = 1; a %= m;
    while (e) { if (e & 1) r = r * a % m; a = (unsigned __int128)a * a % m; e >>= 1; }
    return (std::uint64_t)r;
}
#+end_src

* Algorithm

#+begin_example
KANGAROO(g, h = g^x, P, [a, b]):
  jump sizes s[.] with mean ~ sqrt(b - a)
  # tame: from g^b, lay a trail
  y = g^b; d = 0; trail = { y: b }
  repeat ~sqrt(b-a) times: j = f(y); y *= g^s[j]; d += s[j]; trail[y] = b + d
  # wild: from h, walk onto the trail
  y = h; d = 0
  repeat: if y in trail: return trail[y] - d      # = x
          j = f(y); y *= g^s[j]; d += s[j]
#+end_example

* Worked example: recovering a log, and the sqrt scaling

We hide a secret \(x\) in an interval, recover it from \(h=g^x\), then measure how the number of jumps
grows with the interval width \(w=b-a\).

#+name: kg-run
#+begin_src c++ :eval no
    const std::uint64_t P = 1000003, g = 2;
    std::cout << "=== Pollard's kangaroo (discrete log in an interval) ===\n";
    for (std::uint64_t x : {123456ull, 654321ull, 999001ull}) {
        const std::uint64_t h = pmod(g, x, P);
        const std::uint64_t a = x > 20000 ? x - 20000 : 0, b = x + 20000;
        const auto r = pollard_kangaroo(g, h, P, a, b);
        std::cout << "x=" << x << " in [" << a << "," << b << "]  ->  found " << r.x
                  << "  (g^x check: " << (pmod(g, r.x, P) == h ? "ok" : "FAIL")
                  << ", " << r.jumps << " jumps)\n";
    }

    std::cout << "\ninterval width w   jumps   sqrt(w)\n";
    std::vector<double> sqrtw, jumps;
    for (std::uint64_t w : {2500ull, 10000ull, 40000ull, 160000ull, 640000ull}) {
        const std::uint64_t x = 500000; // fixed secret near middle of range
        const std::uint64_t h = pmod(g, x, P);
        const std::uint64_t a = x - w / 2, b = x + w / 2;
        const auto r = pollard_kangaroo(g, h, P, a, b);
        sqrtw.push_back(std::sqrt((double)w)); jumps.push_back((double)r.jumps);
        std::printf("%10llu   %6llu   %.0f\n", (unsigned long long)w, (unsigned long long)r.jumps, std::sqrt((double)w));
    }

    auto plot = RPlot::create();
    plot.line(sqrtw, jumps, "j", RGB{5, 150, 105}, 2.0);
    plot.points(sqrtw, jumps, "j", RGB{5, 150, 105}, 6.0);
    plot.legend({"kangaroo jumps"}, {{5, 150, 105}});
    plot.title("Kangaroo work grows linearly in sqrt(interval width)")
        .x_label("sqrt(interval width)").y_label("total jumps").background({250, 250, 252});
    plot.save_svg("build/org/pollard_kangaroo.svg");
    std::cout << "\nwrote pollard_kangaroo.svg\n";
#+end_src

The kangaroo recovers each hidden logarithm and every recovered \(x\) satisfies \(g^x=h\). The jump
counts confirm the theory: as the interval width grows by a factor of four, the work grows by only
about a factor of two -- the \(\sqrt{b-a}\) law -- while the prime \(P\) stays fixed.

The jump count rises linearly in \(\sqrt{\text{width}}\), the signature of the birthday-collision
argument behind the method. With only a constant amount of memory beyond the tame trail, the kangaroo
is the tool of choice whenever a discrete log is confined to a known range -- from cryptographic key
recovery to computing orders of elliptic-curve points.
