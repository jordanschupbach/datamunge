#+begin_abstract
Before searching a constraint-satisfaction problem, it pays to *think*: many candidate values
can be ruled out by pure deduction. *AC-3* (Mackworth, 1977) enforces *arc consistency* --
it deletes any value from a variable's domain that has no compatible partner in a neighbour's
domain, cascading the deletions until nothing more can be removed. Often this alone collapses
the domains dramatically, sometimes solving the problem outright and always shrinking the
search that follows. This report drives =datamunge='s =algorithms::ac3=, verified to leave
every arc consistent, and shows the domains contracting.
#+end_abstract

* Revise, and re-enqueue

A binary CSP has variables, each with a *domain* of allowed values, and constraints relating
pairs of variables. A directed *arc* \((i,j)\) is *consistent* when every value in
\(i\)'s domain has at least one *support* in \(j\)'s domain -- a value of \(j\)
compatible with it. AC-3 keeps a worklist of arcs and repeatedly:

1. *Revises* an arc \((i,j)\): removes from \(i\)'s domain each value with no support in
   \(j\).
2. If that removed anything, *re-enqueues* every arc \((k,i)\) pointing into \(i\) --
   because shrinking \(i\)'s domain may have destroyed support elsewhere.

It stops when the worklist empties (fully arc-consistent) or a domain becomes empty (the CSP
is unsatisfiable). The running time is \(O(e\,d^3)\) for \(e\) arcs and domain size
\(d\). Arc consistency is *necessary but not sufficient* for a solution -- it prunes, it
does not always solve -- which is why it is run as propagation *inside* backtracking search.

* Algorithm

#+begin_example
AC-3(domains, arcs, compatible):
  queue <- all arcs
  while queue not empty:
      (i,j) <- pop
      if REVISE(i,j):                       # removed some value from domain[i]
          if domain[i] empty: return INCONSISTENT
          for each arc (k,i): enqueue (k,i)
  return domains

REVISE(i,j): drop each a in domain[i] with no b in domain[j] where compatible(i,a,j,b)
#+end_example

* Worked example: an ordering chain

Five variables with domains \(\{1,\dots,9\}\) and the constraints
\(x_0<x_1<x_2<x_3<x_4\). Arc consistency alone forces each variable into a narrow band.

#+name: ac-run
#+begin_src c++ :eval no
    const int nvars = 5;
    std::vector<std::vector<int>> domains(nvars, std::vector<int>{1, 2, 3, 4, 5, 6, 7, 8, 9});

    std::vector<std::pair<int, int>> arcs;
    for (int i = 0; i + 1 < nvars; ++i) { arcs.push_back({i, i + 1}); arcs.push_back({i + 1, i}); }
    // For arc (i,j): if i<j require value(i) < value(j), else value(i) > value(j).
    auto rel = [](int i, int a, int j, int b) { return i < j ? a < b : a > b; };

    std::vector<int> before(nvars, 9);
    const Ac3Result r = ac3(domains, arcs, rel);

    std::cout << "=== x0 < x1 < x2 < x3 < x4, domains 1..9 ===\n";
    std::cout << "consistent: " << (r.consistent ? "yes" : "no") << "\n";
    std::vector<double> vx, sz_before, sz_after;
    for (int i = 0; i < nvars; ++i) {
        std::cout << "x" << i << " domain: ";
        for (int v : r.domains[i]) std::cout << v << " ";
        std::cout << "\n";
        vx.push_back(i - 0.2);
        sz_before.push_back(9);
        sz_after.push_back(static_cast<double>(r.domains[i].size()));
    }
    std::vector<double> vx2; for (int i = 0; i < nvars; ++i) vx2.push_back(i + 0.2);

    auto plot = RPlot::create();
    plot.bars(vx, sz_before, "before", RGB{203, 213, 225}, 0.38);
    plot.bars(vx2, sz_after, "after AC-3", RGB{37, 99, 235}, 0.38);
    plot.legend({"domain size before (9)", "domain size after AC-3"}, {{203, 213, 225}, {37, 99, 235}});
    plot.title("AC-3 contracts every domain in the ordering chain")
        .x_label("variable index").y_label("domain size").background({250, 250, 252});
    plot.save_svg("build/org/ac3.svg");
    std::cout << "\nwrote ac3.svg\n";
#+end_src

Arc consistency alone squeezes each nine-value domain down to a narrow band: \(x_0\) can
only be small (it needs four larger values above it), \(x_4\) only large, and the middle
variables to nested ranges in between. No search has happened yet -- this is pure
propagation, and it has already discarded the large majority of the assignment space.

Every blue "after" bar is far shorter than its grey "before" counterpart: AC-3 has removed
the values that could never participate in a solution. Running this as propagation inside a
backtracking search means the solver branches on a tiny fraction of the original
possibilities -- the reason arc consistency is a fixture of every serious CSP engine.
