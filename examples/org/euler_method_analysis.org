#+begin_abstract
Every numerical solver for @math{y'=f(t,y)} begins with Leonhard Euler's idea (1768):
you know the *slope* at your current point, so take a small step along it and repeat.
The *Euler method* is the simplest possible integrator -- one slope evaluation per step --
and its virtues (transparency) and vices (first-order accuracy, fragile stability) are
the yardstick for everything more sophisticated. This report implements it in
=datamunge='s C++ =algorithms::euler_method=, verified against the exact solution of an
exponential decay, and exhibits its characteristic @math{O(h)} error.
#+end_abstract

* Stepping along the tangent

Given @math{y'=f(t,y)} and a state @math{y_n} at time @math{t_n}, the derivative
@math{f(t_n,y_n)} *is* the tangent slope there. The Euler method assumes the slope holds
over a small step @math{h} and moves to

\[ y_{n+1} = y_n + h\,f(t_n, y_n), \qquad t_{n+1} = t_n + h. \]

It is *explicit* (the new value is an outright formula, no equation to solve) and uses
one function evaluation per step. Its *local* error -- committed in a single step -- is
@math{O(h^2)}, from the dropped second-order Taylor term; accumulated over
@math{(t_1-t_0)/h} steps this gives a *global* error of @math{O(h)}. So Euler is
*first-order*: halve the step, halve the error. That slow payoff, plus a small stability
region that lets big steps diverge, is exactly why higher-order and implicit methods
exist -- but Euler is where the story starts.

* Algorithm

#+begin_example
EULER(f, y0, t0, t1, steps):
  h <- (t1 - t0) / steps
  y <- y0;  t <- t0
  record (t, y)
  repeat steps times:
      y <- y + h * f(t, y)        # step along the tangent
      t <- t + h
      record (t, y)
  return the recorded trajectory
#+end_example

* Worked example: exponential decay, and the O(h) error

We integrate @math{y'=-y} (exact solution @math{y=e^{-t}}) with a deliberately *coarse*
step to see the tangent-following error, then measure how the final error shrinks as the
step size @math{h} halves.

#+name: eu-run
#+begin_src c++ :eval no
    auto f = [](double, const std::vector<double>& y) { return std::vector<double>{-y[0]}; };

    // Coarse trajectory (8 steps over [0,4]) vs the exact curve.
    const OdeSolution coarse = euler_method(f, {1.0}, 0.0, 4.0, 8);
    std::vector<double> te, ye, tx, yx;
    for (std::size_t i = 0; i < coarse.t.size(); ++i) { te.push_back(coarse.t[i]); ye.push_back(coarse.y[i][0]); }
    for (int i = 0; i <= 200; ++i) { const double t = 4.0 * i / 200.0; tx.push_back(t); yx.push_back(std::exp(-t)); }

    std::cout << "=== Euler on y' = -y, 8 steps over [0,4] ===\n";
    std::cout << "final Euler y = " << coarse.y.back()[0] << ", exact e^-4 = " << std::exp(-4.0) << "\n\n";

    // Error vs step size: global error should be proportional to h (slope 1 on a log-log plot).
    std::cout << "steps   h        final error   error/h\n";
    std::vector<double> logh, logerr;
    for (int steps = 10; steps <= 2560; steps *= 2) {
        const OdeSolution s = euler_method(f, {1.0}, 0.0, 1.0, steps);
        const double      h = 1.0 / steps;
        const double      err = std::fabs(s.y.back()[0] - std::exp(-1.0));
        logh.push_back(std::log10(h));
        logerr.push_back(std::log10(err));
        if (steps <= 160 || steps == 2560)
            std::printf("%5d   %.5f   %.3e     %.4f\n", steps, h, err, err / h);
    }

    auto plot = RPlot::create();
    plot.line(tx, yx, "exact e^-t", RGB{16, 185, 129}, 2.0);
    plot.line(te, ye, "Euler (h=0.5)", RGB{220, 38, 38}, 2.0);
    plot.points(te, ye, "Euler steps", RGB{220, 38, 38}, 6.0);
    plot.legend({"exact e^{-t}", "Euler, 8 steps"}, {{16, 185, 129}, {220, 38, 38}});
    plot.title("Euler follows the tangent and undershoots the exact decay")
        .x_label("t").y_label("y").background({250, 250, 252});
    plot.save_svg("build/org/euler_method.svg");
    std::cout << "\nwrote euler_method.svg\n";
#+end_src

With only eight steps Euler tracks the shape of @math{e^{-t}} but visibly lags it -- each
step commits to a straight tangent while the true curve keeps bending. The error table
tells the quantitative story: the final error divided by @math{h} is nearly *constant*,
the fingerprint of first-order @math{O(h)} convergence. Every halving of @math{h} buys
one more correct step's worth of accuracy, no more.

The red Euler polyline stays below the green exact curve: because @math{e^{-t}} is
convex, each tangent step cuts under the arc, and the small errors accumulate. Refining
the step would pull the red line onto the green one -- but only linearly, which is the
whole motivation for the Runge-Kutta and implicit methods in the companion reports.
