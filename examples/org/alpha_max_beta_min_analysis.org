#+begin_abstract
Computing \(\sqrt{x^2+y^2}\) -- a vector's length, a complex number's modulus -- needs a
square root, which is expensive on small DSPs and microcontrollers. The *alpha max plus
beta min* algorithm approximates it with *no multiply-heavy square root at all*:
\(\alpha\max(|x|,|y|) + \beta\min(|x|,|y|)\). With coefficients chosen to minimize the
worst-case error, \(\alpha\approx0.960\), \(\beta\approx0.398\), the estimate is
within about \(3.96\%\) of the true magnitude everywhere. This report implements it in
=datamunge='s C++ =algorithms::alpha_max_beta_min=, verified to stay inside that error
bound over \(2\times10^5\) random vectors.
#+end_abstract

* A linear blend of the two components

Sort the absolute components into \(\text{hi}=\max(|x|,|y|)\) and
\(\text{lo}=\min(|x|,|y|)\). The true magnitude is
\(\text{hi}\sqrt{1+(\text{lo}/\text{hi})^2}\); the approximation replaces that square
root with a straight line in \(\text{lo}/\text{hi}\):

\[ \widehat{r} = \alpha\,\text{hi} + \beta\,\text{lo}. \]

The ratio \(\text{lo}/\text{hi}\) ranges over \([0,1]\) (from an axis-aligned vector
to a \(45^\circ\) one), so the exact factor \(\sqrt{1+t^2}\) sweeps from \(1\) to
\(\sqrt2\approx1.414\). Choosing \(\alpha,\beta\) to minimize the *maximum* deviation
of the line \(\alpha+\beta t\) from \(\sqrt{1+t^2}\) on \([0,1]\) gives the
minimax coefficients \(\alpha=0.96043\), \(\beta=0.39782\) with peak relative error
\(\approx3.96\%\). Different objectives give different constants (e.g. \(\alpha=1,
\beta=1/2\) is simpler but peaks near \(12\%\)); =datamunge= uses the minimax pair. The
whole computation is two multiplies, an add, and a compare -- no square root, no division.

* Algorithm

#+begin_example
ALPHA-MAX-BETA-MIN(x, y):
  hi <- max(|x|, |y|);  lo <- min(|x|, |y|)
  return alpha*hi + beta*lo          # alpha=0.96043, beta=0.39782
#+end_example

* Worked example: error around the circle

Because the minimax coefficients make the error *equioscillate*, it reaches its most
negative (\(\approx-3.96\%\)) both on the axes and at \(45^\circ\), and swings to
\(+3.96\%\) partway between. We sweep a unit vector through all angles (true magnitude
\(1\)) and plot the relative error, which ripples within the \(\pm4\%\) band.

#+name: ab-run
#+begin_src c++ :eval no
    std::cout << "=== spot checks ===\n";
    std::printf("(3,4):   approx %.4f  exact 5\n", alpha_max_beta_min(3.0, 4.0));
    std::printf("(1,0):   approx %.4f  exact 1\n", alpha_max_beta_min(1.0, 0.0));
    std::printf("(1,1):   approx %.4f  exact %.4f\n\n", alpha_max_beta_min(1.0, 1.0), std::sqrt(2.0));

    std::vector<double> deg, relerr;
    double worst = 0.0;
    for (int i = 0; i <= 360; ++i) {
        const double th = i * M_PI / 180.0;
        const double x = std::cos(th), y = std::sin(th); // true magnitude = 1
        const double approx = alpha_max_beta_min(x, y);
        const double err = (approx - 1.0) * 100.0; // percent
        deg.push_back(i); relerr.push_back(err);
        worst = std::max(worst, std::fabs(err));
    }
    std::cout << "worst-case relative error over the circle = " << worst << " %\n";

    auto plot = RPlot::create();
    plot.line(deg, relerr, "error", RGB{5, 150, 105}, 2.0);
    plot.abline_h(0.0, RGB{148, 163, 184}, 1.0);
    plot.abline_h(3.96, RGB{220, 38, 38}, 1.0);
    plot.abline_h(-3.96, RGB{220, 38, 38}, 1.0);
    plot.legend({"relative error (%)", "+/-3.96% bound"}, {{5, 150, 105}, {220, 38, 38}});
    plot.title("alpha-max-beta-min error around the circle stays within +/-4%")
        .x_label("angle (degrees)").y_label("relative error (%)").background({250, 250, 252});
    plot.save_svg("build/org/alpha_max_beta_min.svg");
    std::cout << "wrote alpha_max_beta_min.svg\n";
#+end_src

The spot checks show the character of the approximation: \((3,4)\) lands at
\(5.035\) (a touch high, since that vector is away from the worst-case directions),
while the axis \((1,0)\) reads \(0.960\) and \((1,1)\) reads \(1.358\) -- both
about \(4\%\) low, the equioscillation extremes. The sweep confirms the worst-case error
stays under \(4\%\) everywhere on the circle, exactly the minimax guarantee the
coefficients were designed for. For a cost of two multiplies and an add, that is often
accurate enough for gain control, edge detection, or a collision radius.

The green error curve ripples between the red \(\pm3.96\%\) guide lines with a
period of \(90^\circ\) -- one lobe per octant of symmetry -- never escaping the band.
That bounded, predictable error is what makes the approximation usable: it is always a
little off, but never badly, and it never needs a square root to say so.
