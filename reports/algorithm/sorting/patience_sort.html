    Patience sort: actual piles and heap sources

    Abstract

    Each incoming value goes to the leftmost pile whose top is greater than or equal to it. Binary search locates that pile. A min-heap then merges pile tops, breaking equal-value heap ties by pile index. Pile count equals the strictly increasing LIS length, including when values repeat; it does not equal the nondecreasing subsequence length. Sorting is O(n log n); retaining every top snapshot can require quadratic history. No external dataset is appropriate for the mechanism.

    Mechanism and scope

    Each incoming value goes to the leftmost pile whose top is greater than or equal to it. Binary search locates that pile. A min-heap then merges pile tops, breaking equal-value heap ties by pile index. Pile count equals the strictly increasing LIS length, including when values repeat; it does not equal the nondecreasing subsequence length. Sorting is O(n log n); retaining every top snapshot can require quadratic history. No external dataset is appropriate for the mechanism.

    \[L_i=1+\max_{j<i,\ a_j<a_i} L_j,\qquad \operatorname{LIS}(a)=\max_i L_i.\]

    The maximum over an empty predecessor set is zero; empty input has LIS length zero. This independent quadratic recurrence is used in tests, not to populate the captured pile history.

    API and interpretation

    All four blocks are complete editable C++ programs. Numerical tables retain raw native values; figures display only those returned records. Trace limits count documented logical records or scalar entries, not peak bytes or wall-clock work. Validation is complete before unchecked indexing; captured histories are educational owned storage. A returned result is interpreted under the algorithm-specific scope above, without a universal optimality, convergence or statistical-quality claim.

    Aldous and Diaconis connect patience sorting with strictly increasing subsequences. The native heap extraction is an additional sorting phase.
