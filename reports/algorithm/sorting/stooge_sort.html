    Stooge sort: actual overlapping recursive calls

    Abstract

    Stooge sort compares endpoints, then sorts overlapping two-thirds ranges three times. Its deliberately expensive recursion makes the difference between asymptotic references and actual executed calls visible.

    Mechanism and mathematical scope

    For length n>2 recurse on the first n-floor(n/3), last n-floor(n/3), then first range again. Each invocation makes one endpoint comparison. Thus C(n)=1+3*C(ceil(2n/3)) for n>2, with C(2)=1. Rounding creates plateaus; nlog_(3/2)(3), approximately n2.71, is an asymptotic reference rather than the exact count. This implementation records completed calls in postorder, with any endpoint exchange occurring before its children.

    API and interpretation

    Generic copyable keys require a strict weak ordering. Floating nonfinite keys fail. The compatibility in-place sort replaces caller data only after successful completion of the owned run. Default work limits protect against explosive execution. Endpoint exchanges are unstable; no stability claim is made. The original count-only report recurrence is replaced with actual executions for every n through200.

    Reusable producers, fixtures and histories live in the canonical C++ library. Captured records own their values and do not come from a separate report replay. Selected counters and record/scalar policies are specified at their API boundaries; they are not peak-byte or wall-time budgets. Synthetic structural inputs are controlled fixtures for these mechanisms.
