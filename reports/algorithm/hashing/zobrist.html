    Zobrist Hashing: Updating a Digit One Pixel at a Time

    Abstract

    A Zobrist hash assigns a random key to each cell/category pair and XORs the keys belonging to a configuration. Replacing one cell takes two key lookups and two XORs, regardless of the configuration's size. We apply this idea to the 8 by 8 handwritten images in dm::datasets::digits(): grey levels are categories, and changing pixels is the analogue of changing board squares. We derive the update identity and the expected number of colliding pairs, verify every step of an image transformation, and compare truncated hashes across 64 seeded key tables. A four-configuration identity explains why these hashes must not be treated as fully independent random numbers.

    The data: small images as categorical configurations

    The built-in digits frame contains 1797 images, each with 64 integer pixel values from 0 (white) to 16 (dark), plus a numeric digit label. The image, rather than its class, is the object to identify. Remove digit before encoding: otherwise two identical images with different labels would hash differently. The remaining column order is row-major pixel order.

    The method: cancellation replaces a complete scan

    Let \(x=(x_0,\ldots,x_{c-1})\) be a configuration with \(q\) categories per cell. Generate keys \(K_{i,v}\) for each cell \(i\) and category \(v\ne0\), with \(K_{i,0}=0\). For a \(b\)-bit hash,

    \[H(x)=\bigoplus_{i=0}^{c-1}K_{i,x_i}.\]

    XOR is associative and commutative, and \(a\oplus a=0\). Replacing \(x_j=u\) by \(v\) therefore gives

    \[H(x')=H(x)\oplus K_{j,u}\oplus K_{j,v}.\]

    The old contribution cancels and the new one is inserted. Reversing the replacement cancels the same two keys again, restoring the original hash. For a set \(S\) of changed cells, the same argument gives

    \[H(y)=H(x)\oplus\bigoplus_{j\in S}\left(K_{j,x_j}\oplus K_{j,y_j}\right).\]

    The result depends only on the final configuration, not the order of updates. This is why positions reached by different move sequences can share a transposition-table entry. Real game keys must also encode every rule-relevant state variable, such as side to move and castling rights. Here the configuration contains only pixels; the digit label is metadata.

    Initialising the table costs \(O(cq)\) time and space; computing a full hash costs \(O(c)\); one changed cell costs \(O(1)\). Updating \(k\) known changes costs \(O(k)\), but discovering those changes by comparing two complete images still costs \(O(c)\). This distinction prevents a false speed claim for unrelated records.

    For ideal independent keys a single nontrivial replacement produces a uniform XOR difference, so the number of changed bits has distribution \(\operatorname{Binomial}(64,1/2)\): mean 32 and standard deviation 4. A large jump is therefore expected, but an attractive scatter plot alone cannot establish randomness or security.

    Collisions: count pairs, and separate repeated data

    Fix two distinct configurations \(x\ne y\). Choose any differing cell. At least one nonzero-category key at that cell occurs exactly once in \(H(x)\oplus H(y)\). Condition on all other keys: this remaining key is uniform, so the XOR is zero with probability \(2^{-b}\). This proof still works with category zero keyed to zero. The all-zero board itself has a deterministic hash, so not every individual board hash is uniform.

    For \(n\) distinct input boards, define a collision as an unordered pair whose truncated hashes agree. Linearity of expectation gives

    \[C_b=\sum_{i<j}\mathbf{1}\{H_b(x_i)=H_b(x_j)\},\qquad \mathbb{E}[C_b]=\binom{n}{2}2^{-b},\qquad \Pr(C_b\ge1)\le\min\left(1,\binom{n}{2}2^{-b}\right).\]

    The final inequality is the union bound; it needs no independence between pair events. By contrast, \(1-\exp(-\mathbb{E}C_b)\) is a birthday/Poisson approximation, not an exact theorem here. Repeated input boards must first be removed: equal data are not hash failures. A bucket with \(r\) distinct boards contributes \(r(r-1)/2\) pairs, not merely \(r-1\).

    The library removes exact duplicates and averages over 64 consecutive MT19937-64 seeds. Ideal-key theory is a model for those pseudorandom tables; consecutive seeds are not a proof of independent randomness.

    All 1797 images are distinct. At eight bits the observed mean is close to the ideal expectation; at 24 bits only five pairs occur across all 64 tables. At 64 bits the ideal expected count per table is about \(8.75\times10^{-14}\). Thus zero observed collisions at full width is unsurprising and cannot validate such a small probability experimentally. The additional scientific-notation rows preserve expectations that round to zero in the main table.

    A deterministic dependency that survives every seed

    Take four configurations that agree everywhere except at two cells, where they contain respectively \((a,c),(a,d),(b,c),(b,d)\). Every key appears an even number of times across their hashes. Consequently,

    \[H(a,c)\oplus H(a,d)\oplus H(b,c)\oplus H(b,d)=0.\]

    Once three hashes are known the fourth is determined. Fully independent uniform 64-bit hashes would satisfy this identity only with probability \(2^{-64}\). This does not force a pair collision and does not contradict the pairwise collision proof. It does rule out treating every collection of configurations as fully independent, and makes Zobrist hashing unsuitable as an adversarial integrity check.

    Conclusion

    The incremental identity holds at every changed pixel, and reduced-width collisions can be measured against an exact expectation without claiming full independence. At 64 bits and this dataset's size, the ideal union bound is tiny; seeing no collisions provides little additional evidence. A cache that must return exact answers should verify the stored configuration after a hash match. Wider keys reduce accidental collisions but do not remove the algebraic dependencies. For changing categorical states, the useful property is cheap, reversible updates with a precisely defined collision model.
