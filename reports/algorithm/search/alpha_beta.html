    Alpha-Beta Pruning: Minimax Without the Wasted Work

    Abstract

    Minimax values a game position by searching every line of play, so its cost grows as \(b^d\) for branching factor \(b\) and depth \(d\). Alpha-beta pruning returns the same value while skipping lines that cannot change it. We prove why the pruning is safe, derive the Knuth-Moore count of the leaves it must still examine with perfect move ordering, \(b^{\lceil d/2\rceil}+b^{\lfloor d/2\rfloor}-1\), and state Pearl's branching factor for random ordering. The library's order_moves reproduces the Knuth-Moore count exactly. On random trees, measured effective branching factors approach Pearl's values (1.618, 2.148 and 2.630 for \(b=2,3,4\)) from above. The data is the complete game tree of tic-tac-toe: 255 168 games and 549 946 positions. Minimax confirms that the game is a draw. Alpha-beta reaches the same verdict from 7 330 of the 255 168 final positions in the natural move order, 781 with perfect ordering, and 84 100 with the worst.

    Minimax and the alpha-beta window

    Minimax

    Write \(V(n)\) for the value of node \(n\) under best play. A leaf has its own score. A max node takes the largest child value and a min node the smallest:

    \[V(n)=\begin{cases}\text{score}(n) & n \text{ a leaf},\\ \max_{c}V(c) & \text{max to move},\\ \min_c V(c) & \text{min to move}.\end{cases}\]

    Computing \(V\) this way touches every node.

    The window and why it is safe

    Alpha-beta evaluates a node with a window \((\alpha,\beta)\). Let \(F(n,\alpha,\beta)\) be the value the routine returns. The claim, by induction on height, is

    \[F\le\alpha \Rightarrow V\le F,\qquad \alpha<F<\beta \Rightarrow F=V,\qquad F\ge\beta \Rightarrow V\ge F .\]

    So inside the window the answer is exact, and outside it is a bound in the right direction. At a max node the routine raises \(\alpha\) to the best child value found so far and stops as soon as \(\alpha\ge\beta\). Stopping is safe: the node's value is already at least \(\beta\), which by the claim is all the caller needs. A min node one level up compares this value with its own \(\beta\), which came from a sibling line it already has, so it will never choose this node. The min node is symmetric. Started with \((-\infty,+\infty)\), the window never excludes the root value, so alpha-beta returns exactly \(V(\text{root})\).

    How many leaves survive?

    Perfect ordering: the Knuth-Moore minimal tree

    Take a uniform tree with distinct leaf values, where every node's best child is searched first. Knuth and Moore (1975) sort the nodes that alpha-beta visits into three types:

    • Type 1: the root, and the first child of every type-1 node. These lie on the principal variation and are searched with a full window. All their children are visited.
    • Type 2: every other child of a type-1 node, and the first child of each type-3 node. The first child of such a node already refutes the move (it causes a cutoff), so only one child is visited.
    • Type 3: the visited child of a type-2 node. Its parent's bound cannot be beaten by any of its children, so all of them are visited.

    Count the leaves by asking what each player has to prove. Let \(v\) be the root value. To show \(V\ge v\), max needs a strategy: one good move at each max node, but an answer to every move at each min node. The leaves of that strategy form a subtree that branches \(b\) ways at min levels only. The root is a max node, so min moves at depths \(1,3,5,\dots\) below \(d\), and there are \(\lfloor d/2\rfloor\) such levels. The proof has \(b^{\lfloor d/2\rfloor}\) leaves. To show \(V\le v\), min needs a strategy that branches at the \(\lceil d/2\rceil\) max levels, giving \(b^{\lceil d/2\rceil}\) leaves. With distinct leaf values the two proofs share exactly one leaf, the end of the principal variation. The type-1 and type-3 nodes above are exactly where these strategies branch. Hence

    \[L_{\min}(b,d)=b^{\lceil d/2\rceil}+b^{\lfloor d/2\rfloor}-1 .\]

    Any correct algorithm must examine both proofs, so \(L_{\min}\) is also a lower bound for every ordering. Its growth rate is \(\sqrt b\) per ply, so perfect ordering lets alpha-beta search twice as deep for the same cost.

    Random ordering: Pearl's branching factor

    With children in random order and leaf values independent and continuous, Pearl (1982) showed that alpha-beta evaluates about \(R_b^{\,d}\) leaves for large \(d\), where

    \[R_b=\frac{\xi_b}{1-\xi_b},\qquad \xi_b^{\,b}+\xi_b-1=0,\ \ 0<\xi_b<1 .\]

    \(\xi_b\) is the fixed point of the probability that a uniform tree's minimax value lies below a given threshold, as the depth grows. For \(b=2\) the equation is \(\xi^2+\xi-1=0\), so \(\xi_2=(\sqrt5-1)/2\) and \(R_2=(1+\sqrt5)/2\), the golden ratio. For large \(b\), \(R_b\approx b^{3/4}\). Random order therefore sits between the minimal tree's \(\sqrt b\) and minimax's \(b\). alpha_beta_branching_factor solves the equation by bisection.

    Every measured rate is above Pearl's value and falling towards it. The approach is slow: at the deepest trees searched the gap is 0.07 for \(b=2\), 0.14 for \(b=3\) and 0.08 for \(b=4\). This is expected: Pearl's argument is a limit, and the probability \(\xi_b\) only settles once the tree is deep enough for the root value's distribution to sharpen. The finite-depth rates happen to sit close to \(b^{3/4}\), but that is a coincidence of the depths reachable here. Random order is clearly far from the \(\sqrt b\) of the minimal tree. Engines therefore invest heavily in move ordering (killer moves, history tables, iterative deepening), to move from \(R_b\) towards \(\sqrt b\).

    Back to tic-tac-toe: ordering and windows

    Tic-tac-toe is not a uniform tree: the branching factor falls from 9 to 1, games end early, and the leaf values are only \(-1\), \(0\) and \(+1\). The last point matters. Ties mean that \(\alpha\ge\beta\) is often reached with equality, which the uniform-tree analysis excludes. The next block compares orderings on the full tree. It also tries narrow windows, which ask a yes/no question instead of computing a value. With the window \((-0.5,0.5)\), alpha-beta returns a value strictly inside it only if the game is a draw. With \((0.5,1.5)\) it asks whether X can force a win, and with \((-1.5,-0.5)\) whether O can.

    Every search agrees on the value 0. Square order, which tries squares in reading order, already avoids 97% of the final positions. The coarse values help: a tie with the bound already counts as a cutoff (\(\alpha\ge\beta\)), and with only three possible values ties are common. Perfect ordering needs only 781 leaves, 0.31% of the game. The worst order still prunes two thirds, because bounds inherited from above cut off deep lines, as on the uniform trees.

    The windows read as the bound rule says. For "can X force a win?" the result 0 is at most \(\alpha=0.5\), a fail low, so \(V\le0\) and the answer is no. For "can O force a win?" the result 0 is at least \(\beta=-0.5\), a fail high, so \(V\ge0\) and again the answer is no. That test is the cheapest of all, 462 leaves: X only has to show one line that avoids losing. The draw window returns 0 strictly inside \((-0.5,0.5)\), an exact answer, from 6 740 leaves, fewer than the 7 330 of the full window. Narrow windows prune more because \(\alpha\ge\beta\) is reached sooner, which is the idea behind aspiration search, PVS/NegaScout and MTD(f).

    Summary

    • Alpha-beta returns the exact minimax value. Inside the window the answer is exact; outside it is a bound in the right direction, so cutoffs are safe.
    • With perfect ordering it examines \(b^{\lceil d/2\rceil}+b^{\lfloor d/2\rfloor}-1\) leaves, about \(\sqrt b\) per ply, and no algorithm can do with fewer. order_moves(…, MoveOrder::BestFirst) reproduces the count exactly.
    • With random ordering on continuous leaves the rate is Pearl's \(R_b=\xi_b/(1-\xi_b)\), close to \(b^{3/4}\). Measured rates approach it slowly from above.
    • On the complete tic-tac-toe tree, alpha-beta proves the draw from 7 330 of 255 168 final positions in square order and 781 with perfect ordering. Narrow windows answer yes/no questions more cheaply still.
