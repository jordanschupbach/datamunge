    Random-hyperplane locality-sensitive hashing

    Abstract

    Random hyperplanes give nearby nonzero directions a higher probability of agreeing on a sign bit. Concatenating bits and searching several tables trades candidate count against missed neighbors. We retain the original collision experiment and2000-by30 near-duplicate workload, expose actual query decisions, and distinguish fewer cosine evaluations from the implementation’s total query cost.

    A tiny actual signature and candidate search

    For a nonzero vector x and a sampled plane normal r, assign bit one when dot(r,x) is nonnegative, otherwise zero. Exact zero maps to one in this implementation. A table concatenates k such bits into an unsigned key. Query only the matching key in each table, suppress duplicate input identities, and choose the first strict maximum cosine among encountered candidates. It can miss the exact neighbor or find no candidates; it is not an exact search certificate.

    The tiny example uses three two-dimensional directions, two tables, two bits each and seed7. Its diagram/table show actual stored-plane signs, real keys and actual bucket visits. The trace is emitted during one producing query, rather than replaying signatures or recomputing candidates for the illustration.

    Why the ideal collision law is angular

    For two nonzero directions separated by angle theta in[0,pi], only their spanned plane matters. Isotropic random normal orientation separates their signs on a fraction theta/pi of directions, so single-bit agreement has probability p=1−theta/pi. With k independent bits per table, all-bit agreement has probability pk. With L independent tables, at least one matching table has ideal probability1−(1−pk)^L. This is a collision probability for one pair under ideal independent planes, not the probability that a finite candidate search returns the exact nearest neighbor.

    The original experiment samples20000 independent two-dimensional Gaussian planes at angles0,20,...,180 degrees, using mt19937_64 seed3. The native study then continues the very same generator stream for the original indexed data and queries. The displayed agreement counts are measured, while the reference curve is the isotropic law. No calibration or deterministic finite-sample equality is claimed.

    Ownership, finite arithmetic and honest query cost

    The index now copies complete finite rectangular input data. Destroying or changing the caller’s vectors cannot invalidate it or silently mismatch old buckets and new coordinates. Copies of the index own their data, planes and buckets. Const queries share no mutable state. This intentionally fixes the earlier borrowed-pointer lifetime/stale-bucket hazard. Nonempty input requires positive dimension; query dimension must match exactly, including an empty query for an empty-data index. Zero vectors are supported operationally with cosine0 and nonnegative-dot bits, but have no mathematical angle for the isotropic law.

    Signature widths0..64 are checked; zero bits put every row in each table’s key0 and zero tables deliberately yield no candidates. A full64-bit key uses a safe unsigned shift through bit63. Complete malformed/nonfinite inputs are rejected before indexing, even if no tables would be searched. Finite ordinary dot/cosine arithmetic retains its original order. If nonfinite raw arithmetic occurs, positive max-magnitude scaling supplies the deciding plane sum or cosine; no exact-sign certificate is implied by floating arithmetic. Extreme finite and subnormal vectors are covered separately from ordinary seeded compatibility.

    A query initializes N dense visited marks before searching, so total query work is O(N+L*k*d+V+C*d), where V is actual bucket-member visits and C is distinct cosine evaluations. This is not a worst-case sublinear implementation, even when C is small. Index storage includes O(N*d+L*k*d+L*N) owned values/ids, excluding map overhead. Trace storage additionally owns query coordinates, actual projection records, table probes with their real members and candidate visits. Logical admission counts each of those records before its copy, default one million and zero disabling only the optional cap; it excludes fields, capacities, model/runtime copies, visited marks and bytes.

    The controls below show operational consequences directly. With zero bits, every row is examined once despite duplicate visits across tables. With one plane, an antipodal query to a single indexed direction produces no bucket candidate. No-candidate results use SIZE_MAX and similarity sentinel−2, not an invented nearest neighbor.
