    Backtracking Search: Simple Paths and Knight's Tours

    Abstract

    Backtracking extends a partial solution one choice at a time and undoes the last choice when no extension works. On a graph, the partial solutions are simple paths, and the search tree is the tree of all simple paths from the start. We derive its size for complete graphs, where the number of simple paths between two vertices is exactly \(\lfloor e\,(n-2)!\rfloor\), and count it by exhaustion on grids, where the corner-to-corner paths grow from 12 on a \(3\times3\) grid to 1,262,816 on a \(6\times6\) grid. Looking for one path that visits every vertex (a Hamiltonian path) explores the same tree, so the order of branches and the ability to cut dead subtrees decide everything. On the knight's graph of a chessboard, trying moves in index order solves only 6 of the 64 starting squares within a million nodes; a connectivity prune raises that to 30; Warnsdorff's rule, which tries the most constrained square first, solves all 64 with a median of 64 nodes, meaning no backtracking at all. The same rule still stalls on some larger boards, which is where backtracking earns its keep.

    The algorithm

    Backtracking keeps a simple path \(v_0v_1\cdots v_k\) (no repeated vertex) and a mark on each vertex currently on it:

    The marks are the invariant: a vertex is marked exactly while it is on the path, so the path is always simple, and every reported path is valid. Every simple path from the start corresponds to exactly one call of SEARCH, so the calls form the tree of simple paths: the root is the start, and each node's children are its one-vertex extensions. Memory is only the path and the marks, \(O(V)\), but time is the size of the tree, which is usually exponential.

    dm::algorithms::backtracking_search() stops at the first path it finds. On a \(4\times4\) grid from one corner to the other it follows the lowest-numbered neighbour each time:

    First path found: 0 → 1 → 2 → 3 → 7 → 6 → 5 → 4 → 8 → 9 → 10 → 11 → 15 (12 edges; the shortest has 6). Calls before reaching the goal: 13.

    Exhausting the tree instead: 184 simple paths from 0 to 15, 1271 search nodes, 208 dead ends, longest path 14 edges.

    The first path found is not short: always taking the lowest-numbered neighbour sweeps the grid row by row and reaches the goal after 12 edges, twice the 6 of a shortest path. Backtracking answers "is there a path?", not "which is best?"; for shortest paths, breadth-first search or Dijkstra's algorithm visit each vertex once. Here the first branch happened to succeed, so 13 calls sufficed. Listing every path is a different matter: the \(4\times4\) grid has 184 simple corner-to-corner paths, and finding them took 1,271 search nodes, 208 of them dead ends where the path had trapped itself.

    How big is the tree?

    Complete graphs, exactly

    In the complete graph \(K_n\) every ordering of distinct vertices is a path. A simple path from \(s\) to \(t\) with \(k\) intermediate vertices chooses them, in order, from the other \(n-2\): \((n-2)!/(n-2-k)!\) ways. Summing over \(k\) and substituting \(j=n-2-k\),

    \[P_n=\sum_{k=0}^{n-2}\frac{(n-2)!}{(n-2-k)!}=(n-2)!\sum_{j=0}^{n-2}\frac1{j!}=\bigl\lfloor e\,(n-2)!\bigr\rfloor\quad(n\ge3).\]

    The last step holds because the tail \((n-2)!\sum_{j>n-2}1/j!\) is positive and, for \(n\ge4\), below \(\tfrac1{n-1}+\tfrac1{(n-1)^2}+\cdots=\tfrac1{n-2}<1\) (and equals \(e-2<1\) at \(n=3\)). The search tree has one node for every path from \(s\) that avoids \(t\) except perhaps at its end. Those ending at \(t\) number \(P_n\); those ending elsewhere are the same choices without the final step to \(t\), also \(P_n\). So the tree has exactly \(2P_n\) nodes.

    Grids, by exhaustion

    On a grid there is no closed form. The number of corner-to-corner simple paths on a \(k\times k\) grid of vertices is sequence A007764 in the OEIS, and it is known that it grows like \(\lambda^{k^2}\) with \(\lambda\approx1.7445\) per vertex.     The grids grow more slowly but still exponentially: the blue curve is close to a straight line in the number of vertices. The per-vertex growth \(\text{paths}^{1/k^2}\) rises from 1.19 to 1.48 and is still far from its limit of about 1.74, so the next grid, \(7\times7\), has 575,780,564 paths and would need roughly \(10^{10}\) nodes. The 6×6 grid took 18.5 million nodes, about 90 ms on this machine. The ratio of nodes to paths grows too, from 2.5 to 14.6, and over a fifth of the nodes are dead ends. Exhaustive backtracking is only useful for small instances.

    Hamiltonian paths: order and pruning

    A Hamiltonian path visits every vertex once. Deciding whether one exists is NP-complete, and backtracking searches the same tree of simple paths, stopping at the first path of length \(V-1\). Two levers change how much of the tree it sees:

    • *Branch order.* Trying the most constrained neighbour first, the one with the fewest unvisited neighbours of its own, tends to visit awkward vertices before they are cut off. For knight's tours this is Warnsdorff's rule (1823).
    • *Pruning.* If the unvisited vertices are not all reachable from the end of the path through unvisited vertices, no completion exists, and the whole subtree can be skipped. The test is one graph traversal, \(O(V+E)\), per node.

    The knight's graph joins two squares of a board when a knight can move between them. A Hamiltonian path in it is an open knight's tour. A knight always changes square colour, so a tour alternates colours. On a board with an odd number of squares the tour must start and end on the majority colour; from any other square, no tour exists and backtracking must exhaust the tree to prove it.

    The order of branches matters more than anything else. In index order, backtracking found a tour from only 6 of the 64 squares within a million nodes. The connectivity prune made each node more expensive but cut whole subtrees, and raised that to 30. Warnsdorff's order found a tour from all 64 squares, and from the median square it needed 64 nodes, exactly one per square: it never backtracked. Its hardest start needed 67,771 nodes.

    The figure shows why the rule works. Squares near the edge and in the corners have few knight moves, so they are the ones that get stranded. Warnsdorff's order visits them first, sweeping around the rim (moves 1 to 30 stay mostly in the outer two rings) and leaves the well-connected centre for the end, when flexibility is most needed.

    When the heuristic is not enough

    Warnsdorff's rule is a heuristic, and ties (several squares with the same number of onward moves) are broken here by square index. On larger boards that tie-break sometimes walks into a dead end, and backtracking has to recover. The block runs Warnsdorff-ordered search from the corner of every \(k\times k\) board for \(k=5,\dots,60\) with a limit of two million nodes, and lists the boards where it needed to backtrack, with and without the connectivity prune.

    From the corner, Warnsdorff's order completes 50 of the 56 boards without a single backtrack. On \(11\times11\), \(25\times25\) and \(43\times43\) it makes a wrong choice but recovers, the last only after 325,927 backtracks: a mistake early in a long path is undone only after the whole subtree below it is exhausted. On \(49\times49\), \(58\times58\) and \(60\times60\) it does not recover within two million nodes. The connectivity prune detects the stranded squares as soon as they are cut off, rather than at the end of the path, and solves the 43, 49 and 58 boards in a few thousand nodes. On \(60\times60\) it prunes 941,133 subtrees and still runs out of budget, so the mistake must lie further back than the prune can see. Better tie-breaking rules, such as Pohl's (1967) or Squirrel and Cull's (1996), avoid many of these failures.

    Summary

    • Backtracking explores the tree of simple paths: one node per path from the start, \(O(V)\) memory, exponential time.
    • In \(K_n\) there are exactly \(\lfloor e(n-2)!\rfloor\) simple paths between two vertices and \(2\lfloor e(n-2)!\rfloor\) search nodes, confirmed up to \(n=11\). Grids grow more slowly but still exponentially: 1,262,816 corner-to-corner paths and 18.5 million nodes on \(6\times6\).
    • For Hamiltonian paths the branch order decides the outcome: on the \(8\times8\) knight's graph, index order solved 6 of 64 starts within a million nodes, a connectivity prune 30, and Warnsdorff's rule all 64, usually without backtracking.
    • On larger boards the rule's ties occasionally lead it astray; backtracking with the prune recovers on most of them but not all.
