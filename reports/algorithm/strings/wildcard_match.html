    Wildcard Matching: Whole Fields, Byte Semantics and Suffix Rescans

    Abstract

    A restricted glob has two metacharacters: a star accepts any byte sequence and a question mark accepts exactly one byte. We apply this language to Name fields in dm::datasets::titanic(), separating whole-field filtering from substring occurrence counting. A trace of the canonical matcher shows how the most recent star expands; a separate prefix dynamic program explains the accepted language. The same loop's counters expose a quadratic family, correcting the tempting inference that monotone star expansion implies linear total work. A regression involving a star inside the text illustrates why pattern metacharacters must retain their meaning before literal comparison.

    The data: independent passenger-name fields

    The built-in Titanic frame contains 891 passenger records. We treat each non-null Name cell as an independent byte string; matching never bridges two records. Names include surnames, titles, given names and punctuation. The query language does not parse those components. The first table and length distribution describe the strings being filtered.

    The language, precisely

    Matching is case-sensitive and anchored to the complete field. A star * matches zero or more bytes; ? matches exactly one. Every other pattern byte is literal, including period, comma, slash, brackets and backslash. There is no escaping, bracket class, path rule or case folding. This is a restricted glob language, not a regular expression, a full shell expansion engine, SQL LIKE or the complete .gitignore syntax.

    Consequently Mr.* requires the field to begin with the literal bytes Mr.. *Mr.* permits a prefix and suffix and asks whether those literal bytes occur anywhere. A question mark refers to a byte, not a Unicode character: UTF-8 é needs two question marks. Embedded NUL bytes remain ordinary text bytes. If text contains *, a pattern star still acts as a wildcard. For example, text *ba matches pattern *a; interpreting their first equal-looking stars as a literal match would incorrectly reject it. The canonical loop now handles the pattern star before literal comparison.

    A last-star scan and why only one retry point is needed

    Use text offset \(i\), pattern offset \(j\), most recent star position \(s\), and its current text endpoint \(q\). At a literal or question match, advance both offsets. At a pattern star, remember it and first try an empty match. On a mismatch, if a star exists, extend its matched text by one and restart immediately after that star. Otherwise reject. Trailing pattern stars may accept an empty suffix.

    Between stars the pattern consists of fixed-length blocks of literals and question marks. Choosing the earliest feasible placement of a block leaves at least as much suffix text as any later placement. Once another star is reached, that newer star can absorb any extra gap needed later; there is no benefit in retaining alternative placements before it. This exchange argument justifies remembering the most recent retry point. It does not claim that all text positions are examined only once.

    A separate prefix dynamic program describes the same language

    Let \(D(i,j)\) mean that pattern prefix \([0,j)\) accepts text prefix \([0,i)\). Start with \(D(0,0)=1\), \(D(i,0)=0\) for positive \(i\), and \(D(0,j)=D(0,j-1)\) only for a trailing star in that empty-text prefix. For positive indices,

    \[D(i,j)= \begin{cases} D(i,j-1)\lor D(i-1,j), & p_{j-1}=*,\\ D(i-1,j-1), & p_{j-1}=?\text{ or }p_{j-1}=t_{i-1},\\ 0, & \text{otherwise}. \end{cases}\]

    The star case has priority over literal equality, including when the text byte itself is a star. Induction on prefix lengths proves the recurrence: the final action of any accepting match is one of the listed cases, and each listed predecessor extends to a valid match. The whole field is accepted exactly when \(D(n,m)\) is true. This explanatory grid is not the state path executed by the greedy matcher.

Survival fractions describe these matched records and their associated demographics. They do not establish a causal title effect or turn the glob into a survival model. Null strings are distinct from empty strings: a null is skipped, whereas an empty string is a valid field matched by an empty pattern or stars.

    Why monotone star expansion does not prove linear time

    The star endpoint \(q\) only increases, but the current text offset \(i\) can return to the beginning of the suffix being retried. Take text \(a^{2r}\) and pattern \(*a^r b\). For each failed candidate, the matcher consumes \(r\) matching a bytes and tests the final b again. There are \(r\) such failing suffix attempts, then a final \(r\)-byte scan reaches text exhaustion with b still unmatched. Including the initial star transition, the exact loop-step count is

    \[C(r)=1+r(r+1)+r=(r+1)^2.\]

    Both input lengths grow linearly with \(r\), so this family is quadratic. The general scan bound is \(O((n+1)(m+1))\): at most \(n\) star expansions, each allowing another pattern suffix scan, plus the initial and trailing work. It avoids exponential enumeration of star assignments, yet constant auxiliary storage is compatible with repeated work. Optimised glob implementations may use additional strategies; this bound describes this actual local loop.

    The full explanatory DP takes \(O((n+1)(m+1))\) storage as well as time. Its public helper checks a cell budget before allocating. The trace helper also checks its retained-event budget. The ordinary decision and counter APIs need constant auxiliary storage and do not build either diagnostic artifact.

    Conclusion

    Whole-field glob filters are precise about anchoring, byte consumption, case and punctuation. On Titanic names they produce reproducible row subsets and record-level summaries. A shared scan gives both decisions and actual work traces; a separate DP explains acceptance independently. Correct pattern-star handling includes stars inside the text. Finally, an exact adversarial count makes the performance limit explicit: this last-star matcher uses constant workspace but can take quadratic time.
