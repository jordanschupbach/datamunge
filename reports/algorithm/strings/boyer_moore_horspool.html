    Horspool Search: The Window-Ending Byte Chooses the Shift

    Abstract

    Horspool simplifies Boyer–Moore by using one shift table keyed by the text byte at the end of the current pattern window. That byte can differ from the one that caused a mismatch. We illustrate the distinction, retain the original abra search and shift-table plot, and inspect actual native alignment records. Exact comparison counts show both large skips and a quadratic mismatch family. Finally, built-in Titanic passenger names provide a record-wise text-search example against an independent naive baseline. Logical work counts describe these inputs; they do not establish a universal runtime ranking.

    A small example: mismatching X, but shifting on A

    Search for ABCA in AXCABCA. At the first window, the ending A and preceding C match, then B mismatches text byte X at pattern index one. Horspool uses the window's ending A to choose shift three. It does not use the mismatching X, whose table entry is four. The next window starts at offset three and matches ABCA. The two windows cost three and four comparisons respectively.

    The diagram reads those decisions from the same core scan as ordinary search. Red cells are failed comparisons, green cells matched, and the blue outline marks the text byte used for the shift lookup. Other cells were not compared at that alignment.

    The table and why the shift is safe

    For a nonempty pattern P of length m, initialize every byte's shift to m. For each position i<m-1, overwrite shift[P[i]] with m-1-i. Later positions win, so the result uses the rightmost occurrence in the prefix that excludes the final pattern byte:

    \[\operatorname{shift}[c]= \begin{cases} m-1-\max\{i<m-1:P[i]=c\}, & c\text{ occurs in }P[0..m-2],\\ m, & \text{otherwise}. \end{cases}\]

    Let c be text[s+m-1]. Any occurrence starting between s+1 and the proposed next start would put c at a pattern position to the right of its rightmost eligible prefix occurrence. That cannot match. If c has no prefix occurrence, all starts before s+m are excluded. This argument depends on the final window byte rather than on where the right-to-left comparisons stopped, and also applies after a full match.

    Excluding the final pattern position guarantees positive shifts and preserves overlapping occurrences. For pattern aa, shift[a]=1, so searching aaaa finds starts zero, one and two. For a one-byte pattern every shift is one. Empty patterns match nowhere by this library's convention; their all-zero table is never used to advance a search.

    Boundary controls and a quadratic mismatch family

    Matching is case-sensitive on bytes. Embedded NUL and high-byte values are supported; offsets in UTF-8 are byte offsets, with no decoding or normalization. Empty and oversized patterns produce no search windows. The trace still builds their table so it can be inspected.

    For text A repeated n times, pattern A repeated m times produces n-m+1 full overlapping matches, each taking m comparisons. Pattern B followed by m-1 copies of A produces no matches, yet each window compares the m-1 trailing As before failing at its first byte. For m>=2, its ending A has shift one, so this no-match family also requires exactly m(n-m+1) comparisons. Omitting the good-suffix heuristic therefore has a visible cost on these inputs. In contrast, pattern B repeated m times needs one comparison per m-byte jump.

    Real text: separate searches over passenger names

    The built-in Titanic table contains 891 passenger records. Search each Name separately for the five literal patterns below, with no case folding or word boundary rules. A match cannot span records, and a passenger can contain a pattern more than once. These counts describe substrings in this table, not categories inferred from titles or names.

    The one-shot function takes O(m+256) preprocessing work and O(256) auxiliary storage, plus O(K) returned offsets. Search is O((n-m+1)m) comparisons in the worst eligible case. The trace retains O(A+K+256) storage for A actual windows and K matches, without copying the pattern or text. Calls borrow inputs without mutation and own their outputs; independent calls share no state. The comparison counter is checked for size_t overflow. A larger shift on one window is useful evidence about that window, while performance conclusions need the actual workload, preprocessing costs and timing context.

    Reference

    R. N. Horspool (1980), Practical fast searching in strings, Software: Practice and Experience 10(6), 501–506. [Original paper](https://doi.org/10.1002/spe.4380100608). The core uses right-to-left comparisons and extends the search to report every overlapping occurrence.
