    Bitap: Parallel Prefix States and Substitution Windows

    Abstract

    Given a byte string and a short pattern, locate every equal-length window that matches exactly or differs in at most a chosen number of positions. Overlapping windows and partial matches must survive while new matches begin. Bitap packs these prefix states into machine words. We derive the update, inspect a three-byte example, retain the original synthetic DNA motif, and exhaust a four-letter Hamming ball. The report uses canonical match and trace APIs rather than counting windows with a separate search implementation.

    The method

    For pattern P of m bytes, build one mask for every possible byte c: bit j of \(M_c\) is one exactly when \(P_j=c\). Bit j of the state R means that the length-\(j+1\) pattern prefix matches the text suffix ending at the current position. Reading c performs

    \[R' = ((R\ll1)\lor1)\land M_c.\]

    The low seed bit starts a fresh candidate at every position. Every higher bit extends a matching shorter prefix only when its next byte agrees. Induction on the consumed text proves the state interpretation; bit \(m-1\) signals a full match. An earlier full match does not prevent a new overlapping one.

    For at most d substitutions, keep states \(R_0,\ldots,R_k\). With every right-hand state taken from the *previous* text position,

    \[R'_0=((R_0\ll1)\lor1)\land M_c,\qquad R'_d=\left(((R_d\ll1)\lor1)\land M_c\right) \lor\left((R_{d-1}\ll1)\lor1\right),\quad d\ge1.\]

    The words are masked to m bits. A complete length-m window is accepted at the smallest level whose top bit is active, which gives its actual Hamming distance. Every window consumes exactly m text bytes. Insertions and deletions are outside this mode. The budget is clamped into \([0,m]\): allowing more than m substitutions cannot admit another length-m window.

    Simple example: parallel restarts in AABA

    Use pattern ABA. The exact states after A, A, B, A are 001, 001, 010, 101, written with the longest prefix bit on the left. The last state has both the full prefix ABA and the one-byte prefix A active. Thus a complete occurrence and a fresh possible occurrence coexist.

    The legacy interfaces use different index conventions: bitap_search returns a *start*, while bitap_fuzzy_search returns an *inclusive end*. For the first exact seven-byte motif these are 5 and 11. Modern match records instead use the consistent half-open interval \([5,12)\), plus the actual substitution count. The repeated occurrences at starts 5 and 38 are separate windows.

    Checking the theory: exhaust a Hamming ball

    For a fixed m-byte pattern over an alphabet of q symbols, the number of strings at exactly d substitutions is

    \[H_d={m\choose d}(q-1)^d.\]

    For pattern ACGT over ACGT, the coefficients of \((1+3z)^4\) are \((1,12,54,108,81)\). Their sum is 256, the number of all four-byte strings. The program constructs those strings, asks Bitap for each full-window distance, and compares the measured histogram with the exact formula.

    If a text were independently sampled uniformly from that alphabet, the expected number of qualifying windows would be \((n-m+1)\sum_{d=0}^k H_d/q^m\). Linearity of expectation does not require windows to be independent; overlapping window indicators generally are dependent. The constructed motif example is not sampled from this model, so its counts are not a significance calculation.

    Requested budget INT_MAX: effective budget 4, 5 windows, 8 bytes, 40 word updates. Empty pattern in ab: 3 boundary matches. Insertion example ABXCD versus ABCD at budget 1: 0 windows.

    The ABXCD example contains a one-insertion alignment with ABCD, but neither four-byte window is within one substitution. This distinguishes Hamming windows from variable-length edit-distance matches. Empty patterns produce n+1 empty boundary intervals in modern helpers; the two legacy first-match calls retain their special return value zero.

    For a nonempty pattern, preprocessing uses 256 masks and m assignments. A full scan with effective budget k performs exactly \(n(k+1)\) state-word updates, plus acceptance checks and output handling. The overall work is \(O(n(k+1)+m+256)\), with fixed word-state storage and one result per reported window. Tracing additionally owns \(n(k+1)\) recorded words. Work counts do not establish a runtime advantage over another string-search algorithm.

    All indices and lengths count bytes. Matching is case-sensitive, supports NUL and arbitrary byte values, and performs no Unicode normalisation. The exact legacy call supports patterns through 63 bytes; its fuzzy counterpart retains the older 62-byte limit. Modern helpers support 63 bytes and use one active-bit convention at every error level.

    Conclusion

    The hand example exposes simultaneous full matches and restarts. Canonical match records reproduce the original motif counts and index conventions, while exhaustive enumeration verifies the Hamming-distance histogram. Native tests also check every recorded prefix bit against direct suffix comparisons. These synthetic and exhaustive controls establish the algorithmic claims without introducing biological conclusions or an unrelated observed dataset.
