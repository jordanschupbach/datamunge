    Boyer–Moore: Exact Byte Matching and the Shifts It Actually Takes

    Abstract

    Boyer–Moore compares a pattern against the text from right to left, then skips forward using bad-character and strong good-suffix rules. We first inspect a five-byte example, retain the original DNA search and its six alignments, and read the preprocessing tables, mismatch positions and comparison counts directly from the canonical C++ search loop. A final experiment contrasts large skips, unit shifts and repeated full matches. Skipping can reduce inspected bytes on suitable inputs; this all-occurrences implementation can still do quadratic comparison work when many long matches overlap.

    Simple example: shift two positions, then match

    Search for ABC in XXABC. The first comparison is pattern[2]=C against text[2]=A. A's rightmost pattern index is zero, giving bad-character shift 2-0=2. The good-suffix rule offers one, and the core takes max(1,2,1)=2. The next alignment matches ABC at offset two, comparing C, B and A in that order. The two visited alignments require four byte comparisons in total.

    Both panels use actual records from boyer_moore_trace. Coloured cells show compared bytes: red for the failed comparison and green for equal bytes. Uncoloured cells in a visited alignment were not compared during that alignment.

    Exact problem and the two safe shift rules

    For text length n and pattern length m, return every start s with 0<=s<=n-m whose m bytes equal the pattern. Matches may overlap. The library returns no matches for an empty pattern or one longer than the text. Strings are byte sequences: embedded NUL and high bytes work, comparison is case-sensitive, and UTF-8 offsets count bytes rather than characters.

    At alignment s, suppose the first mismatch encountered from the right is at pattern index j. The suffix pattern[j+1..m-1] already matched. If c is the mismatching text byte, the raw bad-character proposal is j-last[c], where last[c] is the rightmost pattern index containing c, or -1 if absent. It can be negative when the rightmost occurrence lies to the right of j. The core floors progress at one and combines it with the positive good-suffix shift:

    \[d=\max\{1,\ j-\operatorname{last}[c],\ \operatorname{shift}[j+1]\}.\]

    The strong good-suffix rule looks for an earlier copy of the matched suffix preceded by a different byte from pattern[j]. If none works, it aligns a pattern prefix with a suffix of the matched part. The condition on the preceding byte rules out an alignment known to repeat the same mismatch. The core builds the shift array in two passes over border positions: first record eligible repeated suffixes, then fill remaining entries using prefix borders. Index zero is the full-match shift, based on the longest proper border; it preserves overlapping occurrences.

    Each rule excludes occurrences before its proposed next alignment. Taking the larger safe lower bound remains safe. It does not prove that this choice is fastest in elapsed time or that all bytes between alignment starts were unread: each alignment can inspect several trailing bytes.

    At s=16, the last G matches and the next comparison fails on absent A at pattern index four. The raw bad-character shift is five, while good-suffix shift[5] is two, so the chosen shift is five. At s=12, C is present in the pattern and the chosen shift is one. Each full match shifts three, preserving the pattern's GCG border. These are observations from this input, rather than an average-case claim about all DNA sequences. A small alphabet can make substrings recur frequently and limit skipping.

    Large skips, unit shifts and the all-match worst case

    Fix text A repeated n=2048 times and vary pattern length m. Three deterministic families separate the reasons for a low or high comparison count:

    • Pattern B repeated m times: every mismatch is against a byte absent from the pattern, so each alignment costs one comparison and shifts m.
    • Pattern A repeated m-1 times followed by B: the rightmost comparison fails immediately, but the mismatching A occurs at pattern index m-2. Shifts are one, so every possible start is visited with one comparison.
    • Pattern A repeated m times: every start is a full overlapping match, the period shift is one, and the core rechecks all m bytes each time.

    The last family makes exactly m(n-m+1) comparisons. With m proportional to n, this is quadratic, even though the method can skip well on other inputs. The implementation does not remember already matched regions across alignments.

    Boundary and byte controls

    The trace exposes the raw negative bad-character proposal when it occurs. For AABB against ABAB, the final B matches and the next B mismatches A at pattern index two. The rightmost pattern B is at index three, hence bad=-1. The strong good-suffix rule supplies four, ensuring safe forward progress. The sentinel for a full-match mismatch index is m, not a valid pattern index.

    Preprocessing takes O(m+256) work and storage. Ordinary search allocates the match offsets but no alignment records, and its worst-case comparison bound for this implementation is O((n-m+1)m). A trace retains O(A+K) records for A visited alignments and K matches, plus the tables. Both APIs borrow inputs without mutation and own their outputs. Trace always preprocesses the pattern, even for impossible searches; ordinary search returns immediately for empty or oversized patterns. Signed border-index range and recorded counter overflow are checked. Generated byte strings suffice for the algorithmic experiments; no observational dataset is required.
