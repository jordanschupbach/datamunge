    Zhu–Takaoka Search: When a Pair of Bytes Buys a Longer Shift

    Abstract

    Zhu–Takaoka combines Boyer–Moore's good-suffix rule with a shift indexed by the final two bytes of a text window. We derive the digram table, including its easily missed prefix-overlap case, and show why taking the larger of two safe bounds preserves every occurrence. A compiled matcher searches dm::datasets::titanic() names independently, reports actual byte comparisons, and exposes each alignment's chosen shift. Naive search and Horspool give reference results and work counts on the same records. The comparison includes the algorithm named in the title; preprocessing cost and periodic worst cases are kept explicit.

    The data: names are separate records

    The built-in Titanic dataset contains 891 passengers and 12 columns. Its Name column has surnames, titles, given names and parenthesised names. This gives natural exact-substring queries with different lengths and frequencies. Search is case-sensitive on bytes; no linguistic tokenisation or Unicode normalisation is implied. Each name is searched separately, so a match cannot run from the end of one passenger's name into the next.

    The method: right-to-left comparison with two safe bounds

    For pattern \(P\) of length \(m\ge2\), align its first byte with text position \(s\). Compare \(P\) against \(T[s,\ldots,s+m-1]\) from right to left. On a mismatch, inspect the final window digram \((a,b)=(T[s+m-2],T[s+m-1])\).

    Consider a possible occurrence starting \(d>0\) bytes later. If \(1\le d\le m-2\), the old trailing digram must align with \((P[m-2-d],P[m-1-d])\). If \(d=m-1\), only the old final byte remains in the pattern, so it must equal \(P[0]\). A shift of \(m\) places both old bytes before the candidate. The smallest permitted shift is therefore

    \[D(a,b)=\min\left(\{m\} \cup\{m-1:b=P[0]\} \cup\{m-1-i:1\le i\le m-2,\ (P[i-1],P[i])=(a,b)\}\right).\]

    Initialise every entry to \(m\), set the column for \(P[0]\) to \(m-1\), then visit internal digrams from left to right, overwriting entries with decreasing distances. The terminal pattern digram is excluded: its zero distance would prevent forward progress.

    For Miss. the internal digrams Mi, is and ss permit shifts 3, 2 and 1. Any pair ending in M permits prefix overlap at shift 4. Most remaining pairs permit shift 5, including s.: a candidate with the same terminal pair still has to move by a positive distance.

    Combining the digram bound with a strong good suffix

    Suppose the comparison mismatches at pattern index \(j\), after matching \(P[j+1,\ldots,m-1]\). The strong good-suffix shift \(G_j\) moves to the next occurrence of that suffix preceded by a different byte. If none exists, it aligns the longest possible suffix with a pattern prefix. Candidates starting before \(G_j\) contradict either the matched suffix or the mismatching predecessor. Independently, candidates starting before \(D(a,b)\) contradict the trailing pair. Hence

    \[\Delta=\max\{G_j,D(a,b)\}\]

    is safe: any start smaller than the maximum violates at least one necessary condition. After a full match, use the full-match good-suffix shift, equal to \(m-\ell\), where \(\ell\) is the length of the longest proper border of the pattern. This preserves overlapping matches: aa in aaaa occurs at offsets 0, 1 and 2.

    Work and storage

    Preprocessing takes \(O(m+\sigma^2)\) time and space for alphabet size \(\sigma=256\). The digram table has 65 536 integer entries: 256 KiB when int is four bytes. Horspool uses 256 shifts instead. A compiled ZhuTakaoka object pays the digram cost once and reuses it for every record; the one-shot zhu_takaoka_search rebuilds the tables each call.

    At most \(n-m+1\) alignments are visited, with up to \(m\) comparisons at each: the safe worst-case bound is \(O(nm)\). For repeated a text and pattern, every alignment matches and the full-match shift is one, so this bound is attained. A useful average shift does not prove linear worst-case complexity or a speed advantage on short records.

    For a fixed pattern with \(d\) distinct internal digrams, an independently uniform window-end pair over \(\sigma\) symbols is absent from that set with probability exactly \(1-d/\sigma^2\). Absent pairs usually license long shifts, subject to prefix overlap. Passenger names are structured, and visited window ends are selected by previous shifts, so this toy probability is not a performance prediction for this dataset.

    All 15 method/query combinations agree record by record. Across the five queries, naive search performs 108 699 comparisons, Horspool 30 351 and Zhu–Takaoka 27 981. The digram rule saves about 7.8% relative to Horspool on these records. Its advantage is a measured property of these queries, not a guarantee for every name corpus or pattern.

    Counts exclude allocation and table construction, and are not elapsed-time benchmarks. The larger digram table can lose on cache or setup costs even when it saves comparisons. Reusing a matcher is particularly relevant for many short strings such as these names.

    Testing the periodic limit

    The worst-case construction needs no random generator. For pattern aaaa in aaaaaaaa, every possible alignment matches, all four bytes are compared, and the period-one good-suffix shift advances by one. This diagnostic is a theoretical counterexample, separate from the dataset analysis.

    Conclusion

    A two-byte shift supplies a stronger necessary condition than a single byte in many windows. The prefix-overlap case and strong good-suffix rule are both needed to move safely. Actual instrumented scans show whether that extra information reduces work on these passenger names; the trace explains each chosen advance. The larger preprocessing table and periodic worst case remain relevant even when the comparison chart is favourable.
