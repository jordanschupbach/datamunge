    Subset sum: exact half sums and actual witness lookups

    Abstract

    Meet in the middle replaces full-subset enumeration with two exponential half spaces. Actual widened sums, sort comparisons and lookup probes retain the original signed examples while avoiding overflow in sums and target differences.

    Mechanism and mathematical scope

    Split n keys at floor(n/2). Enumerate every right-half mask, sort its sums, then enumerate left masks and binary-search target-left_sum. Any full witness decomposes into exactly such a pair. Directly scanning each mask costs O(n*2ceil(n/2)); sorting and repeated binary searches add their logarithmic factors. The original2n versus2^(n/2) curves compare search-space sizes, not measured runtime speedups. Negative values and the empty subset are valid. Private signed128 arithmetic is exact for at most62 signed64 keys and one signed64 target difference.

    API and interpretation

    Complete half-subset geometry is checked before allocation; intrinsic n<=62 protects masks and exact accumulator capacity. Default policies permit at most2million right masks. Sorting equal sums does not promise a particular tied right witness. The API returns one actual subset rather than all witnesses, and the report labels theoretical search-space ratios as references.

    Reusable producers, fixtures and histories live in the canonical C++ library. Captured records own their values and do not come from a separate report replay. Selected counters and record/scalar policies are specified at their API boundaries; they are not peak-byte or wall-time budgets. Synthetic structural inputs are controlled fixtures for these mechanisms.
