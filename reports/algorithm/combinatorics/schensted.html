    Schensted row insertion: actual bumps and paired tableaux

    Abstract

    Insert an integer sequence into rows and retain the insertion tableau P and recording tableau Q. Native row histories show which value was bumped; the original permutation [4,1,3,6,2,5] remains the central tableau example.

    Mechanism and mathematical scope

    In a row, replace the first value strictly greater than the carried value and carry the replaced value into the next row. If none is greater, append and record the insertion index in Q. P has weakly increasing rows and strictly increasing columns; Q has the same shape. For distinct inputs, Schensted's theorem identifies the first row length with the strict longest increasing subsequence length. With duplicates, this insertion convention instead corresponds to a longest nondecreasing subsequence. Direct row scans take O(N^2) worst-case time and O(N) intrinsic storage.

    API and interpretation

    The histories are actual row mutations. A standard-tableau interpretation assumes distinct inputs. Capture stores copied row states and can exceed the intrinsic tableau size; it has its own admission cap.

    Reusable producers, fixtures and histories live in the canonical C++ library. Captured records own their values and do not come from a separate report replay. Selected counters and record/scalar policies are specified at their API boundaries; they are not peak-byte or wall-time budgets. Synthetic structural inputs are controlled fixtures for these mechanisms.
