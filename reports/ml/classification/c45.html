    Continuous Gain-Ratio Trees: A Checked C4.5-Inspired Learner

    Abstract

    A continuous decision tree asks binary threshold questions until it reaches a class label. We derive information gain and gain ratio on four hand-checkable rows, inspect the candidates actually considered by datamunge, and evaluate five-fold predictions on the native iris dataset. The original 180-point, three-cloud experiment remains as a training-fit control. The existing c45_train API implements a restricted, unpruned, maximum-ratio learner inspired by C4.5; it omits C4.5's average-gain filter, categorical and missing-value machinery, pruning and later threshold penalties. New native tracing exposes actual row memberships, candidate scores and stopping reasons, without replaying training.

    Four rows: derive the first split

    Use two identical numeric features with rows (0,0), (1,1), (2,2), (3,3), and labels 0,0,1,1. Parent class entropy is one bit. For class proportions p_c, with zero terms omitted, define

    \[H(S)=-\sum_c p_c\log_2 p_c,\qquad G(S,t)=H(S)-p_LH(L)-p_RH(R),\]
    \[I(S,t)=-p_L\log_2p_L-p_R\log_2p_R,\qquad R(S,t)=G(S,t)/I(S,t).\]

    At t=1.5 each child is pure, so G=I=R=1. At t=0.5 the left child has one class-zero row and the right has labels 0,1,1: conditional entropy is three quarters times H(1/3,2/3), giving G about 0.311278 and ratio about 0.383689. Every boundary splits nonempty groups, so I is positive. Both features offer identical candidates; the first strict maximum chooses feature zero.     At each node the learner sorts distinct observed values per feature, considers all adjacent boundaries, and chooses the first strictly positive maximum ratio. An explicit work stack grows the left subtree before the right. Every split has two nonempty children, so each path has fewer rows after a split and the unlimited tree terminates. Majority labels use the smallest integer to break class ties. A node without a positive computed ratio stays a majority leaf.

    Gain ratio normalizes by the entropy of the partition, rather than by its number of children. It does not universally remove attribute-selection bias. Quinlan's account restricts selection to tests with at least average gain; the later continuous-attribute modification also charges a threshold-description penalty and changes threshold selection. This API retains its original unrestricted maximum-ratio rule. All tests here are binary, and the report does not claim to implement the full C4.5 system. See the [original paper](https://arxiv.org/abs/cs/9603103).

    Iris: measure predictions on flowers excluded from fitting

    The native iris frame contains 150 flowers, 50 per species, with four measurements in centimetres. We use every measurement and code setosa, versicolor and virginica as 0,1,2. Row index modulo five defines fixed folds, each containing ten flowers per species. Every prediction in the cross-validation column comes from a model fitted on the other 120 flowers. This deterministic fold rule depends on dataset order; it is a reproducible illustration, not an independent external validation. Dataset structure follows the [R iris documentation](https://stat.ethz.ch/R-manual/R-devel/library/datasets/html/iris.html).

    The separate full-data training fraction measures fit on the model's own 150 rows. Looking at all six depth settings uses the same folds repeatedly; selecting a depth from this table and treating its maximum as an unbiased final estimate would require a further outer evaluation. There is no imputation, scaling or feature selection. Classification uses only coordinate ordering.

    The depth cap is a growth control, not statistical pruning. With a fixed root and deterministic search, relaxing it only refines leaves. Child majorities cannot have fewer total correct training labels than retaining the parent's majority at those rows. Thus training fit cannot decrease solely from deeper growth; this argument places no lower bound on held-out accuracy.

    Retain the original three-cloud experiment

    The original report generated sixty points per centre at (0,0), (6,0) and (3,6), coordinate standard deviation 0.6, with mt19937_64 seed five. That reusable generator now lives in dm::datasets::gaussian_blobs(). It preserves centre/row/coordinate draw order and has no shared RNG state. The C++ normal distribution can differ across standard libraries, so the seed is a same-toolchain repeatability guarantee, not a promise of portable bit-identical coordinates. The current program prints the actual full tree as flat nodes, then recreates the original training-accuracy-versus-depth plot.

    Stopping, numeric boundaries and complete-call budgets

    A parent with at least min_samples rows may split off a single row. This parameter is not a minimum leaf size. Identical feature rows with contradictory labels cannot be separated by a threshold. Pure XOR also has zero gain at every root test, so this greedy learner stops at a majority leaf with half the labels correct; two levels of a manually chosen XOR tree would classify all four.

    The old midpoint expression could overflow on finite values or round to the upper boundary and discard a valid separating test. The checked implementation uses std::midpoint and falls back to the lower observed value if necessary. Training rejects nonfinite features, mismatched labels and ragged rows before purity shortcuts. Prediction checks the visited path, including tested feature availability, finite tests/values, child indices and cycles. Unvisited branches and unused query values are deliberately not a whole-model validation.

    XOR: 2 root candidates; model nodes 1; majority label 0. Adjacent doubles: threshold 1, at lower -> 3, at upper -> 7. Alternating four labels: 6 candidates, 20 row tests, 7 nodes; one-short budget rejected: true. Nonfinite singleton training rejected: true; short visited query rejected: true.

    The complete-call candidate budget includes zero-gain tests and throws before partitioning an excess candidate. It returns no partial model. candidate_row_tests counts only row/threshold comparisons used to evaluate candidates; it excludes sorting, class-map operations, the final selected repartition and prediction. Neither counter is a timing or a full operation count.

    At a searched node of m rows and d features there are at most d(m-1) candidates. This implementation repartitions all m rows and recomputes ordered-map entropies for each, giving the upper bound O(d*m*m*log(m)) per searched node, summed over the tree. It does not use a prefix-count threshold sweep. Ordinary training keeps no provenance records. Tracing additionally stores node row memberships and every actual candidate, requiring O(n*h+c) storage for reached depth h and c candidates. All construction and ownership use flat arrays and explicit pending partitions.

    Native verification compares 37,324 exhaustive small one-dimensional training configurations and 1,000 random multifeature/multiclass cases against a separate recursive, materialized-label trainer. Additional cases check exact scores and ties, original cloud draw order, ownership, stopping reasons, whole-call budgets, invalid training and visited prediction paths, extreme finite midpoints, adjacent representable values and subnormals. The tests check the implemented restricted learner; they do not establish equivalence to a full C4.5 release.
