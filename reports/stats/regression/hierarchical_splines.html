    B-splines, P-splines and hierarchical spline fits

    B-splines, P-splines, HB splines and HP splines

    Compare four cubic spline fits to the same 241 observations: a smooth wave, a narrow bump near x = 0.65, and deterministic oscillatory measurement errors. Each language tab is a complete program using the native datamunge solvers and plotting API. Run blocks from this document's directory. Python and R use the local packages built with just build-python and just build-r; rebuild R after the hierarchical spline bindings change.

    • *B-spline:* BSplineRegression fits 40 global cubic basis functions by ordinary least squares, without a smoothing penalty. It has the same 37 uniform knot spans on [0, 1] as the P-spline below.
    • *P-spline:* PSplineRegression uses 40 global basis functions with a second-difference coefficient penalty and lambda = 0.5.
    • *HB:* HierarchicalBSpline first fits 10 global basis functions, then adds a 32-coefficient local residual patch on [0.5, 0.75]. Both fits are unpenalized.
    • *HP:* here this means *hierarchical penalized splines*. The same hierarchy calls fit_cell_penalized with lambda = 0.5 and difference order 2 on each patch. This is a use of HierarchicalBSpline, rather than a separate HP class.

    The B-spline repeats its boundary knots; the P-spline extends uniform knots past the boundaries. Their cubic spline spaces on [0, 1] agree: setting the P-spline penalty to zero reproduces the B-spline predictions to numerical precision. The positive P-spline penalty acts on its extended-basis coefficients.

    For each penalized fit, the coefficients minimize

    \[\|y - B\beta\|^2 + \lambda\|D_2\beta\|^2.\]

    For a local patch, y in this expression is the residual after the ancestor patches. Pass the original observations to the API; it computes that residual itself. Child bases use local coordinates on [0, 1]. Refining the upper half of the root and then its lower half selects [0.5, 0.75]; the intermediate cell has no patch. All polynomial degrees stay at 3: this example's HP does not mean hp refinement with variable polynomial degree.

    The HB/HP implementation is a Forsey–Bartels additive patch hierarchy. Independent patches do not enforce continuity at cell boundaries; this is also different from the nested basis in TruncatedHierarchicalBSpline. The table reports RMSE against the known noise-free signal at 1,001 grid locations. Coefficient counts are stored coefficients, not effective degrees of freedom. These illustrative settings use different spline spaces and are not an equal-complexity model selection comparison.

    The refinement figure below each fit shows the actual HB and HP cell trees. Each horizontal bar is an instantiated cell at its refinement depth. Vertical ticks mark the distinct knots of that cell's fitted basis, mapped from local coordinates back to global x; repeated endpoint knots are drawn once. The root has seven knot spans and 10 coefficients. The fitted [0.5, 0.75] patch has 29 spans and 32 coefficients; its parent [0.5, 1] is a routing cell with no fitted patch. Both methods use the same mesh and cubic degree: HP changes the penalty, not the refinement geometry. These are overlapping additive patches, so the bars do not represent disjoint leaf elements.

    With these settings, the standard B-spline has the lowest signal RMSE (0.01567). Local refinement and a fixed penalty do not automatically improve a fit; the mesh figure explains where the hierarchical models spend their additional coefficients.
