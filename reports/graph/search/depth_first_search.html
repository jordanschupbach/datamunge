    Depth-First Search: Actual Backtracking, First Paths and Complete Finish Times

    Abstract

    Given a directed graph, a source and a target, we want to know whether a path exists and return one if it does. Depth-first search follows one unseen successor at a time, returning to an earlier vertex only after its current branch is exhausted. The original two-vertex example is retained with visible results. A seven-vertex control then shows genuine backtracking, a cycle edge, early stopping and a first DFS path longer than the shortest path. Native traces record discoveries, scanned original arcs, target states and actual finishes without replay. Complete source traversal supplies valid finish intervals, while explicit heap frames preserve the old recursive order on a 200,000-vertex chain. We derive the reachable-work and linear storage bounds, test adjacency-order effects, and distinguish active frames from total graph/history memory.

    Keep the original path, then expose a backtracked branch

    The original input, two vertices and the arc 0→1, returns [0,1], found=true and expanded=2. Here expanded means first entries, including the goal; it does not mean scanned edges. The larger prescribed graph has source zero and goal six. Source adjacency is [1,2,6]. DFS first follows 0→1→3, scans 3→0 but finds zero already active, then finishes three and one.     Derive the frame invariant and reachability guarantee

    The canonical implementation keeps an explicit frame (vertex,next successor) for each active vertex. Its stack is the current directed tree path from source to the current vertex. A newly entered vertex is marked immediately, so a loop or another incoming arc cannot enter it twice. Before descending, the parent's successor position advances. When the child finishes, that position identifies exactly where the corresponding recursive call would resume. Induction over entries, edge scans and returns shows that this explicit loop preserves the old recursive adjacency order and first path. It avoids dependence on the process's recursive call-stack depth.

    A returned path is valid because every non-root frame was pushed through an actual directed arc from its parent. Vertices on it are distinct because all entries obey global marking. If the target is entered, the kernel stops before examining its outgoing arcs. It does not pop the successful path or fabricate finish events during a hypothetical unwind. If the stack becomes empty without the target, every reachable vertex has been entered: otherwise, a source-to-unseen path would contain a first unseen vertex whose reached predecessor must have scanned and entered it before finishing, a contradiction. This proves the reachability decision, not minimum path length.

    Let R be discovered vertices and E_scan the actual adjacency entries scanned before termination. Each entry is discovered once, each finished frame pops once, and each source list position advances once. Thus traversal work is O(R+E_scan), with R≤n and E_scan≤m. The wrapper still validates all input arcs, constructs adjacency and initializes n states, giving O(n+m) total worst-case time even when start=goal. Adjacency occupies O(n+m), search state and possible output path O(n), and optional actual history O(n+m). Only the current frame count can be smaller on a shallow tree. No stack snapshot is copied at each event, avoiding an accidental quadratic trace cost.

    Full traversal gives genuine discovery and finish intervals

    The next run has no goal stop. It retains the same eight arcs, adds a parallel 0→1 arc, a self-loop 2→2 and an unreachable self-loop at vertex seven. Complete traversal visits the source component, not every graph component. Its result.found=false and empty path mean that no goal was requested; preorder/expanded still describe all seven reached vertices. All ten reachable adjacency entries are scanned, including the duplicate and reachable loop, while the unreachable loop is only validated/stored.

    Timestamps tick only on discoveries and actual finishes. For a tree parent u and child v in the completed run,

    \[d(u)<d(v)<f(v)<f(u).\]

    The child call begins after its parent's entry and ends before the parent can exhaust its remaining adjacency. Repeating this fact nests descendant intervals; intervals of separate completed branches are disjoint. In a successful early-stop run, active vertices have no finish time, so no completed-interval conclusion is inferred for them. Missing times use 2n, checked for representability before graph allocation; root/unseen parents and depths use n, and an absent original parent-edge id uses m.

    For directed graphs, a scanned arc to an active vertex closes a cycle along the ancestor path, including a self-loop. Arcs to finished vertices need not cause descent; they may be forward or cross arcs. In a complete traversal of a reachable DAG there are no active-target arcs, and reverse postorder is a topological order of that reachable subgraph. This report's loop-containing control is not claimed to have such an order. The API does not restart at unseen vertices to construct a whole-graph DFS forest.

    Input order changes the first path and stopping work

    The direct edge 0→6 exists in both larger goal-search runs. Move it from last to first in source zero's adjacency and DFS returns [0,6], with two entries and one scan. In the original order it returns a four-edge path after seven entries and seven scans. BFS on that same graph returns the one-edge path because it searches by hop distance. DFS's entry count is not BFS's dequeue count; the table below compares DFS counts only.     Linear trace work and worst-case active depth

    For a completed source traversal, every reached vertex is discovered and finished exactly once, and every outgoing adjacency entry of those vertices is examined exactly once. There are therefore

    \[N_{\rm events}=2R+E_R.\]

    A successful goal run instead has R discoveries, F genuine finishes, E_scan examinations and one goal event; its actual total is R+F+E_scan+1. For the seven-vertex example, 7+2+7+1=17. A full tree has R=n and E_R=n−1, so its trace has 3n−1 events regardless of branching shape. Active frames are different: a chain reaches n, a binary tree grows logarithmically, and a nontrivial star reaches two. The complete graph, state arrays and retained history still use linear space in n+m even for a shallow tree. Explicit frames remove recursive call-stack limits, not the need for memory.

    Complete endpoint/terminal validation precedes adjacency allocation and all optional caps, even for a trivial goal or bad unreachable arc. Trace limits bound every original vertex and edge, including unreachable records, and every actual retained event. Event caps are online; exhausting one throws without a partial result. Zero disables only that optional cap, while 2n timestamp arithmetic and container capacities remain checked. The old four-argument result function has no optional trace limits and allocates no trace events. No external dataset is needed for these graph-order and work controls; the reusable native tree generator supplies their exact inputs.

    Independent controls and scope

    Nine new tests pass AddressSanitizer and UndefinedBehaviorSanitizer. Exhaustive controls enumerate all directed graphs with loops through three vertices and all loop-free directed graphs on four vertices: 4,626 graphs in total. They compare 70,210 source-goal searches and 17,954 complete source traversals with a small recursive oracle that scans the original edge sequence. A separate transitive-closure computation checks reachability independently of DFS order. Tests compare selected paths, entry/finish orders, parents, original parent edges, depths, timestamps, target states, counters and replayed event/frame boundaries. One thousand seeded ordered multigraphs add loops, duplicate arcs and reversed edge orders. The original minimal case, backtracking/early-stop/shortest-path distinction, complete interval nesting, DAG reverse postorder, ownership, graph/event caps, timestamp arithmetic and native tree-generator guards pass. A 200,000-vertex ordinary path and 20,000-vertex complete chain test deep entry and finish behavior. Existing search_more cases verify compatibility with neighbouring search APIs.

    The API answers directed reachability and returns its first DFS-tree path. It does not enumerate all simple paths, minimize hops or weights, or scan unreachable components unless another source is requested. Discovery, expansion and completion are separate observable events; early stopping does not silently turn partial state into a completed DFS forest. The native report inputs make these distinctions visible without a forced external dataset.
