    Brute-Force Path Search: Incumbents, Pruning and Factorial Work

    Abstract

    Given a directed unweighted graph, find a start-to-goal path with the fewest edges. Backtracking can solve this by exploring simple path prefixes, but many prefixes can reach the same vertex and the search can require factorial work. This implementation retains the shortest path found so far and prunes prefixes that cannot improve it. We inspect that actual search, retain the original three-vertex chain, and verify a closed-form dense unreachable case. The canonical native loop supplies the paths, visit records, bounds and counts.

    A worked graph: a long incumbent, a shorter replacement and a tie

    Start at zero and seek five. Input order first follows 0→1→2→5, a three-edge path. The edge 2→0 is rejected because zero is already on that live path. The next root branch finds 0→3→5, which has two edges and replaces the incumbent. The last root branch first reaches prefix 0→4→1. That prefix already has three vertices, as many as the incumbent, and is cut off. Path 0→4→5 also has two edges; a strict-improvement tie rule retains 0→3→5.

    The graph highlights the returned path in green. The table lists the two actual incumbent changes; it does not reconstruct them using another search.

    The search space and the safe bound

    Mark only vertices on the current path. On descent, append a new vertex and mark it; on return, remove it and clear its mark. Rejecting an arc to a marked vertex keeps every explored prefix simple. A vertex can still be revisited through another prefix after backtracking. A shortest path in a unit-cost graph can always be simple: deleting a repeated-vertex cycle shortens a walk.

    Let L be the incumbent's vertex count and let a current prefix have l vertices. Every extension has at least l vertices. Thus a non-goal prefix with l≥L cannot lead to a strict improvement and can be pruned. Goals are handled first: the first goal path or a strictly shorter goal path replaces the incumbent, while an equal-length goal leaves it unchanged. This retains the first shortest alternative in the directed adjacency order.

    Before the first incumbent, the search explores every permitted prefix. After finding one, it can omit longer goal paths under pruned prefixes. The original claim that the implementation enumerates every simple start–goal path is therefore too strong. Optimality follows instead from the combination of simple path coverage and the safe length bound: no pruned prefix can contain a better solution. The bound is tested once on entry to a non-goal prefix; an already active parent's successor scan continues after a descendant improves the incumbent, preserving the historical traversal and visit count.

    BFS provides an efficient native reference for the final minimum number of edges; it is the preferable algorithm when this is the only required result. Here the backtracking search is useful for inspecting search-space repetition and incumbent bounds. A full trace copies each live prefix; recording can omit those path copies while retaining ids, parents, depths and decisions.

    Original chain and boundary controls

    The original report's three-vertex chain is retained. It returns [0,1,2], which has three vertices and two edges, after three entered prefixes. Input pairs are directed arcs. Reversing the terminals does not insert reverse arcs. Self-loops are rejected by live-path membership; parallel arcs retain their original order and can cause repeated visits to the same labelled prefix. All terminals and arc endpoints are validated before adjacency allocation, even when start equals goal. An empty graph has no valid terminals.

    A factorial family: dense reachable component, isolated goal

    Place the start in a complete directed graph on k vertices and leave goal k isolated in a graph of k+1 vertices. No incumbent can be found, so no length bound activates. Every ordered subset of the k−1 other reachable vertices is a simple prefix from the start. The exact number of entered prefixes is

    \[V_k=\sum_{j=0}^{k-1}\frac{(k-1)!}{(k-1-j)!},\qquad V_1=1,\qquad V_k=1+(k-1)V_{k-1}.\]

    Every visited endpoint has k−1 outgoing arcs and all are scanned. Hence A_k=(k−1)V_k, with A_k−V_k+1 rejected cycle arcs. The native generator supplies all directed non-loop arcs within the component. A trace without prefix copies measures this search, while BFS exhausts only k vertices on the same input.     The explicit stack has at most n live frames, and it avoids native recursion depth limits. Ordinary search uses O(n+m) live storage. With V entered prefixes, A inspected arcs and I vertex ids copied into improving incumbents, its work is O(n+m+V+A+I). A trace adds O(V) record storage and, by default, the total length of copied prefixes. Disabling those copies preserves every other field. The factorial argument above assumes unique arcs; duplicate arcs can repeat equivalent prefixes and add more work.

    The search maintains only a unit-edge length objective. It does not solve a weighted shortest-path problem, and the bound is too weak to prevent factorial work when no incumbent is available. These limitations explain why the example is a study of exhaustive search with bounding rather than a replacement for BFS.

    References and verification

    [NIST's Dictionary of Algorithms and Data Structures](https://xlinux.nist.gov/dads/HTML/exhaustiveSearch.html) uses exhaustive search for trying every possibility. This library's existing brute_force_search name denotes the more specific incumbent-bound path-prefix method described here. A. H. Land and A. G. Doig (1960), An Automatic Method of Solving Discrete Programming Problems, Econometrica 28(3), 497–520, [doi:10.2307/1910129](https://doi.org/10.2307/1910129), is general branch-and-bound background; the simple graph bound here is derived directly from prefix length.

    The original chain and worked graph are fully specified; the dense family is generated in the core without a dataset or random seed. Native tests compare all directed graphs through four vertices and every terminal pair with independent Floyd–Warshall distances and first-adjacency shortest-path recovery. They also check actual incumbent history, counters, ordered loops/duplicates, the factorial family, complete-call limits, invalid inputs and a 50,000-vertex chain with path snapshots omitted. Every report block is an editable complete C++ programme; figures are local SVG files rather than XML printed into the results.
