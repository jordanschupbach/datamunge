    Multi-Goal Best-First Search

    Abstract

    Given a directed graph with nonnegative edge costs, find the cheapest route from one start to any vertex in a goal set. The first goal discovered need not be the cheapest. We derive the lower-bound stopping rule, inspect a four-vertex example by hand, and show why inconsistent estimates require reopening vertices. The historical b_star_search API implements multi-goal A*: its result is optimal when the supplied estimate never exceeds the distance to the nearest goal and is zero at every goal. An overestimating example demonstrates the limit.

    The method

    Let \(T\) be a nonempty goal set. For each vertex retain the best discovered cost \(g(v)\) from the start and a parent pointer. Queue vertices by

    \[f(v)=g(v)+h(v),\qquad h(v)\le d(v,T)=\min_{t\in T}d(v,t),\qquad h(t)=0\quad(t\in T).\]

    Remove the smallest key, ignoring obsolete entries. If the vertex is a goal, return its parent path. Otherwise relax every outgoing edge: a strictly smaller cost replaces the stored label and queues another entry, even if this vertex was expanded earlier. Equal priorities prefer the smaller vertex identifier; equal-cost alternatives retain their original parent.

    For an optimal path of cost \(C^*\), before termination there is a frontier vertex reached with its optimal prefix cost. Its key is at most \(C^*\). A removed goal has key equal to its route cost, so a goal costing more than \(C^*\) cannot precede that frontier. This proves the stopping rule in exact arithmetic. Discovery alone gives no such comparison.

    The API name is retained for compatibility. Its queue rule is the A* method of Hart, Nilsson and Raphael (1968), extended to a goal set. Berliner's 1979 paper, The B tree search algorithm: A best-first proof procedure*, instead separates optimistic and pessimistic game-tree bounds. This report studies the actual datamunge graph API.

    Simple example: two possible destinations

    Vertex 0 has a route to goal 2 costing \(1+5=6\), and a direct route to goal 3 costing 2. The lower bounds \((2,5,0,0)\) are exact. After removing 0, the queue contains vertex 1 with key 6 and goal 3 with key 2; removing 3 proves the answer.

    Reopening when the bound is inconsistent

    A bound is consistent when \(h(u)\le w(u,v)+h(v)\) on every edge. Consistency means queue keys cannot decrease along an improving route and each vertex needs at most one expansion. Admissibility alone still permits an estimate to fall sharply across an edge; reopening then preserves the optimal-path frontier used in the proof.

    Consider edges \(0\to1\) costing 3, \(0\to2\) costing 1, \(2\to1\) costing 1, and \(1\to3\) costing 3. Goal 4 is isolated. The bound \((0,0,4,0,0)\) is admissible but inconsistent on \(2\to1\): \(4>1+0\). Vertex 1 first expands with cost 3, then again with cost 2. Its improved route reaches goal 3 at cost \(1+1+3=5\).

    Checking the theory and its limits

    Keeping the same graph, increase only \(h(2)\). The exact remaining cost there is 4. Values through 4 are admissible; sufficiently larger values delay vertex 2 until after the cost-6 goal is removed. The library checks dimensions and finite values, but cannot establish admissibility without solving the path problem.

    With \(n\) vertices and \(m\) edges, a consistent estimate gives at most one non-stale removal per vertex and at most one successful relaxation per edge. The lazy binary heap therefore costs \(O((n+m)\log(n+m))\) time and \(O(n+m)\) storage. An inconsistent bound may produce exponentially many re-expansions and queued improvements. The returned count measures queue removals, including the goal, rather than distinct vertices or elapsed time.

    No observed dataset is needed: these small directed graphs isolate the stopping rule, disconnected goals, and reopening without introducing modelling assumptions. All costs use double precision. Nonfinite weights or estimates are rejected; overflowing accumulated costs or keys raise an error. Floating-point ties can still affect which equally good path is returned.

    Conclusion

    The four-vertex graph returns the cheaper goal after two removals. The second graph demonstrates that admissible but inconsistent estimates can expand a vertex twice while retaining the cheaper answer. Overestimation removes the guarantee. Use zero bounds when a justified lower bound is unavailable; this is uniform-cost search and remains optimal for nonnegative costs.
