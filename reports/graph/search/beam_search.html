    Beam Search

    Abstract

    Beam search keeps only the \(B\) most promising nodes of each layer of a search and forgets the rest, so its memory is bounded by the beam width rather than the size of the graph. We state the algorithm with a cost bound that makes it anytime. We then prove the two ends of its range: \(B=1\) is a greedy walk that can trap itself, and unlimited \(B\) is a label-correcting Bellman–Ford search that is optimal for any admissible heuristic. On the Maunga Whau elevation map, the same problem as the A* report, a beam of 16 cells finds the optimal route while holding only 16 cells per layer. Narrower beams return routes up to 26% dearer or none at all. Wide beams expand more cells than A*, because they re-expand cells whose cost improves.

    The method

    Layers and a beam

    Beam search (Lowerre 1976) explores a graph in layers, like breadth-first search, but keeps only the \(B\) most promising nodes of each layer, the beam. Each beam node's neighbours are generated and ranked, and only the best \(B\) form the next layer. Everything else is forgotten. The memory held at any time is one layer, at most \(B\) nodes, whatever the size of the graph.

    algorithms::terrain_beam_search() runs this on the terrain grids used in the A* report. Each cell \(v\) carries the cheapest cost \(g(v)\) found so far and a parent pointer. Let \(h\) be an admissible heuristic (a lower bound on the remaining cost), and \(U\) the cost of the best path to the goal \(t\) found so far (initially \(\infty\)). One layer works as follows:

    The search stops when the beam is empty, and the best path is read from the parent pointers. Classic beam search stops as soon as the goal is first reached (stop_at_first); continuing with the bound \(U\) turns it into an anytime search whose answer can only improve.

    Two rankings are available. With \(\text{key}=g+h\) the beam keeps the cells that look cheapest end to end, as A* would. With \(\text{key}=h\) it keeps the cells that look closest to the goal, ignoring what it cost to reach them: this is greedy best-first search with a bounded frontier.

    The two extremes

    *Width one.* With \(B=1\) the beam is a single cell, and each layer moves to its best-ranked neighbour that improves on any earlier visit. With \(\text{key}=h\) this is steepest descent on \(h\), and it can stop in a cell all of whose neighbours were reached more cheaply before, a dead end. The search uses \(O(1)\) memory beyond the cost table and follows one path.

    *Unlimited width.* If \(B\) is at least the number of cells, nothing is ever cut, and the search becomes a label-correcting shortest-path method: each layer relaxes the out-edges of exactly the cells whose \(g\) improved in the previous one. This is the queue form of the Bellman–Ford algorithm, with the extra rule that discards cells with \(g+h\ge U\). It is optimal.

    Proof. Let \(s=v_0,v_1,\dots,v_m=t\) be an optimal path of cost \(C^*\), and suppose the search ends with \(U>C^*\). Every prefix of the optimal path is optimal, so \(g^*(v_i)+h(v_i)\le g^*(v_i)+h^*(v_i)=C^*<U\) for every \(i\), using admissibility \(h\le h^*\). Hence no \(v_i\) with \(g(v_i)=g^*(v_i)\) is ever discarded by the bound. Take the largest \(i<m\) for which \(g(v_i)\) reaches \(g^*(v_i)\) at some point; \(i=0\) qualifies, since \(g(s)=0\). In the layer where that happens, \(v_i\) enters the next beam (no cell is cut when \(B\) is unlimited), and when it is expanded,

    \[g^*(v_i)+c(v_i,v_{i+1})=g^*(v_{i+1})<g(v_{i+1})\quad\text{and}\quad g^*(v_{i+1})+h(v_{i+1})\le C^*<U,\]

    so \(g(v_{i+1})\) is set to \(g^*(v_{i+1})\), contradicting the choice of \(i\). (If \(v_{i+1}=t\), \(U\) drops to \(C^*\).) So \(U=C^*\) at the end. \(\blacksquare\)

    The proof uses only one property of unlimited width: no cell on the optimal path is ever cut. With a finite beam, the optimal path survives only if each of its cells ranks among the best \(B\) of its layer. When one is cut, it may never be reached again, and the search returns a worse path or none at all. Beam search with finite \(B\) is therefore incomplete and not optimal, and the width trades memory and time against the quality of the answer. The bound \(U\) still gives a guarantee: the returned cost is the cost of a real path, so it is an upper bound on \(C^*\), while the A* lower bound \(h(s)\le C^*\) brackets it from below.

    The terrain

    We use the same problem as the A* report. dm::datasets::volcano() is the topography of Maunga Whau, Auckland, on an \(87\times61\) grid with 10 m spacing. A step costs its horizontal length plus \(\lambda=5000/600\approx8.3\) for every metre climbed (Naismith's rule), and the walker crosses the map from the south-east foot to the north-west foot. The heuristic is the octile distance plus \(\lambda\) times the net height still to gain, which is consistent. Dijkstra's algorithm gives the optimum \(C^*\) for comparison.

    The optimal route costs \(C^*=1291.5\) and runs north from the start, then west along the top of the map, skirting the cone. A* with the same heuristic expands 1,732 cells to prove it.

    With \(B=1\) the search fails. Ranked by \(g+h\), the single beam cell heads west along the low southern edge of the map, where moves cost no climbing. After 54 layers, at \(x=320\) m on the map edge, it reaches a cell whose four unexpanded neighbours had all been generated earlier at a lower cost and then cut from the beam. Since a cell is kept only when its cost improves, none of them can re-enter, and the beam empties. This is the incompleteness of the proof above: the search remembers the costs of the cells it discarded, but not the cells themselves.

    With \(B=4\) the beam follows the southern route round the cone and reaches the goal after 117 layers, at a cost 26% above the optimum. The beam is wide enough to stay alive but not to explore the northern route at the same time. With \(B=16\) both routes survive side by side in the beam, and the northern one reaches the goal first, after 97 layers, at exactly \(C^*\). The bound \(U\) then cuts off the southern band, so the search expands 1,525 cells, fewer than A*'s 1,732. With \(B=64\) the answer is the same but the beam spreads over most of the low ground and expands 4,109 cells.

    Ranking by \(g+h\) fails for \(B\le2\), is 24–26% above the optimum for \(B=4\) and 8, and is optimal for every \(B\ge16\). For this ranking the first path found is already the final one: once the goal is reached, the bound removes everything else in the beam.

    Ranking by \(h\) alone never fails. The beam always moves toward the goal, so even \(B=1\) arrives, at 16.7% above the optimum, in 75 layers. But the first path it finds is 15.4% above the optimum for every width from 2 to 8192, because \(h\) ignores the climbing already done and the first beam cell to reach the goal is the one that came most directly. The anytime continuation is what improves it: after the first path, the bound \(U\) prunes the beam and later layers find cheaper routes, reaching \(C^*\) from \(B=256\).

    The work grows almost in proportion to \(B\) until the beam stops being cut. From \(B=256\) the largest beam actually held is 145 cells for \(g+h\) and 310 for \(h\), and every wider beam does the same search. That unlimited search expands 5,439 cells for \(g+h\), more than the 5,307 cells in the grid, and 11,885 for \(h\). The reason is the Bellman–Ford structure of the proof: a layered search can reach a cell cheaply only after reaching it expensively, and every improvement re-expands the cell. A*'s priority queue avoids this by always expanding the cheapest \(f\) first, so with a consistent heuristic each cell is expanded once. The beam's advantage is memory. With \(B=16\) it holds 16 cells per layer and still finds the optimum, whereas A* pushes 3,571 entries onto its queue for the same answer. All searches take under a millisecond on this machine.

    Summary

    • Beam search keeps the best \(B\) cells per layer, so memory is \(O(B)\) per layer, but it is incomplete and not optimal for finite \(B\). algorithms::terrain_beam_search() adds the cost bound \(U\), so after the first path it keeps searching for cheaper ones until the beam empties.
    • With \(B=1\) it is a greedy walk that can trap itself; with unlimited \(B\) it is a label-correcting Bellman–Ford search, optimal for any admissible heuristic, as proved above.
    • On Maunga Whau, ranking by \(g+h\) fails for \(B\le2\), is about 25% off at \(B=4\) or 8, and is optimal from \(B=16\), where it expands fewer cells than A*. Ranking by \(h\) never fails, but its first path stays 15% off at every width; only the anytime bound brings it to the optimum.
    • Unlimited beams expand more cells than A*, up to 2.2 times the grid for the \(h\) ranking, because layered search re-expands cells whose cost improves. Beam search trades that extra work for bounded memory.
