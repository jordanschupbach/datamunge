    Beam-Stack Search

    Abstract

    Beam search bounds memory by keeping the best \(B\) nodes per layer, but it can miss the goal or return a poor path. Beam-stack search keeps the same beam and stores a range of \(f\)-values for each layer on a stack. When it reaches a dead end it backtracks, regenerating the deepest layer with the next slice of that range. We prove that this makes the search complete and optimal with at most \(B\) nodes per layer. On the Maunga Whau elevation map, every beam width finds and proves the optimal route, from \(B=1\), holding 121 nodes, upwards. The proof hides a cost: once a layer is dropped its cells are forgotten. Without a table of finished cells, widths up to 16 were still running after \(10^7\) expansions, with one cell expanded 83,392 times. With the table every width finishes within 205,000 expansions and 21 ms on this machine.

    The method

    From beam search to beam-stack search

    Beam search keeps the best \(B\) nodes of each layer and forgets the rest. The beam search report showed what that costs on a terrain map: with \(B\le2\) it found no path at all, and with \(B=4\) or 8 it returned a route about 25% too dear. Beam-stack search (Zhou and Hansen

    1. keeps the beam's memory bound but remembers which part of each layer it has explored,

    so that it can come back for the rest.

    Write \(f(v)=g(v)+h(v)\), with \(h\) admissible, and order the candidates of a layer by the key \((f(v),v)\), using the cell index to break ties so the order is total. Each stored layer \(l\) carries a half-open range \([\ell_l,u_l)\) of keys on a stack, starting at \([-\infty,\infty)\). Layer \(l+1\) is built from layer \(l\) exactly as in beam search, with three filters: only children whose key lies in \([\ell_{l+1},u_{l+1})\) are kept, children with \(f\ge U\) (the best goal cost so far) are pruned, and a child is dropped if its cell already sits in a stored layer with no greater \(g\). If more than \(B\) children survive, the best \(B\) are kept and \(u_{l+1}\) is set to the key of the first one left out. The search goes deeper until a layer comes out empty. Then it backtracks:

    Each layer is thus explored in consecutive slices \([-\infty,u^{(1)}),[u^{(1)},u^{(2)}),\dots\), at most \(B\) nodes at a time, in increasing order of \(f\).

    Completeness and optimality

    The slices of a layer partition its candidates. The candidate set of layer \(l+1\) depends only on the stored layers \(0,\dots,l\) and on \(U\), and neither of those changes while layer \(l+1\) is being sliced, except that \(U\) can fall. A fall in \(U\) only prunes candidates that could not improve on it. So when layer \(l+1\) is dropped, every child of the current slice of layer \(l\) with \(f<U\) has been placed in some slice, and by induction from the deepest layer upwards, every extension of it has been explored or pruned.

    The pruning is safe. Admissibility gives \(g^*(v)+h(v)\le C^*\) along an optimal path, so no prefix of an optimal path is pruned by the bound while \(U>C^*\). A child dropped as a duplicate has a copy in a stored layer with \(g\) no greater. Every path through the dropped child can be re-routed through the copy at no greater cost, and the copy's extensions are being explored. When the stack empties, every path cheaper than \(U\) has therefore been ruled out, and

    \[U=C^*\quad\text{(if a path exists)}.\]

    The memory is at most \(B\) nodes per stored layer. With \(U\) finite and every step costing at least \(c_{\min}\) (one cell, 10 m here), no layer deeper than \(U/c_{\min}\) can hold a node with \(f<U\), so

    \[\text{stored nodes}\;\le\;B\left(\frac{U}{c_{\min}}+1\right).\]

    The catch: forgotten cells

    The price of the memory bound is time. When a layer is dropped, its cells are forgotten, so the duplicate check no longer sees them. On a graph with many routes of similar cost, a grid most of all, the same cell can then be reached and re-explored along exponentially many paths, one for each combination of slices above it.

    algorithms::terrain_beam_stack_search() therefore has an option, remember_finished. When a layer is dropped, every node in it is finished: all its extensions with \(f<U\) have been explored, and \(U\) only falls. The smallest such \(g\) per cell goes into a table \(F\), and a later node \(v\) with \(g\ge F(v)\) is pruned. It is dominated by the finished copy, whose extensions were already covered. This keeps the result optimal and removes the re-expansion, but the table holds one number per cell, so the memory is no longer bounded by \(B\).

    The terrain

    As in the A* and beam search reports, dm::datasets::volcano() gives the topography of Maunga Whau, Auckland, on an \(87\times61\) grid with 10 m spacing. A step costs its horizontal length plus \(\lambda=5000/600\approx8.3\) per metre climbed. The walker goes from the south-east foot to the north-west foot. The heuristic is octile distance plus \(\lambda\) times the net height still to gain. A* gives the optimum \(C^*=1291.5\).

    With the finished-cell table, every width from 1 to 128 ends with the optimal cost 1291.5 and a proof that it is optimal. The first path is often much worse: 28% above the optimum for \(B=1\) and 54% for \(B=4\). The anytime curves then show the bound \(U\) creeping down as backtracking tries slice after slice. With \(B=1\), the search holds at most 121 nodes in its layers, one per layer down to depth 120, within the bound \(B(U/c_{\min}+1)\approx166\) from the first path. It needs 155,657 expansions and 31,894 backtracks, about 16 ms on this machine. Width 4 is slower than width 1 (204,666 expansions), because its first path was worse and took the search down a deep southern detour (depth 142). From \(B=8\) the work falls quickly. It is smallest at \(B=32\), with 4,167 expansions, 27 backtracks and 3,003 stored nodes. At \(B=64\) and 128 the beam is never cut below \(U\), so there are no backtracks, and the search is plain beam search with a bound. A* expands only 1,732 cells, but it keeps a queue of up to 3,571 entries and a cost for every cell it touches.

    The right panel is the trade-off: the narrower the beam, the less the layers hold, and the more the search has to work to make up for it. Note that the table itself holds one number for each of the 5,307 cells; the store counts only beam nodes.

    Without the table, the search finished only for \(B\ge32\). Widths 1 to 16 used up the budget of \(10^7\) expansions, about a second each, still holding their first or second path. The \(B=16\) search had already found the optimal route, but could not prove it. \(B=32\) needed 8,074 expansions without the table and 4,167 with it.

    Where the work goes

    The re-expansion without the table is easiest to see on the map. We count how often each cell is expanded by beam-stack search with \(B=16\), with and without the table, the latter stopped after \(10^7\) expansions.

    Both runs explore roughly the same region: the northern route and a band south of the cone, about 1,850–1,950 cells. Without the table, the \(10^7\) expansions are spread over only 1,843 cells, so the average cell was expanded over 5,000 times and one cell 83,392 times. Each backtrack regenerates a layer from scratch, and every cell below it is rediscovered along a new combination of earlier slices. With the table, a cell is expanded at most 21 times, once per strictly cheaper route found to it, and the whole search needs 8,213 expansions.

    Summary

    • Beam-stack search stores, for each layer, the range of \(f\) still to explore, and backtracks by moving the deepest cut layer on to its next slice. It is complete and, with an admissible heuristic, optimal, while holding at most \(B\) nodes per layer, at most \(B(U/c_{\min}+1)\) in all.
    • algorithms::terrain_beam_stack_search() found and proved the optimal route on Maunga Whau for every width from 1 to 128, where plain beam search failed for \(B\le2\) and was 25% off for \(B=4\) and 8.
    • Forgetting dropped layers makes narrow beams re-expand cells exponentially often. The optional finished-cell table prunes dominated nodes, keeps the guarantee and brings every width under 205,000 expansions, at the cost of one number per cell.
    • The width trades memory against time: \(B=1\) held 121 nodes but needed 155,657 expansions; \(B=32\) held 3,003 and needed 4,167.
