    Floyd–Warshall: actual intermediate stages and bounded shortest paths

    Abstract

    Floyd–Warshall computes a directed cost matrix for every source and destination. It admits intermediate vertices one at a time, updating distances and first hops with a compact in-place recurrence. This report preserves the original five-vertex example, all25 distances and the cost-minus-three route0→4→3→2. Native traces expose actual stage matrices and strict improvements. A separate negative-cycle control shows why a global cycle flag does not make every pair unbounded, while validated, bounded reconstruction prevents malformed next-hop data from causing an endless walk.

    One admitted intermediate can improve a direct route

    A graph has vertices0 through n−1 and directed edges carrying finite double costs. Negative edge weights are allowed. An absent route is represented by positive infinity, while the zero-length route from a vertex to itself starts at cost zero. Parallel edges keep the smallest weight; equal-cost candidates retain the existing first hop. The native API preserves its original matrix layout and strict tie policy.

    The recurrence and the in-place condition

    Let D^(k)[i,j] be the least cost using only intermediates0 through k−1. Initially, it contains direct edge minima and diagonal zeros. With no relevant negative cycle, an optimum can be chosen without repeated vertices: removing a nonnegative cycle cannot make a walk more expensive. Admitting k either keeps the old route or uses an i-to-k piece followed by a k-to-j piece:

    \[D^{(k+1)}[i,j]=\min\bigl(D^{(k)}[i,j],D^{(k)}[i,k]+D^{(k)}[k,j]\bigr).\]

    The outer loop must control the admitted set. In exact arithmetic without negative cycles, D[k,k]=0 and the k-th row and column cannot improve during their own sweep, so the in-place reads give the staged recurrence. This is an existence-of-a-simple- optimum argument, not a claim that every optimal walk avoids zero-cost cycles. With negative cycles, raw in-place numbers are retained as execution evidence; they must not be interpreted as finite shortest costs for affected pairs.

    The historical sources are Floyd's [Algorithm97: Shortest path](https://doi.org/10.1145/367766.368168),CACM5(6),345(1962), and Warshall's related Boolean reachability result, [A Theorem on Boolean Matrices](https://doi.org/10.1145/321105.321107),JACM9(1),11–12(1962). The API here uses positive infinity for absence, finite input weights, strict double comparisons and explicit next hops; it is not an exact-real arithmetic certificate.

    next[i][j] stores the first vertex after i on the chosen route. A strict improvement through k takes the current next[i][k]. Repeatedly following first hops for a fixed destination recovers the route. Cost and hop count are different objectives: the three-edge detour is cheaper than the one-edge direct route. Equal costs retain the earlier route; the library does not promise minimum hops or lexicographic paths.

    A negative cycle affects particular ordered pairs

    A negative cycle makes the cost unbounded below for an i-to-j query exactly when i can reach a negative-cycle vertex and that vertex can reach j. Repeating the cycle then lowers the walk cost without limit. The global flag detects existence; it does not claim every pair can travel through that cycle. Native classification tests negative diagonals together with the two reachability entries, without rewriting raw costs to negative infinity or trusting an externally supplied flag alone.

    Pair queries validate complete distance/next shapes and values before examining a particular pair, so they cost O(n squared) validation plus O(n) querying. The native whole unbounded-pair mask validates once and uses O(n cubed) worst-case work. The small display above queries statuses for clarity; it is not a timing benchmark. In exact arithmetic a negative diagonal certifies a negative cycle. Here the test is a strict double comparison, so near-zero floating cycles require attention to rounding.

    Guarded work, bounded reconstruction and complete trace admission

    The ordinary kernel uses O(n squared+E+n cubed) worst-case work and O(n squared) owned storage. It skips rows/columns with unreachable operands before addition. A dense unit-cost graph performs n cubed additions even with no sweep improvements; a graph with only diagonal reachability performs n additions. Both are actual counts, not elapsed times.     Reconstruction validates both full square matrices, all finite-or-positive-infinity costs and every hop ID before shortcuts. An affected pair throws a domain error; unreachable or broken sentinel chains return empty, while an unaffected diagonal returns its single vertex. External cyclic chains throw after at most n moves. Shape/value validation protects access but does not prove that externally supplied matrices contain optimal costs. Validation makes reconstruction O(n squared+path length), with O(path length) returned storage.

    Input edges must have valid endpoints and finite weights. Every attempted finite candidate addition must remain finite, including a candidate that would not improve a route. Checked counters and matrix/container bounds precede allocations; overflow is reported rather than silently turning a reachable route into the infinity sentinel.

    For full history, define A=2n+2n squared. The complete upper entry bound is

    \[C=E+A+(n+1)(1+A)+n^3.\]

    The units are owned tuples, outer-row entries, cells, stage objects and improvement records, not bytes or peak RAM. The conservative bound is checked before copies or execution, with a default one-million-entry cap. Zero disables only that optional cap. Arithmetic/container limits remain, and a graph with few improvements can still need large full-stage storage. No replay, truncation or partial trace is returned. Inputs and captured matrices/edges are independent owned values.

    The standard all-pairs scope and negative-cycle return convention are also described in the official [Boost.Graph documentation](https://www.boost.org/doc/libs/latest/libs/graph/doc/html/graph/algorithms/shortest_paths/floyd_warshall_shortest.html). The present API adds its own validated matrix/path contracts and actual evidence; this report makes no claim of cross-library floating-point or performance equivalence. All five complete editable programs use native APIs and deterministic graph fixtures, with no external dataset. Independent edge-list Bellman–Ford tests check finite and unbounded pairs; frozen records preserve matrices, next hops, valid routes, stage boundaries and strict updates, alongside address/undefined-behavior sanitizers.
