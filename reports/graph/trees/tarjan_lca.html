    Offline LCA: actual finish events, unions and query answers

    Abstract

    Knowing all ancestor queries in advance lets one depth-first traversal answer them with union-find. The original eight-node tree retains its seven query types, and actual finish/union events explain the representative ancestor invariant.

    Mechanism and mathematical scope

    Initialize singleton disjoint sets and ancestor[representative]=node. Finish every child subtree, merge it with its parent by rank and reset the merged representative ancestor to that parent. Mark u black when its subtree is complete. For a query(u,v) with v already black, answer ancestor[find(v)]. Path compression/rank give near-linear O((n+q)*alpha(n)) producing work, plus the disclosed complete-tree validation. Explicit frames avoid recursion. Self queries occur at both endpoint lists and may write the same answer twice.

    API and interpretation

    Nonempty tree geometry, every query ID, connectivity and absence of cycles/duplicate edges are validated before producing DFS. The old edge-count-only validator could loop on cyclic input; this now fails explicitly. Captured events use already computed representatives without adding find calls. The representative at a black event is tracked through actual unions, which matters when rank chooses a child representative.

    Reusable producers, fixtures and histories live in the canonical C++ library. Captured records own their values and do not come from a separate report replay. Selected counters and record/scalar policies are specified at their API boundaries; they are not peak-byte or wall-time budgets. Synthetic structural inputs are controlled fixtures for these mechanisms.
