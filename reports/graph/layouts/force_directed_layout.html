    Force-directed layout: actual forces, cooling and drawing units

    Abstract

    Edges attract and every unordered pair repels in datamunge's direct Fruchterman–Reingold variant. A tiny two-vertex example makes the force balance and movement cap visible. The original four-vertex path retains its actual seeded coordinates. Native owned traces then expose raw motion, cooling and a diagnostic potential without replay. Coincidence, edge multiplicity and small-graph controls show the method's limits; actual visit counts explain its quadratic repulsion work.

    Start with two vertices and one edge

    Place two vertices at x=−0.25 and x=0.25, both with y=0. The library uses unit area only to set k=1/sqrt(n), so k is approximately0.7071 here. At separation0.5 the repulsion magnitude is k²/d=1, while attraction is d²/k≈0.3536. Vertex0 therefore has net x-displacement about−0.6464. Its first movement is limited to0.1; it reaches x=−0.35. The second and final sweep has temperature0.05, rather than zero. All vertices read the same positions during force accumulation and move afterward.

    The force law and its regularization

    For positions p_u and p_v, write Delta=p_u−p_v, raw distance d=|Delta|, and h=max(delta,d) with delta=1e−9. The implementation adds Delta*k²/h² to u and subtracts it from v for repulsion. Each nonloop edge record instead adds −Delta*h/k to u and the opposite to v. Above the floor these give the familiar magnitudes k²/d and d²/k. Below it, both forces shrink linearly to zero at coincidence; the code does not select a random direction for identical points.

    If F_u is the accumulated vector, the actual movement is

    \[p_u\leftarrow p_u+\frac{F_u}{s_u}\min(s_u,t_i),\qquad s_u=\max(10^{-9},\|F_u\|),\qquad t_i=0.1\left(1-\frac{\operatorname{double}(i)}{T}\right),\quad i=0,\ldots,T-1.\]

    The distance floor also applies to the movement denominator. Thus the exact rule near zero is the expression above, rather than an unrestricted normalized direction. For practical representable schedules the last temperature is approximately0.1/T; very large integers can round when converted to double. T=0 performs no division by T because there are no sweeps. No velocity, box confinement, stopping tolerance, line search or Barnes–Hut approximation is implemented.

    The historical model and direct algorithm are described in Fruchterman and Reingold, [Graph Drawing by Force-directed Placement](https://www.reingold.co/force-directed.pdf), Software—Practice and Experience21(11),1129–1164(1991), [doi:10.1002/spe.4380211102](https://doi.org/10.1002/spe.4380211102). This library's variant omits the paper's frame clamping and random coincident-point directions. Its distance floor, seeded initializer, fixed schedule and final scaling are concrete implementation choices, rather than a claim to reproduce every paper variant.

    The original seeded four-vertex path

    The original example draws0--1--2--3 with500 sweeps and seed7. The first four output lines retain the current canonical function's original coordinates. A local mt19937_64 draws two uniform variates per point in [−0.5,0.5); the seed reproduces these values within the same standard-library environment. Different C++ library implementations need not map a uniform distribution to identical coordinate bits. The figure uses undirected paths, so its links carry no arrowheads.

    -0.56251 0.82679 -0.199704 0.29353 0.199714 -0.293544 0.562501 -0.826776

    Original work: 3000 pair visits; 1500 attraction visits; 2000 moves; 8 uniform variates. Final geometry: centroid (0.000000, -0.000000); maximum centered radius 1.000000; mean edge length 0.666661.

    For n>=2 the final pass computes the double mean in vertex order, subtracts it, finds the maximum centered radius r, then divides every point by r when r>0. Consequently the displayed centroid is approximately zero and nondegenerate maximum radius approximately one. These are floating-point properties, not exact certificates. The unit-area force parameter k does not impose a square boundary on raw positions. For two vertices joined by one edge, the unregularized force equilibrium separation is k; final radius normalization instead makes their output separation two. Raw and final distances must therefore be interpreted in different units.

    Inspect one actual run, rather than rerunning prefixes

    The owned trace captures initial coordinates, every sweep's repulsion and net accumulators, positions after all moves, raw final coordinates, final coordinates and actual normalization metadata. It uses the same kernel without replay. Running an independent prefix with length t would change the cooling denominator; it would not reproduce the first t sweeps of the T-sweep run.

    A useful diagnostic integrates this implementation's regularized forces. Let U=the sum of U_r over unordered pairs plus U_a over nonloop edge records, where

    \[U_r(d)=\begin{cases}-k^2\log d,&d\ge\delta,\\ -k^2\log\delta+\frac{k^2}{2}(1-(d/\delta)^2),&d<\delta,\end{cases}\qquad U_a(d)=\begin{cases}d^3/(3k),&d\ge\delta,\\ \delta d^2/(2k)-\delta^3/(6k),&d<\delta.\end{cases}\]

    The joins agree in value and derivative at delta. Differentiation gives the regularized forces with the negative-gradient sign; zero separation has zero vector force. This is our diagnostic derivation for the library's law. Actual arithmetic is rounded, and the movement cap does not ensure that U decreases each sweep. Long-double metrics are queried separately at O(n squared+m) cost per frame; those queries are not included in the actual kernel counters. The next potential curve uses only raw states, before final normalization changes the fixed-k potential.

    Coincidence, repeated edges and small-graph semantics

    At identical coordinates Delta is zero, so the floor avoids division by zero but cannot separate points. A two-vertex coincident layout stays coincident even with an edge. Repeated and reversed edge records apply repeated attraction; they are not deduplicated. A self loop has a validated endpoint but contributes no force. The following one-sweep controls read actual accumulators, rather than inferring forces from the capped motion. Three attractive records can reverse the net direction.

    With n<2 the original API returns seeded positions immediately; a singleton is not moved to the origin and ignores even an enormous sweep request. Supplied-position variants preserve the same early return. With n>=2, zero sweeps still center and scale. Thus empty, singleton and zero-iteration cases are separate contracts. The pre-existing edge-versus-isolated-distance test is a property of its particular seeded control graph, not a universal guarantee about every adjacent pair or layout. Different seeds can produce different drawings, and the API promises neither a unique embedding nor minimum crossings, edge length, stress or potential.

    Actual work and complete trace admission

    For n>=2 and M nonloop records, T sweeps visit T*n*(n−1)/2 repulsive pairs, T*E edge records (including ignored loops), T*M attractions and T*n vertex moves. Validation and initialization add O(n+E), so total direct work is O(n+E+T*(n squared+E+n)); ordinary output and scratch use O(n) extra storage. The native complete-graph generator supplies the dense control below. Sparse attraction does not remove the all-pairs repulsion cost.     Every endpoint must lie in0..n−1, and every supplied coordinate must be finite. Full domain validation precedes quota checks or copies, including early-return cases. All actual double differences, accumulators, distances, updates and normalization must remain finite. Finite input alone does not guarantee finite intermediate arithmetic: the attraction of a very distant pair can overflow. The same extreme pair without an edge is accepted when its actual repulsion and normalization remain finite; unused attractive forces are not computed. Failures return no partial result and never mutate supplied positions or edges.

    Let S=T for n>=2 and S=0 otherwise. Complete trace admission checks

    \[C=E+3n+S(1+3n).\]

    C counts entry records, not bytes or peak RAM. It includes edges, initial/raw/final point arrays and every frame's positions/repulsion/net vectors; temporary kernel scratch is additional. The default cap is one million entries and zero disables only the optional cap; arithmetic and container capacity checks remain. Admission happens before RNG or input copying and captures every sweep without truncation. A supplied-position call starts a fresh cooling schedule, not an exact continuation of a previous schedule. Histories cost O(E+n+S*n) owned entry storage, while optional per-frame diagnostic queries add their own quadratic work.

    The library retains the original seeded path behavior and the ordinary graph-layout include. Source programs above regenerate all local figures with canonical C++ APIs. The deterministic geometric controls require no external dataset.
