    Chu–Liu/Edmonds: Contract Cycles, Recover a Rooted Directed Tree

    Abstract

    A directed network needs a cheapest set of links that lets one prescribed root reach every vertex. Choosing each vertex's cheapest incoming link can create cycles disconnected from the root. Chu–Liu/Edmonds contracts those cycles, solves the reduced problem and expands the selected links back to the original graph. We retain the original three-vertex example, follow actual nested contractions, verify a controlled cycle family, and distinguish nonexistence, work caps and numerical range failures. Canonical C++ now recovers original edge identities and records the executing kernel's phases without replay.

    The original three vertices: cheap incoming arcs form a cycle

    Root 0 has arcs 0→1 of cost 5 and 0→2 of cost 6. The two other arcs, 1→2 and 2→1, each cost 1. Independently choosing the cheapest incoming arc for vertices 1 and 2 selects both unit arcs. Their total 2 is a lower bound, but those arcs form a cycle and neither vertex is reachable from root 0.

    Contract {1,2}. Entering via 0→1 replaces the chosen incoming arc 2→1, so its reduced cost is 5−1=4. Entering via 0→2 instead costs 6−1=5. The contracted problem chooses the original arc 0→1. Expansion removes 2→1 and keeps 1→2, giving total cost 5+1=6. The table and drawing use actual phase records and the recovered original tree.

    The precise problem and its feasibility condition

    We seek a spanning directed out-arborescence rooted at r: r has no incoming selected arc, every other vertex has exactly one, and every vertex is reachable from r. Those conditions force exactly V−1 arcs and exclude directed cycles. This is a prescribed-root spanning problem, not an unconstrained minimum branching forest, where omitting positive-cost arcs could give a cheaper empty answer. It is also different from choosing an undirected MST.

    An arborescence exists exactly when every original vertex is reachable from r. Necessity is immediate. For sufficiency, a rooted search can choose each newly reached vertex's first incoming discovery arc. The algorithm need not run that search separately: a missing incoming choice, possibly after contracting a closed cycle, detects nonexistence. Checking only the initial incoming choices is insufficient.

    Why normalisation and contraction preserve the optimum

    Let b(v) be the cheapest eligible incoming cost for each non-root vertex and b(r)=0. Every feasible tree chooses one incoming arc for each non-root vertex, so subtracting b(v) from every arc entering v changes every feasible objective by the same baseline:

    \[B=\sum_{v\ne r}b(v),\qquad w(T)=B+\sum_{(u,v)\in T}\bigl(w(u,v)-b(v)\bigr).\]

    Every eligible reduced cost is nonnegative, and the chosen incoming arcs have reduced cost zero. If they are acyclic, following predecessors must end at r: every other vertex has a predecessor, while r has none. They already form an optimum arborescence with reduced cost zero.

    If they contain a zero-cost cycle C, an optimum can be chosen with just one external arc entering C. To see this, take a root-to-C path in an optimum and keep its first entry. Replace the other incoming choices in C with the zero-cost cycle arcs, deleting the cycle arc entering that first entry vertex. All of C becomes reachable along a directed path, outside reachability remains, and no reduced cost increases. Contracting C therefore preserves an optimum. Different entry arcs retain their original identities and reduced costs; parallel entries into a contracted component must remain distinct.

    The implementation contracts all disjoint selected cycles in a round. Edges that become internal remain stored as self loops but are ignored in future incoming choices. On expansion, the chosen original entering arc identifies exactly which previous incoming arc to replace. Current-component maps for original vertices support repeated expansion through nested cycles. Finite negative original weights are valid: the same normalisation applies, and a tree cannot traverse a negative cycle repeatedly.

    Nested cycles need more than one contraction

    Use arcs 0→1 of cost 5, 0→3 of cost 10, the zero-cost pair 1↔2, and arcs 2→3 and 3→1 of cost 1. Initially {1,2} is a selected cycle and vertex 3 chooses 2→3. After contraction, the component {1,2} and vertex 3 select each other. A second contraction is required before a root entry wins. The native expansion recovers 0→1, 1→2 and 2→3 with total cost 6.

    Cycle lists in the API follow predecessor links, which is the reverse of traversing their selected directed arcs. Group membership and selected edge identities specify the cycle without relying on an ambiguous drawing order. The routine now uses iterative cycle detection that follows each previously unprocessed non-root vertex once per successful round, rather than repeatedly walking a long predecessor chain.

    Checking a family with a known optimum and scan count

    The native rooted_cycle_edges(k) fixture has root 0, cycle vertices 1…k, a unit-cost directed cycle, and root-entry cost 5 to every cycle vertex. All k initial choices form one cycle. One root entry is necessary, and every other chosen arc costs at least 1, so OPT≥5+(k−1)=k+4. Keeping one root entry and deleting the cycle arc into its target attains that lower bound.

    This family takes two incoming-choice rounds and one contraction. Every round retains all 2k input arcs, including mapped self loops. Thus actual incoming scans inspect 4k arcs and reweighting inspects 2k, for a named total of 6k. These counts exclude validation, parent walks, copying, expansion and allocation; they are not elapsed time or a worst-case complexity measurement.

    For P rounds, this implementation performs O(P(V+E)) work, with P≤V because every nonfinal contraction reduces the current vertex count. The familiar O(VE) bound applies when E is at least V−1, as it must be for a feasible spanning graph; the V term still matters for sparse impossible inputs. Compact expansion maps require O(E+PV) auxiliary storage even for the legacy cost-returning call. Full tracing additionally retains arcs and partitions for O(P(V+E)) storage. The old cost-only implementation did not recover edges; this implementation's expansion history is part of its memory cost. No observational dataset is needed for these controlled graph identities.

    Nonexistence is not a partial branching

    An isolated vertex without an incoming arc fails immediately. A closed cycle unreachable from the root can give every non-root vertex an initial incoming choice, yet fails after contraction. A finite edge entering the root cannot make that cycle reachable from the root. The returned legacy failure is {total_weight=0, exists=false}; recovered parent/edge arrays are empty. The trace still retains the actual failed round and any earlier reduced baseline.

    Every endpoint and weight validates before caps or algorithmic selection, including arcs that will be ignored. NaN and infinities reject explicitly; absence is represented by omitting an arc, not by an infinite weight. Equal working costs prefer the first original input edge. Parallel input arcs remain separate throughout contraction, selection and expansion. Root self-parenting in the returned parent array is a storage convention, not a selected self loop.

    Work caps and finite-range arithmetic

    Positive BranchingOptions caps bound actual rounds and the combined incoming and reweight edge inspections across the whole call. Zero disables the respective cap. The original example needs two rounds and twelve named visits: eight for incoming choices and four for contraction. Validation is counted separately. Recovery copies and parent walks are outside the edge-visit cap; these controls are not a complete memory budget. Exhaustion throws std::length_error and exposes no partial result.

    A working reduced cost can exceed double range even when the recovered original total fits. Costs and differences therefore use checked long double, then the selected original edges are summed in original destination order and checked before conversion to the unchanged double result field. The reduced baseline total is retained separately; floating roundoff can make it differ from the sum of the recovered original edges. This is numerical optimisation, not an exact-real optimality certificate or arbitrary-precision arithmetic.

    Exact caps return cost 6. One-below phase cap rejects: true. One-below visit cap rejects: true. Ignored root-entering NaN rejects during full validation: true. Wide reduced entry / DBL_MAX = 2; recovered original cost 0. Unrepresentable final original total throws overflow_error: true. Singleton root: parents [0], cost 0.

    A root is required even for an edgeless graph; zero vertices or an out-of-range root throw std::invalid_argument. A singleton root has a valid zero-cost tree. Vertex ids stay size_t throughout, and traversal/expansion is iterative. Calls borrow input without mutation and return owned values. long double's extra range and precision are platform-dependent, and nonfinite working arithmetic still throws. No last-bit reproducibility across floating implementations is promised.

    Verification and limits

    The native tests independently enumerate one incoming choice per non-root vertex and check rooted reachability. All 2,187 three-vertex signed ternary graph/root combinations and 16,384 four-vertex presence/root combinations agree with that brute-force optimum. Another 1,000 seeded signed multigraphs check parallel identities, roots and impossible cases. Every actual phase is checked for its cheapest incoming choices, reduced costs, cycle membership, component maps, baseline and named work. The recovered original edges are verified to form a tree with the returned cost.

    Nested and simultaneous cycles, negative costs, exact and one-below caps, malformed ignored arcs, owned copies, huge size_t domains, wide intermediate costs, positive/negative final overflow and a 100,000-vertex chain are covered. All fourteen new cases pass AddressSanitizer and UBSan, alongside the existing advanced-graph regressions in the native runner. The controlled 6k plot is a check of one two-round family, not evidence that all instances require only two rounds or linear work.
