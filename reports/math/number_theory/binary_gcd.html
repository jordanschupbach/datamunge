    Binary GCD: Exact Integer Reduction with Shifts and Subtractions

    Abstract

    Given two nonnegative integers, find their greatest common divisor, for example to reduce a fraction to lowest terms. Both inputs can span the full unsigned 64-bit range, and zero needs an explicit convention. Binary GCD removes powers of two and subtracts odd operands, avoiding division. We derive the invariant, work through 54 and 24, retain the original 1071 and 462 example, and compare generated cases with an independent reference. The report uses execution states recorded by the same core loop that computes the public function's answer.

    The method

    For positive integers, common divisors satisfy three useful identities:

    \[\gcd(2a,2b)=2\gcd(a,b),\qquad \gcd(a,2b)=\gcd(a,b)\quad(a\text{ odd}),\qquad \gcd(a,b)=\gcd(a,b-a)\quad(0<a\le b).\]

    The first identity follows by dividing every shared divisor and both inputs by two. In the second identity, every common divisor is odd because a is odd, so the factor of two in b cannot matter. For subtraction, an integer divides both a and b exactly when it divides both a and b minus a.

    For nonzero inputs, save the shared power \(s=\min(v_2(a),v_2(b))\), computed as the trailing-zero count of a | b. Make a odd. Each round strips all trailing zeros from b, orders the odd operands so \(a\le b\), then sets \(b\leftarrow b-a\). The invariant is that the original GCD equals \(2^s\gcd(a,b)\). When b becomes zero the answer is \(a2^s\).

    The library returns \(\gcd(0,b)=b\), \(\gcd(a,0)=a\), and \(\gcd(0,0)=0\), without entering the loop. No trailing-zero count is used as a shift on a zero word. Ordered subtraction avoids unsigned underflow; the restored GCD fits because it cannot exceed either positive original input.

    Simple example: 54 and 24

    The common power is \(s=1\). The first operand becomes 27. Stripping the three trailing zero bits of 24 gives 3, so the first ordered odd pair is \((3,27)\). Subtract to get \((3,24)\), strip three zero bits again, and subtract the equal odd pair \((3,3)\). The terminal odd value is 3; restoring the saved factor gives 6.

    Checking the round bound

    Consider successive ordered odd pairs \((a,b)\), with \(a\le b\), before subtraction. Unless this round terminates, \(b-a\) is positive and even. Before the next subtraction it is replaced by \(c=(b-a)/2^k\) for some \(k\ge1\). Ordering does not affect the product, and

    \[ac=\frac{a(b-a)}{2^k}<\frac{ab}{2}.\]

    For w-bit positive inputs the first product is less than \(2^{2w}\), while every nonterminal odd product is at least one. There are at most \(2w\) subtraction rounds. Each round uses a fixed number of word operations, so this is \(O(w)\) word work. For multiprecision inputs, counting each arbitrary-width shift or subtraction as constant work would be wrong; no such complexity claim is made here.

    Conclusion

    The shared core loop reproduces both hand calculations, handles zero without entering the reduction loop, and agrees with the reference across generated input widths. Native tests additionally compare it with a separate modulo-based Euclidean implementation, exhaust all byte-sized operand pairs, and check 20,000 full-width random pairs and their trace invariants. No observed dataset is needed for these exact arithmetic properties.

    Avoiding division does not by itself establish a speed advantage: the machine's instruction costs, branches, compiler and input distribution matter. The unrecorded function uses constant auxiliary storage; the diagnostic trace owns one record per subtraction. This implementation is limited to unsigned 64-bit integers and does not provide a multiprecision or constant-time cryptographic API.
