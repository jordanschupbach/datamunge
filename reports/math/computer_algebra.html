    Computer algebra system

    dm::algebra::Expr builds symbolic expression trees from named variables and numeric constants. In C+, use +, -, *, / and ^, with numeric literals on either side; unary + and - work too. Write (x ^ 3) - 2 * x + 1: C+ gives ^ lower precedence than the arithmetic operators, so combined powers need parentheses. Powers associate to the left; use x ^ (y ^ z) to group a power on the right. C++ also accepts numeric arguments in named methods, such as x.power(3).

    The named methods .add(), .subtract(), .multiply(), .divide() and .power() remain available in every language. Elementary functions include .sin(), .cos(), .exp() and .log(). .differentiate("x") and .integrate("x") return new expressions, while .evaluate({"x"}, {value}) binds a variable to a number. Copies share immutable expression nodes; numeric constants use double.

    Start with \(f(x)=x^3-2x+1\). .to_tex() renders the actual expression tree as an owned dm::Tex value in C++: fractions, powers, functions and grouping come from the symbolic structure. Chain .inline_math() for table cells or .display() for a standalone equation; annotations such as .underbrace() also work. Use .to_tex(precision) to choose significant digits (seven by default). Single-letter variable names render as math symbols; longer logical names are escaped literal text. Formatting leaves the symbolic expression unchanged. Python and R return raw TeX strings from .to_tex(); the examples wrap them in math delimiters.

    Here \(F\) is one antiderivative; the general one is \(F(x)+C\). .simplify() folds constants and identities; it does not collect like terms or perform general factorization. Symbolic integration applies supported rules and throws for unsupported expressions; differentiation currently requires constant exponents in powers.

    dm::algebra::Polynomial stores coefficients in ascending degree order: {-1, 0, 1} represents \(x^2-1\). .divmod() returns a quotient and remainder, poly_gcd() returns a monic greatest common divisor, and RationalFunction cancels common polynomial factors. Their .to_tex(variable, precision) methods use conventional signs and powers; choose a formal variable such as "h" for a Taylor polynomial. Rational functions render as fractions, with a unit denominator omitted. The block composes the original fraction and its reduced form directly from these TeX values.

    The reduced rational-function object does not retain the original excluded point \(x=1\). Polynomial coefficients also use double arithmetic.

    Finally, taylor_series(f, "x", center, order) builds a polynomial in \(h=x-\mathrm{center}\). The code expands \(e^x\) about \(x=1\) through degree four and evaluates the result at value - 1, comparing it with the original expression near the expansion point.
