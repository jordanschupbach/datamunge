    The method

    One differing position contributes one unit

    Choose an alphabet and a common word length n. For two aligned words a and b,

    \[d_H(a,b)=\sum_{i=0}^{n-1}\mathbf1[a_i\ne b_i].\]

    Why this is a metric, and what the algorithm costs

    Nonnegativity, symmetry and the zero-distance condition follow coordinate by coordinate. For the triangle inequality, if \(a_i\ne c_i\), at least one of \(a_i\ne b_i\) or \(b_i\ne c_i\) must hold. Summing that indicator inequality gives \(d_H(a,c)\le d_H(a,b)+d_H(b,c)\). The metric lives on words with one fixed length; hamming_distance() throws std::invalid_argument on unequal byte lengths. Both empty words are allowed and have distance zero.

    The general string implementation compares all n bytes in one scan, using Θ(n) time and O(1) auxiliary storage. This is optimal for a full positional comparison in the worst case: a previously unread position might change the answer. Packed machine words can exploit bit operations instead. For two unsigned 64-bit words,

    \[d_{bit}(u,v)=\operatorname{popcount}(u\mathbin{\oplus}v).\]

    hamming_bit_distance() implements this fixed-64-bit operation. It is O(1) for a machine word, including its leading zero bits; processing an arbitrary packed bit array would still require work proportional to its number of machine words.

    Representation and alignment are part of the contract

    hamming_distance(std::string,std::string) treats every byte, including embedded NUL, as one symbol. It neither decodes UTF-8 nor normalizes Unicode. A printable ASCII binary string has one byte per written bit, so its byte distance agrees with the corresponding bit distance; an arbitrary packed byte is different. Text applications requiring Unicode code points or grapheme clusters must choose and implement that representation first. The byte comparison API does not silently substitute a different alphabet.

    Any substitution-only script is also a legal Levenshtein edit script, hence for equal lengths \(d_L(a,b)\le d_H(a,b)\). Insertions and deletions may allow cheaper realignment, so the inequality need not be equality. The examples keep the same byte positions when showing Hamming comparisons.

    A changed byte is not necessarily a single changed bit

    Compare one raw byte 0x00 with one raw byte 0xff. The byte distance is one; their packed-bit distance is eight. Writing those bytes as 00000000 and 11111111 changes the representation to eight ASCII positions, so that string distance is eight. The NUL is a real byte in the explicitly length-constructed string, not an empty string. For unequal lengths, the example captures the documented exception instead of padding.

    Permitting realignment changes the answer

    abcdef and bcdefa differ at all six fixed positions. Levenshtein distance is two: delete the leading a, then insert it at the end. It cannot be one, because equal-length distinct words at distance one must differ by a single substitution, and these differ at six positions. Thus the edit upper bound is strict here. Whether realignment is desirable depends on what a position represents in the application.

    Minimum code distance separates detection from correction

    A finite codebook C is a set of distinct equal-width words. Its minimum distance is the smallest separation between different valid codewords. If \(d_{min}\ge s+1\), every pattern of one through s symbol changes leaves the codebook, so a receiver checking membership detects it. Unique correction of every pattern of at most t changes requires \(d_{min}\ge2t+1\): if two codewords were both within t of a received word, the triangle inequality would put their separation at most 2t. Conversely, overlapping radius-t balls arise when that bound fails. The universal radii are therefore

    \[s_{detect}=d_{min}-1,\qquad t_{correct}=\left\lfloor\frac{d_{min}-1}{2}\right\rfloor.\]

    For the three-bit repetition code {000,111}, minimum distance three gives detection of up to two changed bits by membership checking and unique correction of one. A hard nearest codeword decoder does not automatically signal every detectable error: starting from 000, two flips can give 110, which is closer to the wrong word 111.

    The even-parity code {000,011,101,110} has minimum distance two and no guaranteed single-bit correction. The query 001 is tied at distance one from three codewords. hamming_nearest() reports every tied minimum and does not silently pick a codeword. No Hamming(7,4) encoder/decoder is needed for these finite geometric examples.

    Checking the theory

    Shell counts, error balls and uniform-word distances

    There are \(\binom nk\) ways to choose k changed positions and \((q-1)^k\) ways to replace them over an alphabet of size q. Therefore a radius-t ball around any fixed word contains

    \[N_k=\binom nk(q-1)^k,\qquad V_q(n,t)=\sum_{k=0}^tN_k.\]

    Disjoint correction balls around M codewords must fit into the q-to-the-n word space, so \(M V_q(n,t)\le q^n\), the sphere-packing bound. For the length-three repetition code, t=1 gives \(2(1+3)=8=2^3\): its two one-error balls partition the cube. The inequality is a necessary packing constraint, not a general construction of a code.

    If a uniformly random independent word is compared with a fixed word, each position differs with probability \(1-1/q\). Thus its Hamming distance is Binomial(n,1−1/q), with mean \(n(1-1/q)\) and variance \(n(1-1/q)/q\). For two independent uniform words the same law holds. This is a model for uniform independent symbols, not a claim about ordinary language, biological sequences or correlated errors.

    The next program computes shell sizes without enumerating every word. For eight bits, the shell counts are 1,8,28,56,70,56,28,8,1; a radius-two ball contains 37 words. For eight four-symbol positions, each changed position has three alternatives, shifting the distance distribution to mean six rather than four. Counts beyond 2^53 in the helper are approximate floating-point integers; it rejects word-space sizes exceeding double range. This example remains in a small exactly representable count range.

    Conclusion

    Hamming distance is a count on an explicitly chosen fixed-width representation. The same raw byte pair can differ in one byte and eight bits; realignment can reduce edit distance without changing the positional count. A code's minimum separation determines universal error guarantees, while nearest-word ties and errors outside the correction radius remain visible. Shell counting links this geometry to error balls and a binomial law under stated uniform-independence assumptions. The examples are small finite constructions, not a forced real-data application or a benchmark of every possible implementation.
