    Vector Environments: Auto-Reset, Final Observations and Worker Threads

    Abstract

    Native C++ simulations expose explicit actions, seeded state transitions and owning observations. The complete editable source protocol retains its policy comparisons and checks. There is no hidden learning loop or external simulator process.

    Follow one actual transition

    Keep the final observation when auto-resetting

    Two CartPoles with limit1 truncate after their first safe step. Each vector row returns both the old episode final observation and the new episode reset observation. These have the same width but different meanings.

    Complete source experiment

    The source seeds, episode counts, controls and checks are preserved. Every rollout and policy loop is visible here, using canonical C++ environment objects. The benchmark compares the same three workloads at four thread counts. Throughput depends on the machine and its load.

    Track auto-reset boundaries explicitly

    Four seeded CartPoles with a five-step limit expose cumulative done counts. Auto-reset observations belong to the next episode; saved final observations belong to the episode that just ended. Two worker threads execute this diagnostic.

    Interpretation

    The source checks report reproducibility and the stated control comparisons. Distinguish the displayed fixed-action diagnostics from the original policies, MDP terminality from time-limit truncation, expected reward from sampled return, and a legal game move from an arbitrary action index. All policies and episode loops remain editable here.
