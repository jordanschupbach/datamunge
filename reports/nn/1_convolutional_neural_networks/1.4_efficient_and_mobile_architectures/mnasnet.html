    MnasNet: Decoded Mobile Blocks and an Explicit A1 Fit

    Abstract

    MnasNet's released mobile architectures use varied kernels, expansions and stage repeats. We decode their tables, inspect a tensor SE bottleneck, verify five complete model budgets and explicitly optimize the full A1 classifier on a bounded CIFAR-10 subset.

    Source example: examples/cpp/source/nn/1_convolutional_neural_networks/1.4_efficient_and_mobile_architectures/mnasnet.cpp.

    The method

    MnasNet's search considers device latency. This report executes the resulting A1/B1 designs; it does not rerun architecture search or measure phone latency. Seven stage specifications encode r repeats, k square kernel, s square first stride, e expansion, i/o widths, optional SE and noskip. A1 has sixteen MBConv blocks and selective .25 input-based SE; B1 has seventeen without SE. The stem has 32 scaled channels, and the head remains 1280 at every width multiplier.

    An MBConv expands by a pointwise filter unless e=1, applies a depthwise spatial filter, optionally uses global-mean SE with max(1,floor(.25*Cin)) hidden channels and a logistic gate, then projects linearly. MnasNet uses ReLU inside blocks, with no activation after the projection. Matching stride-one widths add a raw shortcut. A1's final head uses dropout .2 during training; there is no residual drop-connect in MnasNet. Widths follow the divisor-eight ten-percent rounding rule, except multiplier one retains the exact table widths.

    The small block fixture checks expansion, gates and shortcut values. All five full models below execute actual 224-pixel forwards. A1/B1 have 3887038/4383312 learned scalars and 311579072/314415872 MACs at width one. The complete A1 backward probe at 64 pixels freezes moving updates and shifts BN betas/SE biases away from inactive gates. Some projection BN shift derivatives can vanish: a constant passing only through pointwise filtering followed by training BN cancels. Finite gradients are required; a nonzero claim for every tensor is avoided. The CIFAR A1 fit has 2618848 learned scalars and retains every one of its sixteen blocks.

    All model computation, image scaling, augmentation, losses and optimizer updates use tensors. Architecture strings, integer dimensions and plotted vectors are metadata. Convolutions use He-uniform initialization and TensorFlow SAME padding, BN epsilon 1e-3 with learned scale/shift, and a biased classifier. Training uses batch moments; inference uses saved moving moments. Dropout draws from the learned store's generator. The arithmetic log counts convolution, pooled SE and classifier products, excluding BN, pooling, activations, additions and memory traffic. One MAC is a multiply-accumulate pair, not measured latency or individual FLOPs.

    The bounded fit uses original 32×32 CIFAR-10 images, changes only the stem stride and class count, and retains every block and channel width. It shows 14 epochs, batch eight, Adam(.001), explicit kernel L2=.0001/2 and independent padded crops/flips. Fixed subsets contain 128 fit, 64 validation and 64 official-test rows. The lowest validation NLL selects paired learned/BN checkpoints before test scoring. No accuracy threshold is imposed on this small single-seed experiment; it is not the published ImageNet training schedule or a latency search.

    Conclusion

    Decoded tables expose the released architecture without hiding a search or training loop. Tensor SE/depthwise blocks, complete model counts and a visible full-A1 Adam fit connect the design to executable calculations. Small-data accuracy and MACs do not measure mobile latency.
