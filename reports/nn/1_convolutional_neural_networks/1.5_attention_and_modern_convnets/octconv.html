    Octave Convolution: Frequency Exchange, Exact Geometry and Explicit Fitting

    Abstract

    Octave layers keep some channels at half resolution and exchange information through four paths. We check those paths, quantify arithmetic and storage, fix a final-shortcut geometry bug and explicitly fit the complete compact Oct-ResNet-50 with tensor Adam.

    Source example: examples/cpp/source/nn/1_convolutional_neural_networks/1.5_attention_and_modern_convnets/octconv.cpp.

    The method

    For total C channels and low fraction alpha, low width is floor(alpha*C), high width is the remainder. The names indicate spatial resolution rather than a guarantee of strict Fourier band limitation. At stride one the four bias-free odd-kernel paths compute:

    \[Y_H=f(X_H,W_{HH})+\mathrm{up}_2(f(X_L,W_{LH})),\qquad Y_L=f(\mathrm{avgpool}_2(X_H),W_{HL})+f(X_L,W_{LL}).\]

    Missing low inputs/outputs omit their paths. Pooling is 2×2 VALID average pooling, and upsampling repeats nearest neighbours. All paths use He-uniform fan-in of the FULL input width; BN/ReLU follow independently per stream, with learned scale/shift and epsilon 1e-5. With matched integer-exact splits at stride one, path kernels partition the ordinary kernel, MAC ratio is 1−.75*alpha*(2−alpha) and feature-scalar ratio is 1−.75*alpha. Entry/exit splits and channel rounding differ. Alpha zero at STRIDE ONE equals an ordinary convolution with the same weights. At stride two the source pre-pools before filtering, so equivalence to unpooled ordinary stride-two convolution is not claimed. Native finite differences check all four kernels.

    The source's continuing-low stride-two exchange pre-pools both input streams. The HIGH-ONLY stride-two merge needs a correction: LH uses the original low stream directly, since it already matches pooled high resolution. Pooling that low stream and upsampling it again cannot align an odd 7×7 map with the final high map. The corrected path preserves the final shortcut's spatial detail, changes that source operation, and counts LH work at the true output high side instead of floor(side/2). A controlled 14/7-to-7 fixture and a real 224-pixel forward verify it. Parameter names/shapes/counts stay unchanged; nonzero-alpha budgets below include the correction.

    The complete ResNet-50 body retains stages 3/4/6/3, making all three bottleneck filters and projection shortcuts octave layers. It enters high-only after the stem, uses alpha in the first three stages, then merges the main branch in the FIRST conv1 of stage four before its spatial stride. That stage's shortcut uses the corrected direct-LH merge. Final features are high-only, followed by global mean and a biased classifier. All five full-width splits keep 25557032 learned scalars. Count forwards use 64 pixels; cfg.image_size=224 explicitly describes nominal TARGET MACs, not the actual count-forward image. Alpha .25 additionally executes at 224 pixels. Alpha-zero nominal work is 4089184256 MACs; counts exclude pooling/upsampling/BN/ReLU/addition and memory traffic, and are not latency measurements.

    The compact fit keeps all sixteen bottlenecks at quarter widths, alpha .25 and original 32×32 CIFAR images. A 3×3 stride-one stem without pooling and three remaining stage downsamplings give a 4×4×512 final map and 1484186 learned scalars. Stage stride remains in the 3×3 octave filter. The visible loop uses 128 fit/64 validation/64 official-test images, ten batch-eight epochs (160 updates, kept short for build time), Adam(.001), explicit kernel L2=.0001/2, padded crops/flips and paired parameter/moving-state checkpoints selected only by validation NLL. Every path and both stream BN leaves enter the optimizer. All numerical preprocessing, paths, losses and updates use tensors; host images below serve only as independent oracles. This bounded run does not reproduce paper benchmarks.

    Conclusion

    Two spatial resolutions reduce path arithmetic while retaining kernel capacity. Independent path checks and a corrected odd-resolution merge make their geometry explicit. Complete budgets and a visible optimizer loop connect the full compact model to data, while separating nominal arithmetic, actual forwards and bounded-data performance.
