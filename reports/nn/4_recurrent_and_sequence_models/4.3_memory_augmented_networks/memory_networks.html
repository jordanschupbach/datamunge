    Two-hop memory networks for relational questions

    Two-hop memory networks for relational questions

    Each question asks for the location of a person's item. Four shuffled facts contain the two links needed for the answer and a distractor chain. The model embeds the question, attends over facts, and adds a weighted sum of values to the query state. It repeats that operation with new embedding tables before predicting one of eight locations.

    The end-to-end variant uses the full fact for both key and value. The key-value variant uses subject and relation for addressing and the object for the retrieved value. The report fits both variants on the same disjoint question splits and checks how their attention changes when the facts are reversed.

    VariantEpochValidation NLL
    end_to_end_memory02.123690
    end_to_end_memory11.557825
    end_to_end_memory21.121142
    end_to_end_memory30.966191

    end_to_end_memory test NLL 2.137279 to 0.926727, 63/128 answers, 0/128 bridge and 65/128 answer facts.

    key_value_memory02.094157
    key_value_memory11.473537
    key_value_memory20.970708
    key_value_memory30.842299

    key_value_memory test NLL 2.115805 to 0.906303, 62/128 answers, 0/128 bridge and 64/128 answer facts.

    Both models improve held-out answer loss. The first hop never puts its largest weight on the expected bridge fact in this run, so the answer accuracy alone gives little evidence that either model follows the two facts in order.
