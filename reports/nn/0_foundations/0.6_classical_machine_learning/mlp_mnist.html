    MLP Digit Classification: Nonlinear Hidden Features

    Abstract

    Some label patterns cannot be separated by an affine readout of the original inputs. A multilayer perceptron first learns nonlinear features and then classifies them with softmax. We exhibit XOR's linear limitation, fit a small hidden-layer model and run a fixed-budget demonstration on bundled 8×8 digits. The original full MNIST workflow and its architecture remain available separately.

    The method

    A one-hidden-layer network computes h=ReLU(XW1+b1), z=hW2+b2. Backpropagation chains the softmax score p-y through W2 and the active ReLU mask. Hidden width H gives DH+H+HK+K parameters. An explicit XOR construction on x1,x2 in {0,1} is

    \[f(x)=\operatorname{ReLU}(x_1+x_2)-2\operatorname{ReLU}(x_1+x_2-1).\]

    No affine function can assign opposite signs to the two diagonal XOR pairs: adding the two positive-corner inequalities contradicts adding the negative-corner inequalities. Hidden features remove that restriction. Training is nonconvex; zero training error says nothing by itself about held-out performance. The original 784→256→128→10 network has 235146 parameters. This report's offline dataset model uses 64→32→10, explicit minibatch Adam and fixed pixel scaling by 16; it does not reproduce that MNIST training budget, split or epsilon-LRP analysis. Use just run-nn mlp_mnist with prepared MNIST files for the original complete workflow.

    Checking the theory

    The exact construction above checks representation, while fitted XOR checks optimisation on four points. They answer different questions. The digit model checks normalization of all held-out probability rows.

    A dataset example

    First dataset row of each class; labels 0..4 above 5..9.

    The built-in digits dataset has 1797 8×8 images, distinct from 28×28 MNIST. A seeded stratified four-fold partition reserves fold zero, with hidden width 32 and a fixed 80-epoch budget. Pixels divide by the known maximum 16. The visible loop runs Adam at .003 for 80 epochs, with kernel L2 coefficient .0001 and no test-driven checkpoint selection. The held-out fold is used only after fitting.

    1347 training rows; 450 held-out rows; 80 epochs; 1760 Adam updates.

    Accuracy 0.973333; NLL 0.068156; maximum mass error 0.000000119.

    Original 28×28 MNIST

    The original MNIST benchmark runs the 784→128→64→10 architecture alongside the linear baseline. It restores each model's best validation checkpoint before scoring the official test set.

    Conclusion

    The explicit construction and fitted XOR model show why nonlinear features expand the hypothesis class. The digit run evaluates one fixed architecture on a separate dataset. It does not establish an architecture ranking on the original MNIST dataset. The companion benchmark reports that evaluation.
