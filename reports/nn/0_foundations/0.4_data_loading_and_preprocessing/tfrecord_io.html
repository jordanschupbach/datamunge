    TFRecord I/O: Frames, Checksums and Feature Schemas

    Abstract

    A stream of binary training examples needs exact boundaries, corruption detection and a known feature schema. We round-trip empty and binary payloads through TFRecord compression modes, then inspect typed tf.Example features and defaults. The native codec implements these formats without a TensorFlow runtime; the examples measure storage rather than model accuracy.

    The method

    Each uncompressed TFRecord frame consists of an eight-byte little-endian length, its four-byte masked CRC-32C, the payload and its four-byte masked CRC-32C. For payload lengths L1..Ln,

    \[\mathrm{plain\ bytes}=\sum_i(L_i+16),\qquad \mathrm{mask}(c)=\mathrm{rotateRight}(c,15)+\mathtt{0xa282ead8}\pmod{2^{32}}.\]

    CRC-32C uses the Castagnoli polynomial and differs from ZIP's CRC-32. It detects accidental corruption, not deliberate tampering. GZIP or ZLIB wraps the complete framed stream; compression must be supplied explicitly. An empty payload still has a complete frame. The current reader materialises the file and records in memory rather than streaming lazily. A tf.Example maps names to byte-string, Float32 or Int64 lists. ParseSingleExample returns features in schema order, rejects present values with a wrong type/count and uses a supplied default for an absent key. Use defaults matching the declared type/count. This minimal protobuf codec skips supported unknown fields; it is not a general protobuf implementation. Work is linear in encoded size.

    Simple examples

    The payloads empty, a-NUL-b and last have lengths 0,3,4, so the plain file has 55 bytes. All three records must survive each compression mode in order.

    Conclusion

    Record boundaries, binary payloads, compression and required/defaulted features remain distinct. A checksum failure stops reading. The byte counts show that compression is a workload-dependent choice; these tiny fixtures do not establish throughput or compression ratios for real training data.
