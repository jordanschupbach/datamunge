    DDA Line Drawing: Actual Accumulators, Rational Samples and Visible Rounding Limits

    Abstract

    Rasterizing an integer-endpoint segment means choosing pixel centres near a continuous line. A major-axis sampling rule gives one position per column or row, but rounding and floating accumulation determine which minor-axis centre is selected. This report derives the digital differential analyzer (DDA), begins with a five-sample example, and retains the original fifteen- and eleven-centre rasters. Native traces expose the actual double values before rounding, while an integer rational-sample API supplies an independent mathematical comparison. Tiny accumulated errors change exact halfway choices; large coordinate origins can produce errors greater than half a pixel. We distinguish these effects from Bresenham's directed ties, measure actual additions and rounds, and check complete allocation limits and full-width endpoint arithmetic without attempting an enormous allocation.

    Five samples make the rounding rule visible

    For (0,0)→(4,2), the major extent is four and the exact increments are (1,1/2). These increments are representable in binary, so the actual accumulators agree with the exact rational samples. At x=1 and x=3, the height lies halfway between two integer rows. This API rounds halfway away from zero, selecting heights one and two. The diagram uses equal coordinate scales; filled blue centres are returned pixels, and hollow red marks are the actual pre-rounding half-height samples. Points near the line need not lie on it, correcting the original report's description of rounded samples.

    Derive the major-axis recurrence and separate its two errors

    For signed endpoint differences Δx and Δy, let N=max(Δx,Δy). If N=0, return the single coincident endpoint; dividing by N would be undefined. Otherwise the exact parameter samples are

    \[p_i=\left(x_0+\frac{i\Delta x}{N},\ y_0+\frac{i\Delta y}{N}\right), \qquad i=0,\ldots,N,\qquad h=\left(\frac{\Delta x}{N},\frac{\Delta y}{N}\right).\]

    At least one component of h is +1 or −1, so that major coordinate visits each integer between its endpoints once. Both components have magnitude at most one. The floating implementation computes each increment once, begins at the integer coordinates represented as doubles, rounds both current accumulators, and adds the two increments before each nonterminal sample. The final unused addition in the old loop is omitted without changing its returned points. These are two coordinate additions per transition and two coordinate rounds per sample, rather than one of each for the whole point.

    For exact samples, nearest-integer rounding gives coordinate error at most one half. The major coordinate has zero error, so the selected centre is within half a unit of its sampled point and hence of the segment. Consecutive exact centres are 8-connected and the major coordinate makes them distinct. For a minor increment strictly smaller than one, nearest rounding cannot cross two distinct half-integer boundaries in a single step; when its magnitude is exactly one, the integer start makes every minor sample integer. Reversing the endpoints enumerates the same rational samples in reverse, including the same signed tie choices. These are guarantees of dda_line_exact, not universal claims about a double accumulator.

    To see the distinction, write the stored increment as h+δ and let ρ_j be the real error introduced by the jth floating addition in one coordinate. Then the actual accumulator a_i obeys

    \[a_i-p_i=i\delta+\sum_{j=1}^{i}\rho_j,\qquad |\operatorname{round}(a_i)-p_i| \le\frac12+|a_i-p_i|.\]

    The first identity follows by expanding the recurrence and cancelling the exact additions; the inequality is the triangle inequality. Even very small drift can cross a halfway threshold. Its magnitude also depends on coordinate scale because the spacing of representable doubles grows with that scale. The trace retains actual pre-rounding x and y, exact-rational nearest centres, and approximate error diagnostics. Diagnostics subtract an integer quotient part first and then the signed fractional remainder, avoiding cancellation against a large rounded ideal coordinate. They are ordinary double approximations, not certified error intervals. No accumulator is repaired, clamped or replaced by its reference, and the final minor endpoint is not forced into the ordinary result.

    Observe a missed tie, a reversal difference and coordinate-scale drift

    For (0,0)→(12,1), the exact midpoint height is 1/2. Repeated additions of 1/12 put the current double slightly below that value, so rounding returns row zero, while exact signed halfway rounding returns row one. Both centres are half a unit from that exact midpoint, so this example shows a tie-rule mismatch rather than a strict geometric-error violation.

    The segment (0,0)→(10,7) exposes direction dependence of accumulation: the forward and reverse additions approach the same rational height 7/2 from different floating sides. The exact-sample API remains reversal symmetric. Its tie policy differs from the existing Bresenham implementation: for the reverse segment (2,1)→(0,0), exact signed rounding keeps (1,1), while Bresenham's directed tie chooses (1,0). Negative halves round away from zero, so integer translations across zero can also change exact tie selections. None of these policies is claimed to be universally interchangeable.

    Finally, translate the minor coordinate of a 10,000-step height-one line close to INT_MAX. Increment quantization during addition now produces a visible count of reference differences and a maximum coordinate error strictly greater than half a pixel. The trace computes this diagnostic against rational pieces; it does not obtain it by subtracting two almost equal large ideal-coordinate doubles.     Exact rational selection without a wider-than-64-bit core product

    For one coordinate, write Δ=s d with d≥0 and s∈{−1,+1}. At sample i, divide the unsigned product d i by N into quotient q and remainder r:

    \[d i=qN+r,\quad 0\le r<N,\qquad p_i=(x_0+s q)+s\frac rN.\]

    The integer part stays within endpoint bounds. If 2r<N, keep it; if 2r>N, move one unit in direction s. If 2r=N, move only when that direction points away from zero at the integer part. This last condition rounds the whole signed coordinate, rather than incorrectly rounding the unsigned offset and then translating it. For all 32-bit int endpoints, d and i are at most 2^32−1, so their product fits uint64; the doubled remainder also fits. The production quantizer needs no signed overflowing product, floating selection or nonstandard integer type. A separate test oracle uses a signed 128-bit weighted-endpoint numerator, supplying a different arithmetic route.

    Count actual work and reject whole oversized outputs

    For N nonterminal transitions, this implementation performs 2N coordinate additions and 2(N+1) rounds, returning N+1 centres. Total counted coordinate operations are 4N+2. The trace's rational comparisons, diagnostics, vector allocation and copies are additional work. The ordinary API omits trace and reference calculations. Both output size and running time are O(N+1); only the recurrence's auxiliary state is O(1), so the old report's constant-space claim does not describe the returned vector. Coincidence still costs one point and two rounds, with no additions.

    dda_line_trace and dda_line_exact default to a complete one-million-point cap; a positive cap is inclusive and checked before allocation, while zero disables that optional cap. Container capacity checks remain. The legacy four-argument dda_line has no optional cap. Every coordinate difference is widened before subtraction, and sample/count loops cannot overflow an int. An ordinary rounded accumulator outside int now raises overflow_error before conversion; it is neither silently wrapped nor clipped. A successful call returns its complete sequence, and errors return no partial raster. The random-access exact sample API lets us inspect enormous spans without walking or allocating them. No external dataset is appropriate for these geometric and arithmetic controls.

    Verification and limits

    Nine new native tests pass AddressSanitizer and UndefinedBehaviorSanitizer. All 14,641 endpoint quadruples in the signed grid −5…5 compare exact rasters with the independent signed-128-bit weighted-endpoint oracle, and verify actual accumulator replay, diagnostics, work, endpoint inclusion, exact reversal and 8-connectivity. One thousand seeded short lines at varied coordinate origins check additional octants and drift. Another 25,000 full- range endpoint/index samples and 2,500 extreme-grid/index combinations check random access without allocating huge rasters. Tests retain both original rasters, signed global ties, the measured halfway and reversal counterexamples, the translated half-pixel violation, coincidence at int extremes, ownership, complete caps and invalid indices. A five-million-step control near INT_MAX confirms that actual accumulated overshoot raises overflow_error before an out-of-range conversion; its exact endpoint sample remains valid. Both directions of the twelve-step example miss its tie in the same direction, while the ten-step height-seven example exposes the traversal difference.

    The native tests support the implementation; the derivation explains the mathematical rational rule. The accumulated API deliberately preserves its original floating recurrence, including visible drift and tie differences. The exact comparison API supplies a separate precise sampling contract. Neither implements clipping, antialiasing, supercover rasterization or a GPU rasterization specification. No timing experiment here establishes that floating DDA is slower than integer Bresenham on a particular machine; the report compares arithmetic, rounding contracts and measured counts instead.
