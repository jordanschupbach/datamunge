    Constrained Optimization: Feasibility Is Only Half the Check

    Abstract

    A constrained optimizer must reduce an objective while respecting equalities or inequalities, and a feasible point need not be an optimum. We derive exact primal and dual controls for two Euclidean projection problems, then test the library's augmented-Lagrangian, projection-like SQP and feasibility-backtracked log-barrier implementations. Separate feasibility, stationarity and complementarity diagnostics expose both useful progress and the limits of their native stopping rules.

    The method

    For equalities c(x)=0 and inequalities h(x)<=0, the Lagrangian is L=f+lambda transpose c+nu transpose h. At a regular local solution its gradient vanishes, c=0, h<=0, nu>=0, and nu_j*h_j=0. These necessary KKT conditions become sufficient for the convex quadratic/affine examples below. A raw objective gradient usually does not vanish at a constrained optimum.

    \[\nabla f+J_c^T\lambda+J_h^T\nu=0,\quad c=0,\quad h\le0,\quad \nu\ge0,\quad \nu_jh_j=0.\]

    The native AugmentedLagrangian uses L_rho=f+lambda transpose c+rho*norm(c)^2/2. It takes a fixed inner budget of gradient steps, capping each displacement norm at one, then updates lambda <- lambda+rho*c. It doubles rho unless equality feasibility alone meets tolerance. It does not check the final Lagrangian gradient. Inner work needs an objective gradient and constraint Jacobian each step; constraint dimension and parameter dimension govern dense multiplication cost.

    The concept diagram below is drawn by dm::graphics::Diagram. Its editable C++ source is the complete block below; regeneration uses the same datamunge toolchain as the numerical examples. Exports consume the saved local SVG.

    SQP here is a restricted projection-like routine, rather than a general quadratic programming subproblem solver. It first takes x <- x-eta*grad(f), then corrects each equality row sequentially by -J_k*c_k/(norm(J_k)^2+regularization). Its early-stop condition tests norm(c) and the constant absolute step_size against tolerance, not the actual displacement or Lagrangian gradient. For ordinary positive step sizes it therefore normally consumes its iteration budget.

    InteriorPoint uses c<0 and the log barrier phi_mu=f-mu*sum(log(-c)). It computes grad(phi_mu)=grad(f)-mu*sum(J_k/c_k), backtracking only until a candidate is strictly feasible. It does not require barrier-objective decrease, solve a Newton system, perform a phase-I feasibility search or test KKT stationarity. After every fixed inner budget it multiplies mu by barrier_decay. Driving mu toward zero can make the gradient problem stiff and exhaust floating-point feasible steps.

    Small worked example

    Project a target onto one line

    Minimise .5*norm(x-(2,0)) squared subject to x0+x1=one. Stationarity gives x-target+lambda*(1,1)=0; summing and imposing the equality gives lambda=.5. Thus x-star=(1.5,-.5), f-star=.25. This is the perpendicular projection: a radius sqrt(.5) objective circle is tangent to the feasible line at the solution. One SQP step with eta=.5 from the origin goes to (1,0), already feasible but still short of the tangent optimum. The native diagnostics use the exact multiplier and report distance, equality residual and stationarity separately.

    Checking the implementations

    Inner work controls augmented-Lagrangian stationarity

    All runs start at the feasible but suboptimal point (1,0). With zero inner steps, the outer feasibility test accepts it unchanged at f=.5: its exact KKT residual shows the missing tangential improvement. Then compare one, twenty and two hundred inner steps, with at most twenty outer stages and step_size=.01. More inner work can improve a particular solve, but geometric penalty growth and fixed rates do not supply a general monotonic accuracy or cost guarantee. Curves sample requested gradient points after the run; they are not the augmented objective. Their zero reference is the unconstrained lower bound, so infeasible losses below .25 are not mistaken for improvements over the feasible optimum.

    The routine named SQP uses linearised row corrections

    From the origin, compare the default regularization 1e-6 and a smaller 1e-12, using eta one or .5. With eta one the objective step lands on the target each time and the row correction nearly projects it onto the line. Nonzero denominator regularization leaves a small equality error. Repeating that same construction does not make it a full SQP QP solve. The returned raw gradient norm remains near sqrt(.5) at the correct constrained optimum; the Lagrangian residual is the relevant stationarity check. Callback counts show that these runs consume their 200-step budgets rather than satisfying the routine's constant-step early-stop clause.

    A barrier path with an exact solution, and a default run that fails late

    Minimise .5*norm(x-(-1,2)) squared subject to x>0. The constrained solution is (0,2), f.5, with multipliers (1,0) under c=-x. For a fixed positive barrier weight, each coordinate satisfies x-target-mu/x=0. The positive root is

    \[x_j(\mu)=\frac{t_j+\sqrt{t_j^2+4\mu}}2,\quad \nu_j(\mu)=\mu/x_j(\mu),\quad x_j(\mu)\nu_j(\mu)=\mu.\]

    Run each of mu=1, .1 and .01 separately for 5000 inner steps at .005, then compare with the stable native root formula. The path tends toward the active boundary as mu decreases. This is a controlled fixed-barrier experiment, distinct from the native default schedule. The latter starts strictly feasible at (.5,.5), makes substantial progress, then throws when it cannot find a representable feasible step as the barrier shrinks. Its partial final point and error text are retained; a failure does not mean that every preceding step was useless.

    Conclusions and references

    The equality projection supplies exact primal and dual controls. It exposes a feasibility-only stopping counterexample and clarifies the projection-like routine named SQP. The orthant problem supplies a complete barrier path and complementarity control while preserving a late default-schedule failure. These generated problems need no external dataset: their known answers make stronger implementation checks than an unverified application optimum. General nonlinear constraints require regularity, appropriate scaling and fuller stationarity safeguards than these small native routines expose.

    • J. Nocedal and S. J. Wright (2006), [Numerical Optimization, second edition](https://doi.org/10.1007/978-0-387-40065-5), chapters on optimality conditions, penalties, SQP and interior-point methods. The routines above implement the restricted variants explicitly described here.

    Reading the numerical evidence

    trace_optimize calls the configured native optimizer through its stated abstract interface. It records callback requests without inserting fitting evaluations. Value calls can be rejected trials; gradient calls can be look-ahead points. optimization_comparison explicitly re-evaluates selected points afterwards on these pure objectives. Those diagnostic calls are excluded from fitting counts. Callback indices are neither accepted iterations nor wall time. The plotted gap uses the declared reference (minimum or stated lower bound) and a display floor of 1e-14; that floor does not modify any optimizer update. Returned coordinates, checked objective and appropriate stationarity/feasibility checks carry more information than a return from a finite iteration budget. Native APIs do not expose a uniform stop-status flag. The recorder retains exceptions and rejects nonfinite requested values/gradients; this makes failures visible rather than letting an instrumented run continue on NaN.
