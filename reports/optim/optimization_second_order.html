    Second-Order Optimization: Newton and a Cauchy-Point Variant

    Abstract

    A gradient identifies local slope, while a Hessian also describes how that slope changes. Newton's method uses this curvature to solve a local quadratic model, but a full step can be unsafe away from a well-conditioned minimum. We check an exact quadratic solve, compare the library's Cauchy-point trust-region variant and L-BFGS on Rosenbrock, and retain singular-start failures and conditioning sensitivity with independent final-gradient checks.

    The method

    Expand f(x+s) approximately as f+g transpose s+.5*s transpose H*s. Stationarity of that local model gives H*s=-g. With an SPD constant Hessian, the undamped Newton step reaches the quadratic minimizer in one update. This implementation instead solves (H+damping*I)*delta=g by partial-pivot elimination and subtracts delta. Its fixed damping is not an adaptive trust-region mechanism, and there is no line search to reject an increasing objective.

    \[s_N=-H^{-1}g,\qquad s_\delta=-(H+\delta I)^{-1}g,\qquad e_{\mathrm{next}}=\delta(H+\delta I)^{-1}e \quad\text{for an SPD quadratic}.\]

    The last identity proves the damping bias of a single step, with contraction at most delta/(lambda_min(H)+delta) for nonnegative delta. It requires positive curvature; shifting an indefinite or singular Hessian by a tiny fixed amount does not supply a general descent or stability guarantee. Dense factorisation costs O(p cubed) and stores O(p squared), beyond obtaining the exact Hessian.

    The concept diagram below is drawn by dm::graphics::Diagram. Its editable C++ source is the complete block below; regeneration uses the same datamunge toolchain as the numerical examples. Exports consume the saved local SVG.

    TrustRegionNewton here uses only a Cauchy point. Set s=-alpha*g, where alpha=min(g transpose g/(g transpose H*g),radius/norm(g)) for positive ray curvature; otherwise use the radius boundary. A strict objective decrease is accepted and doubles the radius, up to its maximum; failure halves it. There is no predicted versus actual model-reduction ratio, dogleg step or full trust-region solve. It stops on gradient norm, tiny radius or budget. Hessian use costs O(p squared) per step, but the direction remains parallel to the gradient.

    Small worked example

    A quadratic distinguishes the directions in one step

    For f=x0 squared+4*x1 squared at (1,1), g=(2,8) and H=diag(2,8). Undamped Newton gives (0,0). With radius one, the Cauchy ray uses alpha=1/sqrt(68), since this is smaller than the free ray minimizer 68/520. Its next point is (1-2/sqrt(68),1-8/sqrt(68)), with positive residual loss. The contour and actual native results make the difference visible without claiming a universal ranking.

    Checking changing curvature

    Rosenbrock with the same declared starting point

    Rosenbrock has gradient (2*(x0-1)-400*x0*(x1-x0 squared),200*(x1-x0 squared)) and Hessian with entries H00=2-400*x1+1200*x0 squared, H01=H10=-400*x0, H11=200. Its zero global minimum is (1,1), but the Hessian can be indefinite elsewhere. Run Newton (default damping 1e-10, 100-step budget), the Cauchy variant (200), and L-BFGS (500) from (-1.2,1). Their derivative-request traces are post-run loss checks; Newton can increase the objective because it has no acceptance safeguard, while the Cauchy variant's strict-decrease rule can still make slow valley progress. Budgets, Hessian costs and line-search calls differ, so callback counts are not a throughput measure.

    A singular start separates an exception from a safe step

    At (0,.005), Rosenbrock's Hessian is diag(0,200) and its gradient is (-2,1). With damping zero, the native pivot threshold rejects a singular solve. With default damping 1e-10, the first x0 displacement is about two times ten to the ten: a numerically nonzero pivot permits an enormous step. It need not be a useful regularisation. Compare six-step runs with small/default and .1 damping against a six-step radius-one Cauchy run. The singular exception is printed separately; the finite-budget paths and final checks retain any poor Newton result rather than calling a non-throwing run successful.

    Conclusions and references

    The quadratic calculation proves the undamped one-step property and quantifies fixed-damping error. Rosenbrock and the singular control show why it does not imply a globally safe full Newton step. The routine named TrustRegionNewton uses a Cauchy ray with objective-only radius decisions, so full trust-region model-ratio claims would describe a different implementation. Final loss, gradients, failures and callback types remain separate evidence.

    • J. Nocedal and S. J. Wright (2006), [Numerical Optimization](https://doi.org/10.1007/978-0-387-40065-5), Newton, quasi-Newton and trust-region models. The restricted Cauchy acceptance rule is specified above.

    Reading the numerical evidence

    trace_optimize calls the configured native optimizer through its stated abstract interface. It records callback requests without inserting fitting evaluations. Value calls can be rejected trials; gradient calls can be look-ahead points. optimization_comparison explicitly re-evaluates selected points afterwards on these pure objectives. Those diagnostic calls are excluded from fitting counts. Callback indices are neither accepted iterations nor wall time. The plotted gap uses the declared reference (minimum or stated lower bound) and a display floor of 1e-14; that floor does not modify any optimizer update. Returned coordinates, checked objective and appropriate stationarity/feasibility checks carry more information than a return from a finite iteration budget. Native APIs do not expose a uniform stop-status flag. The recorder retains exceptions and rejects nonfinite requested values/gradients; this makes failures visible rather than letting an instrumented run continue on NaN.
