    Look-Ahead, Coordinate Steps and Nonlinear Conjugate Gradient

    Abstract

    A smooth objective may be easy along one coordinate system and difficult along another. Momentum, coordinate updates and conjugate directions exploit different structure. We inspect exact early steps before comparing Nesterov look-ahead, cyclic coordinate descent, randomized blocks and nonlinear Polak–Ribiere-plus CG on diagonal, rotated, coupled and Rosenbrock objectives. Callback counts and final gradient norms qualify every finite-budget comparison.

    The method

    Classical momentum evaluates the gradient at x. This Nesterov implementation instead uses a look-ahead point x+mu*v, then v_next=mu*v-eta*gradient(x+mu*v) and x_next=x+v_next. A gradient-request curve can therefore show points that are not returned iterates. With fixed eta/mu this is not every acceleration schedule for strongly convex problems, and no universal rate is inferred from these runs.

    CoordinateDescent visits each coordinate in order, requests a full gradient, and backtracks a partial-gradient step until Armijo decrease holds. It does *not* solve the coordinate's exact one-dimensional minimisation problem. An exhausted search restores that coordinate. A full gradient at epoch end supplies its stop test. RandomizedBlockCoordinateDescent reshuffles all coordinates once per epoch, partitions them into blocks and performs simultaneous block steps; it samples permutations, rather than independent coordinate indices with replacement.

    The concept diagram below is drawn by dm::graphics::Diagram. Its editable C++ source is the complete block below; regeneration uses the same datamunge toolchain as the numerical examples. Exports consume the saved local SVG.

    For nonlinear conjugate gradient, start d_0=-g_0 and use the implemented PR-plus coefficient, with negative values clipped and a descent fallback/restart:

    \[\beta_t=\max\!\left(0,\frac{g_t^T(g_t-g_{t-1})}{g_{t-1}^Tg_{t-1}}\right), \qquad d_t=-g_t+\beta_t d_{t-1}.\]

    Armijo backtracking chooses a decreasing step. This is nonlinear CG, not linear CG with exact line minimisation: it does not guarantee a p-step solution to a p-dimensional quadratic. All four methods use O(p) direction/state storage beyond the objective. Cyclic and block epochs can request several full gradients and multiple trial values; equal epoch budgets are not equal work or elapsed time.

    Small worked examples

    Look-ahead points and inexact coordinate minimisation

    Take f=x0 squared+5*x1 squared, starting at (1,2). With eta=.05 and mu=.9, Nesterov's first displacement is (-.1,-1), giving (.9,1). Its next gradient is requested at (.81,.1), not at (.9,1), and the second returned point is (.729,.05). The native trace prints both kinds of request.

    Cyclic coordinate descent starts trial rates at one and halves them. It reaches x0=zero using a .5 step, but accepts x1=-.5 at rate .125, rather than solving that coordinate exactly at rate .1. The one-epoch result has loss 1.25. For CG, the exact first line-minimising rate would be 404/4008, whereas the Armijo grid accepts .125. The two-step result is checked numerically rather than assuming finite-dimensional exact termination.

    Rotate a stiff bowl, then couple five coordinates

    The first test rotates eigenvalues (2,200) through pi/4 without changing their condition number. Axes no longer align with independent directions. The second uses five diagonal curvatures (2,4,8,16,32) plus 30 times the all-ones rank-one matrix, with a known centre. Coupling makes partial updates interact even without an explicit rotation. Nesterov uses eta=.005 here; the other declared controls remain the same. No external dataset is needed: the known minimizers and analytic curvature let the experiment isolate geometry. Different dimensions and callback mixes prevent a universal wall-time conclusion from these traces.

    Conclusions and references

    The small examples distinguish look-ahead evaluation, partial-gradient line searches and exact coordinate/line minimisation. The quadratic controls isolate geometry, while Rosenbrock adds changing curvature. Callback accounting and actual final gradients qualify every result; nonlinear CG is not given the finite-step guarantee of ideal linear CG, and shuffled blocks are not independent coordinate draws.

    • J. Nocedal and S. J. Wright (2006), [Numerical Optimization](https://doi.org/10.1007/978-0-387-40065-5), nonlinear CG, line searches and coordinate geometry.
    • S. J. Wright (2015), [Coordinate Descent Algorithms](https://doi.org/10.1007/s10107-015-0892-3).

    Reading the numerical evidence

    trace_optimize calls the configured native optimizer through its stated abstract interface. It records callback requests without inserting fitting evaluations. Value calls can be rejected trials; gradient calls can be look-ahead points. optimization_comparison explicitly re-evaluates selected points afterwards on these pure objectives. Those diagnostic calls are excluded from fitting counts. Callback indices are neither accepted iterations nor wall time. The plotted gap uses the declared reference (minimum or stated lower bound) and a display floor of 1e-14; that floor does not modify any optimizer update. Returned coordinates, checked objective and appropriate stationarity/feasibility checks carry more information than a return from a finite iteration budget. Native APIs do not expose a uniform stop-status flag. The recorder retains exceptions and rejects nonfinite requested values/gradients; this makes failures visible rather than letting an instrumented run continue on NaN.
