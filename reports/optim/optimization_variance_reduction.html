    Stochastic Gradients: Make the Estimator Match the Loss

    Abstract

    A dataset loss is a sum of observation losses, but sampling one observation usually estimates the gradient of their mean. Mixing those conventions changes the update. We derive the estimators implemented by SGD, SVRG and SAGA, check a two-row problem exactly, and compare their callback costs on generated regression and Iris. The examples include the corrected mean-snapshot scaling in SVRG and report finite-budget error rather than treating every normal return as convergence.

    The problem

    A full gradient visits every row. With n observations and p coefficients, a dense least-squares gradient costs O(n*p), whereas one row gradient costs O(p). Cheap updates introduce sampling noise: even at the best fit, an individual row can still have a nonzero residual. Variance reduction uses previously computed information to cancel that noise near a solution.

    The method

    Our fixture exposes the sum \(f(w)=\sum_i\ell_i(w)\), with \(\ell_i(w)=\tfrac12(a_i^\top w-y_i)^2\) and \(g_i(w)=a_i(a_i^\top w-y_i)\). The three native solvers update at the mean loss scale \(F=f/n\). Their returned objective is still f. A learning rate for sum-gradient descent would be n times smaller for the same displacement. Replicating rows changes the full-sum value but leaves its unpenalised minimizer and the mean gradient unchanged.

    SGD averages the gradients in each mini-batch and optionally reshuffles every row once per epoch. It is sampling without replacement within an epoch, so its conditional estimator is not the independent uniform draw assumed in the simplest SGD proof. Here SVRG and SAGA sample a uniform row with replacement.

    For SVRG, freeze a snapshot \(s\) for an epoch and compute \(G=\nabla f(s)/n\):

    \[v_i(w,s)=g_i(w)-g_i(s)+G,\qquad \mathbb E_i[v_i(w,s)]=\nabla F(w),\qquad w^+=w-\eta v_i(w,s).\]

    The division by n is essential. Earlier native code added the full sum gradient without dividing; that mixes scales and is biased away from the snapshot. This conversion corrects that implementation. The estimator is deterministic when w=s, but can fluctuate inside the epoch. This implementation retains the last inner iterate as its next snapshot, not a randomly selected inner iterate.

    The concept diagram below is drawn by dm::graphics::Diagram. Its editable C++ source is the complete block below; regeneration uses the same datamunge toolchain as the numerical examples. Exports consume the saved local SVG.

    SAGA stores one gradient t_i for every row and their mean tbar. Its direction is g_i(w)-t_i+tbar; afterwards it replaces t_i by g_i(w) and updates tbar. Native storage is O(n*p), compared with O(p) for SGD and SVRG, excluding the dataset. The optional trace adds O(number of callbacks*p) storage for all three. The native SAGA implementation here is smooth and has no composite proximal step.

    SGD and SVRG stop on an absolute full-sum loss change at an epoch boundary. SAGA also tests the last sampled estimator norm there. A small change or one small estimator need not imply a small full gradient, especially with noisy, constant-rate SGD. All stop tests should be read with the final diagnostic.

    Small worked example

    Take \(a=(1,2)\), \(y=(1,3)\) and one coefficient \(w\). Then \(g_0=w-1\), \(g_1=4w-6\), \(\nabla F(w)=2.5w-3.5\), the optimum is \(w=1.4\) and \(f=0.1\). At snapshot zero and current w=one, the two corrected SVRG directions are -2.5 and .5. Their mean -one agrees with gradient(F)(one). Omitting the normalisation produces mean -4.5 instead. At the snapshot both directions are -3.5. With eta=.1 the first step is therefore .35 regardless of the row; the second is .665 if row zero is selected and .56 if row one is selected.     Predict Petal.Length from Sepal.Length, Sepal.Width and Petal.Width, including an intercept, on the 150 Iris flowers. Measurements stay in centimetres without standardisation. The Species summary describes these observations; Species is not a predictor. This is training-loss minimisation, not a claim about held-out predictive accuracy.

    References and scope

    The snapshot estimator follows Johnson and Zhang (2013), [Accelerating Stochastic Gradient Descent using Predictive Variance Reduction](https://proceedings.neurips.cc/paper/2013/hash/ac1dd209cbcc5e5d1c6e28598e8cbbe8-Abstract.html). The gradient table follows Defazio, Bach and Lacoste-Julien (2014), [SAGA: A Fast Incremental Gradient Method With Support for Non-Strongly Convex Composite Objectives](https://arxiv.org/abs/1407.0202). The native smooth, fixed-rate variants and their actual stop tests are described above; published convergence results require their own assumptions and parameter choices. The exact controls isolate estimator scaling; Iris adds nonzero residuals, unequal curvature and meaningful coefficient units.

    Reading the numerical evidence

    trace_optimize calls the configured native optimizer through its stated abstract interface. It records callback requests without inserting fitting evaluations. Value calls can be rejected trials; gradient calls can be look-ahead points. optimization_comparison explicitly re-evaluates selected points afterwards on these pure objectives. Those diagnostic calls are excluded from fitting counts. Callback indices are neither accepted iterations nor wall time. The plotted gap uses the declared reference (minimum or stated lower bound) and a display floor of 1e-14; that floor does not modify any optimizer update. Returned coordinates, checked objective and appropriate stationarity/feasibility checks carry more information than a return from a finite iteration budget. Native APIs do not expose a uniform stop-status flag. The recorder retains exceptions and rejects nonfinite requested values/gradients; this makes failures visible rather than letting an instrumented run continue on NaN.
