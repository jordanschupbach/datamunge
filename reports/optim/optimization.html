    Optimization: Choose the Information Before the Algorithm

    Abstract

    Minimising a scalar is a common interface, but the information supplied to a solver determines what its updates and diagnostics mean. We derive first-order, momentum and limited-memory steps, check a scalar example, and compare native solvers on known bowls, Rosenbrock, Iris least squares and bounded Rastrigin. The report introduces the shared API without presenting unequal callback budgets or finite stochastic runs as a universal method ranking.

    The problem

    We seek a coefficient vector \(x\) that makes \(f(x)\) small. A differentiable objective can supply an exact gradient; a sum of row losses can supply cheap component gradients; a black-box objective may supply only values. Bounds restrict the feasible set and alter the relevant optimum. An objective value alone cannot show stationarity, feasibility, uniqueness or global optimality.

    The method

    For smooth unconstrained \(f\), gradient descent uses \(x_{t+1}=x_t-\eta g_t\). With the native momentum option it instead stores v_next=momentum*v+eta*g and subtracts v_next. This is a velocity evaluated at x, rather than the look-ahead gradient used by the separate Nesterov solver. Every optimize call resets its velocity. For a scalar quadratic \(f(x)=\tfrac12 hx^2\), zero momentum gives

    \[x_t=(1-\eta h)^t x_0,\qquad f(x_t)=\tfrac12 h(1-\eta h)^{2t}x_0^2.\]

    Convergence requires 0<eta*h<two. Small eta is slow, and the boundary eta*h=two flips the sign with unchanged loss. Native gradient descent tests the gradient it just used or absolute loss change, so it can return at that boundary with a large gradient. Normal return must therefore be followed by a diagnostic suited to the problem.

    The concept diagram below is drawn by dm::graphics::Diagram. Its editable C++ source is the complete block below; regeneration uses the same datamunge toolchain as the numerical examples. Exports consume the saved local SVG.

    Adam stores exponential first/second moments with bias correction, then divides its first moment by sqrt(corrected second moment)+epsilon. In this API it uses the full supplied gradient; it does not select stochastic rows automatically. L-BFGS approximates inverse curvature using recent displacement/gradient pairs, with O(history_size*p) storage and a weak-Wolfe line search. Positive-curvature pairs are retained; a failed finite search can use a previous Armijo step or return without a new step. It is a local method, not a global optimizer.

    A full dense gradient costs O(n*p) for least squares. Mean mini-batch SGD costs O(batch_size*p) per update but can retain row noise. Value-only population methods spend many function evaluations exploring a box. Callback counts expose these requests, not their wall-clock cost. The linked focused reports derive [adaptive memories](optimization_adaptive_gradient.mepml), [coordinate and conjugate-gradient steps](optimization_coordinate_cg.mepml), [curvature methods](optimization_second_order.mepml), [constraints](optimization_constrained.mepml), [proximal maps](optimization_proximal.mepml), [residual least squares](optimization_nonlinear_least_squares.mepml), [derivative-free search](optimization_derivative_free.mepml) and [variance reduction](optimization_variance_reduction.mepml).

    Iris: connect sampled updates to an algebraic solution

    Predict Petal.Length from Sepal.Length, Sepal.Width and Petal.Width, with an intercept and all 150 observed flowers. The numeric Formula design uses raw centimetres. The direct linear-model fit solves the same unpenalised least-squares problem, providing the full-sum minimum RSS/2. SGD averages batch gradients, while f remains the sum of .5*residual squared. Use rates .001 and .01, batch size ten, 500 epochs, seed 42, shuffling enabled and tolerance zero. The loss is a training numerical control; the table of Species composition is context, and no held-out predictive performance is inferred.

    Ordinary least squares has nonzero residuals here, so constant-rate sampling can keep fluctuating near the solution.     Values only: explore a bounded multimodal function

    For Rastrigin in two dimensions, f=20+x squared+y squared-10*cos(2*pi*x) -10*cos(2*pi*y), the minimum is exactly zero at the origin. Local basins make it a useful counterweight to the previous convex bowl. PSO moves a particle swarm using personal and global best positions. Differential evolution mutates population differences and retains improvements. The real-valued genetic algorithm selects parents, crosses coordinates and adds Gaussian mutations. All three native routines clamp coordinates to the supplied box and return the best visited point. Their stagnation stops can end a run before its budget.

    Use box [-5.12,5.12] squared, start (3,3), seed 42 and population forty. PSO uses global attraction and its default constant inertia; DE uses rand1 mutation and binomial crossover and default mutation/crossover; GA uses its default tournament selection, blend crossover, Gaussian mutation and elitism. Each allows 500 iterations or generations with tolerance 1e-12. Simulated annealing uses 30000 Gaussian proposals, initial temperature ten, cooling .9995 and sigma .3 with the same seed/start; its native API has no box. It is therefore shown separately. Curves are labelled best visited, including accepted and rejected proposals; they do not represent accepted-state paths. One seed cannot estimate success probability, and neither an apparent plateau nor normal return proves global optimality. Inspect the complete table, including any local-basin results.

    References and interpretation

    Gradient, momentum, line searches and limited-memory curvature are treated in Nocedal and Wright (2006), [Numerical Optimization](https://doi.org/10.1007/978-0-387-40065-5). Adam follows Kingma and Ba (2015), [Adam: A Method for Stochastic Optimization](https://arxiv.org/abs/1412.6980), using the full gradient supplied here. The focused reports give the original sources and exact native variants for the other families. Known optima, direct least squares and appropriate stationarity checks make these experiments reviewable. Choosing a method still depends on available derivatives, dimensionality, noise, bounds, conditioning and evaluation cost; this set of declared runs does not establish a general ranking.

    Reading the numerical evidence

    trace_optimize calls the configured native optimizer through its stated abstract interface. It records callback requests without inserting fitting evaluations. Value calls can be rejected trials; gradient calls can be look-ahead points. optimization_comparison explicitly re-evaluates selected points afterwards on these pure objectives. Those diagnostic calls are excluded from fitting counts. Callback indices are neither accepted iterations nor wall time. The plotted gap uses the declared reference (minimum or stated lower bound) and a display floor of 1e-14; that floor does not modify any optimizer update. Returned coordinates, checked objective and appropriate stationarity/feasibility checks carry more information than a return from a finite iteration budget. Native APIs do not expose a uniform stop-status flag. The recorder retains exceptions and rejects nonfinite requested values/gradients; this makes failures visible rather than letting an instrumented run continue on NaN.
