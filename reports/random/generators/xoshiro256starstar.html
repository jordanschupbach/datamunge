    xoshiro256**: Scrambling a Linear State and Separating Simulation Streams

    Abstract

    xoshiro256** combines a four-word linear state transition with a nonlinear output permutation. We derive the transition's inverse, explain why the star-star scrambler preserves a uniform word, and distinguish those facts from the published maximal-period result. Jump polynomials provide widely separated deterministic stream starting points. A seven-test battery is examined over two reported 40-seed ranges rather than one attractive run. Finally, the generator drives a nonparametric bootstrap of the mean waiting time in dm::datasets::faithful(), with an exact conditional variance as an oracle and jump-separated streams showing Monte Carlo variation.

    The data: two measurements of Old Faithful

    The built-in dataset has 272 records: eruption duration and waiting time to the next eruption, both in minutes. The waiting times are strongly associated with eruption duration and have two main groups. The simulation target below is the mean waiting time; no normal distribution is fitted to the raw waiting-time data.

    The method: a linear transition with a nonlinear output

    Let the four 64-bit state words be \((a,b,c,d)\). All shifts truncate to 64 bits, all arithmetic wraps modulo \(2^{64}\), and \(\oplus\) means bitwise XOR. The output before the state advances is

    \[y=9\,\operatorname{rotl}(5b,7)\pmod{2^{64}}.\]

    Multiplication by an odd integer is invertible modulo \(2^{64}\), and a rotation is a permutation of bit positions. The composition is therefore a permutation of 64-bit words: a uniform input word stays uniform. Carries make multiplication nonlinear over bitwise XOR, obscuring the linear structure of the underlying engine. This is not a cryptographic claim.

    Writing the in-place reference transition as simultaneous assignments gives

    \[T(a,b,c,d)=\left(a\oplus b\oplus d,\ a\oplus b\oplus c,\ a\oplus c\oplus(b\ll17),\ \operatorname{rotl}(b\oplus d,45)\right).\]

    Each operation is linear over \(\mathbf F_2\), so \(T\) is a binary linear transformation on 256 state bits. The all-zero state is absorbing and must be excluded. Seed construction fills the four words with successive SplitMix64 outputs. Its odd counter increment visits distinct counter words, and its invertible scrambling maps those to distinct outputs, so these four words cannot all be zero. A direct-state constructor also rejects the all-zero state.

    Deriving the inverse, without confusing reversibility with period

    Suppose the next state is \((u,v,w,z)\). Put \(q=\operatorname{rotr}(z,45)=b\oplus d\) and \(t=w\oplus v\). Then

    \[a=u\oplus q,\qquad t=b\oplus(b\ll17),\qquad b=t\oplus(t\ll17)\oplus(t\ll34)\oplus(t\ll51),\qquad c=v\oplus a\oplus b,\qquad d=q\oplus b.\]

    The finite XOR-shift inverse works because four left shifts of 17 bits erase a 64-bit word: the geometric series in the shift operator terminates. This proves the transition is reversible. Reversibility alone does not prove every nonzero state belongs to a single cycle. The authors' primitive characteristic polynomial supplies the stronger period result \(2^{256}-1\); a short sample cannot establish that period experimentally. A 64-bit seed also selects only a small subset of possible initial states.

    Jumping to distant starting points

    Let \(\chi(X)\) be the transition's degree-256 characteristic polynomial. Reduce a desired power of \(X\) modulo \(\chi\). By the Cayley–Hamilton identity, evaluating that reduced polynomial at \(T\) gives the same state jump:

    \[p_J(X)=X^J\bmod\chi(X),\qquad T^J s=p_J(T)s=\bigoplus_{j=0}^{255}[X^j]p_J(X)\,T^j s.\]

    The library uses the published polynomials for jump() at distance \(2^{128}\) and long_jump() at \(2^{192}\). Each needs 256 transition steps and XOR accumulation, rather than that enormous number of explicit steps. The following table starts from the authors' state order \((1,2,3,4)\). The regression suite checks these states and output words against compiled upstream reference C code.

    Streams starting \(j2^{128}\) raw transitions apart have disjoint state ranges provided each consumes less than \(2^{128}\) outputs and the ranges do not wrap around the full period. This is spacing, not a proof of statistical independence. A raw-state snapshot excludes a cached second normal variate in the common distribution interface; jumps clear that cache so a previous stream's cached draw cannot be returned after a jump. Copying an entire generator object preserves both its raw state and cache.

    Testing more than one seed

    The existing battery checks marginal uniformity, uniform serial pairs, lag-one correlation, two raw bit frequencies and the raw low-byte counts. Its p-values are interpreted under an ideal random-stream model. One unremarkable run is weak evidence, and one small p-value is not automatically a reproducible defect.

    For a continuous, correctly calibrated test statistic, its null p-value is uniform on \((0,1)\). Running the battery on 40 fresh seeds lets us inspect each test's p-value distribution with another KS test. Discrete counts and approximate first-level reference distributions make this uniformity approximate. With 40 ideal runs, about two p-values below 0.05 and two above 0.95 are expected per test; seven second-level tests also create multiple opportunities for an apparently unusual result.

    The first range gives an unusually high second-level KS p-value, about 0.998, for the uniformity-KS test. A separately reported follow-up on seeds 41 to 80 instead gives a small serial-pair second-level p-value, about 0.0079. Both ranges are retained. With fourteen second-level results and an exploratory follow-up, neither isolated extreme should be turned into a claim of certification or a reproducible generator defect.

    These small diagnostics are not substitutes for a large dedicated PRNG suite or an analysis of high-dimensional dependencies. Adjacent seeds do not mathematically guarantee independent streams. We use published jump spacing for the simulation-stream comparison below.

    Applying it: a bootstrap with an exact conditional variance

    Let the waiting times be \(x_1,\ldots,x_n\), and draw a resampled observation uniformly from those \(n\) values. Conditional on the data, its mean is \(\bar x\) and its variance uses the denominator \(n\). The mean of \(n\) independent resampled values therefore has

    \[\mathbb E_*[\bar X^*]=\bar x,\qquad \operatorname{Var}_*(\bar X^*)=\frac1{n^2}\sum_{i=1}^{n}(x_i-\bar x)^2 =\frac{n-1}{n^2}s^2.\]

    This is an exact oracle for the mean under the resampling model, not an asymptotic standard-error formula. The bootstrap draws come through uniform_u64(0,n-1), whose multiply-and-reject mapping is unbiased. Using a raw word modulo \(n\) would generally be biased when \(n\) does not divide \(2^{64}\). The new bootstrap overload accepts the caller-owned engine and reuses the existing interval calculations. BootstrapOptions::seed controls only the default-engine overload; the supplied engine's seed 2026 determines the draws here.

Under the approximate normal-replicate model, Monte Carlo error for this standard-deviation estimate is about 0.00823, so the difference is roughly 2.2 Monte Carlo standard errors. Independent Python arithmetic reproduces all 5000 resampled means exactly, and R reproduces the summary and percentile endpoints. That verifies the calculation while leaving the finite-simulation difference visible.

    Jump-separated streams and Monte Carlo variation

    The next example copies a stream's starting state for each bootstrap, then jumps the untouched starting-state generator before making the next copy. This gives starts exactly \(2^{128}\) raw transitions apart, rather than adding a jump after a variable amount of resampling work.

    Each run uses 2000 replicates. If those mean replicates are approximately normal, the Monte Carlo standard error of their estimated standard deviation is approximately \(\sigma_*/\sqrt{2(B-1)}\). The plotted reference band uses twice that quantity; it is a rough diagnostic for simulation noise, not a confidence interval for the geyser's population mean.

    Increasing the number of replicates reduces simulation noise, not the uncertainty inherent in the observations. This resampling model treats records as exchangeable. Serial dependence between eruptions would need a different resampling scheme, such as a block bootstrap; generator quality cannot repair a misspecified sampling model.

    Conclusion

    The transition is a reversible binary linear map; the output scrambler is a word permutation, and the maximal period relies on the published primitive polynomial. Reference-code agreement and small statistical batteries check different properties. On the geyser dataset, a caller-owned xoshiro stream drives the existing bootstrap API and can be checked against an exact conditional variance. Jump spacing organises reproducible stream starting points, while the variation of their estimates keeps Monte Carlo error separate from the data model's uncertainty.
