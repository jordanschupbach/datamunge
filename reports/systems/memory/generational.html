    Generational collection: retain the young across an old boundary

    Abstract

    Identify young objects that can be reclaimed while leaving old objects outside the collected generation. References from old to young objects must still protect their targets, including young descendants reached through those targets. This report follows the native collector’s actual events, reproduces the original seven-object example and distinguishes young-object visits from total work. A conservative boundary can retain young garbage that a full trace would reject. A second native heap model maintains exact old-to-young slots on checked writes, allowing sparse young-only analysis after setup. All results describe graph candidates: no real objects, ages or memory are changed by collection.

    A rooted old object can protect a young object

    Object 0 is old and rooted. Its one field points to young object 1, while young object 2 is isolated. The minor analysis records old source 0, marks young target 1, visits 1, proposes its promotion and lists 2 as a reclamation candidate. It does not need to traverse the old source during the young marking phase. The legacy API nevertheless pays for old-field discovery and a separate full comparison.

    Restrict traversal to young objects, while retaining all boundary targets

    The input graph has dense ids 0,…,N−1, ordered root slots and ordered reference fields. Binary ages classify every object as young 0 or old 1. Let Y be the young set, R the graph roots and B the targets of all old-to-young fields. The retained young set is the restricted-graph closure

    \[M=\operatorname{Reach}_{G[Y]}\bigl((R\cap Y)\cup B\bigr), \qquad B=\{v\in Y:\exists u\notin Y,\ (u,v)\in E\}.\]

    All seeds are marked before the LIFO stack is processed. Marking on push prevents cycles, shared targets and duplicate fields from adding duplicate stack entries. Targets that are old stop the young traversal. Returned young survivor and garbage ids are ascending; legacy promoted flags are dense over all N ids.

    [Ungar’s 1984 Generation Scavenging paper](https://doi.org/10.1145/800020.808261), Section 8.1, printed 161, describes remembering old objects that reference new ones as a side effect of stores, then traversing new space from those sources. Its [original algorithm](https://prl.khoury.northeastern.edu/img/u-sde-1984.pdf) uses copying, survivor spaces and later tenuring. This report’s fixed-age graph model omits those runtime policies. It also treats the empirical tendency for objects to die young as workload-dependent; these constructed heaps do not measure real object lifetimes. No pause-time or production-runtime claim follows here.

    Two native interfaces have deliberately different costs. minor_gc rebuilds boundary sources on every call and computes a full-root comparison. GenerationalHeap validates and indexes once, maintains exact reference slots when existing fields change, and returns a sparse young-only result from collect. Neither collection call changes object ages, deletes objects or invokes language finalizers. The legacy names promoted and young_freed describe proposals; they do not apply those changes.

    Safety does not require the minor result to equal full-root liveness. If a full root-to-young path contains no old object, its entire path begins at a young root and lies in G[Y]. Otherwise take its last old-to-young crossing: that target is in B, and the remaining suffix contains only young objects. Therefore

    \[\operatorname{Reach}_{G}(R)\cap Y\ \subseteq\ M.\]

    This proves retention safety for the graph model, including paths that pass through old objects between young segments. It does not prove that all retained young objects are truly live, or that a candidate is physically freed.

    An unreachable old source can preserve floating garbage

    Now remove all roots from old 0→young 1→young 2. A full trace reaches nothing. A conservative minor collection still treats old 0 as a boundary source and retains young 1 and 2. This is floating garbage: young objects survive this minor analysis even though a full collection could reclaim the entire component. Remembered-set membership is evidence of an old-to-young field, not of the old source’s root reachability. Minor retention can consequently exceed full liveness.

    Maintain remembered slots at the actual write boundary

    The new heap model owns its graph, fixed binary ages, a sparse young-id table and an exact ordered set of old-to-young (source,field) slots. Checked set_reference replaces an existing field and updates that one slot’s membership. Two fields from the same source are distinct entries; changing one must not erase the other. Replacing a young target with an old one removes that slot. Writing through a young source never creates an old-to-young entry.

    This invariant is preserved locally because ages and field counts are fixed: only the replaced slot can change category. A new set node is allocated before the graph changes, so invalid indices or failed insertion leave the model intact. Ordered-set maintenance costs O(log(W+1)) per replacement for W boundary slots. This is a modeled write barrier, not a claim about runtime machine instructions. The model deliberately does not apply the collector’s promotion proposals: changing ages would require rebuilding or updating the boundary index under a separate API.

    Separate paid setup from repeated young-only work

    For the legacy API, complete validation checks the whole graph and ages. Boundary discovery tests every object and scans old fields; the collector then marks young objects, constructs dense output and runs a full-root comparison. Its total is O(N+E+R), with N objects, E fields and R root slots. The two-visit number in the original example does not describe this total cost.

    The maintained model pays O(N+E+R) construction once and stores the graph/index. Each collect then needs

    \[T_{\mathrm{collect}}=O(Y+R+W+E_y),\]

    Here Y is the number of young objects, W the exact remembered slots, and E_y fields of retained young objects, including their old targets. It initializes only Y marks and returns sparse young ids, avoiding a dense N-entry result. The explicit graph snapshot method copies the whole graph; it is not part of this bound. Constructors, checked writes and any separate full comparison must still be accounted for. A large W or many surviving young fields can make a minor collection expensive even with few young objects.

    Validation, ownership and resource units remain explicit

    Complete graph/id and exact binary-age validation precede every eager analysis, including trivial/empty outcomes and trace quota checks. The maintained model validates before copying/indexing and admits only checked existing-field writes. This closes the original unchecked short-age, high-root, high-child and short-row accesses. Ages other than 0 or 1 are rejected rather than silently omitting an object from both categories. Slot-based collection still ignores all size metadata.

    The trace checks each actual primitive record online: default one million, zero disables only that optional quota. Records are not numeric entries or bytes, and this is not a peak RAM limit. Owned input vectors, root/work metadata, final ordinary output, working tables/stacks and allocator storage are excluded. No partial trace, truncation, numerical replay or caller mutation is returned on quota failure. The family generator uses a separate whole-object bound before allocation; one original seven-object example requires cap 7 and rejects 6.

    The original result survives unchanged, while its interpretation becomes more precise: two young visits coexist with whole-graph discovery and comparison work. The sparse maintained model makes write-side bookkeeping explicit and avoids that repeated old scan under a fixed age partition. Conservative retention protects all root-reachable young objects but can preserve floating garbage. These graph invariants, actual traces and selected operation counts explain the method without claiming a complete runtime collector or universal generational performance.
