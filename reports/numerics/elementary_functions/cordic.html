    CORDIC: Rotations, Gain and Floating Precision

    Abstract

    Given an angle in radians, approximate its sine and cosine together using a sequence of rotations with binary scales. The recurrence is simple, but its vector length changes, floating arithmetic limits useful precision, and reducing a large angle by a rounded period can lose its phase. This report derives the circular CORDIC updates and compensation, follows actual native before/after states, reproduces the original four-angle comparison and twelve-step path, and measures errors as the stage count grows. The canonical C++ implementation now shares one producing kernel with its trace and uses an immutable prepared table. It is a floating model whose operations and numerical limits are explicit.

    The method: a rotation multiplied by a known gain

    A true rotation by dα, for d in {−1,+1}, maps (x,y) to (x cos α−d y sin α, y cos α+d x sin α). Choose αᵢ=atan(2⁻ⁱ) and drop the common cos αᵢ factor. With sᵢ=2⁻ⁱ the resulting pseudo-rotation is

    \[x_{i+1}=x_i-d_i s_i y_i,\qquad y_{i+1}=y_i+d_i s_i x_i,\qquad z_{i+1}=z_i-d_i\alpha_i.\]

    Start at x₀=1, y₀=0 and the reduced target z₀=φ. Choose dᵢ=+1 when zᵢ≥0, including zero, and −1 otherwise. The two coordinate updates are simultaneous: y's update uses the old x. The sign corrects an angular overshoot without restarting. This API executes the requested count; reaching a zero residual does not stop the next fixed rotation.

    The omitted cosine is not free. Squaring and adding the two coordinate updates gives xᵢ₊₁²+yᵢ₊₁²=(1+sᵢ²)(xᵢ²+yᵢ²). Thus the raw length is amplified by

    \[A_N=\prod_{i=0}^{N-1}\sqrt{1+2^{-2i}},\qquad K_N=A_N^{-1}=\prod_{i=0}^{N-1}(1+2^{-2i})^{-1/2}.\]

    In ideal arithmetic A∞≈1.646760258 and K∞≈0.607252935. The final compensated coordinates are cos≈K_N x_N and sin≈K_N y_N, with the range-reduction sign restored afterwards. Use the finite product for the chosen N. The old report called the reciprocal the gain; here A denotes amplification and K denotes compensation consistently.

    First worked updates at one radian

    The first direction is positive: (1,0) becomes raw (1,1), whose norm is √2. Its compensated or normalized direction is (1/√2,1/√2), at 45 degrees. Since 1−π/4 is still positive, the next raw state is (0.5,1.5). The third direction is negative, giving (0.875,1.375). These exact dyadic coordinates can be checked without evaluating a trigonometric function.

    Binary scales can be implemented as shifts in a chosen fixed-point format. This C++ model uses floating multiplication, subtraction and addition. Its shared immutable table is lazily prepared with 1,075 atan/sqrt records, then reused. Each call still accumulates compensation products and performs two final multiplications; each recorded normalized direction adds hypot and division. These are algorithmic evaluation counts, not a count of FPGA gates or CPU instructions, and the report makes no hardware-throughput comparison.

    Folding a half turn: both output signs change

    The implementation first computes r=remainder(θ,2πd), using a double constant πd. If r>πd/2 set φ=r−πd; if r<−πd/2 set φ=r+πd. Either fold removes a half turn, so both sine and cosine are negated at output. Otherwise φ=r with no sign change. Inclusive endpoints ±πd/2 are not folded.

    For θ=2.5, φ≈−0.641592654. The folded vector is in the fourth quadrant, and negating both coordinates places the answer in the second. This is the same fold used for the original four angles.

    This is reduction modulo a rounded period, not a high-precision reduction modulo mathematical 2π. An error in the period is multiplied by the number of removed turns. Very large finite angles can therefore have large phase error before any CORDIC stage executes. The final numerical controls below expose that limitation.

    Finite-stage error and the floating floor

    In ideal real arithmetic the unit direction has angle φ−z_N. For N≥1, z_N|≤α_(N−1) follows by induction. The first step maps |φ|≤π/2 to |z₁|≤π/4=α₀. If |zᵢ|≤α_(i−1), the next magnitude is ||zᵢ|−αᵢ. Concavity of atan gives α_(i−1)≤2αᵢ, so that magnitude is at most αᵢ. Sine and cosine are one-Lipschitz, giving an ideal per-component truncation bound α_(N−1), approximately 2^(1−N) radians.

    This bound assumes exact rotation arithmetic, exact constants and exact gain compensation relative to the reduced target. It does not bound all rounding or input-period reduction errors of the floating program. Small residual and small unit-norm defect also do not certify the direction for a huge original angle.

    Each successful call performs one range reduction, N table lookups and N raw updates/compensation products, followed by two final compensation products. Analysis uses O(1) call scratch after the one-time shared preparation; a trace owns N constant-size records, O(N) extra storage. The optional complete trace cap counts all requested records before allocation. The sweep checks its complete angle-count product before running and uses bounded stage counts, retaining first worst-angle ties in input order. These counts describe the model, not a runtime comparison with a tuned libm or a fixed-point hardware implementation.

    Large angles, zero stages and checked contracts

    The supported count is 0..1075: stages i=0..1074 cover every nonzero binary64 scale 2⁻ⁱ. Beyond that the scale is zero. Counts outside the domain and nonfinite angles are rejected before reduction/table access; zero stages remains an explicit unrotated approximation. The original SinCos two-double field layout and default count forty remain. There is no early convergence flag, automatic identity fix, signed-zero sine promise or global guarantee of increasing accuracy with N.

    The native implementation assumes the ordinary floating environment. Constants are prepared once and then read only; returned constants and traces own copies. Separate calls use independent work state. Analysis and result-only calls retain no step vectors. Large-angle accuracy to mathematical sin(θ),cos(θ) would require a more accurate reduction policy, which this API does not claim to supply.

    Independent checks compare the rounded-period reduction and the kernel with a standard-library Decimal oracle at 430-digit working precision. Machin's formula supplies π and Taylor series supply reference sine/cosine for both the exact represented input and the actual folded target. This distinguishes a faithful CORDIC approximation of the folded target from an accurate approximation of a huge original angle. The optional CTest oracle requires Python's standard library and no numerical package or language binding.

    Conclusion

    The gain derivation, hand-checked updates and native trace explain the actual circular recurrence. The original four angles and twelve normalized states are preserved, while tables show stage error, compensation and a floating precision floor. The large-angle controls demonstrate that a unit-length answer and a tiny kernel residual can still point in the wrong direction for the original input. Prepared constants, checked budgets and one shared producing kernel make this floating model inspectable with explicit numerical scope.
