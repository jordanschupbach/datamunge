    Gaussian elimination: actual row reduction and numerical limits

    Abstract

    Given a square coefficient matrix and a right-hand side, find the unknowns that satisfy their simultaneous linear equations. Floating-point row operations can introduce rounding error, and some systems have no unique solution. Gaussian elimination first reduces the system to a triangle, then substitutes backwards. This report follows actual core snapshots on a two-equation example and the original three-equation system. Measured work and a maximal-growth family show what partial pivoting controls and what it cannot guarantee. Residuals, absolute pivot cutoffs and history admission provide separate, explicit checks.

    A swap, one elimination, then back substitution

    Start with x+y=3 and 2x+3y=8. The larger first-column coefficient is 2, so row 1 moves above row 0. Subtract half of the new first row from the second: its equation becomes -0.5y=-1. Thus y=2, followed by x=(8-3y)/2=1. The native trace records accepted pivot choices, completed row eliminations and back-substitution assignments at their actual time. A pivot snapshot follows its row interchange; it is not a separate swap event. IDs are zero-based. Before substitution the solution vector is empty; during it, earlier unsolved coordinates are zero placeholders.

    Row operations preserve the equations in exact arithmetic

    For a nonzero selected pivot in column k, eliminating a later row i uses

    \[m_{ik}=a_{ik}/a_{kk},\qquad a_{ij}\leftarrow a_{ij}-m_{ik}a_{kj}\ (j\ge k),\qquad b_i\leftarrow b_i-m_{ik}b_k.\]

    A row swap and subtraction of a multiple of another row are reversible, so they preserve the solution set in exact arithmetic. Once U is triangular, solve

    \[x_i=\frac{c_i-\sum_{j=i+1}^{n-1}U_{ij}x_j}{U_{ii}},\qquad i=n-1,\ldots,0.\]

    The [official LAPACK DGETRF specification](https://netlib.org/lapack/explore-html/d3/d6a/dgetrf_8f_source.html) also uses partial pivoting with row interchanges. Its blocked LU factorization stores multipliers and tests for exactly zero diagonal entries. Our scalar core keeps actual reduced coefficients and transformed RHS, uses an absolute cutoff, and does not return a packed L factor or implement blocked BLAS operations. A current-to-original row permutation describes equation order, not a permutation of solution coordinates.

    Count the implemented work, including the cancelled entry

    At column k, the implementation updates n-k coefficients in each of n-k-1 later rows. It includes the entry being eliminated and does not overwrite a tiny cancellation residue with a manufactured exact zero. For a successful solve:

    \[\begin{aligned} C_{\rm rows}&=C_{\rm comparisons}=C_{\rm RHS}=C_{\rm back\ products}=n(n-1)/2,\\ C_{\rm coefficient\ updates}&=\sum_{q=1}^{n}q(q-1)=n(n-1)(n+1)/3,\\ C_{\rm back\ divisions}&=n. \end{aligned}\]

    One coefficient update is a multiply-subtract, not one floating-point operation. These counters exclude validation, allocation, finite checks and snapshot copies. The ordinary solve needs O(n³) arithmetic and O(n²) storage. A full trace stores O(n²) states of O(n²) entries each, so its worst-case history and copying cost are O(n⁴).     Bounded multipliers do not prevent element growth

    Selecting the largest absolute pivot in its column gives m|≤1 in exact arithmetic. But an updated coefficient may be as large as |a+m pivot-row entry, so the maximum can double at a stage. Repeating this argument gives the classical partial-pivot growth bound 2^(n-1). The native growth counter measures the largest absolute stored coefficient, including the input, divided by the input maximum; it excludes the RHS. Floating rounding and underflow are outside that exact bound.

    The native Wilkinson growth family has diagonal 1, strict lower triangle -1, last column 1 and other entries 0. Equal magnitudes retain the earliest pivot, so there are no swaps and each multiplier is -1. The last column doubles after each stage, attaining the bound. This is not the symmetric Wilkinson matrix used in eigenvalue examples. The construction follows [Higham and Higham (1989), Large Growth Factors in Gaussian Elimination with Pivoting](https://doi.org/10.1137/0610012), with an [explicit matrix from the author's own explanation](https://nhigham.com/2020/07/14/what-is-the-growth-factor-for-gaussian-elimination/). The original error-analysis reference is [Wilkinson (1961), Error Analysis of Direct Methods of Matrix Inversion](https://doi.org/10.1145/321075.321076). The worst-case growth is a possibility, not a claim about every input or the error for every RHS. The selected RHS below can have very small backward error even when coefficient growth is large.

    A small residual still needs a conditioning argument

    Recompute r=b-Ax in widened arithmetic, using the original coefficients. The native summary returns infinity norms and the normwise backward-error expression from the [LAPACK Users' Guide](https://netlib.org/lapack/lug/node81.html):

    \[\eta_\infty=\frac{\lVert b-A\widehat{x}\rVert_\infty} {\lVert A\rVert_\infty\lVert\widehat{x}\rVert_\infty+\lVert b\rVert_\infty}.\]

    The all-zero denominator convention is 0/0=0. A small value describes a nearby system solved by the candidate; it alone does not bound the candidate's distance from the true solution. That inference also needs conditioning. For A=diag(1,10-10) and b=(1,10-10), the exact solution is (1,1). The deliberately inaccurate candidate(1,2) has second-coordinate error 1 but only a 10^-10 residual and a small normwise backward error. The example below contrasts this candidate with the solver output; it does not silently label a residual as forward accuracy. This infinity-norm diagnostic differs from the existing linalg::backward_error(), which uses Frobenius/2-norm units.

    Absolute cutoffs, invalid inputs and whole-history admission

    The legacy Gaussian API keeps its original absolute pivot cutoff 1e-12. A selected pivot strictly below it returns solved=false and an empty solution; equality is accepted. This does not classify inconsistent versus underdetermined systems, and a uniformly tiny but perfectly conditioned identity matrix also fails. New solve/trace APIs expose an explicit positive finite absolute cutoff; they do not silently change the meaning to a relative threshold.

    All row lengths, RHS length and finite entries are checked before pivoting, including entries beyond an early zero pivot. Nonfinite stored arithmetic throws. These checks prevent malformed access and false success with NaN/Inf, while leaving the limits of finite precision explicit.

    History admission counts the entire conservative request before copying inputs or allocating solver state. With E=n(n-1)/2+2n possible events, its bound is

    \[H(n)=n^2+2n+E(1+n^2+4n).\]

    Each event owns its matrix, RHS, permutation and solution state. Input rows/cells and event matrix row records count too. Ordinary final output, work/root metadata, working storage and allocator bytes are excluded: entries are not bytes or peak RAM. The default cap is one million; zero disables only the optional cap, while arithmetic and container limits remain. A failure cannot return a partial trace, and caller inputs remain unchanged. Rejected pivots do not get an early-stop quota discount. Shape/finite/control validation precedes admission.

    The native solve now supplies the row-reduction evidence that previously needed a second implementation in the report. Partial pivoting controls multipliers, while growth, conditioning, residuals and an absolute cutoff answer different questions. These exact generated systems expose those distinctions without an external dataset or a timing claim.
