    Gauss–Jordan elimination: actual inverse construction and its cost

    Abstract

    Given a square matrix and a right-hand side, compute both a solution of the linear equations and a candidate matrix inverse. Row reduction must keep three blocks consistent, while floating-point arithmetic can introduce error or reject a pivot. Gauss–Jordan elimination carries an identity block through the same operations as the equations. This report follows actual native snapshots on a two-equation example, reruns the original three-equation system and checks both inverse products without snapping small entries to zero. Measured work, a large above-pivot clearing factor and cutoff/history controls expose the method's cost and limits.

    Carry the identity block through a tiny solve

    For x+y=3 and 2x+3y=8, swap row 1 above row 0 to select the larger first pivot. Divide that row by 2, then clear the first column of the other row. Its second pivot is -0.5. Normalizing it gives y=2; clearing above it gives x=1. Every operation is also applied to an initially separate identity matrix.

    The native trace records pivot after all row interchanges, normalize after the whole pivot-row division, and eliminate after a complete other-row update. It stores the actual evolving identity block, named transform, as well as the coefficient matrix, RHS and row-interchange IDs. It does not replay the algorithm.

    Why carrying I constructs an inverse

    A row interchange, multiplication of one row by a nonzero number and subtraction of a multiple of another row are reversible. Let T be the product of these row-operation matrices. In exact arithmetic they act on all three blocks:

    \[T[A\mid I\mid b]=[TA\mid T\mid Tb].\]

    If the coefficient block reduces to I, then TA=I. For a square matrix this makes T the inverse, and Tb solves Ax=b. Thus the fully reduced augmented system is I | A^-1 . For a failed pivot, T is only a partial row transformation; it must not be labelled an inverse. Computed floating-point blocks need not be an exact identity, even when the exact-arithmetic argument applies.

    At column k the implementation selects the earliest largest absolute pivot among remaining rows, swaps all three blocks, and applies

    \[\begin{aligned} (A_{k,:},T_{k,:},b_k)&\leftarrow(A_{k,:},T_{k,:},b_k)/d,\qquad d=A_{kk},\\ (A_{r,:},T_{r,:},b_r)&\leftarrow(A_{r,:},T_{r,:},b_r) -f(A_{k,:},T_{k,:},b_k),\quad r\ne k,\quad f=A_{rk}. \end{aligned}\]

    All columns of both matrix blocks are updated, including earlier columns and zero clearing factors. No exact zero or identity is manufactured afterwards. This is a square inverse-and-solve API, not a general rectangular rank or RREF classifier. The related GJ presentation in [Tsao (1989), NASA TM101466, Section3](https://ntrs.nasa.gov/citations/19890011339) reduces to diagonal form under a no-pivoting assumption. Our variant normalizes pivot rows, uses partial pivoting and carries an explicit identity block. Its operation ordering and storage are therefore stated directly rather than borrowing another implementation's cost or a general error guarantee.

    The original three-equation system, with unsnapped products

    Reuse 2x+y-z=8, -3x-y+2z=-11 and -2x+y+2z=-3. Their exact mathematical solution is (2,3,-1); the exact inverse has rows (4,3,-1),(-2,-2,1),(5,4,-1). Native fixtures and diagnostics replace the old report's local matrix-product loop. Diagnostics recompute both A*V and V*A in checked long-double arithmetic, where V is the supplied inverse candidate. They do not assume V is correct.     For a product P, the diagnostic infinity error is max_i sum_j P_ij-I_ij. The product of the supplied matrix norms is ||A||inf ||V||inf. It is a condition number only when V is the true inverse; an arbitrary candidate's norm product cannot certify conditioning. These computed residuals are not interval proofs of inverse accuracy. Long double may have the same range and precision as double on some platforms, so widening is checked rather than promised extra precision.

    The same limitation applies to a solve residual: a small |b-Ax| alone needs a conditioning argument before it bounds forward error. The [LAPACK Users' Guide](https://netlib.org/lapack/lug/node81.html) distinguishes normwise backward error from conditioning and forward error. [G. Peters and J. H. Wilkinson (1975), On the Stability of Gauss-Jordan Elimination with Pivoting](https://doi.org/10.1145/360569.360653) is the original focused stability reference; this report makes no unconditional accuracy claim for the native implementation.

    The inverse block has an explicit cost

    The old report described the inverse as free and quoted roughly 50% more work. That description does not fit this full-block implementation. At each of n columns it normalizes n entries in A, n entries in the identity block and one RHS entry. It then clears n-1 other rows, updating all n entries of both blocks:

    \[\begin{aligned} C_{A\rm\ updates}&=C_{T\rm\ updates}=n^2(n-1),\\ C_{A\rm\ divisions}&=C_{T\rm\ divisions}=n^2,\\ C_{\rm RHS\ updates}&=n(n-1),\qquad C_{\rm RHS\ divisions}=n. \end{aligned}\]

    One update means one multiply-subtract assignment, not one floating operation. The native Gaussian solver's coefficient-update count is n(n-1)(n+1)/3. Comparing that count with the two Gauss–Jordan matrix blocks gives a ratio 6n/(n+1) for n>1. This compares these implementations performing different tasks: inverse-and-solve versus solve-only. It is not a universal ratio, benchmark or timing claim. Counts exclude validation, finite checks, allocation, diagnostics and trace copies. Ordinary arithmetic is O(n³) and storage O(n²). Full histories retain O(n²) events of O(n²) entries each, giving O(n⁴) copying and retained storage.

    Clearing above a normalized pivot can use a large factor

    Partial pivoting selects among the remaining rows in the current column. The native elimination event records raw f=A[r][k] after the pivot row has been normalized. This is not Gaussian elimination's ratio to an unnormalized pivot. It need not be bounded by 1, and earlier rows above the pivot are not candidates in that pivot search.

    For A=[[1,100],[0,1]], the second pivot is 1 and its row needs no scaling change. Clearing row 0 uses raw factor 100. This is an exact, hand-checkable illustration; a large raw clearing factor alone is not a proof that the computed answer is bad. The native inverse is [[1,-100],[0,1]], and both products are exactly I for these representable inputs. Supplying I as a deliberately wrong inverse gives large product errors, even though its supplied norm product is much smaller.

    Cutoff failure leaves a partial transformation, not an inverse

    The legacy absolute threshold remains 1e-12. Selected pivots strictly below it return solved=false with empty solution and inverse arrays; equality is accepted. This does not distinguish inconsistent from underdetermined systems and is not a rank certificate. A uniformly scaled 1e-13 identity matrix is well conditioned yet fails the default cutoff. New APIs expose an explicit positive finite cutoff; choosing 1e-15 accepts that system without changing the legacy default.

    All matrix and RHS shapes and finite entries are checked before pivoting, including entries beyond an early zero pivot. Nonfinite stored arithmetic throws; rounding, underflow and loss of accuracy can still occur. A thrown exception returns no partial trace and does not mutate the caller.

    A trace admits its whole conservative history before copies or inverse/state allocation. With at most E=n²+n actual pivot/normalize/eliminate events:

    \[H(n)=n^2+2n+(n^2+n)(1+2n^2+4n).\]

    The count includes input and event matrix row records. It excludes ordinary final output, root/work metadata, working state and allocator bytes: entries are not bytes or peak RAM. Default cap is one million; zero disables only the optional cap, while arithmetic, container and work-counter checks remain. Successful two-row traces retain exactly the whole bound 110. A first-pivot rejection retains only 25 entries, but still needs admission 110; cap 25 cannot request an early-stop discount. There is no replay, truncation or partial output. Inverse diagnostics use a separate product-row/cell quota with different units.

    The native trace makes inverse construction inspectable while keeping the exact operation ordering of the original implementation. It also makes the costs and failure semantics visible. Inverse products, solve residuals, partial-pivot choices and resource admission answer separate questions; none supplies an unconditional certificate of accuracy. These exact generated systems need no external dataset and do not make an elapsed-time claim.
