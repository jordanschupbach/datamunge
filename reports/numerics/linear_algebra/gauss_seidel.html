    Gauss–Seidel: use each new coordinate immediately

    Abstract

    Solve a square linear system by improving an approximate solution through repeated sweeps, avoiding a full factorization. Whether those sweeps converge depends on the coefficient matrix and its ordering. Gauss–Seidel updates each coordinate using the latest available values. This report opens with two hand-checkable assignments, solves the original three-equation example and tests an exactly analysable family that both converges and diverges. Actual native histories show that a residual can increase even for a strictly diagonally dominant system. Counted dense work and explicit history limits distinguish computational cost, stopping tests and the mathematical convergence guarantee.

    Two equations show what “use the latest value” means

    Solve 2x−y=1 and −x+2y=1, whose exact solution is (1,1). Start at (0,0). The first equation sets x=1/2. The second immediately reads that new x, so y=(1+1/2)/2=3/4. A simultaneous Jacobi sweep would instead produce (1/2,1/2). The diagram and table use snapshots captured by the executing C++ solver; there is no local reimplementation of its recurrence.

    From scalar updates to a triangular solve

    Let A be a real n-by-n matrix with nonzero diagonal and b a matching vector. Write A=D+L+U with diagonal D and strictly lower/upper parts L,U. With row indices increasing through a sweep, the exact-arithmetic update is

    \[x_i^{(k+1)}=\frac{b_i-\sum_{j<i}a_{ij}x_j^{(k+1)}-\sum_{j>i}a_{ij}x_j^{(k)}}{a_{ii}}, \qquad (D+L)x^{(k+1)}=b-Ux^{(k)}.\]

    This is an ordered triangular operation. A generic matrix-vector callback alone does not expose the diagonal and lower part needed by this API. [Barrett and coauthors, Templates for the Solution of Linear Systems, second edition, Gauss–Seidel subsection](https://netlib.org/linalg/html_templates/node14.html) describe the immediate-update dependency and its sensitivity to ordering. The library implements a dense scalar version: zero start, ordered long-double sums and checked double assignments. Its recomputed stopping norm is formed from a dense A x whose row results have first been rounded to double. All input rows, RHS values, controls and nonzero diagonal entries are validated even when the initial residual already meets the tolerance.

    If x* solves the system, subtraction gives the error recurrence

    \[e^{(k+1)}=T e^{(k)},\qquad T=-(D+L)^{-1}U,\qquad e^{(k)}=x^{(k)}-x^*.\]

    In exact arithmetic, convergence from every initial vector is equivalent to spectral radius rho(T)<1: T^k then tends to zero. Eigenvalues inside the unit circle give decaying Jordan-block powers; any eigenvalue outside or on the unit circle prevents decay for some initial vector. This criterion does not promise monotone Euclidean residuals or a perfectly straight logarithmic residual plot. Transient effects, multiple modes, finite termination and rounding all matter.

    Strict row diagonal dominance is sufficient. To see why, let q=max_i sum_(j≠i)|a_ij|/a_ii<1 and E=||e_old||∞. In the first row the new error is at most qE. Inductively, previously updated errors are at most qE≤E and all remaining old errors are at most E; the next new error is therefore also at most qE. Thus a complete sweep contracts the infinity norm by at most q. For symmetric positive-definite A, each coordinate update instead minimizes the strictly convex quadratic f(x)=xᵀAx/2−bᵀx along that coordinate: the exact decrease is a_ii times the squared coordinate change divided by 2. A full nontrivial homogeneous error sweep strictly reduces its A-norm; compactness of the A-unit sphere supplies a contraction factor below 1. Neither proof certifies a particular floating-point residual decrease at every sweep.

    The stopping test is inclusive: computed residual≤tol. It is an absolute, unscaled test, so rescaling both A and b can change when the same tolerance is met even though the mathematical solution is unchanged. A small residual is also not a forward-error certificate: in exact arithmetic e=−A^-1r for r=b−Ax, so the inverse matrix can amplify a small residual. Rounding in the stored A x adds another distinction between this implementation’s stopping norm and an exact real-number residual. A zero computed residual is reported as zero and has no logarithm; no plotted value is substituted for it.

    An exactly analysable family shows decay and divergence

    Choose A=[[1,−q],[−q,1]], b=(1−q,1−q), q>0, q≠1. The exact solution is (1,1). For a zero start, the error after k≥1 sweeps and the exact residual norm are

    \[e^{(k)}=(-q^{2k-1},-q^{2k}),\quad T=\begin{pmatrix}0&q\\0&q^2\end{pmatrix},\quad \|b-Ax^{(k)}\|_2=|q^{2k-1}(1-q^2)|.\]

    These expressions follow by substituting the first coordinate assignment into the second. Hence rho(T)=q². Jacobi’s matrix has eigenvalues ±q and spectral radius q. The square relation explains the commonly observed “twice the rate” for this particular family in exact asymptotic sweep counts. It is not a universal speed ratio, does not compare wall-clock time and says nothing about a general matrix’s Jacobi convergence. Here q<1 gives strict diagonal dominance and decay; q>1 makes this particular zero-start error grow. All requested eight sweeps are kept below, so a false converged flag means the zero-tolerance budget was exhausted. The Jacobi column is the derived exact spectral radius; no Jacobi solver is run.

    A residual can rise before convergence, and order changes the intermediate state

    For A=[[1,1/2],[0,1/128]], b=(0,1), both rows are strictly diagonally dominant. The exact solution is (−64,128). Starting at zero, the first row remains zero; the second becomes 128. This makes the first equation’s residual 64. The next sweep sets the first coordinate to −64 and reaches the solution exactly in binary arithmetic. The sequence of Euclidean residuals is 1,64,0 despite rho(T)=0. This is a nilpotent, nonnormal iteration: finite termination after two sweeps coexists with a large transient residual. It directly disproves an unconditional monotone-residual or straight-log-line claim.

    The second panel returns to the symmetric two-equation example. Reverse both the row and variable ordering, run one forward sweep, then map coordinates back. Its first state becomes (3/4,1/2) rather than (1/2,3/4). In this symmetric example the rate is unchanged, but the intermediate iterates differ; other matrices can also change rate under reordering. A row-only permutation does not perform this same transformation and may introduce a zero diagonal.

    Count dense work and admit complete histories before execution

    After k completed sweeps on n unknowns, the dense implementation has assigned kn coordinates, divided kn times and executed kn(n−1) off-diagonal products. Its post-sweep residual checks add kn² dense products and k+1 norm evaluations, including the initial norm of b without a matrix product. Zero coefficients are still visited. These are algorithmic counts, not floating-operation counts or elapsed time. This dense API uses O(kn²) arithmetic and O(n) extra ordinary storage beyond the input matrix; a sparse implementation would need its own storage and traversal contract.

    Full histories copy two n-vectors per coordinate and one per completed sweep, so their extra storage is O(kn²). Admission for a requested maximum K is

    \[H(n,K)=n+1+K\{n(1+2n)+(1+n)\}\quad(n>0),\qquad H(0,K)=1.\]

    The units mix vector values and fixed-schema metadata records as documented by the API; they are not bytes or peak RAM. Root/work metadata, final ordinary output, original A and b, working state and allocator storage are excluded. The default entry cap is one million; zero disables only the optional quota. Complete count, capacity and quota checks precede initialization or history allocation. Even a zero RHS receives no early-success discount from the requested nonempty-system bound. The actual retained count can be smaller when convergence occurs early. There is no truncation, numerical replay or partial returned history, and inputs and snapshots have independent ownership. The older residual-only trace keeps its separate online cap on actual residual entries, including the initial one.

    The native histories preserve the original solver result and make each dependency visible. Exact convergence theory explains the diagonal-dominant example and the q-family’s decay, while the triangular counterexample shows why residual monotonicity cannot be assumed. Ordering, absolute stopping, arithmetic precision and explicit dense storage all shape the computation a user actually receives. These constructed linear systems test the mathematical claims directly; no external dataset or timing benchmark is needed.
