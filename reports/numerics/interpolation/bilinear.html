    Bilinear Interpolation: Four Corners, Two Linear Blends

    Abstract

    Given values on a rectangular grid, estimate the value between grid nodes without fitting a global surface. Four nearby samples determine a continuous interpolant that is linear in each coordinate separately. We derive its weights, check one uneven cell by hand, reconstruct the original sine–cosine example, and verify an exact quadratic error formula. The datamunge API also extrapolates outside the grid, where its in-cell range and error guarantees no longer apply.

    The method

    For a cell \([x_i,x_{i+1}]\times[y_j,y_{j+1}]\), define fractional coordinates

    \[t=\frac{x-x_i}{x_{i+1}-x_i},\qquad u=\frac{y-y_j}{y_{j+1}-y_j}.\]

    Interpolate along the lower and upper rows, then between them:

    \[a=(1-t)z_{00}+tz_{10},\quad b=(1-t)z_{01}+tz_{11},\quad I(x,y)=(1-u)a+ub=\sum_{r,s\in\{0,1\}}w_{rs}z_{rs},\]

    The weights, in corner order \(00,10,01,11\), are \(((1-t)(1-u),t(1-u),(1-t)u,tu)\). Their sum is one. Inside the cell they are nonnegative, so interpolation cannot leave the range of the four corner values. The rule reproduces \(1,x,y,xy\) separately, hence every \(a+bx+cy+dxy\). Reversing the order of the two linear blends gives the same formula, apart from floating-point rounding.

    Adjacent cells agree along their shared edge because both reduce to the same one-dimensional interpolation there. Values are continuous, but derivatives can jump across grid lines. Uneven spacing is allowed; the grid need only be rectangular with strictly increasing axes.

    Simple example: an uneven cell

    Take \(x\in[0,2]\), \(y\in[0,4]\), corners \((z_{00},z_{10},z_{01},z_{11})=(0,2,4,10)\), and query \((0.5,3)\). Then \(t=1/4\), \(u=3/4\), and the four weights are \((3,1,9,3)/16\). The lower and upper row blends are \(a=0.5\) and \(b=5.5\), so the final result is \(0.25(0.5)+0.75(5.5)=4.25\).

    Deriving and checking the error rate

    Write the two one-dimensional interpolation operators as \(I_x,I_y\). The identity \(f-I_xI_yf=(f-I_xf)+I_x(f-I_yf)\), the one-dimensional linear interpolation remainder, and nonnegative interpolation weights give

    \[|f-I_xI_yf|\le\frac{h_x^2}{8}\sup|f_{xx}|+ \frac{h_y^2}{8}\sup|f_{yy}|.\]

    Thus smooth functions have second-order error as the cell widths decrease. For the sinusoid, both second derivatives are bounded in magnitude by 1, so equal widths \(h\) give the bound \(h^2/4\) printed above. For \(q(x,y)=x^2+y^2\), the identity is sharper and exact:

    \[I q-q=(x-x_i)(x_{i+1}-x)+(y-y_j)(y_{j+1}-y), \qquad (I q-q)_{\mathrm{midpoint}}=\frac{h_x^2+h_y^2}{4}.\]

    On a uniform unit-square grid with \(m\) intervals in each direction, every cell midpoint has error \(1/(2m^2)\). Doubling m must divide the error by four.

    API and numerical limits

    bilinear_interpolate rejects axes with fewer than two points, repeated or decreasing coordinates, nonfinite data or queries, and a sample count other than xs.size()*ys.size(). It checks the full grid on each call, costing \(O(n_xn_y+n_x+n_y)\) validation time and constant auxiliary storage. After validation, binary cell lookup costs \(O(\log n_x+\log n_y)\) and the two blends use four samples. This distinguishes the interpolation kernel's constant work from the checked API's preprocessing cost.

    The implementation uses stable linear blends so a finite in-cell result can survive corner differences that would overflow ordinary subtraction. An unrepresentable coordinate or result raises an overflow error. Near-duplicate coordinates can still amplify data and coordinate noise; rescale poorly conditioned axes. Extrapolation uses the nearest end cell and can overshoot. Neither the convex-hull statement nor the interior smoothness bound applies outside the sampled rectangle.

    Conclusion

    The uneven-cell calculation gives 4.25 and confirms the sample layout. The original smooth reconstruction retains its approximation error, while the quadratic control exactly exhibits a factor-of-four improvement on each grid refinement. These generated controls make a separate observed dataset unnecessary. Bilinear interpolation provides continuity and a second-order smooth-data error bound, with derivative jumps and potentially unstable extrapolation as limits.
