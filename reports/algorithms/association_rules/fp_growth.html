    FP-growth: actual prefix trees and weighted conditional patterns

    Abstract

    FP-growth aggregates shared transaction prefixes and extends frequent patterns through weighted conditional databases. A four-basket example makes every node and count checkable. Owned native traces then replace the original grocery report's hand-drawn schematic with its actual tree and conditional paths. On Titanic passenger attributes, the three native miners agree at a positive threshold. Dense and disjoint controls show why a small initial tree can still have exponentially many answers. Actual work and online history admission keep compression, output size and memory limits distinct.

    Four baskets, three frequent sets

    Take baskets {bread,milk}, {bread,milk}, {bread} and {milk}, with minimum count two. Each singleton occurs in three rows; their pair occurs in two. Baskets are sets, so repeated IDs inside one row count once, while repeated rows remain separate observations. Empty rows also retain their identities. The native miner sorts frequent items by support descending, breaking ties by ascending numeric ID. Bread0 therefore precedes milk1 in this example.

    The first two baskets share the path bread→milk; the third increments bread; the last creates a separate milk node at the root. The following diagram uses the actual created nodes, counts and parent indices. Its coordinates come from the reusable native rooted-tree drawing method, rather than a hand-coded layout.

    Why target-node counts give conditional supports

    For a target item x, the header lists every tree node labelled x. Those nodes partition its weighted occurrences by their shared prefix, so summing their counts gives support(x). For each such node, walk toward the root and keep its ancestors, excluding x and the root. Weight that entire path by the target node's count. An ancestor can have a larger count because other baskets stop early or branch elsewhere; using its count would overstate co-occurrence with x.

    The tiny milk node under bread has count two even though bread has count three. Its conditional base therefore contains bread with weight two. The separate root milk node has no ancestors and contributes no nonempty conditional path. Mining the base emits the pair with support two. Native paths are stored nearest ancestor first; each child builder orders them again by its own weighted frequencies.

    More generally, for a current suffix P and a nonempty extension set X drawn from its retained ancestors, the conditional occurrence accounting gives

    \[\operatorname{support}_{D}(P\cup X) =\sum_{\substack{\text{conditional paths }B\\X\subseteq B}}\operatorname{weight}(B).\]

    Filtering any conditional item whose weighted support is below the threshold cannot remove a frequent extension: every superset has no greater support. A fixed item order within each tree assigns patterns to suffix branches, avoiding duplicates; a result is finally sorted into ascending IDs and then cardinality/lexicographic order. The actual emission sequence can differ from this final presentation: the tiny trace emits {0}, then {1}, then {1,0}, while the returned pair is {0,1}.

    Han, Pei and Yin's [Mining Frequent Patterns without Candidate Generation](https://sigmodrecord.org/2000/06/07/mining-frequent-patterns-without-candidate-generation/), SIGMOD2000,1–12, [doi:10.1145/342009.335372](https://doi.org/10.1145/342009.335372), develops the FP-tree, target-weighted conditional bases and pattern-growth argument. This implementation uses owned vectors of header node IDs and explicit DFS frames. It rebuilds conditional trees directly and omits the paper's single-path shortcut. Avoiding Apriori's candidate join does not mean that counting, filtering or combinatorial output disappears.

    A compact initial tree can have exponentially many answers

    Repeat the same U-item basket R times and set the threshold to R. Every nonempty subset is frequent, so there are F=2U−1 results despite only U nonroot initial nodes. Their item payload alone has U*2(U−1) IDs, because each item belongs to half of all subsets. No miner returning every itemset can avoid that output size.

    For this direct conditional-tree implementation, the dense family also gives checkable work identities: aggregate nonroot node creations F, builds2^(U−1), parent hops F−U, peak active frames U and peak frame-resident node records U*(U+3)/2. The latter sum counts ancestor trees together with the current tree, including their roots; it excludes temporary child buffers, retained history and ordinary output. These are exact counts for this family, not general memory bounds.

    As a contrast, U disjoint one-item baskets at threshold one have the same U initial nonroot nodes but only U frequent sets, one build and no parent hops.     The initial tree has at most one nonroot node per retained normalized incidence, since inserting an item can create at most one node. This does not bound all simultaneously active ancestor trees, output records or captured history by the size of one initial tree. Prefix sharing stores the frequent-item projection with counts; it is not a lossless copy of raw transaction order, duplicate IDs or discarded items.

    Normalization sorts each raw basket. Each build counts weighted item visits, sorts retained items by support, filters every weighted row, sorts its retained IDs by rank and inserts them. Hash-map access has expected rather than universal constant cost. Repeating those operations over conditional databases and copying all emitted IDs means that an unsorted build is not simply O(N*width), and the entire mining process is not completed by two scans of the original database. Two logical passes describe each tree build, after normalization, rather than every conditional construction combined. The native counters count visits and records; they exclude sort comparisons, hash internals, allocation and capture copies.

    Online history admission, ownership and threshold zero

    FP-growth cannot cheaply know all future conditional trees in advance. Its trace therefore admits retained history online. The raw base N+raw item occurrences is checked before copying or normalization. Later records are admitted before their history copies; a working tree or conditional base may have to be formed first to determine its size. Failure returns no partial trace.

    For the tiny fixture, raw input costs ten entries, tree snapshots nineteen and step records with their paths nine: total38. This cap covers retained history, not ordinary canonical output, active working trees, normalized input, conditional buffers or allocator bytes. The units are records and array entries, not bytes or peak RAM. The default is one million entries; zero disables only the optional cap, while checked arithmetic and container bounds remain.

    Threshold zero preserves the historical FP API: only positive-support co-occurring sets are returned. Apriori and Eclat instead include all nonempty observed-universe subsets meeting zero, including unsupported combinations. The disjoint two-item control below therefore gives two FP sets and three from each other miner. Their complete-output equivalence claim requires a positive threshold.

    The trace captures these states in the same executing kernel, with no replay. The trace owns raw rows, nodes, headers, emitted sequences and conditional paths. Caller edits cannot change those records. The ordinary result and work-only API use the same executing kernel without retaining this history or imposing its optional quota. Captured raw inputs preserve duplicates; mining still counts each item once per row. Opaque SIZE_MAX item IDs remain valid because only node index zero denotes the root.

    Every figure is regenerated by the complete native C++ program beside it. The canonical passenger table is the only real dataset used; the tiny, grocery, dense and disjoint controls have explicitly constructed inputs.
