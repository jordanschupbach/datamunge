    Fletcher-16: two residues, exact error patterns and real aliases

    Abstract

    A receiver can compare a short tag with a recomputed checksum to detect some accidental changes to a byte stream. The important question is which changes are detected, not whether the tag looks complicated. Raw Fletcher-16 maintains two sums modulo 255, which detects every single-input-bit change when the original tag is held fixed. It also has exact aliases, including a byte changing between zero and 255 and certain transpositions. This report preserves the original examples, inspects actual native states, counts complete corruption candidates, and distinguishes those guarantees from probabilistic claims or protocol-specific check-byte formats.

    The method and its raw-tag convention

    Start with A=B=0. For every unsigned input byte x, perform

    \[A\leftarrow(A+x)\bmod255,\qquad B\leftarrow(B+A)\bmod255,\qquad \operatorname{tag}=(B\ll8)\mathbin{|}A.\]

    The library uses canonical residues 0 through 254, so both an octet zero and an octet 255 contribute residue zero. Empty input has tag zero; embedded zero bytes do not terminate the input. This is the original library's raw packed tag. Protocols can instead compute complemented check bytes at prescribed header offsets and reserve special values. Those wire conventions are not supplied by this API.

    Each byte costs two modular recurrence updates. The implementation reduces after every byte, not in delayed batches. The residues fit in eight bits, while transient additions need nine; the core uses sixteen-bit arithmetic. There is O(n) work and constant ordinary state, without a hardware speed ranking against Adler-32, CRC or plain sums.

    Two bytes: inspect the actual fold

    For bytes [1,2], after the first byte A=B=1. After the second, A=3 and B=4, giving raw tag 0x0403. Equivalently, A=1+2 and B=2×1+1×2. The program reads these states from the native byte kernel; it does not implement a second checksum in the report.

    Preserve the original reference and corruption examples

    For n bytes x_i indexed from zero, expanding the recurrence gives

    \[A=\sum_{i=0}^{n-1}x_i\pmod{255},\qquad B=\sum_{i=0}^{n-1}(n-i)x_i\pmod{255}.\]

    Keep the original abcde reference, all 88 independent one-bit changes to abracadabra, and the ABCD versus ABDC transposition. The complete bit scan recomputes the ordinary checksum for every candidate, using one toggled/restored scratch message. Its budget is n(8n+1) byte folds including the baseline; it neither samples nor truncates candidates.     What is guaranteed, and the zero/255 exception

    For one altered input bit, the integer byte change is δ=±2^b for 0≤b≤7. None of these values is zero modulo 255, so A changes and the raw tag must change, independently of the position or the message length. This assumes the original tag is held fixed. A simultaneous change to data and the transmitted tag is a different error model.

    A general single-byte replacement instead has δ between −255 and 255. Apart from an unchanged byte, its only nonzero multiple of 255 is the change between zero and 255. Thus the original blanket claim about all single-byte errors was false. The following complete census includes every possible replacement at one zero byte: 255 changed candidates, of which 254 change the tag and the replacement 255 is missed. Candidate zero is an unchanged control and is not counted as an undetected error.

    The raw container has sixteen bits, but only 255²=65,025 canonical residue pairs. This count alone does not establish a collision probability for arbitrary inputs. Both empty input and every all-zero/all-255 sequence have raw tag zero. Leading a message with zero or 255 also leaves this zero-initialised raw checksum unchanged; the tag therefore does not independently bind a message length.

    Position sensitivity has exact transposition aliases

    Suppose i<j initially contain bytes a,b. Exchanging them leaves A unchanged, while

    \[\Delta B=(j-i)(b-a)\pmod{255}.\]

    An adjacent exchange of distinct octets is detected except for the zero/255 pair. At greater distances, 255=3×5×17 has zero divisors. A distance of three and a byte difference of 85 give a product of 255 and an unchanged raw tag, even when neither byte is zero or 255. For example, [1,0,0,86] and [86,0,0,1] both produce 0x5A57. Other examples are distance five with difference 51, distance seventeen with difference 15, and distance 255 with difference one. Position-sensitive does not mean every reordering is detected.

    The scalar delta API evaluates that exact modular formula. The table independently recomputes both complete messages through the native checksum.     Streaming, composition and bounded owned evidence

    The update API accepts only canonical packed states whose two lanes are below 255. An empty update returns that validated state. If L and R are separately initialised messages and m is the length of R, concatenation satisfies

    \[A_{LR}=A_L+A_R\pmod{255},\qquad B_{LR}=B_L+B_R+mA_L\pmod{255}.\]

    The combine operation reduces m before multiplication and supports every uint64 length without reading the messages. The caller supplies the correct right-message length. For a virtual all-zero suffix, its raw tag is zero at every length. In particular, 2^64−1 is divisible by 255, so appending that virtual zero suffix leaves this tag unchanged. This is an algebraic operation, not a huge allocation or an invalid byte view.

    Byte traces check their complete event cap before allocation/folding. Bit scans check n(8n+1) whole byte folds; one-position replacement scans check 257n. Zero disables only the optional cap, while arithmetic/container limits still apply. Records own their values, no input view is retained, and no partial census is returned on failure.

    What the examples establish

    The original reference, all 88 one-bit checks and the detected ABCD/ABDC swap are retained. The raw recurrence also proves a general single-input-bit guarantee, while complete byte replacement and explicit transposition controls expose its exact exceptions. A plain sum misses the original reordering but catches the zero-to-255 substitution that Fletcher misses, so a universal strength ladder would be misleading. Corruption models, tag width, message structure and implementation costs must be specified before comparing algorithms. These are accidental-error checksums, not authentication tags. No external dataset is needed for the finite byte domains and controlled error patterns studied here.

    References

    • J. G. Fletcher (1982), [An Arithmetic Checksum for Serial Transmissions](https://doi.org/10.1109/TCOM.1982.1095369), IEEE Transactions on Communications 30(1),247–252. Citation verified; the modular recurrence and protocol distinctions here are supported by the accessible RFC sources below.
    • [RFC 926](https://www.rfc-editor.org/rfc/rfc926.html), appendices A.3 and C.2–C.4: modulo-255 arithmetic, zero/255 aliases, single-bit detection and protocol check-byte construction. Its protocol reserves an all-zero check field; the library's raw zero tag is a valid arithmetic result.
    • J. Zweig and C. Partridge (1990), [RFC 1146](https://www.rfc-editor.org/rfc/rfc1146.html), appendix I: two zero-initialised one's-complement accumulators and the weighted second sum. The raw packed integer convention in this report is specified independently of any wire representation.
