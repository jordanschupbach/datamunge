    Girvan–Newman: shortest-path shares and batch community cuts

    Abstract

    A bridge between two triangles carries every shortest path between their two sides. Removing that bridge reveals two components. Girvan–Newman repeatedly recalculates edge betweenness to find such boundaries, but the details of removal and arithmetic matter. This report begins with hand-checkable bridge and equal-path examples, then follows the native implementation’s simultaneous near-maximum batches. A four-cycle overshoots a requested two-way split. The original karate-club graph supplies a real network, with every visited partition evaluated against the original edges. Actual primitive histories, independent exact-path fixtures and explicit floating-count and record limits distinguish the method from guarantees it does not provide.

    Nine cross-pairs must use the bridge

    Join triangles {0,1,2} and {3,4,5} by edge 2–3, as in the original example. Each of the three left vertices can pair with each of the three right vertices. All nine cross-pair shortest paths use the bridge, so its conventional undirected betweenness is 9. Edge 0–1 is used only by its own endpoint pair and has score 1. The four other triangle edges have score 4. Native raw accumulation visits both source directions, producing twice these conventional values.

    For a simple unweighted undirected graph, let σst be the number of shortest paths from s to t, and σst(e) the number using edge e. Disconnected pairs contribute zero:

    \[B(e)=\sum_{s<t,\;\sigma_{st}>0}\frac{\sigma_{st}(e)}{\sigma_{st}}, \qquad R(e)=2B(e).\]

    Equal shortest paths share a pair’s unit weight; they are not each counted as a whole independent pair. [Girvan and Newman’s original paper](https://doi.org/10.1073/pnas.122653799) removes a highest-betweenness edge and recalculates after removal. Here the preserved native variant removes every edge within an absolute 10^-12 of the maximum RAW score in one batch, then recalculates. It may therefore follow a different hierarchy and return more communities than requested. All edges and paths are unweighted.

    BFS stores distances, predecessor lists and counts σs(v). A shortest path to v ends at one predecessor, so its count is the sum of predecessor counts. Accumulating in reverse BFS order assigns the edge u–v the contribution

    \[a_s(u,v)=\frac{\sigma_s(u)}{\sigma_s(v)}[1+\delta_s(v)],\qquad \delta_s(u)\mathrel{+}=a_s(u,v),\qquad R(u,v)\mathrel{+}=a_s(u,v).\]

    The term 1 accounts for v itself; δs(v) accounts for farther targets. Positive unweighted distances make the predecessor graph acyclic, so reverse order has the successor dependencies ready. [Brandes’s original dependency derivation](https://doi.org/10.1080/0022250X.2001.9990249) is the basis of this shared native recurrence. Counts and dependencies here remain ordered double arithmetic; the later numeric example states their limitations.

    A target is a minimum, and tied batches can overshoot

    The original bridge is uniquely maximal. Its one-edge batch yields {0,1,2} and {3,4,5}, preserving the original example. A four-cycle instead has equal scores on all four edges. The native batch deletes all four at once: requesting two communities returns four singleton components. An already disconnected graph can meet its target without any betweenness computation.

    The exact native keep condition is R(e)<max R−10-12. Thus its half-score scale would have a 5×10-13 threshold, not 10^-12. Directions and duplicates are ignored, self-loops discarded, and the remaining edges sorted before adjacency construction. Output components follow ascending roots and BFS member order; they are not promised to have sorted members. The empty graph accepts only target 1, returning no groups; its default target 2 is invalid. These are API contracts, not evidence of any particular social grouping.

    Score every visited partition against the original graph

    A divisive method always produces some partition, including on graphs without a meaningful community interpretation. Modularity compares internal edges with a degree-based baseline. For group c, let Lc be its internal ORIGINAL edges and Kc its sum of ORIGINAL degrees, with m original edges:

    \[Q=\sum_c\left[\frac{L_c}{m}-\left(\frac{K_c}{2m}\right)^2\right].\]

    [Newman and Girvan’s modularity definition](https://doi.org/10.1103/PhysRevE.69.026113) uses the full original network even after detection removes edges. The native helper therefore receives the original edge list each time. It validates a complete, disjoint partition and defines Q=0 for an edgeless graph. Maximizing Q over the visited batch stages does not prove global optimality or a true community count. Every actual stage below is retained, including unchanged component counts and worse late partitions.

    An independent development oracle uses all-pairs distances, enumerates shortest paths explicitly and splits exact rational pair weights. It agrees with all 78 initial edge scores and all 34 target requests for this pinned graph. Separate fixtures cover every simple graph through five vertices and every valid target. Those checks establish implementation agreement on the checked inputs; they do not turn modularity or shortest-path communities into sociological ground truth.

    Selected operation counts reveal implementation costs

    The textbook unweighted dependency traversal can run in O(nm). This preserved implementation additionally initializes n-slot working arrays for every source and uses a binary search to find each edge’s score slot. One scored pass therefore has an O(n²+n m log(m+1)) bound. Input normalization adds O(r log(r+1)) for r raw records; connected-component passes add O(n+m). At most m scored batches give O(r log(r+1)+m n²+n m² log(m+1)), plus terminal component work. Scoring scratch is O(n+m). Normalization can retain capacity for r copied records after duplicates collapse, so total ordinary auxiliary storage is O(r+n+m), excluding the caller input and final result. Retained history is additional storage.

    The following family has two equal cliques and one bridge. The bridge carries size² unordered cross-pairs. Each example needs one scored batch to split, so source slots grow as n². Counted binary-search comparisons expose an extra cost that is absent from a claim based only on BFS visits. These selected counts exclude allocation, sorting comparisons, validation and arithmetic FLOPs; they are not timings.

    Floating path counts need a numeric boundary

    A double can represent every nonnegative integer only through 253. The native flag path_counts_integer_guaranteed becomes false once an actual count exceeds that range. False is conservative: a power of two above the threshold can still be exactly represented. The guard checks the integer bound before rounding: an exact count of 253+1 can round back to 2^53 and must still clear the guarantee. True concerns path counts only, not exact dependency fractions, tie rankings or an error certificate.

    Consecutive width-two complete-bipartite layers create exponentially many shortest paths. Sixty layers produce finite counts beyond the integer guarantee. With 1030 layers, the original unchecked kernel generated nonfinite counts, dependencies and a maximum, then NaN comparisons deleted all edges. The updated core throws on a nonfinite update before propagation or deletion. It preserves the original finite double order and does not silently switch to exact arithmetic or long double.

    Complete online records and whole generated graphs have distinct limits

    Primitive traces count fixed-schema canonical edges, round/component metadata, source initializations, actual BFS/path/dependency operations, score rows and removal decisions. The positive quota is checked before each whole-record append; its default is one million, and zero disables only that optional quota. Earlier local work may occur before a later append rejects. No partial trace returns, no numerical replay reconstructs it, and no caller input is mutated or truncated.

    Input vectors, root/work metadata, final ordinary output, working predecessor/BFS arrays and queues, and allocator storage are excluded. Complete records are not numeric entries or bytes; this is not a peak RAM limit. Ordinary/run APIs have no trace quota. Even empty early-stop calls retain their actual metadata records. Graph generators separately admit whole vertex counts before allocation; that quota has different units from history records. Numeric and container guards remain when optional quotas are zero.

    All endpoints are validated before target and history checks. Counts must fit the legacy int distance range; target is positive and valid for the vertex count. Modularity requires a complete disjoint partition, including isolated vertices. The GML reader separately validates original ids, endpoints, syntax and bounded source/node/edge ingress; the verified dataset accessor does not invent missing data.
