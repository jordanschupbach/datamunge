    Dinic’s Maximum Flow: Blocking Phases, Cancellation and Cut Checks

    Abstract

    Given a directed network with capacities and distinct source and sink, we want the largest flow that respects every edge limit and conserves flow at intermediate vertices. A route chosen early may need to be undone before other routes can carry more flow. Dinic’s algorithm groups pushes into blocking-flow phases on residual BFS levels. We begin with the original single edge of capacity 7.5, then inspect an actual cancellation path that requires a second phase. The classic six-vertex network reaches value 23, checked against its per-edge feasibility and cut capacity. Controlled path families expose phase and current-arc work. Positive capacities below the old absolute cutoff, bounded trace capture, an iterative long-path traversal and explicit arithmetic failures make the numerical limits visible.

    One edge: retain the original answer and expose the residual pair

    The original executable sends flow from vertex 0 to vertex 1 on one edge of capacity 7.5. Its unique maximum flow is 7.5. Before the push, the forward residual is 7.5 and the paired cancellation residual is zero. The bottleneck is 7.5; afterwards those values are zero and 7.5. The terminal BFS cannot reach the sink, so the source side of the minimum cut is {0}, and the crossing capacity is also 7.5.

    The new trace records those actual operands and both BFS searches, rather than rerunning the algorithm at selected prefixes. The same program scales the single edge over four capacity units. The former fixed residual test capacity>1e−12 returned zero for 7.5e−13; the canonical kernel now uses strict positivity and returns that positive flow. It does not introduce an absolute unit-dependent cutoff.

    Flow conservation and residual cancellation

    For each original arc e=(u,v) with capacity c_e, retain its own flow f_e with 0<=f_e<=c_e. Net outflow is zero at every vertex except source s and sink t; the value is net outflow from s, also net inflow to t. Parallel and antiparallel input arcs keep separate identities. Each input arc gets a forward residual c_e−f_e and a paired reverse residual f_e. A reverse push cancels previous flow on that particular original arc. It is distinct from a separately supplied opposite-direction input arc.

    BFS assigns each reachable residual vertex its shortest arc-count distance from s, considering only positive residual capacities. During a phase, DFS follows arcs whose head is exactly one level beyond the tail. The level graph is acyclic. A blocking flow leaves no residual s-to-t path advancing through those fixed levels: every such path has lost an available arc. This need not be a maximum-flow solution when rerouting is allowed. The next example makes that distinction concrete.

    There are two left vertices L1,L2 and two right vertices R1,R2. Unit arcs connect s to each left vertex, L1 to R1 and R2, L2 to R1, and each right vertex to t. Input order first selects s→L1→R1→t. That blocks all remaining forward paths in the first level graph, at flow one. A second BFS finds the length-five residual path s→L2→R1→L1→R2→t. Its R1→L1 arc cancels the earlier L1→R1 flow. The two final matches are L1→R2 and L2→R1, giving value two.

    Why the shortest residual path grows after a blocking phase

    Let old BFS levels be ell. Every residual arc already present before the phase satisfies ell(v)<=ell(u)+1. Any newly positive cancellation arc reverses a used level arc, so its old level change is minus one. Thus a new residual path cannot increase the old level by more than one per arc. A new s-to-t path no longer than the old sink level would have to advance exactly one old level at every step. The blocking flow has removed all such paths, a contradiction. Hence the next reachable sink distance strictly increases. A simple residual path has at most V−1 arcs, so there are at most V−1 successful phases in exact arithmetic, followed by one failed BFS. In the executed cancellation example those distances are three, five, then unreachable.

    The implementation uses an explicit path stack instead of recursive DFS. Each vertex’s current-arc pointer advances permanently through its adjacency within a phase. Successful path prefixes may be tested again, while an exhausted arc or dead end is not retried in that phase. If J counts current pointer advances and L counts successful path-arc updates, the recorded DFS inspections satisfy inspections=J+L. At most 2E pointer advances occur per phase. Every positive path push saturates a level arc, and cancellation arcs go backwards in the fixed levels, so at most E pushes are needed in one phase. With each path length at most V−1, a phase costs O(VE), and all phases cost O(V^2 E), after O(V+E) initialization. Ordinary working storage is O(V+E), including the explicit stack.

    [Dinic’s original paper](https://www.cs.bgu.ac.il/~dinitz/D70.pdf) gives the polynomial operation bound. The report’s current-arc counters measure this concrete iterative variant; they are not elapsed-time or arbitrary-precision bit-complexity measurements.

    Recover the classic value 23 and check the cut independently

    The ten-arc six-vertex network used by the existing tests has maximum flow 23. We now run it in the report itself. The final residual source side is S={0,1,2,4}; crossing original arcs have capacities 12,7,4, whose sum is 23. The table retains every original arc’s individual flow, including the antiparallel pair between vertices 1 and 2.

    For any feasible flow and any source/sink-separating cut S, summing conservation over S cancels internal arcs and gives

    \[|f|=\sum_{u\in S,v\notin S}f_{uv}-\sum_{u\notin S,v\in S}f_{uv} \le\sum_{u\in S,v\notin S}c_{uv}=c(S,\bar S).\]

    At exact residual termination, every outgoing crossing arc is saturated and every incoming crossing flow is zero, since either would otherwise create a residual arc leaving S. Equality therefore proves optimality. This is the [flow/cut bound of Ford and Fulkerson](https://doi.org/10.4153/CJM-1956-045-5). The separate core check computes edge-bound errors, intermediate-vertex conservation, terminal/value agreement and the signed cut-minus-value gap. It does not call Dinic, search for a replacement cut or repair the result. Default absolute tolerance is zero; positive tolerances are numerical agreements and keep the actual error and gap visible.

    Controlled phase growth and measured work

    Two canonical generated families separate path multiplicity from path length. In the first, p internally disjoint unit-capacity paths all have length four: E=4p and V=2+3p. BFS finds them at the same sink level, and one blocking phase pushes all p units. In the staircase family, there is one unit path of each length 1,...,p. Then E=p(p+1)/2, V=2+p(p−1)/2 and each successful phase removes exactly the next shortest path. Its successive sink levels are 1,...,p. This tests increasing phase counts while remaining below the general V−1 bound; it is not a tight worst-case construction.

    Counters include BFS visits to reverse and zero-capacity residual arcs of reached vertices. DFS inspections include retries of still-current arcs after successful pushes. The identity J+L separates permanent pointer movement from the successful path work. Both charts use the executed counts, rather than values inferred from graph size.

    Feasibility, optimality and finite arithmetic are separate checks

    A feasible flow of seven on a capacity-ten edge is not optimal: its cut bound is ten and its gap is three. Conversely, a reported value equal to a cut bound can accompany an infeasible per-edge assignment. Deliberately supply flow three on 0→1 and flow two on 1→2, both with capacity three, while reporting value three and cut {0}. The scalar gap is zero, but vertex 1 accumulates one unit and the sink receives only two. The independent check rejects feasibility and optimality. The following figure illustrates that supplied invalid record, not a Dinic output.

    A tolerance of 0.5 would accept a feasible value 9.5 against a cut of ten within that tolerance; the displayed gap remains 0.5. These flags are numerical checks of the supplied result. They do not replace independent exact tests when a proof over exact integer data is needed.

    The kernel checks every residual pair and cumulative flow before a positive push. Nonfinite sums raise overflow_error. A positive update lost to rounding raises runtime_error; for example, trying to subtract one from an edge residual of 1e100 cannot change that double. No partial flow or trace is returned. There is no hidden unit-dependent epsilon or automatic rescaling. The original four-argument name, advanced_graph.hpp include path and MaxFlowResult layout remain available.

    Trace storage is explicitly bounded. If P includes the final failed BFS, A is the number of augmentations and L sums successful path lengths, the entry cost is C=P(V+1)+A+L: each phase, each stored vertex level, each augmentation and each path-arc snapshot counts one. Original graph, result and working arrays are outside that optional history budget. The default cap is one million entries; zero disables only that cap. The single-edge trace costs eight entries exactly; seven fails before the final BFS. Capture adds O(C) time/storage to the ordinary algorithm.

    Verification and limits

    Native tests enumerate all 729 three-vertex networks with each directed non-loop capacity in {0,1,2}, from all six ordered terminal pairs, and all 4096 four-vertex unit/zero-capacity networks from all twelve terminal pairs. These 53,526 source/sink computations match independently enumerated cut minima. Plain and traced per-edge flows and cut sides agree. A separate replay checks every BFS level, path bottleneck, residual operand/update, blocked level graph and inspection identity against the owned original input.

    The original single edge and classic value 23, the cancellation example, parallel/antiparallel arcs, self-loops, scale changes, exact/one-short history caps, malformed supplied certificates, complete input guards and arithmetic failures receive explicit controls. Generated path counts and phase counts match their closed forms, and a 30,000-edge native test uses the explicit stack without vertex-depth C++ recursion. The report itself runs the 20,000-edge version. All inputs are small educational networks or canonical generated fixtures; no external dataset is required.

    The mathematical flow/cut proof and phase bound hold in exact arithmetic. The implementation uses checked doubles and numerical diagnostics; a wide capacity range may require rescaling or a different arithmetic model. Within the exhibited representable cases, the trace exposes how blocking and cancellation achieve the result, and the independent flow/cut check establishes the reported numerical agreement.
