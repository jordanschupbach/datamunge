    Euclidean Minimum Spanning Trees: Actual Edges, Cuts and Work

    Abstract

    Given labeled planar points, connect every point with minimum total straight-line edge length, without adding new junctions. The canonical C++ implementation measures every unordered pair and runs one shared stable Kruskal kernel. We begin with the original unit square, then inspect an actual cycle rejection, coincident vertices, scale and translation, and exact input-generation work. A checked owned trace records the decisions made by the same kernel that returns the tree.

    The original unit square: three sides suffice

    Four vertices in cyclic order have four unit-length sides and two sqrt(2) diagonals. A tree needs three edges. Three unit sides connect the square with total length three, and every edge has length at least one, so no spanning tree can be shorter. Equal weights are scanned in the original lexicographic pair order. This chooses a reproducible tree from several equally good trees; it does not make the minimum unique.

    Derive the greedy rule and its geometric objective

    For vertices p[i]=(x[i],y[i]), the complete graph has M=n(n-1)/2 edges, with weights

    \[w_{ij}=\operatorname{hypot}(x_i-x_j,y_i-y_j),\quad i<j, \qquad \min_T\sum_{(i,j)\in T}w_{ij}.\]

    Kruskal scans these edges in nondecreasing weight order. It accepts an edge exactly when its endpoints belong to different current components. An accepted edge reduces the number of components by one without creating a cycle. Starting from n components, n-1 accepted edges give a connected acyclic spanning tree when n>0. The empty graph is connected by this API's convention; a singleton needs no edges.

    Why is each greedy acceptance safe? Maintain a minimum tree containing the already accepted forest. If the next edge e is absent, insert it into that tree: a cycle appears. That cycle contains an edge h crossing the current component cut. Such an edge cannot be lighter than e; an earlier lighter crossing edge would already have joined components. Replacing h by e therefore preserves a minimum tree containing the new forest. Ties permit this exchange, so the lightest cut edge belongs to some minimum tree, rather than necessarily every minimum tree.

    The generic kernel uses path halving and union by rank. Its trace records the actual roots before each decision and the actual number of components afterwards. Roots are implementation representatives, not sorted component labels. Point indices and endpoint orientations remain attached to their original records throughout sorting.

    Labeled duplicates and coordinate transformations

    Equal coordinates do not merge input records. Distinct vertex indices can be connected by a zero-length edge, and the algorithm still accepts exactly n-1 edges for n>0. The next fixture adds a second record at the unit square's origin. Its tree has one zero-length edge and three unit edges. Plot markers at identical coordinates overlap; the table keeps the separate vertex identities and their zero edge visible.

    Translation cancels in pair differences. Multiplying every coordinate by a positive factor a multiplies all exact distances and the minimum length by a; the selected tree can be retained. These identities are mathematical statements. In general floating rounding can alter very close ties. Here the exact integer translation and factor three keep all selected lengths exactly representable, and the stable selected endpoint sequence is checked directly.

    An MST minimizes total length over edges joining the given vertices. It does not form a tour visiting every point in cyclic order, minimize root-to-point path lengths, or introduce Steiner junctions. Comparing squared distances preserves individual edge ordering in exact arithmetic, but summing squared selected weights is a different objective from the Euclidean length reported here. The core uses hypot lengths throughout. These coordinates are Cartesian units, not latitude/longitude distances.

    Every pair is generated even when scanning finishes early

    The implementation builds the full M-edge graph, sorts a stable index permutation, then performs union-find scans. With M=n(n-1)/2, this costs O(n2 log(n+1)) time and O(n2+n) runtime storage. Early tree completion can save scans, but does not save pair-distance generation or the sort. No Delaunay sparsification is implemented by this API.

    For n equally spaced collinear points at coordinates 0,...,n-1, all n-1 adjacent unit edges come first and connect the line. The exact minimum is n-1: its extremes are distance n-1 apart, and a spanning tree's path between them cannot have smaller total length. This family therefore gives M actual distance evaluations, S=n-1 actual scans, and optional capture C=n+M+S=M+2n-1. Input sizes and outputs are logical counts, not elapsed-time benchmarks or peak-memory estimates.

    A generated geometric workload is appropriate for these exact properties; an unrelated real dataset would not establish the cut proof or the operation counts. The native tests additionally exercise random point clouds, independently computed Prim minima, exhaustive small labeled trees and a tree-path bottleneck certificate for every point pair.

    Finite domains, capture quotas and owned results

    All coordinates must be finite, including singleton inputs that would otherwise generate no distances. Pair arithmetic and container limits are checked without allocating the requested graph. Finite coordinate differences, hypot distances and accepted-edge totals are required; numeric overflow throws instead of returning a connected tree whose total is infinity or NaN. The generic Kruskal API accepts finite negative weights, parallel edges and self-loops, and checks every endpoint and weight before sorting. A disconnected generic graph returns a minimum forest with is_connected=false.

    The Euclidean trace counts C=N+M+S logical records: N points, M complete input edges and S actual decisions. It checks known N+M before generating or copying the graph, then checks each next decision online before scanning it. The default quota is one million; zero disables only that optional quota. Struct scalar fields, the separate output tree, runtime sort/DSU storage, capacities and allocator bytes are excluded. This is not a peak-RAM bound. Ordinary result/work calls retain no optional history or quota. Every returned container owns its values, and errors return no partial trace.

    The native tests preserve 306 frozen valid legacy outputs, including stable ties and generic signed-weight forests, and check actual scan certificates, 350 random planar fixtures, 30 exhaustive small-tree comparisons, 400 generic graphs, duplicate vertices, coordinate transformations, exact work families, ownership and quota boundaries. Full finite validation intentionally changes old nonfinite behavior. The original square remains a three-edge tree of total length three.

    Reference

    J. B. Kruskal, Jr. (1956), On the shortest spanning subtree of a graph and the traveling salesman problem, Proceedings of the American Mathematical Society 7(1), 48-50, https://doi.org/10.1090/S0002-9939-1956-0078686-7. The greedy forest construction is applied here to a complete graph of planar Euclidean distances. Stable input-order ties, checked finite arithmetic and bounded actual scan histories are implementation choices.
