    Cipolla's Modular Square Roots: An Exact Detour Through a Quadratic Field

    Abstract

    Given an unsigned integer n and a prime p, find a residue r whose square is n modulo p, or establish that no such residue exists. Cipolla's method constructs a quadratic extension in which one exponentiation produces a root back in the base field. We inspect a small actual computation, retain the original roots and complete census modulo 1009, and measure deterministic auxiliary search. Canonical C++ now checks the prime domain, includes the missing zero auxiliary, uses full-range modular arithmetic, records its actual operations, and returns representable legacy roots without losing unsigned root identities.

    A hand-checkable field: square root of 10 modulo 13

    The squares of 6 and 7 are both 10 modulo 13. To obtain one by Cipolla's construction, try auxiliary values a until w=a²−10 is a quadratic nonresidue. The actual search rejects a=1 because w=4 is a square, then accepts a=2 because w=7 is not. Introduce a formal symbol s with s²=7. The exponent is (13+1)/2=7, and the native right-to-left bit loop starts from result 1 and base 2+s. Its accumulator visits 2+s, 11+6s and finally 6+0s. These are actual executing-kernel records, not a separately simulated path.

    Why the extension calculation gives a base-field square root

    For an odd prime p, first reduce n modulo p. Handle zero directly; for n≠0, Euler's criterion says a root exists exactly when n^((p−1)/2)=1 modulo p. Choose a with w=a²−n a nonresidue, so X²−w is irreducible over F_p. In the quadratic field F_p[s]/(s²−w), multiplication is

    \[(x_1+y_1s)(x_2+y_2s) =(x_1x_2+w y_1y_2)+(x_1y_2+x_2y_1)s.\]

    Here s is a formal field basis symbol, not the complex number i. Since w((p−1)/2)=−1, we have sp=−s. Thus z=a+s has Frobenius conjugate z^p=a−s and norm

    \[z^{p+1}=(a+s)(a-s)=a^2-w=n.\]

    Let r=z((p+1)/2). Then r²=n. Moreover, r(p−1)=n((p−1)/2)=1, so rp=r. The fixed elements of Frobenius are exactly the base field: writing r=x+ys gives x−ys=x+ys, hence y=0 because p is odd. The resulting x is therefore the desired ordinary residue root. The implementation checks both the vanishing y coefficient and x²=n.

    Every nonzero quadratic residue has exactly two roots, r and −r: if u²=r², then (u−r)(u+r)=0 in a field. They are distinct for odd p. Zero has one root, and F_2 has one root for each of its two elements. These exceptions matter to the old report's unrestricted claim that every residue has two roots.

    Squaring pairs each nonzero field element x with −x, so the p−1 nonzero elements map two-to-one onto exactly (p−1)/2 square classes. This explains 504 out of 1008; it is an exact count, not an empirical probability estimate. Zero is deliberately excluded from this figure and count.

    Candidate density is not a guarantee about deterministic trial count

    For a fixed nonzero square n, exactly (p−1)/2 auxiliary values a in F_p make a²−n a nonresidue. A short count explains this. The equation b²=a²−n is equivalent to (a−b)(a+b)=n. Each nonzero choice of a−b determines one pair (a,b), because two is invertible, so there are p−1 pairs. In terms of the quadratic character χ, this says

    \[\sum_{a\in F_p}\bigl(1+\chi(a^2-n)\bigr)=p-1, \qquad \sum_{a\in F_p}\chi(a^2-n)=-1.\]

    Exactly two values give a²−n=0. Combining the total count with the character sum gives (p−1)/2 nonresidues and (p−3)/2 nonzero residues among the tested differences. Independent uniform random auxiliary choices would therefore succeed with probability (p−1)/(2p), for mean 2p/(p−1) trials.

    This implementation instead retains the reproducible order 1,2,…,p−1,0. The random-choice expectation is not a guarantee for that sequential order. The table measures averages over every nonzero square input for each fixed prime; the histogram describes that fixed-input census modulo 1009. Neither is a runtime benchmark or a random independent-trial experiment.

    For exponent E=(p+1)/2, the retained right-to-left loop performs popcount(E) result multiplications and bit_width(E) base squares. The latter includes the last unused square. Each pair operation performs five reduced scalar products; it does not optimise away products with zero coefficients. Scalar Euler powers also retain their closing square. These details explain the reported actual counts, rather than substituting counts for a different optimised loop.

    For T actual candidates, the solver performs O((T+1) log p) named modular products in a fixed-word model, including the bounded deterministic prime validation. Sequential search can inspect up to p candidates; a positive candidate cap bounds that work. The ordinary call retains constant numeric state; a trace owns O(T+log p) records. The counters exclude primality's internal products and are not an arbitrary-precision bit-cost model. No throughput comparison with another square-root method is inferred.

    The missing-zero case and the full unsigned range

    Modulo 3, the nonzero square 1 exposes a bug in a search restricted to auxiliaries 1 and 2: both give w=0. The only suitable auxiliary is a=0, where w=2. The revised order reaches it after those two failures and produces the valid root 2, with complementary root 1. Zero differences are rejected as auxiliaries rather than mistaken for a quadratic field.

    The legacy return type is signed long long, while the input prime can occupy all of uint64. A raw computed root above LLONG_MAX cannot be cast safely into that interface. One complementary root is at most p/2, so the legacy call now uses the other root when necessary. The unsigned-result API retains the actual raw root, its complementary root and the selected legacy representative. The original small-prime choices remain intact.

    Every scalar product widens its two operands to unsigned 128 bits before reduction. Extension coefficients combine already reduced products, so their sums stay below 2p; the code never adds two unreduced 128-bit products. Candidate subtraction uses a difference of canonical residues instead of forming a²+p−n in uint64. The exponent is computed as p/2+1, avoiding a potentially overflowing p+1 expression. Prime validation occurs before n%p, so p=0 cannot trigger division by zero, and composite zero inputs cannot silently take the zero shortcut.

    Caps, final checks and operation accounting

    CipollaOptions uses zero for an unlimited cap. Positive limits bound actual candidate visits and actual extension pair operations for the whole call. The latter counts the closing square. Cap exhaustion throws std::length_error and returns no partial root or trace, even if an intermediate accumulator already contains a root. Prime validation, scalar Euler tests and final verification are separate from the extension-product cap. Nonresidues and valid zero/binary shortcuts do not consume unused candidate or extension work.

    The variable candidate search and exponent-bit branches expose variable work; this routine makes no secret-independent timing claim. Equation verification certifies the modular root for a validated prime, not the ordering of the root pair or any property of a cryptographic protocol. All returned records own their values and calls share no mutable state.

    Fourteen new native tests enumerate every residue in the 55 prime fields through 257, totalling 6,338 residue inputs, and check normalized aliases against explicit square sets. They retain the original four roots and all 1009 residue verdicts. A separate add-and-double modular arithmetic oracle verifies every recorded candidate and pair transition, independently of the core's unsigned-128 products. Another 1,000 known squares span four large primes through 18446744073709551557, including raw roots above the signed range and their safe legacy complements. Signed/unsigned endpoints, pseudoprime/composite rejection, the missing-zero case, exact/one-below caps, closing-square accounting, shortcut paths and owned copies pass. All fourteen cases also pass AddressSanitizer and UBSan; existing arithmetic regressions remain in the native runner.

    No observational dataset is needed for these exact finite-field identities. The report's complete census describes a particular prime and deterministic search order. It does not establish a universal trial count or a performance ranking.
