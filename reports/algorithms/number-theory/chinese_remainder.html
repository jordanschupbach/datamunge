    Chinese Remainders: Compatible Congruences and Checked Periods

    Abstract

    Several remainder measurements may describe one unknown integer, but they can also contradict each other. Generalised Chinese remainder reconstruction finds the unique compatible class modulo the least common multiple, or detects a contradiction. We follow actual sequential merges for a small example, retain the original coprime residue grid and non-coprime controls, and enumerate the fraction of compatible residue pairs. The canonical C++ solver records its Bezout coefficients and wide candidates, checks periods before narrowing, and distinguishes mathematical inconsistency from a fixed-width range failure.

    A small reconstruction, one merge at a time

    Find an integer with remainders 2, 3 and 2 modulo 3, 5 and 7 respectively. Starting from every integer, represented by 0 modulo 1, the first condition leaves 2 modulo 3. The second leaves 8 modulo 15: 8 has remainders 2 and 3. The third leaves 23 modulo 105. These are actual accumulator states from the native solver, rather than a second implementation of its merge rule.

    Deriving the general merge

    Suppose the current class is x=R modulo M and the next target is x=r modulo m, with positive moduli and canonical remainders. Every member of the first class has the form x=R+Mt. The new condition becomes Mt=r−R modulo m. Let g=gcd(M,m), and obtain the actual Bezout coefficients P and Q from the extended Euclidean algorithm:

    \[MP+mQ=g.\]

    A solution exists exactly when g divides r−R. Necessity follows because g divides both M and m. When divisibility holds, divide the identity by g to make P an inverse of M/g modulo m/g. Then choose

    \[t=\left(\frac{r-R}{g}P\right)\bmod(m/g),\qquad L=M(m/g),\qquad R'=(R+Mt)\bmod L.\]

    This construction satisfies both congruences. The difference between any two solutions is divisible by M and m, hence by L=lcm(M,m). The class is therefore unique modulo L. Applying the argument inductively proves the sequential solver correct whenever each compatible intermediate period is representable. An inconsistent prefix proves the whole system inconsistent. A range failure alone gives no such verdict about unvisited constraints.

    The second merge above has M=3, m=5, P=2, Q=−1 and r−R=1, so t=2 and R'=2+3·2=8. The third has M=15, m=7, P=1 and Q=−2. Its difference is −6, so t=−6 modulo 7=1 and R'=8+15=23. Non-coprime moduli use the same rule; the period is their least common multiple rather than their product.

    For an arbitrary collection, compatibility is equivalent to

    \[\gcd(m_i,m_j)\mid(r_i-r_j)\quad\hbox{for every pair }i,j.\]

    Necessity follows by subtracting any two congruences. For sufficiency, consider each prime separately and select an input containing its largest power among the moduli. Pairwise agreement forces every smaller power to have the same residue. The selected prime powers are mutually coprime, so the coprime theorem combines them into one class modulo their product, which is the full least common multiple. This argument establishes the mathematical condition without requiring factorisation in the implementation.

    The original controls and the residue grid

    For x=2 modulo 6 and x=8 modulo 12, the difference 6 is divisible by gcd(6,12)=6, giving 8 modulo 12. For x=1 modulo 2 and x=0 modulo 4, the difference −1 is not divisible by 2, so no integer works. The following program retains these controls and the original coprime grid.     The map x modulo 15 to (x modulo 3,x modulo 5) is a bijection. This is the coprime Chinese remainder theorem. With non-coprime moduli, some target pairs are incompatible: the two components must agree modulo their shared gcd.

    Counting compatible pairs

    Among the m·n canonical pairs, each of the g=gcd(m,n) common residue classes contains (m/g)(n/g) pairs whose components agree modulo g. Therefore

    \[N_{\rm compatible}=g(m/g)(n/g)=mn/g=\operatorname{lcm}(m,n),\qquad \Pr(\hbox{compatible})=1/g.\]

    This is an exact finite count, not a probabilistic model for arbitrary input data. We enumerate every pair for five small modulus choices, compare actual solver verdicts with the formula, and plot observed fractions against 1/g. There is no natural observational dataset for these arithmetic identities.

    Widened intermediates do not make the result arbitrary precision

    The public CrtSolution layout remains a boolean and two signed 64-bit integers. A successful result has 0≤R<M and 1≤M≤INT64_MAX. Merely calculating with 128-bit intermediates before an unchecked cast could wrap the returned period. The solver now checks the wide candidate period before narrowing it.

    There are two separate boundaries. The product used to find t can exceed 64 bits even when the final period fits. Conversely, compatible congruences can require a period outside the result type. The trace retains the first wide candidate and the last representable prefix in that case. Its status is Overflow and its optional solution is absent. The ordinary API throws std::overflow_error. Neither response means that the congruences conflict.

    With canonical R<M, 0≤t<m/g and M,m≤B=INT64_MAX, the candidate period is at most B²<2¹²⁶ and 0≤R+Mt<L. Reducing each factor of the correction product modulo m/g bounds its magnitude below B² as well. These operations fit signed 128-bit intermediates. The returned period must additionally fit signed 64 bits. Bezout coefficient updates use the widened type too. Normalisation reduces first and adds a modulus only to a negative remainder; it never forms the potentially overflowing expression (r%m+m)%m for a positive remainder near the limit.

    The mathematical solution set is independent of merge order. A fixed-width sequential interface can encounter a range boundary before discovering a later contradiction. The three-condition example demonstrates that limit: full input validation succeeds, but only two conditions are merged. The trace is not an arbitrary-precision continuation through the remaining system. The representative checker tests a particular integer against the conditions; it does not certify a claimed solution period or uniqueness.

    Work budgets, input validation and boundary cases

    The default positive-modulus contract includes modulus one. No conditions leave every integer, represented by 0 modulo 1. All residue/modulus lengths and all moduli are validated before the first arithmetic operation or work cap. CrtOptions uses zero for an unlimited cap; positive values bound the actual attempted merges and extended-gcd quotient/remainder steps across the whole call. The initial zero quotient when M<m counts as a Euclidean step. A cap failure throws std::length_error and returns no partial trace.

    For n inputs, full validation costs O(n) visits. Each attempted merge performs an extended gcd and a constant number of widened arithmetic operations; its division count is logarithmic in the positive modulus magnitudes. The ordinary solver uses constant numeric working state beyond the borrowed input. The trace owns O(a) merge records for a attempts, including the first rejected attempt. These are operation counts for bounded integer arithmetic, not a bit-complexity analysis for unbounded integers or a wall-clock benchmark. Calls have independent state; inputs are borrowed without mutation and trace records own their values.

    The native tests independently enumerate 12,286 small two- and three-condition systems and compare all verdicts, periods and representatives with a brute-force oracle. They check each actual Bezout identity, candidate and counter. Another 1,000 signed random systems and 1,000 constructed near-limit systems cover normalisation and representable periods. Wide correction products, Fibonacci Euclidean chains, first-overflow versus first-contradiction ordering, exact and one-below caps, malformed trailing input, owned traces and 100,000 unit constraints exercise the boundaries. Existing reconstruction and inconsistent random tests remain. All 24 CRT tests pass with AddressSanitizer and UBSan.

    What the reconstruction establishes

    Compatible congruences determine one class modulo the least common multiple. The gcd test explains non-coprime failure, and the residue-pair census verifies its exact compatible fraction. Actual merge certificates expose how the solver reaches its answer. Checked narrowing prevents a wide compatible period from becoming a wrapped 64-bit result; range failure, work-budget failure and a mathematical contradiction remain separate outcomes.
