    Fibonacci Coding: Exact Weights, Strict Frames and Actual Word Spans

    Abstract

    Represent a sequence of positive integers without transmitting a separate length for each value. A decoder must identify word boundaries and recover every value exactly. Fibonacci coding uses nonconsecutive Fibonacci weights and a final one-bit terminator. We start with the six-bit encoding of ten, retain the original codewords, round trip and length comparison, then extend the native codec to every positive uint64 value. Actual word spans and work counts come from the encoder and strict whole-frame parser. Malformed tails, width overflow, bit-flip experiments and explicit capture limits distinguish self-delimiting framing from error detection, correction and recovery.

    Ten is eight plus two

    Use coding weights W0=1,W1=2 and W(i+2)=W(i+1)+Wi. Ten is eight plus two, so its ascending-weight payload is 01001. Append one terminating bit to obtain 010011. Its final two ones form the delimiter: the first is the highest payload digit, and the second is the appended terminator. This overlap matters when labelling word spans and counting work.

    The native trace below captures the actual output and its spans in the same pass. The figure reads its bits directly and obtains the coding weights from datamunge. The reusable bit-text renderer has the historical name exp_golomb_bit_string but simply prints any vector<bool>; it performs no coding or decoding.

    Why greedy digits and the delimiter work

    Choose the largest Wk≤n. Since n<W(k+1)=Wk+W(k−1), subtracting Wk leaves less than W(k−1), so the next weight cannot be selected. Repeating therefore gives nonconsecutive selected weights. Existence follows by induction on the remaining positive integer. For uniqueness, the largest sum using nonconsecutive weights below Wk is Wk−1; two distinct such representations cannot disagree at their largest selected weight and still have equal sums. This is the Zeckendorf representation for the weights1,2,... .

    The last payload digit is one and its predecessor, if present, is zero. There is no payload11; appending one introduces a first11 exactly at the word end. From a known frame start, a decoder reads payload weights until that pair, emits one value and resets its weight index and previous-bit state. A longer word cannot begin with an entire shorter word, because that would already contain the first terminating11. This establishes a prefix code and unique parsing from the supplied start. It does not by itself establish error correction or synchronization from an arbitrary bit.

    If Wk≤n<W(k+1), payload length is k+1 and complete length k+2. Growth Wk=Theta(phi^k) gives length log_phi(n)+O(1), about1.44042log2(n)+O(1). The native length API uses exact integer weights, not rounded logarithms.

    Full uint64 coverage and strict parsing

    There are92 coding weights representable in uint64: W0=1 through W91=12200160415121876738. The next recurrence value exceeds uint64. The new core stores those exact weights once as an immutable fixed array; it never forms the overflowing next weight. UINT64_MAX needs92 payload digits and one terminator, for93 bits. The parser recognizes a terminating one before requesting another weight, and checks value sums before addition.

    The old encoder grew an unchecked Fibonacci vector until a weight exceeded n, which cannot happen when n=UINT64_MAX after unsigned wrapping. The old decoder used an even shorter table: the valid word with90 zero digits followed by11 already indexes beyond its logical table. A hardened-library probe confirms that violation; a longer malformed word triggers a heap read overflow under ASAN. The replacement checks both the index and sum.

    Whole-frame parsing now rejects unfinished tails, including a complete word followed by a lone zero. Those bits are not implicit padding. Zero is outside the positive code domain; it is rejected before append mutation. The old zero encoder produced a lone1, which decoded to no value.     A delimiter is not an error-correction code

    Changing the first bit of0011, the code for three, gives1011, the valid code for four. The parser accepts it and the value changes silently. Other changes destroy a terminator and produce an unfinished frame. A strict parser checks structural validity and representability, not whether the source values are still correct. External framing, checksums or error correction would be separate format choices.

    The experiment flips each bit of the original ten-value stream once and runs the native whole-frame decoder. The categories describe this exact frame and this single-bit substitution model. They establish neither a universal bound on damaged values nor recovery from arbitrary insertions, deletions, bursts or arbitrary starting offsets. Overlapping11 patterns can occur across word boundaries, so treating the next visible11 as an unconditional original-boundary certificate is unsafe. The original blanket “at most two codewords” statement is not part of this API's contract.

    Actual spans, work and owned history

    The encoder and strict parser share their ordinary/work/trace kernels; there is no explanatory codec replay. Work counts complete values, actual payload bits and actual single terminating bits. bit_visits counts only emitted or consumed positions; preflight, copying, allocation, table lookups and greedy candidate checks are excluded. It is not a CPU-operation count or timing measurement. Ordinary encoding uses O(N+B) word work and O(B) output; parsing uses O(B) word work and O(N) output, with fixed scratch.

    A trace owns B bit positions, N values and N whole span records, giving logical capture C=B+2N. Scalar metadata, container capacity and headers, allocators and runtime temporaries are excluded: this is not peak RAM. Encoding checks complete C before copies/emission. Decoding admits B before copying its input, then two entries before each completed value/span append. Default quota is1000000; zero disables only that optional quota. No partial trace is returned on any error. Ordinary/work APIs store no optional history and have no history quota. The packed-bool container does not specify byte serialization, endianness, padding or outer framing.

    Verification and source

    The core now supports the full positive uint64 range, while preserving 69634 frozen records of valid old codewords, decoded values, a1000-value batch and arbitrary-prefix append, plus all25 lines of original program stdout. Strict sanitizer tests enumerate17710 small nonadjacent codewords independently of greedy encoding, test every representable weight boundary, 10000 seeded full-width values and600 variable batches, strict tails, unsigned value overflow, actual spans, quotas and ownership. An optional arbitrary-precision Python oracle independently checks23578 encode/decode results; it is not a report runtime dependency.

    A. Apostolico and A. S. Fraenkel, [Robust Transmission of Unbounded Strings Using Fibonacci Representations](https://docs.lib.purdue.edu/cstech/464/), Purdue technical report CSD-TR-545, October1985; subsequently IEEE Transactions on Information Theory33(2),1987,pp.238–245, [doi:10.1109/TIT.1987.1057284](https://doi.org/10.1109/TIT.1987.1057284), studies generalized Fibonacci representations and their delimiter structure. The inspected1985 report distinguishes several representations. This report specifies datamunge's order-two ascending-weight positive-integer variant and tests its strict parser directly; it does not infer a universal corruption recovery guarantee from the paper's title. The repository's existing native Exp-Golomb APIs supply the comparison lengths and generic bit-text rendering.
