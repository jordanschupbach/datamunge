    Cycle Sort: Minimum Value-Cell Writes, Quadratic Rank Searches

    Abstract

    Cycle sort pays for repeated rank searches to avoid repeatedly overwriting array cells. The comparison-based variant here writes precisely those cells whose initial keys differ from the nondecreasing target sequence, once each. We begin with a three-item cycle, derive that minimum and the quadratic search cost, expose duplicate-key instability, then retain the original seven-key example and forty-size seed-three experiment. Datamunge's sorting, work-only and trace APIs share one executing core: the report no longer measures a separate reimplementation. Logical writes exclude argument copies, held-item stores and tracing; they do not predict flash erase cycles or device lifetime. A final cost model contrasts an efficient sorted-input bubble scan with a write-heavy reversal, showing why fewer writes alone need not mean less work.

    Three cells and one held item

    For A=(3,1,2), the ascending target is S=(1,2,3). Item 3 belongs at index 2, where it displaces 2; item 2 belongs at index 1, where it displaces 1; item 1 then closes the cycle at index 0. There are three changed value-cells and three writes. The program draws the actual core placements, retaining each item's original identity. A write means one assignment to a cell of the working value vector, not the assignments involved in keeping the displaced item.

    Derive the ranks and the minimum number of writes

    At an outer start s, all earlier positions are final. Hold item=A[s]. Counting strictly smaller values in A[s+1..n) gives its first remaining target position

    \[r=s+\sum_{i=s+1}^{n-1}\mathbf{1}\{A[i]<\mathrm{item}\}.\]

    If this initial r equals s, the start already has a minimum remaining key and needs no write. Otherwise, advance past any equal keys already in the target block, then place the held item at the first different cell. Keep its displaced value as the next held item and repeat the rank search, closing the rotation when the destination is s. The start cell is unchanged during the active rotation. The conceptual multiset is the held item together with A[s+1..n), which remains exactly the original remaining multiset after each placement. This explains why the rank search remains valid even though a physical intermediate array may temporarily duplicate a value at the start.

    Let S be the unique nondecreasing sequence of input key values. The invariant above makes r the first position of the held key's target block in S[s..n). Skipping equal candidates leaves already-correct cells alone; the chosen cell has the wrong key and becomes final after this write. Every open cycle has an unfilled cell in the held key's block, so the duplicate skip stays in range. A final cell is never overwritten: another copy of the same key skips it, and a different key has a disjoint target block. Each write therefore removes exactly one mismatch. There are finitely many mismatches, so rotations close; then the outer loop advances a correct prefix. The last cell is forced by the remaining multiset. Consequently

    \[M(A)=\sum_{i=0}^{n-1}\mathbf{1}\{A_i\ne S_i\},\qquad W_{\rm cycle}(A)=M(A)\le n.\]

    Every correct key-sort must change all M mismatching cells, so M is a lower bound independent of the method. The invariant shows that this algorithm attains it, including repeated keys. For distinct items, the rearrangement is a permutation decomposed into disjoint cycles; a nontrivial cycle of length k requires and receives k writes, and a fixed point receives none. With repeated keys, there are multiple valid identity permutations, even though S as a key sequence is unique. The write minimum above does not prescribe their order.

    The legacy API takes its vector by value. An lvalue argument is copied before sorting, while an owned temporary can be moved. The kernel then uses constant auxiliary storage. Work-only calls add checked counters; traced calls own two value vectors, final identities and at most n compact placement records. None of these extra copies, identity stores, allocations or held-item assignments are charged as value-cell writes. Physical persistent-memory instructions, transaction logging, cache writebacks and flash page/block operations are separate cost models.

    Duplicate keys: write minimal does not imply stable

    Use original identities to distinguish equal values: A=(2a,2b,1c). Its key sequence target is (1,2,2). The middle value 2 is already correct, so the minimum is two writes. The rank of held 2a begins at index 1, skips the equal 2b, and places 2a at index 2. Then 1c closes at index 0. The final record order is (1c,2b,2a): equal keys have reversed their original order. A stable target would instead be (1c,2a,2b), changing all three record positions. Comparing value-cell and stable-record lower bounds without specifying the requirement would mix two different problems.

    Why the comparison count remains quadratic

    For n≥2, each outer start s=0,...,n−2 scans exactly n−s−1 keys even when it opens no cycle. These initial scans alone contribute

    \[B(n)=\sum_{s=0}^{n-2}(n-s-1)=\frac{n(n-1)}2.\]

    If a nontrivial cycle at start s has k_s writes, its initial scan already accounts for the first placement. Each remaining k_s−1 placement repeats that same-length scan. Writing C for the number of nontrivial cycles and W for writes gives the exact rank-test count and the total number of rank scans:

    \[R=B(n)+\sum_{s\,\mathrm{opening\ a\ cycle}}(k_s-1)(n-s-1),\qquad N_{\rm scans}=n-1+W-C.\]

    For the original seven keys, B=21 and the extra scans contribute (2−1)6+(3−1)5+(2−1)2=18, giving R=39. For n≥2, W≤n and a nonzero W implies C≥1, so

    \[B(n)\le R\le B(n)+(n-1)^2.\]

    Sorted and all-equal inputs attain the lower bound, with zero writes and no duplicate equality tests. A one-step left rotation of distinct sorted keys forms one full cycle at start zero and attains the upper bound. Thus this rank-scan variant has Θ(n²) rank comparisons on every growing input family, including its best case. Equal-candidate searches add equality tests: precisely W+D, where D is the number of successful duplicate skips. Each search skips at most n−1 candidates, so they also fit an O(n²) bound. The measured old “comparisons” column is R; a total key-test count must include both categories. Empty and singleton inputs perform no scans, cycles or writes.

    A cost model separates cheap sorted input from expensive writes

    For a transparent model, charge one unit per key test and ρ units per logical value-cell write, ignoring copies and other instructions. Then T_cycle=R+E+ρW. The existing native bubble_sort_work counts actual strict comparisons and exchanges; charge two value-cell writes per exchange for T_bubble=Q+2ρX. This is a chosen model, not a wall-clock or endurance result. The following comparison fixes n=200 and varies ρ. Sorted input lets bubble sort terminate after 199 comparisons with no writes; cycle sort still performs 19900 rank comparisons. For a reversal, cycle sort uses 200 writes while bubble sort performs 19900 exchanges, modelled as 39800 writes. This native bubble baseline scans all 199 adjacent pairs on every pass, including its terminating zero-swap pass: the reversal takes 200 passes and 39800 key tests. Its model cost therefore exceeds cycle sort even at rho zero for this input, and the difference grows with the assumed write price. Sorted input favours the bubble early exit regardless of that price because both methods write zero cells. The input structure and chosen kernel both matter.

    The trace's default complete input cap is 4096 elements. It rejects an oversized input before copying, allocating identity/history storage or sorting, even if the input is already sorted and would emit no placements. Zero disables only this optional cap. Work-only and legacy calls are uncapped; checked aggregate work counters throw length_error rather than wrap. Results own their values and identities; they retain no caller views and no shared mutable state.

    Permanent tests replay actual trace records against an independent std::sort target, check unique destination cells, preserve every initially correct cell, validate held/displaced identities, and reconstruct exact comparison/scan counts. All 88,573 ternary sequences through length ten and all 46,234 distinct permutations through length eight pass, alongside 1000 seeded mixed/full-range inputs, signed extremes, exact sorted/equal/reverse/full-cycle formulas, empty/singleton/ownership/cap cases and the original forty-size experiment. The new cases also run under AddressSanitizer and UBSan. These algorithmic controls need no unrelated external dataset.

    References and reproducibility

    • B. K. Haddon (1990), “Cycle-Sort: A Linear Sorting Method,” The Computer Journal 33(4), pp. 365–367: https://doi.org/10.1093/comjnl/33.4.365 . The paper describes cycle-based methods with conditional linear-time applicability. Datamunge's variant repeatedly counts smaller keys to obtain ranks; the paper's title does not turn these repeated scans into a linear-time algorithm.
