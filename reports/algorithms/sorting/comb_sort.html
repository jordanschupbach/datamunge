    Comb Sort: Gaps, Actual Work and Unstable Identities

    Abstract

    Sorting a sequence by adjacent forward exchanges can leave a small value moving left only one position per scan. Comb sort permits distant exchanges first, then finishes with adjacent scans. We retain the original seven integers and the seed-four, forty-size shuffle experiment, using actual counters from the native sorting kernels. The report distinguishes measured comparison savings from an asymptotic guarantee, identifies the original full-width bubble baseline, and shows that already sorted input still traverses the wide gaps. Carried original identities expose instability even though equal keys never swap directly. Gap arithmetic is exact for the complete size_t range without multiplying a possibly huge gap by ten.

    One wide exchange, then a shrinking gap

    For the original [5,3,8,1,9,2,7], the first gap is floor(7×10/13)=5. The pass compares positions (0,5) and (1,6), swapping values 5 and 2 in the first pair. The small value jumps five positions left. Each subsequent pass uses

    \[g_{k+1}=\max\left(1,\left\lfloor\frac{10g_k}{13}\right\rfloor\right),\qquad g_0=n.\]

    The gap is shrunk before scanning, and pairs are visited in ascending left-index order. One pass costs n−g key comparisons. A zero-swap pass with g>1 does not stop the algorithm: smaller gaps still have work to do. Only a zero-swap gap-one scan certifies the complete sequence as sorted. This is the plain 10/13 schedule; it does not replace a computed gap of 9 or 10 by 11.

    Correctness, inversions and what the bound says

    Every exchange preserves the input multiset. The gap strictly decreases while it exceeds one, so a logarithmic number of wide scans leads to gap one. From then on this is ordinary full-width forward bubble sorting: the largest remaining misplaced value reaches its final rightmost position on each successful scan. At most n−1 successful adjacent scans and one zero-swap scan suffice. That last scan tests every adjacent pair and establishes nondecreasing order.

    A wide scan alone does not completely sort every gap-separated subsequence; it makes one bubbling traversal. This distinction matters when comparing comb sort with Shell sort's gapped insertion passes.

    Wide scans take O(n log n) key tests in total; the final adjacent phase has the upper bound n(n−1). Hence an O(n²) worst-case upper bound follows for this implementation. The random experiment below does not establish a sharper universal rate. On sorted input there are no swaps, but every wide gap is still visited before one gap-one scan stops. The geometric schedule has Θ(log n) scans, most costing a constant fraction of n, so sorted-input work is Θ(n log n). Sorted bubble input needs just n−1 comparisons. A benefit on one input family is not a guarantee of adaptivity to all nearly ordered inputs.

    The original seed-four shuffle experiment

    Keep one local mt19937 engine seeded with four. For n=10,20,...,400, construct [0,...,n−1] and consume the next std::shuffle permutation from that same engine. This retains the original workload sequence. A seed repeats for this standard library; the shuffle mapping is not promised identical across implementations.

    Sorted and turtle controls

    Generated families isolate claims that a random curve cannot settle. Sorted input verifies comb's compulsory gap schedule and bubble's single scan. A turtle [1,2,...,n−1,0] makes zero travel left only once per full-width bubble scan: n−1 swapping scans and one stopping scan give exactly n(n−1) comparisons. Comb can carry it left by wide exchanges, but its remaining gap-one scan count is measured rather than assumed to be one.

    Strict comparisons still allow unstable equal-key identities

    Label the two equal values in [2a,2b,1] by their original positions zero and one. The first gap is two. Exchanging 2a with 1 gives [1,2b,2a]; the following gap-one scan makes no swap, so the equal twos finish reversed. They never swapped with each other. Nonadjacent exchanges let one pass the other indirectly.

    final positionvalueactual original position
    012
    121
    220

    Actual exchanges 1; initial strict inversions 2.

    More generally, exchange x>y at positions i<j. Their mutual inversion disappears. An intervening z strictly between y and x removes two more inversions; z equal to either endpoint removes one; other z values contribute no change. Thus

    \[I_{\rm before}-I_{\rm after} =1+2\#\{k:i<k<j,\ y<a_k<x\} +\#\{k:i<k<j,\ a_k=x\text{ or }a_k=y\}.\]

    Every gapped strict swap removes at least one inversion, so total swaps are at most the input's strict inversion count. Equality is guaranteed for adjacent swaps, as in the bubble baseline, but not for comb: this example needs one exchange for two inversions. Swap count and comparison count measure different work.

    Exact gap arithmetic and API costs

    The former expression (gap×10)/13 can overflow before dividing, even when the result fits. Write gap=13q+r, with 0≤r<13. Then

    \[\left\lfloor\frac{10g}{13}\right\rfloor =10q+\left\lfloor\frac{10r}{13}\right\rfloor.\]

    The first product and final sum are at most the original gap; the remainder product is at most 120. This is exact size_t arithmetic, with no floating-point shrink factor or larger integer type in the library. The helper also accepts zero and returns one, though empty/singleton sorts skip their pass loops.

    Five records succeed; four throw length_error. Zero cap throws invalid_argument, even for empty input. Caller input is unchanged.

    The legacy and work-only calls sort an owned input buffer with constant extra state; an lvalue call copies the caller's vector. “In-place” describes the internal exchanges, not caller mutation. Work counters exclude vector copies, gap calculations, loop conditions and elapsed time, and throw on overflow. The optional trace owns input, final identities and two length-n snapshots per pass. With p passes it adds O(np) time/storage. Its positive default cap of 1024 records is checked online, before each pass, and throws without returning a partial trace. All calls use independent state. Signed extreme integers are valid because comparisons and exchanges never subtract key values.

    Conclusion

    The original example takes gaps 5,3,2,1,1, twenty-three key comparisons and six exchanges. Wide gaps help the original shuffled and turtle inputs, while sorted inputs expose compulsory work that a single bubble scan avoids. Actual counters support these comparisons without turning one sample curve into a universal linearithmic claim. Carried identities show why strict gapped exchanges remain unstable, and exact quotient/remainder arithmetic makes the gap schedule safe throughout size_t's range.
