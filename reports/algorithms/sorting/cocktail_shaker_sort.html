    Cocktail Shaker Sort: Direction, Inversions and Actual Work

    Abstract

    Sorting an integer sequence means producing nondecreasing values while retaining every occurrence. Adjacent exchanges make that task easy to inspect, but a small value near the end can move left only one position per forward scan. Cocktail shaker sort alternates forward and backward scans. We retain the original seven-integer example and obtain every snapshot from the executing C++ kernel. The actual bounds stop at [2,4], rather than meeting; a final zero-swap scan certifies sortedness. Generated families verify linear best-case and quadratic worst-case comparisons, exact inversion counts and stable duplicate identities. Two directions help some inputs, without a universal factor-of-two work saving.

    Two directions, one adjacent-exchange rule

    The input [5,3,8,1,9,2,7] contains ten strict inversions: pairs of original positions i<j with a[i]>a[j]. A forward scan compares adjacent pairs in increasing index order and swaps only if the left value is greater. Its running maximum reaches the right boundary. A backward scan visits the pairs in reverse order and carries the running minimum to the left boundary.

    The inclusive unsorted window starts at [lo,hi]=[0,n−1]. A forward scan with swaps lowers hi by one; a backward scan raises lo by one. Either scan stops the run when it makes no swaps. The library retains the historical one-position bound updates, including a possible empty final scan. It does not jump to the last swap position. The native records below come from that same kernel as cocktail_shaker_sort(); the report does not run a second sorting loop.

    Why is the result correct? Before a pass, the prefix before lo and suffix after hi are already in their final sorted positions, with every middle value between them. The running maximum or minimum justifies the next boundary update, so the invariant persists. A zero-swap scan has inspected every adjacent pair in the current window and found it ordered. Together with the invariant, that makes the entire sequence ordered. An empty scan also certifies its singleton window. Every successful pass shortens the window, so termination follows.

    Swapping adjacent x>y removes their mutual inversion. Every third item is on the same side of both before and after, so its total inversion contribution does not change. Therefore, if I(a) is the initial strict inversion count,

    \[\text{total swaps}=I(a),\qquad 0\le I(a)\le\frac{n(n-1)}2.\]

    The original window plot, including the stopping scan

    Two complete cycles perform four directional passes and fix two positions at each end. After the fourth pass the values are already sorted, but the kernel has not yet certified that. It scans [2,4] forward, performs two comparisons and stops. Thus five passes perform 6+5+4+3+2=20 comparisons and ten swaps. The bounds need not meet. A directional pass and a full two-pass cycle are different units; counting cycles alone hides the stopping work.

    Exact best, worst and misplaced-end families

    For n≥2, the first pass performs n−1 key comparisons. If the input is already sorted, including an all-equal input, none swap and that is the complete cost. Each subsequent pass has one fewer comparison. Hence the worst possible count is the triangular sum below. Reverse distinct input attains it and also has that many inversions. The historical kernel records a final zero-comparison pass in this case; that record changes pass counts, but not key work.

    \[n-1\le C(a)\le(n-1)+(n-2)+\cdots+1=\frac{n(n-1)}2.\]

    Now fix n≥3. A turtle input [1,2,...,n−1,0] has just n−1 inversions. The first forward pass moves zero left one position, the backward pass carries it all the way to the start, and a final forward scan certifies the remaining window. The lengths n−1, n−2 and n−3 give C=3n−6. A forward-only bubble sort that shrinks its right end by one and stops after a zero-swap pass needs n−1 swapping passes on this turtle, with n(n−1)/2 comparisons. This follows because zero can move left only once per forward pass. Here reversing direction changes quadratic work into linear work, rather than merely halving it.

    For the rabbit [n−1,0,1,...,n−2], the first forward pass already sorts the input; the following backward scan stops, giving C=2n−3. A forward-only variant's second forward scan has the same length, so it has the same comparison count. Reverse order is quadratic for both methods. There is no uniform work ratio. Even one inversion can require a second linear scan; inversion count determines swaps, while the placement of inversions also influences comparisons.

    Stability is about identities, not only equal integers

    An integer-only sorted vector cannot distinguish repeated occurrences. The trace therefore carries original zero-based positions through the very same swaps. For [2,1,2,1,2], the two ones must emerge with original positions [1,3] and the three twos with [0,2,4]. Equal values can change position when a smaller or larger value crosses them, but two equal occurrences can reverse their order only by crossing each other. The strict comparison never exchanges such a pair, so their order is stable throughout the run.

    Costs and limits of the API

    The legacy output-only call takes its vector by value: an lvalue caller keeps the original, while the kernel sorts its owned buffer with constant auxiliary state. Calling it “in-place” describes the internal swaps, not a promise to mutate the caller or avoid its input copy. Signed extreme integers are valid because the kernel compares and exchanges values without subtracting them.

    The optional trace owns every full value snapshot and original-index snapshot. For p directional passes it uses O(np) storage and snapshot-copy work, in addition to the sorting comparisons; p≤n, so tracing can use quadratic memory. Counters do not measure those copies or elapsed time. Its default positive cap of 1024 records is checked before each pass, including an empty terminal pass; zero is invalid even for empty input. Exceeding the cap throws without returning a partial trace. Callers can supply a different positive cap. The legacy output-only call has no such cap. Empty/singleton inputs execute no passes. Returned vectors own their contents and retain no references to the input.

    Conclusion

    The original sequence needs two full cycles plus one stopping scan, with twenty comparisons and ten swaps. Actual bounds stop before meeting. The mechanism preserves sorted outer regions and equal-key identity order; every adjacent swap removes exactly one inversion. Direction matters for comparison work: the turtle family becomes linear, while reverse order remains quadratic and the rabbit gains no comparison saving over a matched forward-only variant. The evidence concerns exact key operations on controlled inputs, rather than a claim about practical speed or every nearly sorted sequence.
