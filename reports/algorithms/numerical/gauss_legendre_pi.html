    Gauss–Legendre π: quadratic mathematics, fixed-precision limits

    Abstract

    Compute π rapidly while tracking how arithmetic precision limits the result. A fast-converging formula can still stagnate at a value that is not correctly rounded. The Gauss–Legendre iteration combines arithmetic and geometric means with a correction accumulator. This report follows an actual first step, reruns the original six-step example and separates reference differences from error against mathematical π. Native snapshots show that the estimate stalls before the means do, while the means themselves eventually remain one ULP apart. Work counters and explicit record/domain limits expose what further fixed-count iterations actually do.

    Start with one arithmetic mean, one geometric mean and a correction

    Initialize a=1, b=1/sqrt(2), t=1/4 and p=1. The arithmetic mean of a and b is about 0.853553; the geometric mean is about 0.840896. Use the old a and its new arithmetic mean to update t, then double p. The diagram reads these values from the first actual native record, including the correction used by the kernel.

    Quadratic gap contraction needs a separate connection to π

    For positive a and b, let a'=(a+b)/2 and b'=sqrt(ab). Their exact gap satisfies

    \[a'-b'=\frac{(\sqrt a-\sqrt b)^2}{2} =\frac{(a-b)^2}{2(\sqrt a+\sqrt b)^2}.\]

    As both approach a positive common limit L, the denominator approaches 8L. The gap therefore contracts quadratically in exact arithmetic. This alone does not determine π: its connection also uses the correction terms and Legendre's relation for elliptic integrals. With the stated initial values, the update is

    \[\begin{aligned} a_{n+1}&=(a_n+b_n)/2,&b_{n+1}&=\sqrt{a_nb_n},\\ t_{n+1}&=t_n-p_n(a_n-a_{n+1})^2,&p_{n+1}&=2p_n,\\ \widehat\pi_n&=(a_n+b_n)^2/(4t_n). \end{aligned}\]

    [Brent (1976), Fast Multiple-Precision Evaluation of Elementary Functions](https://doi.org/10.1145/321941.321944), Section 5, printed 246, gives the limit identity π=A²/T, where A is the common AGM limit and T is the limit of t, and explicitly recommends the displayed finite estimate ([author's full paper](https://maths-people.anu.edu.au/~brent/pd/rpb034.pdf)). It follows the elliptic identities in Section 4. The [author also credits Salamin's independent discovery](https://maths-people.anu.edu.au/~brent/pub/pub034.html). The paper's precision-based stopping and variable working precision differ from this library's fixed-count double model. This is an AGM π algorithm, not Gauss–Legendre quadrature for numerical integration.

    Rerun the original six-step example without a fabricated error floor

    The original program subtracts a double literal for π. That compares two rounded floating numbers; it is not an exact real-number error. The native helper keeps that subtraction and separately compares with std::numbers::pi_v<long double>. The [C++ mathematical constants specification](https://eel.is/c++draft/numbers) uses the nearest representable value of π in the selected type. Long double may add precision on this platform, but that reference is rounded too and may have no extra bits on other platforms. These differences are diagnostics, not certified error bounds. The plot includes only available positive differences; it never replaces zero with a made-up floor.

    The old report's “last bit” claim is contradicted by the actual result: the plateau is two ULPs above the nearest double π, where one ULP here is the spacing at that reference. It is also an approximation to an exact-arithmetic lower formula that rounding can move above π. Such computed values are not certified brackets. A first unchanged estimate only says that two computed estimates compare equal. Extra iterations of the same rounded recurrence do not repair past rounding.

    A nonzero correction can disappear when t is stored

    At stage 4, the used correction is positive but too small to change the rounded t. The means still change at that stage. At stage 5, a, b and t all stop changing, yet a and b remain distinct, one double ULP apart. The doubling weight p continues to change, so it is intentionally excluded from the mean-state stagnation flag. Neither flag asserts mathematical convergence.     Requested fixed-precision work still grows linearly

    For N admitted stages, the shared recurrence executes N arithmetic means, N geometric means, N correction updates and N weight doublings. Including initialization, it uses N+1 square roots. The analysis APIs evaluate N+1 estimates to detect changes, whereas the legacy scalar API evaluates only the final estimate expression. No API stops early merely because an estimate or mean state stagnates. Ordinary analysis uses O(N) arithmetic and O(1) result storage; owned fixed-schema histories use O(N) records and copying.

    This operation count differs from the complexity of obtaining more mathematical digits with variable precision. Brent's discussion on printed 247 requires guard bits and gives O(M(n)log n) cost for n-bit π using n-bit multiplication cost M(n). It also notes that AGM is not self-correcting. Quadratic exact convergence cannot create millions of digits inside a fixed double; arithmetic precision must grow. The following plot counts actual square-root evaluations, not elapsed time.

    Reference zero, owned records and bounded control counts

    Comparing the nearest double π with itself gives a zero double-reference error and no available logarithm. A genuinely wider reference still reveals that this double constant approximates an irrational real value. The helper reports log availability explicitly; it does not convert zero into a guessed error floor. ULP offsets below use the local spacing at rounded double π.

    Checked analysis/trace counts must lie from 0 through the format's safe used-weight limit, 1024 for binary64. The final unused p can become infinity at that boundary, while the estimate stays finite; a later use is forbidden. The old function returned NaN at 1025. New calls reject that suffix before work. Legacy negative counts retain their zero-stage behavior; new checked analysis/trace APIs reject negative counts instead of silently interpreting them as precision requests.

    Whole history admission counts one initial-state record plus N complete stage records before initialization or allocation. These units are records, not scalar entries or bytes, and exclude ordinary final output, root/work metadata, working storage and allocator bytes. This is not a peak RAM limit. Default cap is one million; zero disables only that optional cap. There is no truncation, replay or partial returned trace. A zero-stage trace still contains its one initial record.

Quadratic mathematics explains the rapid initial improvement; finite precision explains the plateau, disappearing corrections and the gap between equality tests and mathematical convergence. These generated constant-iteration states need no external dataset.
