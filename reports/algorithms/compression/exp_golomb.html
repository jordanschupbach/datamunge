    Exp-Golomb: Length Prefixes, Orders and Exact Bit Boundaries

    Abstract

    A sequence of nonnegative integers needs recoverable word boundaries without assigning every value the width of the largest one. Exp-Golomb uses a short length prefix and a binary payload, favouring small values while still allowing large ones. We begin with the five-bit order-two encoding of ten, preserve the original codewords and mixed-sequence round trip, and measure how order and magnitude affect payload size. Actual emission/parsing spans expose the boundary; checked native arithmetic supports all uint64 values, including a 129-bit word. The caller supplies the order and message framing.

    Start with ten at order two

    Order k splits n into a quotient q=floor(n/2^k) and its k low bits. For n=10 and k=2, q=2 and the low bits are 10. Encode q+1=3 as binary 11 with one leading zero, then append 10. The actual word is 01110. Its three fields have lengths one, two and two. The diagram reads captured indices from the same kernel that emitted the bits; decoding records them too.

    Derive the code and its inverse

    For a known order k>=0, write n=q·2k+r, with 0<=r<2k. Let m=floor(log2(q+1)) mathematically. Emit m zeros, binary(q+1) in m+1 bits, then r in exactly k bits, most significant bit first:

    \[L_k(n)=m+(m+1)+k=2\lfloor\log_2(\lfloor n/2^k\rfloor+1)\rfloor+1+k.\]

    After seeing m zeros and the first one, the decoder knows that m+k further bits complete this word. If their combined unsigned value is z, then n=(2m−1)·2k+z. Equivalently, recover the quotient from the m bits after the one, then attach the low k bits. This is the order-k inverse in ITU-T H.274 section 9.1, equation (72).

    For fixed k, two different zero-run lengths first differ where one word has reached its leading one and the other still has zero. Equal zero-run lengths imply equal total word lengths. Hence no distinct word is a prefix of another. Each fixed-length field is preserved exactly, so concatenated complete words have a unique inverse. The outer message still needs a stopping rule: prefix-free words alone do not identify where one message ends and another begins.

    The mathematical construction admits arbitrarily large integers. This API accepts every uint64 value and orders 0 through 63. It avoids forming q+1 when that would equal 2^64, and never shifts a uint64 by 64. Order zero is gamma coding of n+1, so zero is valid and encodes as 1. This differs from positive-integer gamma coding of n itself.

    A vector<bool> stores the logical bit sequence using its specialised container representation. The API defines neither a packed-byte format nor byte endianness. exp_golomb_bit_string produces ASCII debug text; its one-character-per-bit storage is different again. All comparisons below count payload bits, excluding order, count, width and other framing.

    Preserve the original examples and find the exact threshold

    The original report lists zero through eight and round-trips {0,1,3,7,15,100,1000,65535}. These codewords remain unchanged. Its eight values occupy 90 order-zero bits against 128 bits for a 16-bit common field. Here 16 is also the smallest common width, because 65535 occurs in the sample.

    Length is a staircase in n, including on a log2(n+1) axis. It is constant for 2m−1<=n<=2(m+1)−2 and increases by two at each threshold. L_0(n)<16 exactly when 0<=n<=254; at 255 the length jumps to 17. The native length helper obtains this from integer widths without encoding an unnecessary temporary word.

    Choose an order for the source magnitudes

    For n<2^k, q=0, so every word has length k+1. Increasing k therefore penalises very small values but can reduce the doubled quotient prefix for large ones. No single order wins on every source. For example zero costs one bit at order zero but 64 bits at order 63; UINT64_MAX costs 129 bits at order zero and 66 at order 63.

    Measure actual work and optional retained history

    For N copies of ten at order two, the kernel actually visits N zero positions, 2N quotient positions and 2N low-bit positions, for B=5N. These counters describe logical bit positions, excluding scalar preflight, allocation, copies and validation; they are not CPU instruction counts. Both encoding and parsing take O(N+B) time. Ordinary encoding owns O(B) output, while decoding owns O(actual values) output and borrows its input. Ordinary/work calls keep no optional word history.

    A trace owns B bits, N value entries and N whole word records, so the defined logical capture is C=B+2N=7N for this family. Scalar metadata, capacity, runtime temporaries and allocator/container bytes are excluded; C is not peak RAM. Encoding checks known C before copies or emission. Decoding first reserves its whole input B, including any unread tail, then two entries before each completed value/span append. The quota defaults to one million; zero disables only this optional quota. Checked arithmetic and container limits remain, and exceptions expose no partial trace.

    Full range, framing and invalid attempted words

    At UINT64_MAX and order zero, q+1 is mathematically 2^64. Its binary representation is a one followed by 64 zeros: a real 65-bit payload. The entire word has 64 prefix zeros and 129 bits. The implementation emits that representation without wrapping n+1. The saved old implementation instead encoded UINT64_MAX as the single bit zero, and sanitizer probes exposed shifts by 64, negative shifts and truncated-stream reads beyond the bit vector. Those cases now have specified results or errors.

    The decoder's count is a nonnegative upper limit, preserving the legacy bounded-prefix contract. It returns fewer values when the input ends at a complete-word boundary, and reads nothing for count zero. Once the limit is met it leaves any tail unread and unvalidated. Every attempted word must be complete, however: a partial zero run, quotient or suffix throws invalid_argument. An overwide prefix or value beyond uint64 throws overflow_error. Invalid order or negative count is rejected even on empty input. Exact-count/full-frame callers must additionally check values.size()==requested_count and consumed_bits==bits.size().

    Appending one word preserves any existing bit prefix without parsing it. It validates/reserves complete append geometry before writing. Trace results own their input/output, values and word records independently. The next program exercises prefix framing, append mutation, native limits and exact/one-short capture quotas.

    Scope and reference

    Short word boundaries solve integer delimiting for a known order. They do not select a source model, choose the best order, frame a message, or pack a byte stream. A complete codec must supply those layers. The executed examples preserve the original nine codewords, eight-value round trip and ten sampled lengths, while checking full-width arithmetic, actual spans, distribution-dependent costs and malformed attempted words.

[Official English specification](https://www.itu.int/rec/dologin_pub.asp?id=T-REC-H.274-202205-S!!PDF-E&lang=e&type=items). The native API follows the unsigned order-k mathematical coding rule on uint64 with checked framing parameters and complete attempted words. Field-specific video syntax constraints, signed mappings, NAL framing and full video bitstream conformance are outside this API.
