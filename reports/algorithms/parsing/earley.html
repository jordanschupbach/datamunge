    Earley Recognition: Actual Dotted Items, Nullable Closure and Measured Joins

    Abstract

    Given a context-free grammar and a word of atomic tokens, we want to decide whether the start symbol can derive the whole word. Left recursion, ambiguity and empty productions make a simple recursive search difficult to terminate correctly. Earley recognition instead closes finite sets of dotted production items. We begin with one token and four actual items, retain the original balanced-word and expression examples, and inspect a nullable completion that a later waiter must reuse. Owned first-insertion reasons, exact family work counts and checked capture controls make the recognizer's result reproducible without claiming to enumerate parse trees.

    Four actual items for one token

    Use S→A and A→a, with the one-token input [a]. Boundary zero seeds S→.A, predicts A→.a, then scanning a creates A→a. at boundary one. Completion combines that finished A with the original waiting S item to produce S→A. spanning the whole input. The printed table and native diagram come from those actual inserted items and their first parents. The dotted text quotes atomic symbol names and prints the origin in parentheses.

    Define closure over a finite chart

    An item in column k has coordinates (production id, dot, origin). For A→α.β with origin j, α has matched tokens in [j,k), and β remains. A symbol is nonterminal exactly when it occurs as a production left-hand side. The operations are:

    • Prediction: before a nonterminal B, add each original B→.γ at origin k.
    • Scanning: before a matching terminal token, advance the dot into column k+1.
    • Completion: a finished B from j to k advances every item in column j waiting for B.

    Seed every original start production in column zero. Acceptance requires a completed start production at the final boundary, with origin zero. No synthetic start item is added, preserving the original chart statistics. Rules retain their original ids and duplicate rules remain distinct items.

    Soundness follows by induction over these deductions: prediction starts an empty prefix, scanning consumes the specified token, and completion joins adjacent matching spans. For completeness, every successful derivation's prediction, token advance and completed child must eventually be joined. An agenda processes each inserted item once, and deduplication makes its closure finite. If M is the sum of RHS-length-plus-one over all original productions, at most M(N+1)(N+2)/2 distinct items can occur across N+1 columns: each dotted production has at most k+1 origins in column k. This remains finite even when a nullable cycle admits infinitely many trees.

    The implementation interns opaque symbol strings, predicts a requested nonterminal once per column, and indexes waiters and first completed spans. It uses integer comparisons in the recognition loop. Insertion-ordered vectors determine output order; hash indexes only answer membership/lookup queries. Expected constant hash access gives the usual fixed-grammar O(N³) general join bound and O(N²) item/index storage. String preparation is additional. These are not unconditional worst-case hash-time claims. No lookahead, LR(0) precomputation, Leo optimization or parse forest is included.

    Retain the original balanced words and left-recursive expressions

    The original grammar S→a S b | a b recognizes ak bk for k>=1. The next program retains all six original tests. It also retains the left-recursive precedence grammar E→E+T|T, T→T*F|F, F→(E)|id and its three original input words. Naive recursive descent on that left recursion would call itself without consuming a token; Earley needs no grammar rewrite. The E/T/F grammar specifies precedence and is not the ambiguous S→SS|a grammar used later.

    Empty rules require both arrival orders

    Use S→A B, A→ε and B→A with an empty input. A can complete before B→.A is predicted. When that later item begins waiting for A, simply processing A's old completion once is insufficient. The waiter must notice the already completed zero-width span and advance immediately.

    The earlier implementation also iterated a column's vector by reference while nullable completion appended to the same vector. A compiled old-header sanitizer probe reproduces a heap-use-after-free. The new kernel copies the current item before inserting, indexes processed waiters, and remembers the first completed span. It joins either when the span finishes or when a later zero-width waiter arrives. No borrowed item reference survives insertion.

    The same closure handles unit cycles and S→SS|ε|a without an infinite search. It recognizes language membership; it does not enumerate all parses. Even the epsilon-free S→SS|a has five binary parses for four a leaves: splitting the root gives 1·2+1·1+2·1=5. Several derivations can therefore share one item. First-insertion reasons record one sound way each item arrived, not every derivation that could justify it.

    Derive two exact growth families

    For the original accepted word ak bk, N=2k. Its column sizes are 2 initially, four at each a, two at each nonfinal b, and one at the end. Thus I=6k+1=3N+1 unique items. Every inner completed S has one outer waiter, while the root has none, giving k−1 completion joins. This particular family is linear; a bounded count in this plot does not establish a general bound for every grammar.

    For S→SS|a on a^N, every positive substring is an S. At boundary j there are j completed items, j items after their first S, and two predicted items, for 2j+2 items. Consequently

    \[I=\sum_{j=0}^{N}(2j+2)=(N+1)(N+2).\]

    At origin j there are j+1 waiters for S, and N−j nonempty S spans can finish later. Each waiter/span pair is joined once, giving

    \[J=\sum_{j=0}^{N-1}(j+1)(N-j)=\frac{N(N+1)(N+2)}{6}.\]

    Capture budgets and precise token semantics

    A trace owns its grammar, tokens, actual chart and parallel first reasons. Its base cost is 2N+P+sum(rhs lengths)+2 logical records: start/LHS/RHS symbol strings, token strings and one metadata record per chart boundary. Each new unique item and first reason add two records. String bytes, runtime hash indexes, scalar fields and allocator overhead are excluded. The default cap is one million; zero disables only that optional quota. Raw geometry and the base cap are checked before copying or column allocation. Each further unique insertion is checked online; duplicate attempts consume no capture entries. Failure returns no partial trace.

    The original eight-token chart therefore costs 25 base records plus 2·25 item/reason records, exactly 75. A one-short budget fails even though the grammar is valid. Counts, production/dot/origin indices and legacy int column sizes have mandatory representability checks.

    Symbols are opaque names. An empty RHS derives an empty word, while a RHS containing the one empty string names a terminal and consumes one atomic token. Empty strings, embedded NUL and UTF-8 symbol names remain valid; tokenization is the caller's responsibility. The selected-item formatter escapes control bytes and checks its local coordinates. It does not certify every field of a caller-edited trace.

    What was verified

    Separate old/current binaries preserve 8,194 original verdict/chart-size cases: every a/b word through length twelve and all original expression examples. The old nullable use-after-free is reproduced separately; the new seven-case sanitizer suite covers all 8,191 short a/b words, 7,560 queries on seeded nullable/cyclic grammars against an independent least fixed point of interval languages, rule-order and duplicate controls, opaque symbols, exact/short/disabled capture limits, ownership and a 20,000-rule unit chain without recursive library calls.

    Every captured item's first parents are checked as a sound earlier prediction, scan or completion. Final-chart certificates independently count requested predictions, matching scans, distinct completed spans and all waiter/span pairs, verifying work identities without replaying the implementation. A finite item chart establishes recognition, not a count or enumeration of all parses. A rejected word also does not provide automatic error recovery or an explanation of the intended source text.

Horspool (2002), [Practical Earley Parsing](https://webhome.cs.uvic.ca/~nigelh/Publications/PracticalEarleyParsing.pdf), The Computer Journal 45(6), 620–630, doi:10.1093/comjnl/45.6.620, explains the nullable late-waiter problem and reviews Earley's earlier completed-symbol remedy. The implementation here uses indexed waiters and completed spans for that handshake; it does not implement their LR(0) automaton construction or claim to return a parse forest.
