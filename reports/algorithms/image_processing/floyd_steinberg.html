    Floyd–Steinberg dithering: actual diffusion, finite edges and tone

    Abstract

    A binary image can suggest intermediate brightness by varying the density of white pixels. Floyd–Steinberg error diffusion quantizes pixels in raster order and transfers the resulting errors to future neighbors. This report preserves the original forty-by- sixty-four gradient and all its output pixels, inspects actual native updates, and compares a threshold baseline with diffusion. Image edges discard weighted error, so finite images do not have a guarantee of exact global or local tone preservation. Work counts, floating-point evidence and input/quota controls make those limits explicit.

    The implemented raster rule

    Scan each row left to right, from the top row down. At a pixel, the working value already includes earlier diffusion. Values strictly below 128 become zero; values at or above 128 become 255. Set e to working value minus that output and update the future neighbors in this order: right by 7e/16, down-left by 3e/16, down by 5e/16, and down-right by e/16. Skip neighbors outside the image, without renormalizing.

    The fixed128 convention and traditional stencil are described in section3 of [Speigle and Feng's research paper](https://corporate.jp.sharp/rd/journal-76/pdf/76-05.pdf). Their later threshold-modulation and color extensions are outside this implementation. The historical reference is R.W.Floyd and L.Steinberg, “An Adaptive Algorithm for Spatial Greyscale,” Proceedings of the Society for Information Display17(2),75–77(1976).

    The cutoff is part of the existing library contract. For an arbitrary double, 127.75 is closer to 255 than to zero, yet this implementation outputs zero for a single pixel of that value. Describing it as unrestricted nearest-level rounding would be incorrect. Working values are not clipped to0..255; feedback can push them beyond that nominal grayscale range.

    Compare independent thresholding on a uniform patch

    On a uniform128 patch, independent thresholding makes every pixel white. Error diffusion can instead mix black and white pixels so that the arithmetic mean is closer to the input.     Visual artifacts depend on image content and scan direction. The primary research paper cited above discusses patterning, worm-like structures and edge effects in traditional error diffusion. Our fixed raster scan is not a serpentine variant, a color halftoner, a noise-driven method or their improved threshold-modulation algorithm. No claim that it is always best-looking or faster is needed here.

    Boundary loss and finite-image tone balance

    For a pixel p let e_p be its actual quantization error and a_p the sum of weights whose destinations lie outside the image. In exact arithmetic, summing every pixel cancels internal transfers, leaving

    \[\sum_p\mathrm{input}_p-\sum_p\mathrm{output}_p =\sum_p a_p e_p.\]

    The right-hand side is signed: positive loss means the output sum is smaller; negative loss means it is larger. For floating-point computation the native balance_residual is input sum minus output sum minus that signed boundary term. A small residual checks this accounting, not perceptual fidelity. It is not a promise that image means match. A single pixel of127.5 becomes zero and discards its entire 127.5 error, providing a direct counterexample to exact finite-image preservation.

    For a nonempty R-by-C rectangle, the valid-update count is R(C-1)+(R-1)C+2(R-1)(C-1). Counting this stencil and validating every row/value gives O(R+N) work for N pixels. The by-value ordinary API owns a double scratch image and returns an integer image, requiring O(R+N) storage. The earlier constant extra-memory claim omitted these images. Only the per-pixel scalar state is constant.

    An owned trace additionally retains the input, N steps and at most4N updates. Its complete admission bound is2R+7N entries: two outer-row arrays, two cell arrays, one step per pixel and up to four updates per pixel. Temporary scratch, bytes and peak RAM are not the quota units. The default one-million-entry cap is checked before copying trace input; zero disables only that optional cap. No partial trace or sampled/truncated history is returned.

    Domain, geometry and ownership controls

    Every row width is validated before scanning source values. Ragged rows reject even when the first row has width zero. Every source value must be finite; finite values outside nominal0..255 are accepted without clipping. Actual double transfers and updated values must stay finite, so an extreme source can fail if it has a valid neighbor even though an extreme single pixel succeeds. The grayscale renderer has its own display domain0..255; that does not change the numerical kernel's input rules.

    Checked controls: ragged rejected true; NaN rejected before quota true; whole cap31 rejected true; cap32 steps 4; neighbor arithmetic overflow rejected true. Ownership: source unchanged after call true; owned input independent after caller edit true. Cutoff127.75 output 0; exact128 output 255; finite maximum single-pixel output 255. Virtual size_t-max top-right center: right false; down-left true; down true; down-right false. One-pixel tone control: input 127.5; output 0; discarded 127.5; residual 0.

    The ordinary by-value overload copies an lvalue before its body validates; an rvalue can transfer its storage. Work and trace overloads validate read-only input before copying. No numerical API mutates the caller's source, and failures return no partial output. Empty and zero-width rectangular images retain their shapes.

    All five programs are complete editable C++ sources and call the shared native kernel, fixtures, threshold baseline and statistics helpers. There is no external dataset. Verification preserves original pixel decisions and exact floating-point update bits, checks small grids against independent rational gathering, uses higher-precision conditional controls, replays actual update evidence, tests signed edge balance, full-width geometry, quotas and ownership, and runs address/undefined-behavior sanitizers. Native figures are saved locally and copied into the report.
